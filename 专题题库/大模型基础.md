### LLM-001：大模型是怎么训练出来的？

**常见问法**

- 大模型是怎么训练出来的？

- 预训练和微调的区别是什么？

#### 面试回答

主流路径分三段。口述时按“每个阶段解决什么问题”展开，别只报名词：

- 预训练：在海量文本上做自回归的下一 token 预测，用交叉熵损失学语言和世界知识，绝大部分算力花在这里。
- 后训练：先用监督微调（SFT）配指令—回答数据，教会模型遵循指令；再做偏好对齐，塑造有用、诚实、无害的回答风格。对齐有两条路：RLHF 是以人类偏好训练奖励模型后再做强化学习，DPO 直接从偏好对优化。
- 部署优化：用蒸馏、量化、剪枝压缩模型；推理模型还会再用强化学习训练更长的思考行为。

#### 技术细节

**预训练**

- 目标就是“预测下一个 token”。
- 规模与数据质量决定能力上限，数据要经过清洗、去重与配比。

**后训练的两条技术线**

- SFT 的数据量远小于预训练，但对质量很敏感。
- RLHF 的流程是“偏好标注 → 奖励模型 → PPO 类优化”；DPO 跳过显式奖励模型，直接优化。
- 对齐可能带来副作用：谄媚（迎合而不是纠错）与模式坍塌，需要评测监控。

**一条常被追问的因果**

- 训练好的权重是冻结的，推理时不再学习 —— 这正是“模型知识有截止日期、需要 RAG 补新”的根因（见 [[专题题库/大模型基础#LLM-008：微调和 RAG 的区别与优劣势是什么？|LLM-008：微调和 RAG 的区别与优劣势是什么？]]）。

#### 深挖追问

1. **为什么预训练能涌现出推理能力？**（补充练习）

   机制尚无定论，能确定的是涌现和规模相关。工程上可以这样答：“更大的参数加更多样的数据，让下一 token 预测学到了更可迁移的表征。”别把它说成已经解决的问题。

2. **预训练和微调到底差在哪？**（面经实际出现；[[面经/美团/一面/0003#Q14：预训练和微调的区别。|MJ037 · 美团 · 一面 · Q14]]）

   按四个维度说：

   - 数据：预训练用海量无标注语料做自监督；微调用小规模标注数据（SFT 指令对、偏好对）。
   - 目标：预训练学语言与世界知识，决定能力上限；微训练“怎么表现”，也就是听指令、格式、风格。
   - 算力与频率：预训练是千卡级的一次性投入；微调可以反复做、成本也低，LoRA／QLoRA 单机就能跑。
   - 风险：微调过量会灾难性遗忘，要混入通用数据或者用 PEFT。

   一句话收口：预训练造能力，微调塑行为；知识更新两头都不负责，那是 RAG 的活（见 [[#LLM-008：微调和 RAG 的区别与优劣势是什么？|LLM-008]]）。

### LLM-002：Transformer 的 Encoder 和 Decoder 是什么？

**常见问法**

- Transformer 的架构，Encoder 和 Decoder 是什么？
- Transformer 架构的组件和功能。

#### 面试回答

Transformer（2017）用自注意力替代循环。每一层里做的事：

- Q、K、V 三个投影，实现“用 query 对所有 key 加权取值”，全并行、不需要顺序传递。
- 多头注意力把交互拆到不同子空间。
- 残差连接＋层归一化稳住深层训练，前馈网络做逐位置变换。

Encoder 和 Decoder 的差别：

- Encoder：堆叠“自注意力＋FFN”，每个位置都能看全文（双向），适合表示与理解任务（BERT 系）。
- Decoder：额外需要因果掩码自注意力，也就是每个位置只能看左侧，保证自回归生成不偷看未来；还可以加交叉注意力读取 Encoder 输出，翻译类 seq2seq 就是这个结构。
- 当前主流大模型多为纯 Decoder 堆叠，靠因果掩码逐 token 生成。

#### 技术细节

**序列长度为什么贵**

- 注意力复杂度随序列长度平方增长，这是长上下文的主要成本。
- 于是衍生出分组查询注意力（GQA）、滑窗／线性注意力等优化。

**顺序信息从哪来**

- 自注意力本身对顺序无感，位置信息靠位置编码注入：原始正弦编码、可学习编码、RoPE 旋转编码等。

**常被一起问的 KV Cache**

- 它是推理期把已算过 token 的 K/V 缓存下来复用，避免重算。
- 和“训练架构”无关，但面试官常把它和架构放在一起问。

**两种整体结构的取舍**

- Encoder-Decoder（T5 类）与 Decoder-only：理解任务用双向信息更全；生成任务用统一的因果结构，更简单也更好扩展。

#### 深挖追问

1. **自注意力和 RNN 的本质区别？**（补充练习）

   连接方式不同。自注意力让任意两个位置一步直连、整条序列并行计算，代价是平方复杂度；RNN 只能顺序传递，复杂度线性，但难并行，长程信息还会衰减。

### LLM-003：大模型的分词器是什么？

**常见问法**

- 大模型分词器是什么？

#### 面试回答

分词器（tokenizer）把原始文本切成模型词表里的 token 序列。现代 LLM 普遍用子词算法（BPE 及其变体、SentencePiece／Unigram）：高频词保留整体，低频词拆成子词片段，这样既控住词表规模，又能表示没见过的词。

工程上要记住三点：

- 上下文长度、计费和截断都按 token 算，token 数不等于字数。
- 中文、数字、代码在不同词表下的切分效率差异明显。
- 分词器不通用：同一段文本换个模型，长度可能显著变化。

#### 技术细节

**BPE 是怎么训练和使用的**

- 训练时从字符出发，按语料统计反复合并高频词对，形成词表。
- 推理时按这套训练好的合并规则切分。

**特殊 token**

- 角色分隔、EOS 这些由分词器与模板共同处理。
- 把特殊控制符拼进用户输入，是注入风险面之一。

**数字为什么吃亏**

- 数字被切碎会影响算术与精确匹配的表现，是“模型算不好数”的成因之一（还叠加表示与训练方面的因素）。

**别和 embedding 混成一步**

- 分词只产出离散 ID，随后查 embedding 表才得到向量 —— 两步不要混为一谈（见 [[专题题库/RAG#RAG-005：查询时为什么使用 embedding，如何使用？|RAG-005：查询时为什么使用 embedding，如何使用？]]）。

#### 深挖追问

1. **为什么按 token 而不是按字计费？**（补充练习）

   因为模型的计算量和上下文占用都由 token 序列决定，字数和它不成比例。只有按 token 计，才和真实成本对应。

### LLM-004：CoT 思维链是什么，为什么有效，有什么缺点？

**常见问法**

- CoT 是啥？为啥效果好呢？有啥缺点？

#### 面试回答

CoT（Chain-of-Thought，思维链）是让模型把中间推理步骤显式生成出来、再给结论的提示技术。两种起手：zero-shot 时加一句“让我们一步步想”，few-shot 时在示例里带上推理过程。

为什么有效：

- 多步问题一步输出，等于把组合搜索压进一次前向计算。
- 显式生成的中间 token 会进入后续步骤的条件上下文，相当于用自回归的串行计算换取额外深度，每一步只需要解决局部的小问题。

缺点要一起说：

- token 与延迟成本明显上升。
- 中间步骤出错会沿链放大。
- 生成的推理链可能只是事后合理化，并不忠实反映实际的计算过程，不能当解释用。
- 简单任务上反而引入噪声、拉低效果。
- 推理模型把思维链隐藏起来时，外部拿不到过程。

#### 技术细节

**常见变体**

- 自洽性：采样多条链再投票。
- ToT：树状展开搜索。
- Least-to-Most：先分解问题，再逐步求解。

**和 Agent 规划的关系**

- 同源：都是把长程任务摊成中间状态。
- 区别：CoT 全在单次生成的 token 流里；Agent 的中间步骤可以调用工具，拿外部反馈来纠偏。

**评测与上线**

- 只报最终答案正确率，分不清是“链对了”还是“蒙对了”，需要过程级检查。
- 生产上按任务复杂度分级启用，不默认全程开。

#### 深挖追问

1. **CoT 和 Prompt 里写“分步骤执行”是一回事吗？**（补充练习）

   两者都属于激发模型逐步生成，但不是一回事。效果依赖模型能力与任务类型，措辞本身不是充分条件，有没有增益要在评测集上验证。

### LLM-005：温度、top-p、top-k 是什么，各场景怎么设置？

**常见问法**

- [[面经/美团/一面/0002#Q16：提示词进入生成初步参数后可能有很多，你怎么选择参数？|MJ032 · 美团 · 一面 · Q16]]
- 温度值／top-p／top-k 分别是什么？各个场景下的最佳设置是什么？

#### 面试回答

三者都作用在采样阶段：

- 温度：logits 除以 T 之后再 softmax。T→0 趋近贪心（总选概率最大的那个），T 越大分布越平、随机性越高。
- top-k：只在概率最高的 k 个 token 里重新归一化后采样，k=1 等价于贪心。
- top-p（核采样）：按概率从高到低取累计概率≥p 的最小候选集再采样，候选数会随分布形状自适应。

至于“各场景最佳设置”，只有方向、没有全场景答案：

- 事实问答、抽取、代码、函数调用用低温（0～0.3），求稳定、可复现。
- 创意生成调高。
- 收窄 p／k 同样是在降低发散。

重要的参数组合应该在固定 seed 下用评测对比出来，而不是背一个标准答案。

#### 技术细节

**温度改变不了知识**

- 它只改变分布形状。低温同样会自信地答错 —— 幻觉不会因为 T=0 就消失。

**top-k 与 top-p 的差别**

- top-k 是固定截断，分布平坦时可能把正确候选砍掉；top-p 自适应，所以更常用。两者可以叠加。
- 贪心解码容易掉进复读循环，用采样或 penalty 可以缓解。

**格式问题不归温度管**

- 结构化输出要配合受限解码／JSON mode 来保证格式合法，而不是指望低温自动守格式。

**回归评测要注意的**

- 多轮会话里温度也会影响上下文利用的方差，回归评测要多次运行取分布。

#### 深挖追问

1. **temperature=0 输出就一定可复现？**（补充练习）

   不一定。同一模型、同一版本、同一硬件下通常接近确定性，但服务端批处理、MoE 路由和版本更新都可能引入差异。别把它当成严格的事务保证。

2. **“提示词进入生成初步参数后可能有很多，你怎么选择参数？”怎么答？**（面经实际出现；[[面经/美团/一面/0002#Q16：提示词进入生成初步参数后可能有很多，你怎么选择参数？|MJ032 · 美团 · 一面 · Q16]]）

   原句省略较多，先确认口径再答，两种都要会讲。

   若指**模型推理超参**：

   - 判定、抽取、代码生成这类要求稳定复现的任务，把 temperature 压到接近 0，确实需要多样性时才调高。
   - top-p 控制候选宽度，一次只动一个参数，便于归因。
   - 有严格格式要求时配结构化输出＋schema 校验，而不是指望低温自动合规。

   若指**模型给出的多套候选参数／方案如何择优**：

   - 先按硬约束过滤，把超限、违规的剔掉；再按目标函数排序，比如成本、延迟、准确率、可维护性。
   - 能自动评测就用固定评测集跑分；不能自动判定的抽样人工复核。
   - 保留被选参数与评测记录，方便复现。

   两种口径的共同落点：能确定的规则交给代码，模型只负责生成候选。

### LLM-006：Prompt Caching 是什么？

**常见问法**

- Prompt Caching 是什么？

#### 面试回答

Prompt Caching 就是对请求里稳定不变的前缀（系统提示、工具定义、长文档等）复用已经算过的注意力状态。后续请求前缀命中时跳过重算，首 token 延迟下降，命中部分按更低价格计费。各家机制不同：Anthropic 用显式的 cache_control，OpenAI 是自动前缀缓存。

用起来记三条：

- 它是前缀精确匹配：稳定内容放最前，易变内容追加在后面，别在长前缀中间插动态值。
- 各家都有最小可缓存长度、TTL，以及写缓存的加价。
- 它只省计算和费用：不减少上下文占用，也不改变模型行为。

#### 技术细节

**什么场景收益最大**

- Agent 场景：每轮循环都携带同一份系统提示与工具 schema，前缀稳定、命中率高。
- 把时间戳、请求 ID 这类易变值放到消息尾部，避免击穿前缀。

**失效与隔离**

- 缓存按模型版本隔离，升级模型就失效。
- 多租户下的缓存边界是供应商侧的隔离实现；敏感数据仍要按“会进入供应商计算”的合规口径处理。

**别和语义缓存混为一谈**

- 语义缓存是按问题相似度直接返回历史答案，和 Prompt Caching 是两回事。
- Prompt Caching 不改变生成结果；语义缓存会复用答案，存在串数据风险（见 [[专题题库/RAG#RAG-006：如何设计垂直业务 RAG 路由与多 Agent 知识库复用？|RAG-006：如何设计垂直业务 RAG 路由与多 Agent 知识库复用？]]）。

#### 深挖追问

1. **上下文里内容越多缓存越省钱吗？**（补充练习）

   不是。只有稳定前缀那部分受益，总量仍然占着上下文窗口，也照样影响检索与生成成本。该裁剪的内容，不能指望缓存替你豁免。

### LLM-007：微调的方案有哪些？

**常见问法**

- 微调的方案有哪些？自己做过没有？

#### 面试回答

按改动范围分两大类：

- 全参数微调：更新全部权重。效果上限高，但显存与算力开销大、容易灾难性遗忘、多租户也难维护。
- 参数高效微调（PEFT）：最常用的是 LoRA。基座权重冻结，只在注意力等投影旁边加一对低秩矩阵 A·B，只训这部分；训练完可以合入基座，推理时零额外延迟。QLoRA 再往前一步，把基座 4bit 量化，单卡也能跑大模型。此外还有 Adapter、Prefix／Prompt Tuning 等。

数据侧的通用要点：构造指令集、控制质量与多样性、与评测集去污染。训练后在保留集上和基座对比，既验证目标能力提升，也验证通用能力没有回退。

做过就按【基座、数据规模、方法、指标】讲；没做过就如实分层说明。

#### 技术细节

**LoRA 的关键超参**

- 秩 r、alpha、作用在哪些模块、dropout。
- 任务越是“改行为、改格式”，低秩就越够用；要注入大量新知识时性价比会下降，那种需求该走 RAG（见 LLM-008）。

**另外两类常被叫作“微调”的做法**

- 继续预训练（domain-adaptive pretraining）：介于预训练与 SFT 之间，用在领域语料充足的时候。
- 对齐阶段的微调（DPO 等）：改的是偏好行为，不是知识。

**迭代与部署上的坑**

- 多轮迭代时把每一版的评测都存下来，防止“越调越像样例”。
- 部署侧还要处理基座升级之后 LoRA 要不要重训的问题。

#### 深挖追问

1. **LoRA 权重能热插拔吗？**（补充练习）

   可以。要么按任务切换适配器，要么合并进基座。区别在于合并之后就失去了快速回退的能力，而且多任务之间还可能互相干扰，要按场景选。

### LLM-008：微调和 RAG 的区别与优劣势是什么？

**常见问法**

- 微调和 RAG 的区别是啥？
- 微调和 RAG 的优劣势？

#### 面试回答

一句话：RAG 改“模型能看到什么”，微调改“模型本身会什么”。

- RAG：知识外置在检索库里。更新即生效、可溯源引用、权限可控、成本低。限制是吃检索质量和上下文预算，而且不改变模型的表达风格与行为模式，检错了就答错。
- 微调：用领域数据继续训练，把风格、格式、术语和任务行为内化进模型。推理时不占上下文、延迟稳定。代价是知识固化进了权重 —— 新信息要重训、答案难给出处、数据与算力成本高、还可能遗忘通用能力。

选型方向：

- 事实随时间变化的问答，优先 RAG。
- 输出格式或领域表达不稳、要压缩长 Prompt、端侧小模型做专精任务，优先微调。
- 常见的组合是微调打底行为＋RAG 供实时事实。

做过没有按【真实经历】答。

#### 技术细节

**三条判别口诀**

- 知识还是能力：缺的是可查询的事实，用 RAG；缺的是稳定的行为与表达，用微调。
- 更新频率：高频更新的知识写进权重，后继必然乏力。
- 可审计性：合规要求给出证据来源时，RAG 占优。

**两者都治不好的那类问题**

- 任务拆解错误是 Agent 编排层的事（见 [[专题题库/Agent开发#AGENT-025：主流 Agent 架构有哪些，如何选型？|AGENT-025：主流 Agent 架构有哪些，如何选型？]]）。

**评测怎么设计**

- 在同一任务集上对比：只换检索、或者只换权重，归因才清晰。

#### 深挖追问

1. **RAG 能替代微调吗？**（补充练习）

   替代不了。RAG 补不进“按特定格式稳定输出”这种行为层面的改变；微调也装不住需要即时更新、还要能溯源的事实。

### LLM-009：Function Call 是怎么训练的？

**常见问法**

- Function Call 是怎么训练的？

#### 面试回答

工具调用能力主要来自训练：

- 构造大量“对话上下文＋可用工具 schema → 正确行为”的指令数据做 SFT，要覆盖三类决策：该调用时输出规范的工具名与参数 JSON；不该调用时直接回答；参数缺失时向用户追问。
- 再用偏好数据对齐调用选择与格式质量。

推理时还有机制在配合：框架把工具定义注入上下文，用受限解码／文法约束保证输出是合法 JSON，宿主解析后执行、再回填结果。

一句提醒：纯 Prompt 也能诱导未训练模型输出“像调用的 JSON”，但可靠性和意图判断明显更差 —— 这正是模型厂商要专门训练它的原因。

#### 技术细节

**数据难点在负样本与边界**

- 过多调用（不该调也调）和漏调用，都靠带标注的决策样本校正。
- 参数幻觉（编造不存在的字段值）要求数据里含“缺参追问”与“从上下文取值”这两类示范。
- 并行调用、多轮连续调用，各有各对应的样本形态。

**运行时校验不可省**

- 模型输出只是一个意图。schema 校验、鉴权与执行结果检查都留在应用层做（见 [[专题题库/Agent开发#AGENT-010：工具调用如何设计并校验执行结果？|AGENT-010：工具调用如何设计并校验执行结果？]]）。

**怎么评测**

- 用固定工具集与任务集，按工具选择准确率、参数正确率、不必要调用率来统计。

#### 深挖追问

1. **开源模型没有 FC 训练能直接用吗？**（补充练习）

   可以用 Prompt 模板模拟，但格式和决策的稳定性都差。常见做法是自己用工具调用数据集微调补齐，质量以评测集为准。

### LLM-010：大模型产生幻觉的原因是什么，如何缓解？

**常见问法**

- 大模型产生幻觉的原因及解决方案？
- RAG 的流程是什么，如何缓解大模型幻觉？（与 [[专题题库/RAG#RAG-001：知识库问答系统如何设计？|RAG-001：知识库问答系统如何设计]] 的缓解侧互补）

#### 面试回答

先破题：幻觉不是 bug 级故障，而是自回归生成机制的固有产物 —— 模型优化的是“下一个 token 的条件概率”，训练目标里没有“真”这个量。

原因分四层：

- 数据层：语料含错误与冲突、长尾事实稀疏、知识有截止日期。
- 模型层：知识以参数化记忆存储，相似事实会互相串扰；注意力在长上下文里会稀释，或者偏向表面相关。
- 解码层：采样随机性加上错误沿自回归传播 —— 第一步偏了，后面越编越像。
- 提示层：问题预设了不存在的前提、指令互相矛盾时，模型倾向于顺着答而不是纠错。

解决方案也按层给：

- 知识侧：用 RAG 接地，并强制引用。
- 推理侧：把可以确定的计算交给工具（SQL、检索、计算器），并用 CoT 拆步。
- 生成侧：提示词里显式允许拒答、固定输出格式。
- 验证侧：多采样做自一致性比对、校验引用支持度，关键链路人工复核。
- 训练侧：SFT 提数据质量，DPO 对齐“不确定要坦白”。

收口两句：只能压低幻觉率、缩小影响面，不能归零；工程上要按场景算容忍预算 —— 财务数字必须校验兜底，创意写作可以宽松。

#### 技术细节

**为什么模型不承认自己不知道**（高频追问）

- 训练分布里，“给出貌似合理的答案”几乎总被奖励；拒答样本稀缺，而且很难自动判定什么时候该拒。
- 对齐阶段专门注入“不知道”的行为（RLHF 对诚实给奖励）能改善，但不会变成万能开关。

**评测口径**

- 把“检索没拿到证据”和“有证据仍答错”分开统计（见 RAG-001 的幻觉评测）。
- 准备无答案、过时、冲突事实的样本题集，度量忠实度与适当拒答率。
- 只报“感觉变少了”不算数。

**两条容易说过头的**

- 温度只影响随机性，不修正事实。
- 模型自评不能替代可核对的证据链与人工抽检。

**先确认题目问的是哪类**

- 创意生成里的想象是特性，问答场景里的想象才是幻觉。

#### 深挖追问

1. **RAG 能完全消除幻觉吗？**（补充练习；与 [[专题题库/RAG#RAG-001：知识库问答系统如何设计？|RAG-001]] 的“RAG 如何缓解幻觉”问法呼应）

   不能。RAG 只保证“证据在场”，模型仍可能曲解、拼贴，或者引用不支持结论的段落；检索失败时还可能倒回参数记忆瞎补。

   所以要有引用支持度校验和拒答约束，把“有据不依”和“无据硬答”都拦在出口 —— 能显著降，不能保证消除。

2. **微调能治幻觉吗？**（补充练习）

   分两类看：

   - 行为性幻觉（不装懂、该拒就拒、格式忠实）：有效，SFT＋DPO 能塑造。
   - 知识性幻觉（记错长尾事实）：作用有限。微调不会新增可靠知识，反而可能强化编造；有时效性的知识交给 RAG（见 [[#LLM-008：微调和 RAG 的区别与优劣势是什么？|LLM-008]]）。

3. **长上下文时代还需要 RAG 接地吗？**（补充练习）

   需要。窗口大不等于检索准：百万 token 里的“中间流失”（lost in the middle），以及成本和延迟，都是真实存在的。长窗口更适合作为 RAG 之后的精读层，两者互补、不互斥。

### LLM-011：微调训练集怎么构造，微调效果怎么评测？

**常见问法**

- 实验室项目微调的训练集是怎么构造的？
- 微调后的效果怎么样，怎么评测微调效果？
- 微调数据要多少条，怎么保证质量？

- 在构建数据集的过程中遇到了哪些挑战？花了多长时间？

#### 面试回答

数据构造按“来源—加工—质控—配比”四步讲：

- 来源：【人工标注／规则模板生成／强模型蒸馏出草稿再人审／线上日志与文档改写】。
- 加工：统一成指令格式（单轮指令，或带历史轮次的对话格式），每条含输入、期望输出与必要约束。
- 质控：去重、检查长度与格式是否合法、做标注一致性抽检；和评测集相似的数据要剔除，避免污染。
- 配比：按难例与边界样本上采样，而不是无脑堆量。

数据量级要如实：几千到几万条指令是小规模微调的常见量级。说“几十万条”又讲不清来源，会立刻被追问。

效果评测分三件事：

- 在从未参与训练的保留集上对比基座模型与微调模型，指标要和任务对齐：分类看准确率／F1，生成看可规则判定的结果或者人工盲评。
- 跑通用能力回归，看有没有把原来会的训坏（灾难性遗忘）。
- 给 badcase 分析与上线灰度。

最后一点别漏：必须点出对照维度。在同一评测集下比较“只改检索、只改权重、两者都改”，才说明得了微调带来的增量（与 [[#LLM-008：微调和 RAG 的区别与优劣势是什么？|LLM-008]] 的取舍一脉相承）。

如果结论是“微调收益不明显、最后靠 RAG 解决”，如实说出来反而更可信。

#### 技术细节

**每种来源都有对应的陷阱**

- 模板生成：量大，但表达单一。
- 模型蒸馏：快，但会继承教师模型的错误与风格，要人审抽样。
- 线上日志：真实，但含敏感信息与噪声，脱敏与授权先行。

**指令格式怎么定**

- 按所用基座与训练框架的模板组织：单轮指令对，或者带多轮历史的对话序列。
- 字段名与序列化格式以训练框架和基座的文档为准，别在面试里含糊地说“随便存成 JSON”。

**质量控制的手段**

- 去重（含近重复）、长度与截断检查、控制拒答与无效样本。
- 按类别看分布，检查是否被某类淹没。
- 标注一致性用双人抽检算一致率。
- 难例（边界条件、易混类别）单独上采样，比堆简单样本有效。

**去污染是硬要求**

- 同一文档派生出的样本跨了集合，指标就会虚高（评测集与验证集的分工与泄漏见 [[专题题库/RAG#RAG-008：如何定义并评测检索成功率？|RAG-008：如何定义并评测检索成功率]]）。

**评测设计要撑得起追问**

- 目标能力指标之外，加一组“必须仍然会”的回归集：通用指令跟随、格式约束、原有领域知识。
- 再加安全与稳定性检查：拒答是否合理、输出格式是否合规。
- 样本量小要报原始成功数或置信区间，只看一次跑分容易被随机性骗。

**人工评测与自动指标**

- 人工评测要有标注规范与盲评，不告诉评审哪一份是微调结果。
- 自动化指标（含 LLM 当评委）适合做回归，但要抽样校准。

**已有分层看别的题**

- 训练超参与方法分层（LoRA／QLoRA／全参）见 [[#LLM-007：微调的方案有哪些？|LLM-007：微调的方案有哪些]]。
- 若目标是让模型学会调用工具，参数格式与负样本构造见 [[#LLM-009：Function Call 是怎么训练的？|LLM-009：Function Call 是怎么训练的]]。

**汇报口径的通用纪律**

- 数字必须带基座、数据规模、方法、评测集与指标名，缺一就被判定为“没真做过”。

#### 深挖追问

1. **数据量多少才够？**（补充练习）

   看任务复杂度和基座能力。格式与行为改写类，几百到几千条常常就能看到明显变化；要注入大量新事实，就不是堆指令能解决的（该走检索）。

   回答要给“我用了【N】条，因为【任务边界】”，而不是背一个通用数字。

2. **怎么判断提升来自微调而不是随机性？**（面经实际出现；[[面经/阿里国际/二面/0001#Q10：实验室项目微调的训练集是怎么构造的？微调后的效果怎么样、怎么评测？|MJ038 · 阿里国际 · 二面 · Q10]] 的延伸）

   三件事一起做：固定评测集与判定脚本；用多个随机种子或多次推理取分布；报告分组指标与样本量。同时保留基座与原方案在同一批数据上的结果做对照，否则“看起来变好了”不能归因。

3. **微调后通用能力退化了怎么办？**（补充练习）

   四个方向，最后要有数据支撑：

   - 混入通用指令与原始任务样本做配比。
   - 降低学习率，或者改用参数高效方法。
   - 缩短训练轮次，并按检查点早停。
   - 用“必须仍然会”的回归集量化退化幅度，再决定是否回退版本。

4. **构建数据集遇到了哪些挑战，花了多久？**（面经实际出现；[[面经/字节/一面/0009#Q04：大模型微调的训练数据集是如何构建的、数据量多大；构建过程中遇到哪些挑战、花了多长时间？|MJ041 · 字节 · 一面 · Q04]]）

   讲三个真实难点最可信：

   - 标注一致性：不同人对“正确答案”的理解不同，靠标注规范＋仲裁样本收敛。
   - 分布偏斜：简单样本会淹掉难例，靠分层采样与边界样本上采样解决。
   - 教师模型错误继承：蒸馏结果流畅但含事实错误，要抽样人审，并沉淀 badcase 集。

   耗时按“数据准备占大头”答：清洗与标注通常远长于训练，再给训练轮次、每轮多久，以及为什么在这里停（指标不再提升，或者时间预算用完）。

   只答“没遇到什么困难，几天就做好了”，会被判定为没真做过。
