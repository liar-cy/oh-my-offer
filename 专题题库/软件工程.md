### ENG-001：使用 AI／vibe coding 开发项目的流程是什么？

**常见问法**

- [[面经/美团/一面/0002#Q19：那可能是未来，当下你是怎么使用 AI 的？|MJ032 · 美团 · 一面 · Q19]]
- [[面经/美团/一面/0002#Q18：AI 与程序员协作应该是什么样的关系？人负责什么，AI 负责什么？|MJ032 · 美团 · 一面 · Q18]]
- [[面经/美团/一面/0002#Q15：看一下 AI Coding 结果，拿到问题你是怎么考虑去处理的？|MJ032 · 美团 · 一面 · Q15]]
- vibe coding 一个项目的大概流程是怎样的？

- 平时如何用 AI 辅助开发，哪些工作不能交给 AI？

- AI Coding 有改变你的工作／生活吗，结合自己的体验详细讲讲。

- 基于内存做一个缓存，如何写 AI Coding 流程中的提示词？

#### 面试回答

我的流程是：

- 先明确目标、输入输出和验收标准，读取项目规则与现有结构。
- 再让 AI 把它拆成可检查的小任务。
- 每次只实现一个可运行的改动：自己检查 diff、跑相关测试、验证真实用户流程，通过后再继续下一步。
- 遇到失败先定位原因，避免不断追加提示，那样代码会越改越偏。

能交给 AI 的范围，由数据政策、授权和可验证性决定：

- 禁止外传的数据不交给未经批准的服务；不让 AI 在无授权下执行生产变更。
- 业务规则确认、关键设计取舍、结果责任，这三样由人承担。
- 敏感模块可以让 AI 辅助分析，但要用合规环境、最小必要上下文和适当验证。
- 底线：我自己解释不了关键代码、验证不了行为，就不直接合入。

个人经历用实际案例补充，不编造效率提升数字。

#### 技术细节

**先建立共同理解，再划范围**

- 从需求示例和失败场景入手建立共同理解，然后确定已有的技术约束。
- 让 AI 在指定的文件和接口范围内修改，不把范围放开。
- 评审时重点看四件事：业务语义、依赖变化、异常路径、有没有误删既有逻辑。

**验证要匹配改动类型**

- 纯文案改动看渲染效果。
- 逻辑改动做行为测试。
- 接口改动去检查调用方。
- 完成后要说明改动内容、验证结果和已知限制。未经自己核验，不能把“模型说通过”当成证据。

**内存缓存那道题的 AI Coding 提示词**

- 先限定 API、容量、过期、淘汰和并发语义，再要求实现和对应的行为验证。
- 原题没有要求 LRU 或 TTL，不能替面试官默认加上。
- 示例：“请在【语言／项目】实现进程内键值缓存，提供 get、put、delete；先确认容量单位、是否需要过期和淘汰、是否多线程。未明确处列为假设，方案确认后实现；验证覆盖更新、未命中及已约定的边界，说明复杂度和限制。”

#### 深挖追问

1. **生成的代码不理解能直接提交吗？**（补充练习）

   不能。先理解关键路径和这次改了什么，看不懂就用解释、最小示例和测试去验证。底线是：提交的人要能说明这段代码的行为和维护方式。

2. **如何处理需求变化？**（补充练习）

   先更新验收条件和任务范围，再检查已完成的部分是否受影响，然后做有边界的增量修改。

3. **哪些工作不能交给 AI 独立完成？**（面经实际出现；[[面经/百度/一面/0005#Q22：平时如何用 AI 辅助开发，哪些工作不能交给 AI？|MJ008 · 百度 · 一面 · Q22]]）

   四类不能：禁止外传的数据处理、未经授权的生产操作、需要本人承担的决策、无法验证的关键变更。具体边界按实际规则和任务条件划定。

4. **基于内存写一个缓存，AI Coding 提示词怎么写？**（面经实际出现；[[面经/百度/二面/0002#Q15：基于内存做一个缓存，如何写 AI Coding 流程中的提示词？|MJ010 · 百度 · 二面 · Q15]]）

   先把目标、接口、可选策略和验收讲清楚，别只丢一句“写一个高性能缓存”。原题没有给出实际语言和策略，这些要作为假设先确认。

5. **AI 与程序员协作应该是什么关系，人负责什么、AI 负责什么？**（面经实际出现；[[面经/美团/一面/0002#Q18：AI 与程序员协作应该是什么样的关系？人负责什么，AI 负责什么？|MJ032 · 美团 · 一面 · Q18]]）

   人负责判断与责任：

   - 把模糊需求写成可验收的规格。
   - 在性能／可维护性／工期之间做取舍。
   - 审查关键路径：业务语义、并发与资损、权限与数据边界。
   - 承担提交结果。
   - 守住授权边界：不外传未批准的数据、不让 AI 无授权执行生产变更。

   AI 负责生成与穷举：

   - 写已知模式的代码。
   - 列候选方案和测试用例。
   - 读大量既有代码做摘要和定位。
   - 做机械重构。

   机制上，验证要匹配改动类型（文案看渲染、逻辑做行为测试、接口查调用方），小步提交，失败先定位原因再改提示。

   价值迁移的落点：省下的时间投向需求澄清、架构约束、质量与故障治理 —— 这些正是需要为结果负责的部分。

6. **那可能是未来，当下你是怎么使用 AI 的？**（面经实际出现；[[面经/美团/一面/0002#Q19：那可能是未来，当下你是怎么使用 AI 的？|MJ032 · 美团 · 一面 · Q19]]）

   这题是把愿景拉回事实，要给“具体场景 ＋ 边界 ＋ 一个可核对的例子”。

   - 场景一：读不熟的代码库并画调用链。
   - 场景二：一次一个可验证的小改动 —— 我定接口与约束，它写实现，我读 diff 补测试。
   - 场景三：排障时让它列可能原因，我按验证成本排序。
   - 场景四：生成测试数据与文档初稿。
   - 边界一：不理解的代码不合入。
   - 边界二：真实用户数据与密钥不给它。
   - 边界三：生产操作不由它执行。
   - 边界四：验收标准不由它定义。
   - 收尾：给一个真实任务的耗时对比与确认方式，这比罗列工具名可信。

7. **“AI Coding 的掌握程度”这种自评题怎么答？**（面经实际出现；[[面经/阿里国际/二面/0001#Q13：AI Coding 的掌握程度。|MJ038 · 阿里国际 · 二面 · Q13]]）

   自评要分档并给证据，不要只说“很熟”。四档是：

   - 会问：能把需求写清楚，拿到结果。
   - 会配：能拆任务、给接口约束与验收标准、组织上下文和规则文件。
   - 会验：读得懂生成代码、能定位问题、会补测试，也能拒绝看不懂的改动。
   - 会建：做工具链，把规则、脚本、评测接进 CI。

   说自己到哪一档，就配一个只有该档才答得出的细节，再主动给边界和失败案例（哪类改动自己从不直接采纳）。这比工具清单更能证明判断力。

### ENG-002：如何修改积累十几年的大型遗留项目？

**常见问法**

- 团队维护十几年的大型项目，要在其基础上修改，怎么做？

#### 面试回答

按这个顺序推进：

- 先复现目标行为，跑通最小构建。
- 再定位请求入口、核心调用链和数据依赖，顺带了解历史约束。
- 对要修改的行为，先补特征测试或回归样例。
- 然后选影响范围小的切入点动手，改完验证调用方、数据兼容和部署回滚方式。

一条原则：不会一开始就试图读完整个仓库，也不做整体重构。

#### 技术细节

**怎么读懂陌生代码**

- 入口有这些：路由、错误日志、堆栈、测试、Git 历史。
- 再结合一次实际调用的追踪，形成局部模型，不必追求全局掌握。

**改之前先固定行为**

- 缺测试时，先把当前的对外行为固定下来。
- 发现疑似 bug 也要区分：这是历史兼容要求，还是待修缺陷。

**变更与 AI 的边界**

- 接口、配置、表结构的变更，要先识别消费者，再定迁移顺序。
- AI 可以帮忙检索、解释、草拟测试，但上下文要聚焦相关模块；不能凭局部代码就断言全系统不存在依赖。

#### 深挖追问

1. **项目完全没测试怎么办？**（补充练习）

   先围绕目标接口建立输入输出样例和可重复的环境，必要时隔离外部依赖。覆盖范围至少包括拟改的行为和重要调用方。

2. **什么时候可以重构？**（补充练习）

   当重构是实现目标所必需、而且结果可验证的时候。顺序上先做局部结构调整，再做行为变化，这样出回归时能定位到是哪一步。

### ENG-003：uv 和 pip 有什么区别？

**常见问法**

- uv 和 pip 的区别是什么？

#### 面试回答

两者定位不同，不是同一层的替代品：

- pip：Python 官方包安装器，从 PyPI 下载并安装第三方包，管理的是“包”，虚拟环境要另配 venv。
- uv：用 Rust 写的新一代 Python 包／项目管理器，兼容并可直接取代 pip／pip-tools／virtualenv 的安装能力，还多了“项目管理”和“Python 版本管理”。
- 最大差别是速度：uv 有全局缓存、并行下载、更优的依赖解析与硬链接复用，装包比 pip 快一个量级。

一句话：uv 既是更快的 pip，又是能管依赖锁定、虚拟环境甚至 Python 解释器版本的一体化工具。

#### 技术细节

**能力对比**

- 装包：`pip install x` vs `uv pip install x`（uv 提供 pip 兼容子命令）。
- 虚拟环境：pip 依赖 `python -m venv`；uv 用 `uv venv`。
- 依赖与项目：uv 读 `pyproject.toml`、生成 `uv.lock` 做锁定复现（对标 poetry／pip-tools）；`uv run`／`uv sync` 一条命令建环境＋装依赖＋跑。
- Python 版本：uv 可直接 `uv python install 3.12` 管理解释器；pip 管不了版本。

**为什么会快**

- Rust 实现、全局包缓存＋硬链接、并行下载、更快的版本求解器，重复安装几乎零 IO。

#### 深挖追问

1. **uv 能完全替代 pip 吗？**（补充练习）

   多数日常场景可以（`uv pip` 兼容命令＋项目工作流更快）。但老脚本、CI 里对 `pip` 的硬依赖、或某些只走 pip 的边角用法，迁移时要验证；uv 也仍在快速演进，具体参数以当期官方文档为准。
