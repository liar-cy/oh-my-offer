### ALG-001：如何把任意字符串转换为 int？

**常见问法**

- 手撕：写一个函数，把任意字符串转为 int 型整数。

#### 面试回答

我会先确认四类约定：空白怎么处理、符号怎么读、非法字符算不算错、溢出怎么给值。这里按 atoi 风格实现：

- 跳过前导 ASCII 空格。
- 读一个可选的正负号，再读后面连续的数字。
- 遇到其他字符就停止，不报错。
- 一个数字都没读到就返回 0。
- 溢出时截断到 int 的上下界，null 约定返回 0。

累加每一位之前先检查上界，避免先溢出再判断。原题没给规则，这只是明确选定的一种实现。

#### 技术细节

**先说清前提**

- 上面是明确选定的一种语义，原题没有规定；严格解析也可以要求所有字符合法，遇到非法字符或溢出就抛异常。
- 不能把这里的约定说成原题已经指定。

**溢出边界**

- 负数方向的绝对值最大到 2147483648，比正数上界大 1，所以上界和下界要分开取。
- 用 long 保存当前的非负绝对值，但每一步仍然单独检查；这样超长字符串也不会先把 long 溢出。

**空白与字符集**

- 只有 ASCII 空格会被跳过。
- 制表符、Unicode 数字字符都不纳入本约定。

```java
public static int toInt(String s) {
    // 本题约定：null 返回 0；跳过前导 ASCII 空格；读取可选符号和连续数字；
    // 无数字返回 0；遇到非数字停止；溢出截断到 int 边界。
    if (s == null) return 0;
    int i = 0, n = s.length(), sign = 1;
    while (i < n && s.charAt(i) == ' ') i++;
    if (i < n && (s.charAt(i) == '+' || s.charAt(i) == '-')) {
        sign = s.charAt(i++) == '-' ? -1 : 1;
    }
    long limit = sign == 1 ? Integer.MAX_VALUE : 2147483648L;
    long value = 0;
    while (i < n) {
        char c = s.charAt(i);
        if (c < '0' || c > '9') break;
        int digit = c - '0';
        if (value > (limit - digit) / 10) {
            return sign == 1 ? Integer.MAX_VALUE : Integer.MIN_VALUE;
        }
        value = value * 10 + digit;
        i++;
    }
    return sign == 1 ? (int) value : (int) -value;
}
```

时间 O(n)，额外空间 O(1)。例：`"  -42x" → -42`、`"words 42" → 0`、`"2147483648" → 2147483647`、`"-2147483648" → -2147483648`、`"+-12" → 0`。

#### 深挖追问

1. **如果面试官要求严格转 int？**（补充练习）

   改成全量校验：null、空串、任何非法字符、溢出都直接报错。动手前先问清是否允许空白。别复用上面“中途停止、返回已读前缀”的行为。

2. **为什么不能先乘 10 再检查 int 是否超限？**（补充练习）

   乘完的那一刻 int 可能已经回绕，再判断拿到的就是失真值。要么把比较放到运算之前（拿阈值除以 10 来比），要么用更宽的类型累加，并保证宽类型自身不溢出。

### ALG-002：LeetCode 86：分隔链表

**常见问法**

- 手撕：LeetCode 86 分隔链表。

#### 面试回答

用两条带哨兵（dummy，虚拟头节点）的链表做稳定分区：

- 小于 x 的节点，按原顺序接到第一条链。
- 其余节点接到第二条链。
- 最后把第二条链挂到第一条链尾部。

每摘一个节点前先保存它的 next，再把旧链接断开，避免形成环。这样两个分区内部的相对顺序都保持原样。时间 O(n)，额外空间 O(1)。

#### 技术细节

**这是稳定分区，不是排序**

- 只要求小于 x 的都排在前面，段内不再做大小比较。
- 等于 x 的节点归到第二段。

**实现要点**

- 复用原节点，只额外分配两个哨兵，所以额外空间仍是 O(1)。
- 空链表、全部小于 x、全部大于等于 x 这三种情况都走同一段逻辑，不需要特殊分支。
- 下面的代码按 Java 17 验证过，可以放进外层类中。

```java
static class ListNode {
    int val;
    ListNode next;
    ListNode(int val) { this.val = val; }
}

public static ListNode partition(ListNode head, int x) {
    ListNode smallDummy = new ListNode(0), largeDummy = new ListNode(0);
    ListNode small = smallDummy, large = largeDummy;
    while (head != null) {
        ListNode next = head.next;
        head.next = null; // 摘下节点，避免残留旧链或形成环
        if (head.val < x) {
            small.next = head;
            small = head;
        } else {
            large.next = head;
            large = head;
        }
        head = next;
    }
    small.next = largeDummy.next;
    return smallDummy.next;
}
```

**样例与不变式**

- 例：`1 → 4 → 3 → 2 → 5 → 2`，x=3，结果 `1 → 2 → 2 → 4 → 3 → 5`。
- 循环不变式有两条：两条链都由已处理节点按原顺序组成；链尾不指向任何未处理节点。

#### 深挖追问

1. **为什么要断开旧 next？**（补充练习）

   摘下来的尾节点如果还留着指向原链的旧指针，拼接后就可能重复遍历同一段，甚至成环。

2. **能只交换数值吗？**（补充练习）

   不建议：换值容易破坏稳定性，也改变了节点本身的语义。本题要的是按节点顺序做稳定分区，重连节点更直接。

### ALG-003：如何手写 LRU 缓存？

**常见问法**

- 手撕 LRU。

- 算法：LeetCode 146 LRU 缓存（mid）。

- 要自己实现一个 LRU，要怎么去实现？

- 手撕 LRU；追问：改造成线程安全该怎么做，读多写少怎么优化（并发版正文见 [[专题题库/Java并发#JUC-019：线程安全的 LRU 缓存怎么实现，读多写少如何优化？|JUC-019：线程安全的 LRU 缓存]]）。

#### 面试回答

分工很明确：哈希表负责定位，双向链表负责排序。

- 哈希表存 key 到链表节点的映射，平均 O(1) 就能找到节点。
- 双向链表按最近使用排序，头部是刚用过的，尾部是最久没用的。
- get 命中、put 更新已有 key 时，把该节点移到头部；新节点也插在头部。
- 超过容量就删掉尾部节点，同时删掉哈希表里对应的那条记录。

链表摘除和插入都是 O(1)，所以 get／put 整体平均 O(1)，空间 O(capacity)。

#### 技术细节

**接口约定**

- key 和 value 都是整数，未命中返回 -1。
- 容量为 0 时不存任何数据；负容量直接拒绝。

**实现要点**

- 头尾各放一个哨兵，空链、只剩一个节点时的删除都不用写特判分支。
- 关键是保证 map 里的每个节点在链中恰好出现一次。
- 更新已存在的 key 只改值并移到头部，不会增加容量。

**并发边界**

- 原题没说并发要求，这份实现是单线程版。
- 并发版要把 map 和链表的变更当成一组一致操作一起保护；只把 HashMap 换成 ConcurrentHashMap 是不够的。

```java
static class LRUCache {
    private static class Node {
        int key, value;
        Node prev, next;
        Node(int key, int value) { this.key = key; this.value = value; }
    }
    private final int capacity;
    private final java.util.Map<Integer, Node> map = new java.util.HashMap<>();
    private final Node head = new Node(0, 0), tail = new Node(0, 0);

    LRUCache(int capacity) {
        if (capacity < 0) throw new IllegalArgumentException("negative capacity");
        this.capacity = capacity;
        head.next = tail;
        tail.prev = head;
    }
    public int get(int key) {
        Node n = map.get(key);
        if (n == null) return -1;
        unlink(n);
        addFirst(n);
        return n.value;
    }
    public void put(int key, int value) {
        Node n = map.get(key);
        if (n != null) {
            n.value = value;
            unlink(n);
            addFirst(n);
            return;
        }
        if (capacity == 0) return;
        n = new Node(key, value);
        map.put(key, n);
        addFirst(n);
        if (map.size() > capacity) {
            Node victim = tail.prev;
            unlink(victim);
            map.remove(victim.key);
        }
    }
    private void unlink(Node n) {
        n.prev.next = n.next;
        n.next.prev = n.prev;
    }
    private void addFirst(Node n) {
        n.prev = head;
        n.next = head.next;
        head.next.prev = n;
        head.next = n;
    }
}
```

容量 2：put(1,1)、put(2,2)、get(1)、put(3,3)

- 中间那次 get(1) 刷新了 1 的最近使用顺序，所以 put(3,3) 时被淘汰的是 key=2。
- 更新一个已存在的 key，同样会刷新它的最近使用顺序。

#### 深挖追问

1. **LRU 和 LFU 有什么区别？**（补充练习）

   LRU（最近最少使用）看的是最近一次访问的时间，LFU（最近最不常用）看的是累计访问频次；频次相同时还需要另外定义一条次级规则。

2. **为什么单链表不方便？**（补充练习）

   单向链表就算 O(1) 定位到了节点，删除它仍然要先拿到前驱，而找前驱得从头遍历。双向链表节点自己就带着前驱指针，摘除才是 O(1)。所以关键不在能不能定位，而在能不能 O(1) 摘除。

### ALG-004：如何合并重叠区间？

**常见问法**

- 手撕：如何合并二维数组中的重叠区间？

- 手撕：重叠区间的总长度。

#### 面试回答

先确认区间开闭和输入是否合法。这里的约定是：输入为合法闭区间，端点相接也合并，null 或空数组返回空结果。

算法就两步：

- 先按左端点升序排序。
- 依次扫描：当前区间的左端点不大于结果末区间的右端点，就扩展末区间的右端点；否则把当前区间作为新段加入结果。

排序 O(n log n)，扫描 O(n)。为了不改动入参，复制区间后再排序，额外空间 O(n)。完整 Java 实现与边界案例见关联专题。

#### 技术细节

**约定与选型**

- 原图没给语言及边界约束，这里选用 Java 8+。
- 每个子数组必须有两个元素且 start <= end，违反约定抛出 IllegalArgumentException。
- 按闭区间理解：[1,2] 和 [2,3] 合并，[1,2] 和 [3,4] 不合并。

**一个容易踩的点**

- 排序比较用 Integer.compare，别用端点相减；相减可能溢出。

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class MergeIntervals {
    public static int[][] merge(int[][] intervals) {
        if (intervals == null || intervals.length == 0) {
            return new int[0][2];
        }
        int[][] sorted = new int[intervals.length][2];
        for (int i = 0; i < intervals.length; i++) {
            int[] row = intervals[i];
            if (row == null || row.length != 2 || row[0] > row[1]) {
                throw new IllegalArgumentException("Invalid interval");
            }
            sorted[i] = new int[]{row[0], row[1]};
        }
        Arrays.sort(sorted, (a, b) -> Integer.compare(a[0], b[0]));
        List<int[]> result = new ArrayList<>();
        for (int[] current : sorted) {
            if (result.isEmpty()
                    || current[0] > result.get(result.size() - 1)[1]) {
                result.add(current);
            } else {
                int[] last = result.get(result.size() - 1);
                last[1] = Math.max(last[1], current[1]);
            }
        }
        return result.toArray(new int[result.size()][]);
    }
}
```

**为什么只需和末段比**

- 扫描不变量：结果始终按左端点有序，且各段互不重叠。
- 排序之后，新段只可能和末段合并；一旦超过末段的右端点，就更不可能与更早的段重叠。

**要覆盖的案例**

- 空输入、单区间、乱序输入、包含与重复、端点相接、不相交、负数与 int 极值、非法子数组、确认输入未被修改。
- 示例 [[8,10],[1,3],[2,6],[15,18]] 得到 [[1,6],[8,10],[15,18]]。

### ALG-005：如何求最长回文子串？

**常见问法**

- 手撕：给定字符串，返回最长回文子串。

#### 面试回答

采用中心扩展。回文左右对称，中心要么是一个字符，要么是两个字符之间的空隙。

- 遍历每个位置，分别以字符和以间隙为中心向两边扩展，覆盖奇数和偶数长度的回文。
- 撞到边界或者两端字符不同就停止。
- 用扩展出的长度更新最长区间，最后返回子串。

所有中心都被检查过，所以不会漏掉最长回文。时间 O(n²)，除返回字符串外辅助空间 O(1)。

这里用 Java 示例，按 UTF-16 char 比较；null 和空串返回空串，同长取最先找到的一段。这些只是示例约定，原题未指定字符范围、语言或同长规则。完整实现见专题。

#### 技术细节

**别先审错题**

- 本题要的是连续子串；不要求连续的那个叫回文子序列，是另一道题。

**中心扩展为什么正确**

- 任何回文都有一个中心：某个字符，或者两个字符之间的间隙。
- 从中心向两侧扩展，扩展到首次不匹配时停下，得到的就是该中心能覆盖的最长回文。
- 把所有中心都遍历一遍，同时维护全局最长区间就够了。

```java
class Solution {
    public String longestPalindrome(String s) {
        if (s == null || s.isEmpty()) return "";
        int start = 0, best = 1;
        for (int i = 0; i < s.length(); i++) {
            int len = Math.max(expand(s, i, i), expand(s, i, i + 1));
            if (len > best) {
                start = i - (len - 1) / 2;
                best = len;
            }
        }
        return s.substring(start, start + best);
    }
    private int expand(String s, int left, int right) {
        while (left >= 0 && right < s.length()
                && s.charAt(left) == s.charAt(right)) {
            left--;
            right++;
        }
        return right - left - 1;
    }
}
```

**示例约定**

- null 与空串返回空串；同长保留先找到的一段；按 Java UTF-16 代码单元比较。
- 若题目要求按 Unicode 码点处理，应先把串转成码点数组，并相应处理返回位置，空间口径也会跟着变。

**复杂度与样例**

- 时间 O(n²)，除返回值外辅助空间 O(1)。
- 例：babad→bab，cbbd→bb，a→a，aaaa→aaaa，abc→a。

#### 深挖追问

1. **还有哪些解法，复杂度如何？**（补充练习）

   另有两条路：
   - 动态规划：用 dp[i][j] 表示该区间是否回文，转移条件是两端相同且内部回文（长度不超过 2 时直接判断），按区间长度递增填表，时间和空间都是 O(n²)。
   - Manacher（俗称马拉车）：利用回文半径的对称性，做到 O(n) 时间、O(n) 空间。
   - 面试顺序建议：先写正确的中心扩展，被要求优化时再换上面的解法。

### ALG-006：如何在多个文件中检索一组敏感词？

**常见问法**

- 如何从 100 个文件中检索 100 个敏感词？

#### 面试回答

先确认两件事：文件是不是可直接读取的文本，以及要返回的是文件名、行号、词的位置还是次数。

- 一次性检索：把 100 个非空敏感词逐行放进词表，用固定字符串多模式搜索扫描指定文件就够了。
- 要自己实现算法：把词表构建为 Aho–Corasick 自动机，再复用同一个自动机逐个扫描文件并输出命中。
- 省时间的关键是文本只扫一遍，而不是每个词都把所有文件重扫一次。

#### 技术细节

**能用命令行就不手写**

- 纯文本、逐行匹配的命令示例：`grep -nH -F -f words.txt -- files/*.txt`。
- 前提是这条 glob 恰好覆盖目标文件，否则不要这么写。
- 参数含义：-F 按字面量匹配，-f 从词表文件读取模式，-nH 输出行号与文件名。
- 只要文件名就改用 -l；注意命中行数不等于词出现的次数。

**词表与匹配口径**

- 词表要去除空行。
- 大小写、编码、Unicode 规范化规则要先明确。
- 二进制文档得先提取文本再匹配。
- 子串命中、整词命中、重叠命中是三种不同口径，结果不一样。

**AC 自动机的构成与复杂度**

- Aho–Corasick（AC）自动机由三部分构成：Trie（前缀树）、失败指针、输出链接。
- 在字符集固定、单步转移为常数时间的前提下，预处理 O(M)，扫描 O(N+Z)。
- M 是所有词的总长度，N 是文本总长度，Z 是输出的命中数。

**扫描时状态怎么带**

- 每个文件相互独立，逐文件重置状态。
- 同一个文件分块流式读取时，状态要跨块保留。
- 若各块独立处理，相邻块之间要重叠“最长词长减一”个字符，并对重复命中去重。

#### 深挖追问

1. **为什么不能只用 HashSet？**（补充练习）

   HashSet 只能做“一个完整的词在不在集合里”的成员判断，前提是文本已经切好词。敏感词命中是任意子串匹配，用 HashSet 得先把所有候选子串枚举出来才能查，等于没解决问题。

**常见问法**

#### 面试回答

前提是按“每个用户取窗口内最近一次访问”来聚合。做法两步：

**要自己补的前提**

**一条常见错**

- 不能用“最后遍历到的那一条”代替最大时间，因为日志可能乱序。

**超出本题的部分**

- 在线持续查询要另设有序索引和过期机制，那不是本题的默认要求。

```python
def recent_users(logs, now, window):
    # 前提：window >= 0；时间单位一致；userId 为字符串。
    latest = {}
    for uid, timestamp in logs:
        if now - window <= timestamp <= now:
            if uid not in latest or timestamp > latest[uid]:
                latest[uid] = timestamp
    return sorted(latest.items(), key=lambda item: (-item[1], item[0]))
```

返回的是 (userId, 最近时间) 列表；只要用户列表时取每一项的第一列。若输入已明确过滤到同一窗口，过滤条件可以省去。

### ALG-008：LeetCode 32：如何求最长有效括号子串？

**常见问法**

- LeetCode 32：最长有效括号。

#### 面试回答

用栈保存未匹配的左括号下标，栈底先压一个 −1 当作边界。

- 遇到左括号：把下标入栈。
- 遇到右括号：先弹栈，再看栈的状态。
  - 弹完栈空了：把当前右括号的下标入栈，作为新边界。
  - 栈还非空：用当前位置减去栈顶，更新最大长度。

时间 O(n)，空间 O(n)。

#### 技术细节

**题意与栈的含义**

- 输入按只含左右括号的字符串处理，求的是连续子串长度，不是子序列。
- 栈底存的是最近一个无法匹配的右括号边界，它上面全是还没配对的左括号。
- 这个结构保证“当前位置减栈顶”得到的恰好是有效连续后缀。
- 空串的结果是 0；只数左右括号总数是不对的。

```python
def longest_valid_parentheses(s):
    stack = [-1]
    best = 0
    for i, ch in enumerate(s):
        if ch == '(':
            stack.append(i)
        else:  # 前提：输入只有 '(' 和 ')'
            stack.pop()
            if not stack:
                stack.append(i)
            else:
                best = max(best, i - stack[-1])
    return best
```

#### 深挖追问

1. **为什么初始压入 −1？**（补充练习）

   栈需要一个“上一个没配上的位置”当参照，−1 就是它的初始值。这样当下标 0 开始就是完整匹配时，当前位置减 −1 正好得到长度。之后每遇到一个配不上的右括号，都会用它的下标把边界重置。

### ALG-009：如何手写快速排序？

**常见问法**

- 手撕快速排序。

#### 面试回答

快速排序就两步：

- 选一个基准值，用明确的分区规则把数组拆成两部分，使基准左边的元素都不大于它、右边的都不小于它。
- 然后递归排序左右两个区间。

手写时的要点是选定一种分区法，让分区和递归边界保持一致，并确保每次递归的区间都在变小。平均时间复杂度 O(n log n)，最坏 O(n²)。原地实现的额外空间主要是递归栈：平均 O(log n)，最坏 O(n)。

#### 技术细节

**这份实现的分区**

- 用 Hoare 风格的双指针分区。
- 基准取区间中点的值；循环退出后递归 `[left, j]` 和 `[i, right]`。
- 元素等于基准时也推进指针，否则重复元素会让分区停不下来。

```java
static void quickSort(int[] a, int left, int right) {
    if (a == null || left >= right) {
        return;
    }
    int i = left;
    int j = right;
    int pivot = a[left + ((right - left) >>> 1)];
    while (i <= j) {
        while (a[i] < pivot) i++;
        while (a[j] > pivot) j--;
        if (i <= j) {
            int temp = a[i];
            a[i] = a[j];
            a[j] = temp;
            i++;
            j--;
        }
    }
    if (left < j) quickSort(a, left, j);
    if (i < right) quickSort(a, i, right);
}
```

**两个优化和它们的边界**

- 随机选基准或三数取中：能降低特定有序输入持续产生极端分区的概率，但改不了比较排序最坏 O(n²) 的上界。
- 先递归较短的一侧、用循环处理较长的一侧：能把调用栈控制在 O(log n)，这是工程实现常用的写法。

**稳定性**

- 快速排序通常不稳定；要求稳定性就得换算法，或者付出额外空间。

#### 深挖追问

1. **为什么平均是 O(n log n)，最坏是 O(n²)？**（补充练习）

   每层分区的总工作量都是 O(n)。分区均衡时大约只有 O(log n) 层，乘起来是 O(n log n)；每次只分出一个元素时层数退化成 O(n)，总和就变成 O(n²)。

2. **大量重复元素怎么办？**（补充练习）

   本实现在元素等于基准时同时推进两个指针，所以能保证终止。重复值极多时再上三向切分：把区间分成小于、等于、大于基准的三段，等于基准的那一段不再递归，省掉重复工作。

### ALG-010：如何验证一棵树是二叉搜索树？

**常见问法**

- 代码题：验证二叉搜索树。

#### 面试回答

递归时给每个节点维护一个它允许的取值开区间：

- 根节点是负无穷到正无穷。
- 进左子树时，把上界收紧成当前节点的值；进右子树时，把下界收紧成当前节点的值。
- 任一节点不满足 `low < value < high` 就返回 false。

这样做是因为要检查的是节点与所有祖先共同形成的约束，只比直接父子是不够的。时间 O(n)，递归栈 O(h)。

#### 技术细节

**题意前提**

- 按常见题意，二叉搜索树不允许重复值，所以全程用严格比较。

**一个实现细节**

- Java 里用 `long` 保存边界，避免节点值正好等于 int 上下界时还要做溢出运算。

```java
boolean isValidBST(TreeNode root) {
    return valid(root, Long.MIN_VALUE, Long.MAX_VALUE);
}

boolean valid(TreeNode node, long low, long high) {
    if (node == null) return true;
    if (node.val <= low || node.val >= high) return false;
    return valid(node.left, low, node.val)
        && valid(node.right, node.val, high);
}
```

**另一种写法与要确认的口径**

- 也可以中序遍历，检查得到的值是否严格递增。
- 迭代版用显式栈，能避免树过深导致递归栈溢出。
- 若业务定义允许重复值，必须先确认重复值放左还是放右，再相应修改边界的闭开规则。

#### 深挖追问

1. **为什么只比较节点与左右孩子不够？**（补充练习）

   因为约束是从祖先一路传下来的：右子树中的任意节点都必须大于所有相关祖先，不只是大于直接父节点。开区间能把这份完整的祖先约束传递下去，只比父子会漏判。

### ALG-013：“最长连续子数组长度”题意不完整时如何澄清与选型？

**常见问法**

- 手撕：最长连续子数组长度。（原图缺少完整判定条件）

#### 面试回答

这个题干不足以唯一确定算法，我会先问清三件事：

- “连续”指原数组下标连续，还是数值连续？
- 子数组必须满足什么条件——和、大小关系、元素种类，还是别的？
- 输入规模、值域、重复值和空数组怎么处理？

之所以要问，是因为如果没有任何附加条件，整个数组就是最长的下标连续子数组，答案只是 n——这说明题干必然缺了关键约束。

#### 技术细节

**常见且不等价的版本**

- 原数组中最长严格递增连续段：一次扫描，若 `a[i] > a[i-1]` 延长，否则重置，时间 O(n)、空间 O(1)。
- 最长数值连续序列：元素不必在原数组相邻，可用哈希集合从没有前驱的数开始向后扩展，平均 O(n)。
- 满足某个和、不同元素数或最大最小值差的最长连续子数组：根据数值是否非负和条件是否单调，可能用滑动窗口、前缀和＋哈希表或单调队列。
- 最大子数组和：用 Kadane 动态规划求最大和；如果题目要“长度”，还需定义和相同时的取舍规则，不能直接套用。

**选定版本之后**

- 先用样例把语义复述一遍，确认无误，再给不变式、边界和复杂度。
- 原始截图未提供条件，因此本题不猜测某一版本并把它写成已确认原题。

#### 深挖追问

1. **为什么“最长子数组”不等于“最长子序列”？**（补充练习）

   子数组要求在原数组中下标连续；子序列只要保持相对顺序，可以跳过元素。至于“数值连续序列”，那是第三种含义，跟上面两个都不是一回事。

2. **面试官暂时不补充条件怎么办？**（补充练习）

   把自己选用的版本和边界明确说出来，用一个样例确认后再实现。最忌讳的是心里默认猜了某个版本，代码里却完全不提前提。

### ALG-011：LeetCode 200：如何计算岛屿数量？

**常见问法**

- 岛屿数量怎么做？
- 能否用并查集解决岛屿数量？

#### 面试回答

先明确 LeetCode 200 的常见约束：只有上下左右相邻的陆地算连通，斜角不算。做法是：

- 遍历网格，遇到未访问的陆地就把答案加一。
- 紧接着用 DFS 或 BFS 把这一整块连通分量全部标记掉。
- 每个格子至多访问一次，所以时间 O(mn)，额外空间最坏 O(mn)。

若允许修改输入，可以直接把访问过的 `'1'` 改成 `'0'`，当作已标记。网格可能很深时优先用显式队列，避免递归栈溢出。

#### 技术细节

```java
int numIslands(char[][] grid) {
    if (grid == null || grid.length == 0) return 0;
    int ans = 0;
    for (int r = 0; r < grid.length; r++) {
        for (int c = 0; c < grid[0].length; c++) {
            if (grid[r][c] == '1') {
                ans++;
                flood(grid, r, c);
            }
        }
    }
    return ans;
}

void flood(char[][] grid, int r, int c) {
    if (r < 0 || r >= grid.length || c < 0 || c >= grid[0].length
            || grid[r][c] != '1') return;
    grid[r][c] = '0';
    flood(grid, r - 1, c);
    flood(grid, r + 1, c);
    flood(grid, r, c - 1);
    flood(grid, r, c + 1);
}
```

**并查集做法**

- 先把每块陆地各自当作一个集合，初始连通分量数就等于陆地格子数。
- 扫描时只对右、下两个方向的陆地尝试合并。
- 每成功合并两个不同的根，就把分量数减一。
- 路径压缩配合按大小／秩合并后，每次操作摊还接近 O(1)，总复杂度约 O(mn α(mn))，α 是反阿克曼函数。

**什么时候值得用并查集**

- 更适合动态添加陆地、或者还要继续回答连通性查询的问题。
- 只做静态计数的话，DFS／BFS 的代码通常更短。

#### 深挖追问

1. **为什么扫描并查集时只检查右边和下边？**（补充练习）

   因为每条无向的相邻边处理一次就够了：左边和上边的关系已经由此前扫过的格子覆盖。四个方向都查只是多做了几次 union，正确性不变。

2. **递归 DFS 有什么风险？**（补充练习）

   极端大的连通块，递归深度可能达到 O(mn)，Java 里可能栈溢出。改用显式栈或 BFS 队列就能避免。

### ALG-012：每轮取 1 个或 2 个，如何判断必胜策略？

**常见问法**

- 100 个圆圈，双方每次只能涂 1 个或 2 个，谁能涂到最后一个？

#### 面试回答

先确认前提：“每轮从剩余对象中处理 1 个或 2 个，处理最后一个者胜”。在这个前提下，3 的倍数是当前玩家的必败态，其余数量都是必胜态。

套到 100 个：

- 100 除以 3 余 1，所以先手先处理 1 个，给对手留下 99 个。
- 之后对手取 1 个我就取 2 个，对手取 2 个我就取 1 个，保证两人每轮合计取 3 个。
- 这么维持下去，最后一个必然落在先手手里。

#### 技术细节

**递推怎么看**

- 设 `win(n)` 表示还剩 n 个时当前玩家能否必胜，则 `win(n) = !win(n-1) || !win(n-2)`。
- 边界是 `win(0)=false`、`win(1)=true`、`win(2)=true`。
- 由此得到 `false, true, true` 每 3 个一循环。

**策略怎么构造**

- 先取 `n % 3` 个，之后每轮用 `3 - opponentMove` 回应，让对手始终面对 3 的倍数。

**一般化**

- 每轮可取 1 到 k 个、正常规则下取到最后者胜：`k+1` 的倍数是必败态，其他状态先手先取余数，再与对手凑 `k+1`。

**两种会改结论的题意**

- 规则改成“取最后者输”，边界和策略都会变。
- 圆环上的相邻位置对合法动作有额外限制时也一样，动手前必须先确认题意。

#### 深挖追问

1. **为什么不能只说先手有优势？**（补充练习）

   因为胜负不看先后手，看初始数量对 3 的余数。若初始正好是 3 的倍数且双方都最优，后手用互补策略反而必胜。

2. **如果每次能取 1 到 k 个呢？**（补充练习）

   正常取子规则下，目标是先把对手送到 `k+1` 的倍数上，之后每轮都和对手凑满 `k+1`。反过来，初始数量就是 `k+1` 的倍数时，先手一开始就处在必败态。

### ALG-014：如何求二叉树的直径？

**常见问法**

- 算法：二叉树的直径。

#### 面试回答

先明确口径：直径是任意两节点间最长路径的边数，而且这条路径可能不经过根。

做法是后序遍历，对每个节点算两件事：

- 以该节点为“拐点”的最长路径＝左子树高度＋右子树高度，用全局变量取最大。
- 节点高度＝1＋max(左, 右)，返回给父节点用。

一次 DFS 就能完成，时间 O(n)，递归栈 O(h)。

#### 技术细节

```java
int diameter = 0;

int height(TreeNode node) {
    if (node == null) return 0;
    int left = height(node.left);
    int right = height(node.right);
    diameter = Math.max(diameter, left + right); // 边数口径
    return 1 + Math.max(left, right);
}

int diameterOfBinaryTree(TreeNode root) {
    height(root);
    return diameter;
}
```

**先确认按边数还是节点数**

- 边数口径：答案就是上面的 `diameter`。
- 节点数口径：答案是 `diameter + 1`（单节点树两种口径分别为 0 和 1）。

**一个常见 bug**

- 递归函数返回的是高度，不是拐点路径长度，两者混用是最容易犯的错。
- 树退化成链时递归深度为 O(n)，面试时可以提一句改用迭代栈，或者说明数据约束。

#### 深挖追问

1. **能改成求带权树的直径吗？**（补充练习）

   可以，改动很小：把“高度＋1”换成“高度＋边权”，拐点处仍按左高＋右高更新。另外那种两次 DFS 的解法（任取一点找最远点，再从该点找最远点）对非负权树同样成立。

### ALG-015：“求剩余空间最小值”这类最大子数组和改编题怎么做？

**常见问法**

- 算法：求剩余空间最小值（非 Hot100，像“最大子数组和”改编）。

#### 面试回答

原题只记到一句话，完整约束未知——先向面试官复述确认“剩余空间”的定义，再动手。最可能是两种口径：

- 口径一：给定容量，从数组中选一个连续段装走，剩余＝容量−段和。要让剩余最小，就是求最大子数组和，Kadane 一遍扫描。
- 口径二：直接求最小子数组和，把 Kadane 里的取 max 换成取 min。

确认后按这个顺序作答：说明口径怎么转换、写代码、给出 O(n) 时间／O(1) 空间的复杂度。

#### 技术细节

```java
// ① 最大子数组和（LeetCode 53）
int maxSubArray(int[] a) {
    int cur = a[0], best = a[0];
    for (int i = 1; i < a.length; i++) {
        cur = Math.max(a[i], cur + a[i]);
        best = Math.max(best, cur);
    }
    return best;
}

// ② 最小子数组和：cur/best 全部换成 Math.min
int minSubArray(int[] a) {
    int cur = a[0], best = a[0];
    for (int i = 1; i < a.length; i++) {
        cur = Math.min(a[i], cur + a[i]);
        best = Math.min(best, cur);
    }
    return best;
}
```

**改编题的通用套路**

- 状态一律定义成“以 i 结尾的最优连续段”。
- 然后把“最优”换成题目要的目标：最小剩余、不超过容量的最大、绝对值最接近目标值等等，框架都能直接复用。

**如果题意是“段和不超过容量且剩余最小”**

- 这就得在 Kadane 上再加约束，常用前缀和＋有序结构；数据全非负时也可以用滑窗。
- 必须先确认数据是否含负数——含负数时滑窗不成立。
- 空段是否允许也要确认，允许的话对应“剩余＝容量”。

题意澄清方法同 [[专题题库/算法与数据结构#ALG-013：“最长连续子数组长度”题意不完整时如何澄清与选型？|ALG-013：“最长连续子数组长度”题意不完整时如何澄清与选型？]]。

#### 深挖追问

1. **为什么“以 i 结尾”这个状态定义能兼容各种改编？**（补充练习）

   因为连续段的最优解必然以某个位置结尾，这个状态自带最优子结构。改编题只换目标算子，转移的形式不变，所以框架能照搬。

### ALG-016：如何求无重复字符的最长子串（LeetCode 3）？

**常见问法**

- 算法：LeetCode 3 无重复字符的最长子串（ACM 模式）。

#### 面试回答

用滑动窗口，始终保证窗口 `[left, right]` 内无重复字符：

- 右指针逐字符向右扩张。
- 用哈希表记录每个字符最后一次出现的下标。
- 若当前字符上次的位置 ≥ left，就把 left 直接跳到“上次位置＋1”，不用一格一格缩窗。
- 每一步用 `right-left+1` 更新最大值。

时间 O(n)，空间 O(字符集)。动手前先确认字符集是 ASCII、全小写还是 Unicode，以及大小写敏不敏感——它决定用数组当表还是用哈希表。

#### 技术细节

```java
int lengthOfLongestSubstring(String s) {
    Map<Character, Integer> last = new HashMap<>();
    int left = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        Integer prev = last.get(c);
        if (prev != null && prev >= left) left = prev + 1;
        last.put(c, right);
        best = Math.max(best, right - left + 1);
    }
    return best;
}
```

**一个必须加的判据**

- 判断重复时一定要带 `prev >= left`。少了它，窗口外的旧记录会把 left 往回拉。
- 用 int[128] 数组可以替代哈希表，但前提是先确认字符集。

**ACM 模式要注意**

- 要自己读入：按整行读字符串，是否含空格得先问；输出长度即可。
- 空串返回 0。

**别答错题**

- 求“最长子序列”是另一道题，不要把窗口答成子序列。

#### 深挖追问

1. **变体：最多包含两种不同字符的最长子串怎么改？**（补充练习）

   只换窗口约束：从“无重复”改成“不同字符数 ≤ 2”。用一个计数 Map 维护窗口内各字符的出现次数，种类一超限就缩左边界。整体框架还是滑动窗口。

### ALG-017：如何在两个有序数组中找到第 k 小的元素？

**常见问法**

- 手撕：两个有序数组，找到其中第 k 大的元素。
- 手撕：求两个非降序数组的中位数（LeetCode 4，hard）。

#### 面试回答

先确认口径：“第 k 大”在合并升序视角下换算为第 `m+n-k+1` 小，下面按第 k 小讲。最优解是二分切分：

- 在较短数组 A 上取切分点 i，B 上取 j=k−i，让两数组的左半（A[..i)、B[..j)）共含 k 个元素。
- 当 `A[i-1] <= B[j] 且 B[j-1] <= A[i]` 时，左半的最大值就是第 k 小。
- 条件不满足，就按大小关系移动 i 继续二分。

时间 O(log(min(m,n)))，越界用 ±∞ 哨兵处理（比如 i=0 时左边界取 −∞）。

面试策略：先口述并写出 O(k) 的双指针归并保证正确，再升级到切分二分。

#### 技术细节

```java
int kth(int[] A, int[] B, int k) {           // 第 k 小，1-based，A 为较短数组
    if (A.length > B.length) return kth(B, A, k);
    int lo = Math.max(0, k - B.length), hi = Math.min(k, A.length);
    while (lo <= hi) {
        int i = (lo + hi) >>> 1, j = k - i;
        int aL = (i == 0) ? Integer.MIN_VALUE : A[i - 1];
        int aR = (i == A.length) ? Integer.MAX_VALUE : A[i];
        int bL = (j == 0) ? Integer.MIN_VALUE : B[j - 1];
        int bR = (j == B.length) ? Integer.MAX_VALUE : B[j];
        if (aL <= bR && bL <= aR) return Math.max(aL, bL);
        if (aL > bR) hi = i - 1; else lo = i + 1;
    }
    throw new IllegalArgumentException("k 越界");
}
```

**四条易错点**

- k 的基准：先确认是 1-based 还是 0-based。
- 短数组长度不足时要由另一数组补足，上面 lo/hi 的初值已经处理了这种情况。
- 有重复值时切分仍然成立，因为用的是 ≤ 比较。
- 数组是降序的话要先反转口径。

**一个直接可做的变体**

- 同类变体“两个有序数组的中位数”即 k=(m+n)/2 的特例（LeetCode 4）：取 half=(m+n+1)/2 做同样的切分，奇数时答案就是左边界 max(aL,bL)；偶数时再取右边界 min(aR,bR) 求平均（Java 里记得 `/ 2.0`）。

#### 深挖追问

1. **为什么二分较短数组而不是二分 k？**（补充练习）

   因为切分点 i 的取值受短数组长度限制，在短数组上二分就是 O(log(min(m,n)))。对“值域”二分也可行，但每轮都要数一次两个数组里 ≤x 的总个数，常数更大、边界也更繁琐。

2. **中位数题里总长为偶数时，怎么凑齐中间两个数？**（面经实际出现；[[面经/滴滴/一面/0001#Q10：手撕：求两个非降序数组的中位数（LeetCode 4，hard）。|MJ045 · 滴滴 · 一面 · Q10]]）

   切分满足条件时，左半恰有 half 个元素：偶数情形的“第二个中间数”就是右半最小值 min(aR, bR)，与左半最大值 max(aL, bL) 取平均。数组取空侧时用 ±∞ 哨兵，`i==m` 或 `j==n` 就是右边界越界的信号。

### ALG-018：数组和链表有什么区别，各自适合什么场景？

**常见问法**

- 数组和链表知道吧，讲一下区别以及不同应用场景。
- ArrayList 和 LinkedList 怎么选？

#### 面试回答

一句话：内存布局决定了一切差异。

- 数组：元素连续存放，按下标随机访问 O(1)，地址＝基址＋下标×元素大小。代价是头部／中间插入删除要搬移后续元素 O(n)，而且定长数组的容量要预先确定。
- 链表：节点分散在堆上，靠指针前后串联。已经定位到节点之后，插入删除只改指针，O(1)。代价是不能随机访问——按下标取值必须从头顺着走 O(n)，每个节点还要额外存指针。

场景怎么选：

- 选数组／ArrayList：需要频繁按下标读写、顺序批量遍历、要求缓存友好的场景。
  - 原始 int[]、字符串缓冲也属于这类：StringBuilder 本质是动态数组，靠容量倍增把 append 摊还成 O(1)。
- 选链表／Deque：长度动态变化大、经常在头部或已知位置插拔，并且不想为一块连续内存负责。
  - 典型是 LRU 与 LFU 里的双向链表：哈希表定位节点，链表做 O(1) 摘挂（见 [[#ALG-003：如何手写 LRU 缓存？|ALG-003：如何手写 LRU 缓存？]]）。
  - 还有多路归并中把“下一个元素”挂成链表。

还必须补一句真实结论：

- 现代机器上数组有缓存局部性，线性扫描往往比链表快数倍；渐进复杂度相同、甚至链表“更优”的场景，实测仍常输给数组。
- 所以 Java 里绝大多数场景默认选 ArrayList，LinkedList 只在确实需要双端 O(1) 摘挂且不做下标访问时才考虑。

#### 技术细节

| 维度 | 数组 | 单链表 |
| --- | --- | --- |
| 随机访问 | O(1) | O(n) |
| 头部插入 | O(n)（搬移）或 O(1)（已预留位置） | O(1) |
| 中间插入/删除 | O(n)（搬移，但定位可能 O(1)） | 定位 O(n)＋改指针 O(1) |
| 内存 | 连续、无每元素额外开销，扩容需拷贝 | 每节点多 1～2 个指针＋分配器开销，离散 |
| 缓存 | 好（顺序预取生效） | 差（指针追逐，cache miss 高） |
| 长度 | 定长或倍增扩容 | 天然动态 |

**三条易错点**

- “链表插入一定 O(1)”忽略了查找前驱的成本，多数题面里真正的成本在定位。
- 数组扩容是**摊还** O(1)：第 k 次扩容要拷贝 k 个元素，但 n 次操作总计 O(n)。不能只说“最坏 O(n) 所以慢”。
- 删除单链表节点本身也需要前驱指针，所以实际常用双向链表，或者用“复制后继再删后继”的技巧（LeetCode 237 式，且不能删尾节点）。

**语言实现细节**

- `ArrayList` 的 `remove(i)` 用 `System.arraycopy` 搬移。
- `LinkedList` 是双向链表且 `get(i)` 会从较近的一端开始走——两者都不是 O(1) 随机访问。

#### 深挖追问

1. **为什么 LinkedList 在实际测速中常输给 ArrayList？**（补充练习）

   指针追逐打断了顺序预取，每个节点又是独立对象，还带来分配器与 GC 压力。即便操作次数相同，常数项的差距也可以盖过渐进复杂度上的优势。

2. **既要随机访问又要 O(1) 插入删除怎么办？**（补充练习）

   用组合结构，两条路：
   - 哈希表提供“值→节点引用”的定位，链表提供顺序与摘挂，这就是 LRU 的做法。
   - 或者改用跳表（有序＋期望 O(log n) 定位，见 Redis zset）、树／跳表类索引结构。

3. **数组头部插入有 O(1) 的做法吗？**（补充练习）

   有，两类：
   - 预留头偏移的 deque：环形数组，双端 O(1)、随机访问 O(1)，如 `ArrayDeque`。
   - 分块数组（rope／块表）：插入只需要拆块。
   这类结构正好说明“数组 vs 链表”不是二选一。

### ALG-019：如何判断链表中是否有环，如何找环的入口？

**常见问法**

- 如何判断一个列表里面有环？
- LeetCode 141／142：环形链表与环的入口节点。

#### 面试回答

判环用快慢指针（Floyd 判圈）：

- slow 每次走一步、fast 每次走两步，从同一起点出发。
- 如果 fast 或 fast.next 走到了 null，说明有终点，即无环。
- 如果两者在环内相遇，说明有环。

时间 O(n)、空间 O(1)，比用 HashSet 记录访问节点（要 O(n) 空间）更优。

找入口再走一步：相遇后把其中一个指针移回链表头，两个指针都改成每次一步，再次相遇的位置就是环的入口。

窍门是设三段距离：头到入口 a、入口到相遇点 b、相遇点绕回入口 c。由快慢的路程关系 2(a+b)=a+b+k(b+c)，可以推出 a=(k−1)(b+c)+c——也就是从头走 a 步与从相遇点走 a 步，都正好落在入口。

如果题目给的“列表”其实是数组，而环体现在**下标跳转**上（元素值指向下一个下标，如 LeetCode 457 环形数组、287 寻找重复数）：

- 快慢指针同样能用，因为“每个位置恰好一个后继”就构成了一条隐式链表。
- 更直白的做法还有两种：HashSet 记录已访问下标；或者在不要求保留输入时，把访问过的位置原地打标记／置为 −1，同样能做到 O(1) 空间。

#### 技术细节

```java
public boolean hasCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) return true;
    }
    return false;
}

public ListNode detectCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) {
            ListNode p = head;
            while (p != slow) { p = p.next; slow = slow.next; }
            return p;
        }
    }
    return null;
}
```

**五条易错点**

- 循环条件必须同时判 `fast != null` 和 `fast.next != null`，否则两步跳会 NPE。
- 相遇判断要在**移动之后**做；在起点同一个位置直接比较，会立刻“相遇”而误判。
- 自环（`next` 指向自己）与整条成环都要覆盖到。
- 快指针步长取 2 与取 3 都能判环，但入口推导的等式依赖步长关系，别混用。
- 数组版判环要小心值为负或超出长度（不是合法后继），以及“从 index 0 出发”可能进不了环——这类题常要求先确定入口起点，或者改用图遍历（入度拓扑／visited 状态三色标记）。

#### 深挖追问

1. **为什么不能用 HashSet 一步到位？**（补充练习）

   其实可以，而且更好懂：逐个把节点引用放进 HashSet，第二次遇到就说明有环。代价是 O(n) 时间与空间。面试写完要主动补一句“若要 O(1) 空间则用快慢指针”。

2. **如何求环的长度？**（补充练习）

   相遇后固定一个指针，另一个每次一步再走一圈，回到它时计数就是环长；也可以记录相遇时的步数差来推导。

3. **判环能否用在树上？**（补充练习）

   分三种情况：
   - 树本身：节点的父指针唯一，无环天然成立，不需要判。
   - 节点带 parent 指针：判环等价于判两条根路径是否相交（LeetCode 160），做法是先量深度差再同步前进，或者用 HashSet。
   - 有向图判环：要用 DFS 三色标记，或者拓扑排序后看剩下的节点。

### ALG-020：冒泡排序的原理是什么，如何优化？

**常见问法**

- 排序算法知道吗？讲一下冒泡排序的原理。

#### 面试回答

冒泡排序重复扫描未排序区间：

- 每次比较相邻两个元素，顺序不对就交换。
- 一轮结束后，本轮最大值被“冒泡”到未排序区的最右端。
- 下一轮把右边界左移一位，重复到区间为空。

两个必要优化：

- 记录本轮是否发生过交换。没有交换说明已经有序，可以提前退出，最好情况因此达到 O(n)。
- 记下最后一次交换发生的位置，把它当作新的右边界（该位置右侧已有序），避免死按 n−1 递减。

复杂度：最坏和平均都是 O(n²) 次比较，空间 O(1)。因为只在严格大于时才交换、相等元素不互换位置，所以是**稳定**排序。

工程上不用它排大数据（规模稍大就被插入排序、TimSort 全面取代）。它的价值在于简单、易写对、易验证，教学上承载了“比较排序、稳定性、最好／最坏复杂度”这几个概念。

#### 技术细节

```java
static void bubbleSort(int[] a) {
    if (a == null || a.length < 2) return;
    int lastSwap = a.length - 1;
    while (lastSwap > 0) {
        int boundary = 0;
        for (int i = 0; i < lastSwap; i++) {
            if (a[i] > a[i + 1]) {
                int t = a[i]; a[i] = a[i + 1]; a[i + 1] = t;
                boundary = i;
            }
        }
        lastSwap = boundary;
    }
}
```

**写对的要点**

- 内层循环写 `i < lastSwap`：比较 `a[i]` 与 `a[i+1]`，天然不越界。
- 用 `>` 而不是 `>=` 才稳定。

**横向对比（常被追问）**

- 插入排序：同样是 O(n²)，但在**近乎有序**的数据上远快于冒泡，因为它靠移动而不是逐次交换，比较与写次数都更少。
- 选择排序：交换次数少（O(n) 次），但不稳定，而且比较恒为 O(n²)。
- 工业实现基本是混合策略：Java 的 `Arrays.sort` 对对象用归并系（TimSort，稳定、O(n log n)、需额外空间），对基本类型用双轴快排；C++／Python 亦用 intro-sort／Timsort。

**排序题的标准回答顺序**

- 先说清原理与不变量，再给复杂度与稳定性，最后说“工程上会选什么以及为什么”，参见 [[#ALG-009：如何手写快速排序？|ALG-009：如何手写快速排序？]]。

#### 深挖追问

1. **冒泡排序稳定吗，为什么？**（补充练习）

   稳定。原因是只在严格 `a[i] > a[i+1]` 时交换，相等元素永不互换，所以相等键的相对次序全程不变。

2. **最好复杂度为什么是 O(n)？**（补充练习）

   输入已有序时，第一轮扫描不发生任何交换，靠 swapped／boundary 标志立刻退出，总共只做了 n−1 次比较。

3. **为什么工程里不用冒泡？**（补充练习）

   两个原因：
   - O(n²) 的增长在 n=10⁴ 量级就已经不可接受。
   - 它每轮只能把元素移动有限距离，交换次数与逆序对数同阶。
   插入排序、归并、快排在常数和增长上都占优。

### ALG-021：两数之和如何用哈希表一次遍历求解？

**常见问法**

- 两数之和：给定数组和目标值，返回两个数的下标。

#### 面试回答

一次遍历＋哈希表：

- map 保存“已经扫过的值 → 它的下标”。
- 对每个 `nums[i]`，先算补数 `target − nums[i]` 去 map 里查，命中就返回 `{查到的下标, i}`。
- 没命中，再把当前值和它的下标写进 map。

时间 O(n)、空间 O(n)。关键顺序是**先查后放**：这样每个元素只会与它之前的元素配对，天然避免用自身配自身（例如 target 恰好是某元素两倍时不会自匹配），也满足“同一元素不能重复使用”。

对比其他做法：

- 暴力双重循环：O(n²) 时间、O(1) 空间。
- 左右双指针：O(n) 时间、O(1) 空间，但要求数组已排序。一般无序数组要先排序，就会打乱下标，得额外保存原索引，复杂度也升到 O(n log n)。
- 所以题目要的是下标时，哈希表最直接。

#### 技术细节

```java
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> indexByValue = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        Integer j = indexByValue.get(target - nums[i]);
        if (j != null) return new int[]{j, i};
        indexByValue.put(nums[i], i);
    }
    return new int[0];
}
```

**易错点**

- 存在重复值时，“后写覆盖”会让 map 保留较新的下标。又因为是先查后放，返回的下标顺序是“早出现的在前”；若题目要求升序，得自己调整。
- 判空用 `get` 返回的 `Integer`，不要把 `containsKey` 和 `getOrDefault` 混着写。`0` 是合法下标，别拿返回值当假值判断。
- 溢出：`target - nums[i]` 在 int 范围内做减法仍可能溢出（target 为 `Integer.MIN_VALUE` 且元素为负）。严谨实现可以先用 long 算补数，再判断它是否落回 int。

**常见变体**

- 三数之和：排序＋固定一个＋双指针，去重是关键（思路同类于 [[#ALG-004：如何合并重叠区间？|ALG-004]] 的“排序后双指针”）。
- 四数之和：在三层循环外加剪枝。
- “和为 S 的最多配对数”：用计数 map。
- “两数之和 II（有序）”：用对向双指针。

#### 深挖追问

1. **为什么不用两次遍历？**（补充练习）

   两次遍历（先建 map 再查）也可行，只是要先处理“自己配自己”：得判断 `map.get(complement) != i`。一次遍历的先查后放把这层特判消掉了，代码更短，也少维护一份状态。

2. **哈希表的最坏复杂度是多少？**（补充练习）

   期望 O(1)，最坏 O(n)：大量哈希冲突会退化成链表。Java 8 之后 HashMap 在链表长度超阈值且表长足够时会转红黑树，退化风险降低了，但树化只解决最坏查找，不改变哈希函数的分布问题。极端对抗输入可以考虑随机化或换结构。

3. **数据量到亿级、内存放不下 map 怎么办？**（补充练习）

   走外存／分片的思路，两条路：
   - 按值域哈希分桶落盘，再逐桶加载做两两配对：同桶内必有配对时可以直接处理，跨桶配对的用另一趟排序归并。
   - 先排序＋外部归并，再做双指针扫描。
   核心是把 O(n) 的额外内存换成多趟顺序 I/O。

### ALG-022：如何求字符串数组的最长公共前缀？

**常见问法**

- 最长公共前缀：求字符串数组的最长公共前缀，无公共前缀返回空串，注意空数组边界。

#### 面试回答

纵向扫描最直观：拿第一个字符串当基准，按下标 `col` 逐位比较所有字符串的第 `col` 个字符。

- 只要出现“某个串长度已经到 `col`”或者“字符与基准不同”，就返回 `strs[0].substring(0, col)`。
- 整个基准都被比完了，说明它自己就是答案。

边界先处理：数组为 null 或长度为 0 直接返回空串；数组里含空串时结果自然是空串，这套逻辑已经覆盖。复杂度 O(S)，S 是全部字符总数。

另外两种常见写法：

- 横向归约：把第一个串当答案，依次与后面每个串求“两串公共前缀”并缩短，一旦为空就提前 break。
- 排序法：排序后只需比较最小串与最大串（字典序相邻的两端），取它们的前缀就是整体前缀；代价是多一次 O(n log n) 排序，而且不宜修改入参。

三种都正确，纵向扫描最容易在面试中讲清楚。

#### 技术细节

```java
public String longestCommonPrefix(String[] strs) {
    if (strs == null || strs.length == 0) return "";
    for (int col = 0; col < strs[0].length(); col++) {
        char c = strs[0].charAt(col);
        for (int k = 1; k < strs.length; k++) {
            if (col >= strs[k].length() || strs[k].charAt(col) != c) {
                return strs[0].substring(0, col);
            }
        }
    }
    return strs[0];
}
```

**五条易错点**

- 循环条件顺序：必须先判 `col >= strs[k].length()` 再取字符，短路写法不能反。
- 用 `charAt` 比，不要用 `substring` 拼接来比，避免每步都造字符串。
- 单元素数组直接返回该串。
- 只有 null 与空数组要特判；`strs[0]` 为空串时，外层循环天然不进入并返回 `""`。
- 需要按码点比较的国际化文本时，`charAt` 会拆代理对，要用 `codePointAt`／`offsetByCodePoints`。

**能延伸到哪里**

- 横向归约的“两串公共前缀”可以复用为“任意时刻动态维护前缀”的能力。
- 配 Trie：把一批字符串插入后，沿唯一子路径下探就得到最长公共前缀。
- 数据量大且要支持“任意子区间的最长公共前缀”查询时，可用线段树／稀疏表对逐位相等做区间归约——这是把 LCP 从 O(S) 变成预处理＋O(log n) 查询的思路。

#### 深挖追问

1. **为什么可以只比较排序后的首尾两串？**（补充练习）

   因为字典序最小与最大串之间的所有串，其前缀必然包含这两者的公共前缀：若某串的公共前缀更短，它就会排在首串之前或尾串之后，与“它是首／尾”矛盾。所以排序后只比 `strs[0]` 与 `strs[n-1]` 即得答案，代价换成 O(n log n)＋排序可能改动输入。

2. **能比 O(S) 更快吗？**（补充练习）

   单次查询不能——每个字符至少要被看一次才能确认前缀。但同一批字符串上的多次查询可以预处理，例如“区间 [i, j] 内串的最长公共前缀”，用逐位比较＋ST 表就能在 O(1)～O(log n) 内回答。

### ALG-023：零钱兑换（LeetCode 322）如何用动态规划求最少硬币数？

**常见问法**

- 手撕：硬币找零问题（LeetCode 322）。

#### 面试回答

先复述题意：给定硬币面额 `coins`（每种无限个）和金额 `amount`，求凑出 `amount` 所需的**最少硬币数**，凑不出返回 -1。

这是完全背包型动态规划：

- `dp[j]` 表示凑出金额 `j` 的最少硬币数。
- `dp[0]=0`，其余初始化成一个不可达的哨兵（用 `amount+1`，比任何合法解都大）。
- 转移：对每种面额 `c`，`dp[j] = min(dp[j], dp[j-c] + 1)`（`j>=c`）。
- 最后 `dp[amount]` 若仍是哨兵就返回 -1。

时间 O(amount·|coins|)，空间 O(amount)。

#### 技术细节

```java
int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);
    dp[0] = 0;
    for (int j = 1; j <= amount; j++) {
        for (int c : coins) {
            if (c <= j) dp[j] = Math.min(dp[j], dp[j - c] + 1);
        }
    }
    return dp[amount] > amount ? -1 : dp[amount];
}
```

**遍历顺序**

- 求“最少数量”时，外层遍历金额、内层遍历硬币最直观：每个 `j` 枚举最后一步用哪种硬币。
- 这跟“凑法种数”题（518）的遍历顺序不同——数硬币最少时，两重循环的顺序不影响最值；但计数题必须“外层硬币、内层金额”，否则会把同一种组合按不同顺序重复计数。别把两者混为一谈。

**哨兵为什么选 `amount+1`**

- 用 `Integer.MAX_VALUE` 的话，`MAX_VALUE+1` 会溢出。
- `amount+1` 天然是一个“不可能达到的上界”（最多也就 amount 个面额 1 的硬币），最后判断 `>amount` 就是无解。

**贪心为什么不行**

- 只有当币值体系“规范”（如某些面额）时贪心才最优。
- 反例：`coins=[1,3,4], amount=6`，贪心得 4+1+1=3 枚，最优其实是 3+3=2 枚——所以必须 DP。

#### 深挖追问

1. **如果要输出具体用了哪些硬币，怎么改？**（补充练习）

   加一个 `prev[j]`／`choice[j]`，记录把 `dp[j]` 更新为最优时所用的面额；最后从 `amount` 沿 `choice` 回退到 0，就能还原方案。不要求输出方案时可以不记录，省下这部分空间。

2. **和“凑出金额的组合数”（LC 518）区别在哪？**（补充练习）

   状态定义与转移方向都不一样，别套错：
   - 518 求方案数、组合不计顺序，用 `dp[j]+=dp[j-c]`，而且**外层硬币、内层金额**来保证不重复计数。
   - 322 求最少枚数、用 `min`，两重遍历的顺序对结果没有影响。

### ALG-024：LeetCode 31：如何原地求下一个排列？

**常见问法**

- Leetcode 31，没有让手撕，讲思路和时间复杂度。

#### 面试回答

下一个排列＝字典序中恰好更大的排列；不存在时回绕成最小排列。三步：

- 从右往左找第一个升序相邻对 a[i] < a[i+1]，i 就是枢轴。i 右侧是降序后缀，已经是该前缀下的最大排列。找不到枢轴说明整体降序，直接全局反转。
- 再从右往左找第一个大于 a[i] 的数，与 a[i] 交换。
- 最后把 i 之后的后缀反转成升序。

时间 O(n)，至多两遍扫描加一次反转，原地 O(1) 空间。

口述要点是讲清不变量：交换前后后缀都保持降序，所以“从右找第一个大于枢轴的数”拿到的就是后缀中比枢轴大的最小值；反转尾部是为了让后缀变成最小。

#### 技术细节

```java
void nextPermutation(int[] a) {
    int i = a.length - 2;
    while (i >= 0 && a[i] >= a[i + 1]) i--;          // 找枢轴
    if (i >= 0) {
        int j = a.length - 1;
        while (a[j] <= a[i]) j--;                    // 后缀中 >a[i] 的最小值
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }
    reverse(a, i + 1);                               // 后缀转升序（i=-1 时即全局反转）
}
void reverse(int[] a, int l) {
    for (int r = a.length - 1; l < r; l++, r--) {
        int t = a[l]; a[l] = a[r]; a[r] = t;
    }
}
```

**走一遍例子**

- `1 5 8 4 7 6 5 3 1` → 枢轴 i=3（4<7），j 找到 5，交换得 `1 5 8 5 7 6 4 3 1`，反转后缀得 `1 5 8 5 1 3 4 6 7`。

**一个边界坑**

- 有重复元素时比较要用 `>=`／`<=`（非严格），否则会跳过相等值导致结果错误；这是本题最常见的边界坑。

**要不要在查找里做二分**

- 第二个查找可以在降序后缀上二分（找“大于 a[i] 的最大下标”），但整题复杂度仍是 O(n)，反转是瓶颈之外的常数，面试不值得为此牺牲可读性。

#### 深挖追问

1. **为什么交换后后缀仍保持降序？**（补充练习）

   因为交换对象 j 是后缀中大于枢轴的最小值：
   - 把原 a[i] 放进 j 位后，它和两侧仍满足不升。理由是 a[j-1] ≥ 原 a[i]（否则 j-1 才是可交换的更大值……实际由“从右第一个大于”保证 a[j-1] > a[j] 且 a[j-1] ≥ a[i]）。
   - 原 a[j] 放到 i 位，不影响后缀内部的次序。
   所以后缀仍保持降序，只需一次反转即成全局最小。

2. **如果是上一个排列呢？**（补充练习）

   做法完全对称：找第一个降序相邻对 a[i] > a[i+1]，与左侧“小于 a[i] 的最大值”交换，再把后缀反转成降序。

### ALG-025：如何用异或找出只出现一次的数？

**常见问法**

- 有一堆数，有一个数出现了一次，其他的数都出现了两次，怎么才能快速地找出这个出现一次的数？

#### 面试回答

做法是全体异或一遍。

- 依据：异或满足交换律、结合律，且 x^x=0、x^0=x，所以出现两次的数两两抵消，最终留下的就是只出现一次的数。
- 时间 O(n)、空间 O(1)，不需要哈希表计数，也不需要排序。

前提假设要主动说出来：恰有一个落单、其余都出现两次。条件一变方法就跟着变（出现三次、两个落单的版本见追问）。

#### 技术细节

```java
int singleNumber(int[] nums) {
    int r = 0;
    for (int x : nums) r ^= x;
    return r;
}
```

**适用域**

- 整数按位异或即可，对负数与补码表示同样成立（逐位抵消与符号无关）。

**对比口径**

- 哈希计数：O(n) 时间，但要 O(n) 空间。
- 排序后两两比较：O(n log n)，而且会修改输入。
- 面试一句话总结：“异或赢在线性时间加常数空间”。

**什么时候失效**

- 这个技巧依赖“配对”这一代数结构。元素出现次数不满足可抵消条件时（如 3 次），要换成按位统计再对次数取模。

#### 深挖追问

1. **其余数出现三次、一个出现一次怎么办？**（补充练习；与 [[面经/帆软/二面/0002#Q12：一堆数中只有一个出现一次、其余都出现两次，如何快速找出它？|MJ035 · 帆软 · 二面 · Q12]] 同场的变体问法）

   两条路：
   - 按位统计：对 32 个位分别累加所有数该位为 1 的次数，再对 3 取模，余数就是答案的该位；O(32n) 时间、O(1) 空间。
   - 进阶是 ones／twos 双掩码状态机：`ones = (ones ^ x) & ~twos; twos = (twos ^ x) & ~ones;`，用两个变量记录每一位的“模 3”状态，一趟完成。

2. **有两个数各出现一次，其余两次，怎么找？**（补充练习）

   先全体异或，得到 a^b。再取任一为 1 的位（`v & -v`），这一位为 1 说明 a、b 在它上面不同。按该位把数组分成两组分别异或，两组结果就是 a 和 b。

3. **为什么异或对负数也成立？**（补充练习）

   因为异或是逐位操作，而 Java 的 int 以补码存储：配对的两个负数按位全部抵消，与符号位无关。

### ALG-026：取值范围远小于数据量时如何给海量数据排序？

**常见问法**

- 对 2 亿个数据进行排序，取值范围是 1 万到 2 万之间，怎么实现？

#### 面试回答

用计数排序：值域只有约 1 万种，就开一个长度 10001 的计数数组。

- 第一趟流式扫输入，每来一个数就 `count[x-10000]++`。
- 第二趟按值域从小到大扫描计数数组，每个值重复输出对应的次数。

时间 O(n+k)（k=10001），大约两趟。额外空间只有几千个计数器，2 亿条数据本身不需要全部进内存，瓶颈在顺序 I/O。

选型理由要顺带说明：

- n log n 的内存排序放不下 2 亿条数据。
- 位图只能表达“存在与否”，会丢掉重复次数；要保频次就得用计数数组。

#### 技术细节

```java
// 输入以 int 流（文件或迭代器）给出，值域 [10_000, 20_000]
long[] cnt = new long[10_001];            // 2 亿 > int？计数上限 2e8 < 2^31，int 也够；留余量用 long
while (stream.hasNext()) cnt[stream.nextInt() - 10_000]++;
for (int v = 0; v <= 10_000; v++)
    for (long c = cnt[v]; c > 0; c--) out.writeInt(v + 10_000);
```

**稳定性**

- 计数排序天然稳定（按前缀和定位时）。本场景输出只有值、没有附加信息，所以稳定性无关紧要。

**内存量级**

- 即使 n=2 亿全部进内存也才约 800MB（每个 int 4 字节）。
- 面试官给“取值范围极小”这个条件，就是指向 O(n+k) 的计数法，别一上来答外部排序。

**值域稍大时怎么办**

- 比如上亿种取值但 n 仍是 2 亿，计数数组就放不下了：退到分块外部排序，或者在允许丢失重复次数时用位图。

#### 深挖追问

1. **和基数排序、桶排序什么关系？**（补充练习）

   三者是一条线：
   - 计数排序是“桶＝每个取值一个”的极限情形。
   - 值域连续均匀时，桶排序分 √n 量级的桶、桶内再排，算是它的折中。
   - 基数排序按位分趟，把计数排序当作稳定子过程来用。

2. **数据从磁盘来，怎么减少 I/O？**（补充练习）

   计数阶段只需一次顺序读、输出阶段一次顺序写，这已经天然最优。若还要“排序后原样带附属记录”，就改成两遍：
   - 第一遍只读 key 做计数，得到值域边界。
   - 第二遍按值域分桶，把记录写到 10001 个追加文件里，再一次顺序读出。
   这样仍是 O(n) 趟数。

### ALG-027：如何用位图对已知值域的数据去重排序？

**常见问法**

- 对取值范围 0 到 1000 的数组去重并按顺序打印。
- 如何节约内存？
- 取值范围扩大到 0 到 10 亿且内存放不下全部数据，如何实现？
- 能否用压缩方式直接在内存处理？

#### 面试回答

值域已知且远小于数据量时用位图：0—1000 只需 1001 个 bit，约 126 字节的 long[]。

- 第一趟把每个数 x 置位：`bits[x>>6] |= 1L << (x&63)`。重复置位没有副作用，这一步就是去重。
- 第二趟从低位到高位扫描为 1 的位，按位下标顺序打印。这样“去重＋排序”一步完成。

时间 O(n + 值域)；空间与 n 无关，只与值域有关。

内存还能再省的口子在结构本身：

- 布尔数组每个元素占 1 字节，位图压成 1 bit 已经省了 8 倍。
- 数据稀疏时，进一步按字分块压缩存储。
- 值域大到位图也放不下时，按段分趟扫描，用 k 遍 I/O 换内存 1/k；或者退回分块外部排序。

#### 技术细节

**基础位图与按字压缩位图**

- 下面是编程珠玑式的 word bitmap：稀疏时，全 0／全 1 的字不存 64 位原值。

```java
class CompressedBitmap {                       // 值域 [0, nWords*64)
    static final int EMPTY = 0, FULL = 1, OTHERS = 2;
    final byte[] type; final long[] word;      // word 仅 OTHERS 使用
    CompressedBitmap(int bits) { type = new byte[(bits + 63) >>> 6];
                                 word = new long[type.length]; }
    void set(int i) {
        int w = i >>> 6;
        switch (type[w]) {
            case EMPTY: type[w] = OTHERS;              // 分块惰性分配
            default:    word[w] |= 1L << (i & 63);
        }
    }
    void clear(int i) {                              // 删除：FULL 要先展开
        int w = i >>> 6; long mask = ~(1L << (i & 63));
        if (type[w] == FULL) { word[w] = mask; type[w] = OTHERS; }
        else if (type[w] == OTHERS) {
            word[w] &= mask;
            if (word[w] == -1L) type[w] = FULL;
            else if (word[w] == 0)  type[w] = EMPTY;  // 回收：字归零可不释放，视实现
        }
    }
    boolean get(int i) {
        int w = i >>> 6;
        if (type[w] == EMPTY) return false;
        if (type[w] == FULL)  return true;
        return (word[w] & (1L << (i & 63))) != 0;
    }
    void printAll() {                              // 顺序输出：去重排序的“排序”侧
        for (int w = 0; w < type.length; w++) {
            if (type[w] == EMPTY) continue;        // 全 0 字整块跳过
            if (type[w] == FULL) { for (int b = 0; b < 64; b++) emit(w*64 + b); continue; }
            long x = word[w];
            while (x != 0) { int b = Long.numberOfTrailingZeros(x); emit(w*64 + b); x &= x - 1; }
        }
    }
}
```

**现成实现**

- 普通位图 Java 直接用 `java.util.BitSet`（自动扩容的压缩词结构）；C++ 用 `vector<bool>` 或手写 `uint64_t[]`。

**0—10 亿量级怎么算**

- 完整位图 10^9 bit ≈ 119 MB——其实多数现代机器放得下。
- 面试说“放不下”时给两把钥匙：分趟（第 t 趟只统计区间 [t·M, (t+1)·M) 的数，位图大小 M，扫输入 k 次）与压缩位图（稀疏数据实际字数远小于总字数）。

**位图的固有口径**

- 位图表达“存在性”，天然去重，但丢重复次数；要频次就升级成计数数组（见 [[#ALG-026：取值范围远小于数据量时如何给海量数据排序？|ALG-026：取值范围远小于数据量时如何排序]]）。

**与布隆过滤器的区别**

- 位图存精确存在性、无假阳性，值域必须小且已知。
- 布隆过滤器用极小空间换“可能有假阳性”的判断，见 [[专题题库/Redis#REDIS-002：缓存穿透是什么，布隆过滤器能完全解决吗？|REDIS-002：布隆过滤器]]。

#### 深挖追问

1. **如何节约内存？**（面经实际出现；[[面经/帆软/三面/0002#Q02：0 到 1000 的数组去重并按序打印：位图及其内存优化与超范围扩展（含四个追问）。|MJ035 · 帆软 · 三面 · Q02]]）

   分三层说：
   - 第一层就是位图本身：从“每元素 1 字节”压到“每元素 1 bit”。
   - 第二层是按字类型压缩（EMPTY／FULL／OTHERS），稀疏时全 0 字不占存储。
   - 再往下还可以差值编码＋变长整数，但都会牺牲 O(1) 置位能力。面试给到字级压缩即可。

2. **值域扩到 0—10 亿、内存存不下怎么办？**（面经实际出现；同上来源）

   - 先当场估量级：10 亿 bit ≈ 119MB，这个数要能报出来，先判断是“真放不下”还是“可以硬扛”。
   - 真放不下就分趟扫描：值域切 k 段，每段单独建位图，每趟全文扫一遍只处理本段的数，用 k 遍顺序 I/O 换内存 1/k。
   - 若允许非精确去重，可换布隆过滤器；若是通用排序需求，则分块外部排序。

3. **压缩后能直接在内存处理吗？**（面经实际出现；同上来源）

   能，前提是数据稀疏（实际写入的位置很分散，全 0 字占比高）。这时压缩位图只存非空字，内存占用从与值域线性相关变成与元素数线性相关。置位、判存、顺序打印都能在压缩结构上做，全 1 字还能整块跳读来加速。

4. **写出压缩部分的主要逻辑。**（面经实际出现，要求现场编码；同上来源）

   - printAll 按类型分支顺序输出。

### ALG-028：如何在 0 到 N 中找出缺失的那个数？

**常见问法**

- 给定长度为 N 的数组，取值范围为 0 到 N（本应有 N+1 个数但缺失一个），如何找到缺失数字？如 [0,1,3,4,5,6]，缺失 2。

#### 面试回答

O(n) 时间、O(1) 空间有两条路：

- 异或法：先算 0^1^…^N，再依次异或数组每个元素，成对抵消后剩下的就是缺失值，没有溢出顾虑。
- 求和法：期望和 N(N+1)/2 减去实际和就是差值。但必须主动声明用 long——N 到 10^5 量级时 int 就会溢出，这是本题最常见的追问埋点。

若数组不可修改、只能读一遍，两法都满足。若允许 O(N) 额外空间，布尔标记数组最直观，可以作为对照提一句。

#### 技术细节

```java
int missing(int[] a) {                 // 数组长度 N，值域 0..N 缺一个
    int x = 0;
    for (int i = 0; i < a.length; i++) x ^= i ^ a[i];
    return x ^ a.length;               // 再异或 N 本身
}
```

**异或写法为什么等价**

- 循环内同时异或下标与元素：下标走 0..N-1，最后再补异或 N，等价于“0..N 全体异或数组全体”。

**求和版**

- `long miss = (long) n * (n + 1) / 2 - sum;`

**同族联系**

- 与 [[#ALG-025：如何用异或找出只出现一次的数？|ALG-025：异或找只出现一次的数]] 同族：都靠“配对抵消”，这里把 0..N 的完整序列当作“影子数组”与残缺数组配对。

#### 深挖追问

1. **缺了两个数怎么办？**（补充练习）

   还是用异或：
   - 全集与数组整体异或，得到 a^b。
   - 取结果中任一为 1 的位作分组键，把 0..N 和数组元素各自按该位分成两组，组内分别异或；两个非零组的结果就是两个缺值。
   - 若改用求和，需要 S1、S2 两个方程（和与平方和）联立，还有溢出风险。

2. **取值范围变成 0..M（M>N-1 的稀疏情形）还能这么做吗？**（补充练习）

   不能直接套用。异或／求和都依赖“值域大小与数组长度耦合”的结构；M 远大于 N 时元素不再一一对应，要退回哈希集合或排序后线性扫描，或者在值域可容纳时用位图标记（见 [[#ALG-027：如何用位图对已知值域的数据去重排序？|ALG-027：位图]]）。

### ALG-029：如何求最大子数组乘积（LeetCode 152）？

**常见问法**

- 手撕：最大子数组乘积（LeetCode 152）。

#### 面试回答

与最大子数组和（LC 53）的分岔点在负数：当前乘积是一个很小的负数时，再乘一个负数可能翻身成为最大。所以“以 i 结尾的最大乘积”不能只由前一个最大值转移来。

解法是同时维护以当前元素结尾的最大积 mx 和最小积 mn：

- 每步对 `x`、`mx*x`、`mn*x` 三者取最大／最小——含义是“续接前面的子数组”还是“从 x 重开”。
- 全局答案取历史 mx 的最大值。
- 乘法遇 0 就归零，0 天然充当断点。

时间 O(n)、空间 O(1)。初始化要用 a[0] 而不是 0：全负数组（如 `[-3]`）正确答案是最大负数，初值给 0 会错。

#### 技术细节

```java
int maxProduct(int[] a) {
    int mx = a[0], mn = a[0], ans = a[0];
    for (int i = 1; i < a.length; i++) {
        int x = a[i];
        if (x < 0) { int t = mx; mx = mn; mn = t; }   // 乘负号翻转，先交换再乘
        mx = Math.max(mx * x, x);                      // 续接 or 重开
        mn = Math.min(mn * x, x);
        ans = Math.max(ans, mx);
    }
    return ans;
}
```

**不用交换的等价写法**

- `int p = mx*x, q = mn*x; mx = max(x, max(p, q)); mn = min(x, min(p, q));`
- 关键是先存旧值，避免拿更新后的 mx 去推 mn。

**验证用例**

- `[-2,3,-4]` → 24（整段相乘）。
- `[2,-5,-2,-1,3]` → 20（子数组 `[2,-5,-2]`）。
- `[0,2]` → 2（0 处重开）。
- `[-2]` → -2（单元素负数）。

**溢出**

- 在 int 数组的约束下，连续乘可能越界（如大量 -1 与 2 交替）；LC 官方数据在 int 内安全。
- 口述时主动提一句“生产实现换 long 或按约束设防”即可。

#### 深挖追问

1. **为什么不能只维护一个最大值？**（补充练习）

   反例 `[-2, -3]`：走到 -2 时，最大结尾积是 -2、最小也是 -2；到 -3 时，(-2)·(-3)=6 恰恰由“最小值 × 当前负数”产生。也就是说最大值序列在负数处不闭合，最小值序列携带了翻身信息。

2. **和 LC 53 最大子数组和、ALG-015 改编题的迁移关系？**（补充练习；见 [[#ALG-015：“求剩余空间最小值”这类最大子数组和改编题怎么做？|ALG-015：最大子数组和改编]]）

   同族题，都是“以 i 结尾”的 Kadane 型 DP，只是状态从 1 个（最大和）变成 2 个（最大积＋最小积），转移由 max 换成 max/min 双开口。
   这族题的通式是：先定义以 i 结尾的状态，再判断转移是否需要重开。乘法和负数只是让状态必须成对出现。

### ALG-030：如何做字符串相加（LeetCode 415）？

**常见问法**

- 手撕 LeetCode 415（字符串相加）。

#### 面试回答

题意：两个非负整数字符串，不用内置大整数，模拟竖式加法返回结果字符串。

- 双指针从两个串的末尾起，每轮算 `d1+d2+carry`：本位 `sum%10` 追加到 StringBuilder，进位取 `sum/10`。
- 循环条件写成 `i>=0 || j>=0 || carry>0`，两指针都耗尽且无进位才停；这样不用在循环外补最高位进位。
- 因为是逆序拼接，最后 `reverse()` 一次。

时间 O(max(m,n))，空间 O(max(m,n))。

口述时主动报三个坑：

- char 转数值必须 `c-'0'`，直接把 char 相加得到的是 ASCII 之和。
- `"0"+"0"` 返回 `"0"`：题目约定无多余前导零，不需要额外裁剪逻辑。
- 最长结果可能比长串还多一位（999+1），所以空间预留 max+1。

写完用 `["999","1"]→"1000"` 与 `["0","0"]→"0"` 各走一遍。

#### 技术细节

```java
String addStrings(String a, String b) {
    StringBuilder sb = new StringBuilder();
    int i = a.length() - 1, j = b.length() - 1, carry = 0;
    while (i >= 0 || j >= 0 || carry > 0) {
        int d1 = i >= 0 ? a.charAt(i--) - '0' : 0;
        int d2 = j >= 0 ? b.charAt(j--) - '0' : 0;
        int sum = d1 + d2 + carry;
        sb.append(sum % 10);
        carry = sum / 10;
    }
    return sb.reverse().toString();
}
```

**同族迁移**

- 这道题与字符串相乘（LC 43）、链表相加（LC 2）、二进制求和（LC 67）共用“逐位对齐＋进位”骨架，差别只在结果落位方式（链表节点／数组下标／字符串追加）。
- 会一道就要能现场推其余。

**变体风险**

- 若输入可能有前导零或空串，要先归一化。
- 本题按 LC 约束（非负、无前导零）处理，答题前把这些假设说出口。

#### 深挖追问

1. **为什么进位要放进循环条件而不是循环后补？**（补充练习）

   放进条件里，循环会自然处理“两串耗尽但 carry=1”的最后一轮，少一段收尾代码也就少一个漏判。两种写法都对，面试要的是把边界说清。

2. **两串都 10^5 位，还能优化什么？**（补充练习）

   复杂度已经是下限了——每位至少要被看一次。工程上可以预分配 `capacity = max+1`，避免 StringBuilder 扩容拷贝，其余都只是常数优化。

### ALG-031：如何求多个矩形的重叠总面积（扫描线）？

**常见问法**

- 如果拓展到二维，计算所有矩阵重叠的总面积该怎么做？
- 手撕：重叠区间的总长度（一维铺垫）。

#### 面试回答

先确认口径再动手，“重叠的总面积”有两种读法：

- 所有矩形覆盖到的总面积（并集面积）：这是扫描线经典题。
- 被矩形们公共覆盖的面积（交集面积）：那只是依次求交集，相交部分仍是矩形，逐步收缩边界、最后算面积，复杂度 O(n)。

两种答案差很多，别默认。以下按并集作答，并顺带说清一维铺垫。

**一维铺垫**

- 求区间并集总长度：按左端点排序后线性扫描，维护当前段 `[start, end]`。
  - 新区间的左端点大于 `end`，就结算上一段并另起一段；否则把 `end` 扩到 `max(end, 右端)`。
  - 扫描完最后再结算一次。整体 O(n log n)。
- 若问“被两个及以上区间覆盖的长度”：把每个区间拆成 `(左, +1)`、`(右, -1)` 事件，排序后扫描，累计覆盖计数≥2 的跨度。阈值换成 n 就是全部区间的公共重叠。

**二维并集（扫描线）**

- 把每个矩形拆成两类 x 事件：左边界“加入区间”、右边界“移除区间”，然后按 x 排序。
- 扫描时维护当前有效的 y 区间集合；每处理一个事件，就把“上一个 x 跨度 × 当前 y 覆盖总长度”累加进答案。
- 核心思想是把二维面积降成一维覆盖长度。
- y 覆盖长度的维护有两档：每次对 y 区间排序合并，实现简单、不易写错，O(n² log n)；把 y 坐标离散化后用线段树维护“覆盖计数＋被覆盖长度”，整体 O(n log n)。
- 面试里先给朴素版并说清瓶颈，再给线段树版，比直接上来写线段树更容易讲明白。

#### 技术细节

**线段树版本的要点**

- 节点存两个量：`count`（被完整覆盖的次数）与 `len`（该区间内被覆盖的长度）。
- `count > 0` 时，`len` 直接等于该节点的实际坐标跨度；否则等于左右孩子 `len` 之和（叶子为 0）。
- 因为坐标是离散化后的点，跨度要用原坐标差而不是下标差；相邻离散点之间的“段”才是更新单位，通常把区间端点减一处理半开段。
- 加与删是同一个函数带符号 delta；这里不采用懒传播的常规写法，而是依赖 `count` 的语义，这是该题的标准结构。

**边界与易错点**

- 端点相接算不算重叠：半开处理最省事，面积上不影响并集结果，但“公共重叠”口径会影响。
- 还要覆盖重复矩形、完全包含、只共边这些情况。
- 坐标为负或坐标范围极大时需要离散化，否则数组开不下。
- 面积累加用 long 防溢出。
- 同一个 x 上，先处理后一个加入会导致多算；稳妥做法是把同一 x 的所有事件一起处理，算一次 y 覆盖长度再推进 x 跨度。

**复杂度与取舍**

- n 个矩形的并集面积：线段树版 O(n log n)，排序合并版 O(n² log n)。
- 朴素“逐格统计”只在坐标范围小时可行（网格＋计数，类似 [[#ALG-027：如何用位图对已知值域的数据去重排序？|ALG-027：位图]] 的值域思路）。
- 若题目是 n 维推广，扫描线递归嵌套（分治）会显著变难；面试里点到“可用 k-d tree／区间树但代价高”即可，别硬编。

#### 深挖追问

1. **为什么不能简单两两求交集再相加？**（面经实际出现；[[面经/阿里云/三面/0001#Q03：手撕重叠区间的总长度；拓展到二维计算所有矩阵重叠的总面积（自评：答的一般）。|MJ039 · 阿里云 · 三面 · Q03]]）

   因为会重复计算：三个矩形两两相交于同一块时，成对交集相加会把重叠部分算多次；要按容斥原理做就是 2ⁿ 项，指数级。扫描线的正确性来自“沿 x 推进时把已覆盖区域切成不重叠的竖条”，每条只算一次。

2. **n 很大、坐标范围也很大时，内存怎么省？**（补充练习）

   三层递进：
   - 离散化只保存出现过的坐标（O(n) 个）。
   - 再按 x 分块或外部排序分治处理，把同时活跃的矩形数控制住。
   - 纯位图网格在坐标跨度大时不可行。

3. **一维“覆盖≥2 的长度”用差分不是更简单吗？**（补充练习）

   值域小时可以：差分数组加前缀和就行，O(值域)。值域大就退化成事件扫描（等价于稀疏差分），复杂度只跟区间数走。所以顺序是先问坐标范围，再选实现。

### ALG-032：如何删除链表中所有重复元素（LeetCode 82）？

**常见问法**

- 手撕：删除链表中的所有重复元素。
- 链表里重复的节点全部删掉，一个都不留，怎么写？

#### 面试回答

先确认三件事：

- 链表是否有序。
- 是“重复值全删”还是“保留第一个”（LeetCode 82 与 83 的区别）。
- 能否用额外空间。

全删且有序的解法：

- 建一个哨兵节点指向头，游标 `prev` 始终停在“最后一个已确认保留的节点”上。
- 观察从 `prev.next` 起的同值段：如果连续出现两个及以上相同值，就把整段跳过，让 `prev.next` 指向段后第一个不同值的节点。
- 跳段后不移动 `prev`，因为新接上来的段也可能重复；其余情况 `prev` 前进一步。
- 返回 `dummy.next`：头节点本身可能被删，用哨兵就不用特判。

时间 O(n)、空间 O(1)。两个变体顺带说清：

- 只要求重复值保留一个（83）：逐个跳过相同值就行，不需要“整段”的概念。
- 链表无序且要求所有同值都删除：先扫一遍用哈希表统计每个值的出现次数，再第二遍按计数决定保留或摘除，用 O(n) 额外空间换掉“必须有序”的前提。

#### 技术细节

```java
public ListNode deleteDuplicates(ListNode head) {
    ListNode dummy = new ListNode(0, head);
    ListNode prev = dummy;
    while (prev.next != null) {
        ListNode cur = prev.next;
        if (cur.next != null && cur.val == cur.next.val) {
            int v = cur.val;
            while (cur != null && cur.val == v) cur = cur.next; // 整段跳过
            prev.next = cur;                                    // 不移动 prev
        } else {
            prev = cur;
        }
    }
    return dummy.next;
}
```

**三个易错点**

- 判定相同后要一路跳到值不同的节点，中途 `cur` 可能为 null（末尾整段重复）。
- 跳段后不能立刻 `prev = cur`，因为接上来的段也可能是重复段。
- 返回 `dummy.next`，不是 `head`。

**用例覆盖**

- `[1,1,1,2,3]`→`2→3`、`[1,2,3,3,4,4,5]`→`1→2→5`、全部同值→空、单节点、空表、`[1,1]`（整表被删）。

**无序＋全删的哈希计数版**

- 第一遍用 `merge` 计数，第二遍用同一个哨兵把 `count>1` 的节点摘掉。
- 被跳过的节点不必手动释放：Java 没有手动内存管理；若用 C++ 要 `delete` 被摘节点，注意别再访问已释放内存。

#### 深挖追问

1. **为什么不能用双指针“看一眼下一个就删”？**（补充练习）

   因为删除当前节点需要它的前驱，而单链表拿不到。用 `prev` 停在已确认保留的节点上，等于给每个待删段留了一个可回退的锚点，这也是哨兵存在的理由。

2. **有序链表能不能不用哨兵？**（补充练习）

   可以，但要先处理“头部整段重复”：先把 head 推进到第一个不重复的节点，再从它开始维护前驱。哨兵能把这层特判消掉，写起来更短也更不容易错，所以面试里通常推荐哨兵。

3. **如果要求保留一个且不修改相对顺序，能否 O(1) 空间？**（面经实际出现；[[面经/阿里云/二面/0001#Q05：手撕：删除链表中的所有重复元素。|MJ039 · 阿里云 · 二面 · Q05]] 的延伸）

   分两种情况：
   - 有序时：O(1) 空间单趟跳过重复即可（83）。
   - 无序时：“判断是否首次出现”需要记已见值。要 O(1) 空间就得先排序（会改变顺序、O(n log n)），或者接受平方级比较。
   本质是用空间换时间还是换顺序，取决于题目允许哪一个。

### ALG-033：如何解八皇后／N 皇后问题，时间复杂度是多少？

**常见问法**

- 手撕：八皇后问题。
- 八皇后的算法时间复杂度是多少？
- 求 N 皇后的所有解，怎么剪枝？

#### 面试回答

按行递归是最好写也最好讲的形式。`dfs(row)` 时枚举每一列 `col`，判断这个位置是否已被前面的皇后攻击：同一列、同一斜线。

- 三条约束各用一个布尔数组标记，就能 O(1) 判定：
  - 列：直接用 `col`。
  - 一条对角线上 `row - col` 为常数（值域 `-(n-1)~n-1`，加 `n-1` 偏移作下标）。
  - 另一条对角线上 `row + col` 为常数（值域 `0~2n-2`）。
- 放置时把三个标记置 true、记录 `queen[row] = col`，递归 `row+1`，返回后清标记完成回溯。
- `row == n` 时收集一个解。
- 输出方案按题目要求给字符矩阵或列下标数组，别自己混用。
- 自测锚点：`n=4` 有 2 个解、`n=8` 有 92 个解（去掉旋转与镜像对称后是 12 个基本解）。

时间复杂度答 **O(n!)**：

- 逐行放皇后，第一行至多 n 种选择，第二行受列约束至多 n-1，依次递减，上界即 `n!`；每个解的收集与拷贝再乘一层成本。
- 要能解释这个上界为什么比“每行随便选一列”的 `O(n^n)` 紧：列标记让每行候选数单调减少，斜线标记又进一步剪掉大量分支。
- 所以 `n!` 是最坏分支数的上界，实际访问的节点数明显更少。
- 空间 O(n) 量级（三个标记数组与递归栈，不计输出；要保存全部解则与解数同阶）。

#### 技术细节

**判定条件怎么推**

- 主对角线（左上→右下）上 `row - col` 恒定，副对角线（右上→左下）上 `row + col` 恒定。
- 用偏移 `n-1` 把负下标搬正，这是本题最容易写错的一行。

**为什么用标记数组而不是回扫**

- 不用标记数组、每次沿三个方向回扫检查也正确，但那样每层判定变成 O(n)，整体退化到 `O(n·n!)` 级别。
- 被问“为什么用数组”时，答的就是这个。

**位运算优化（常见第二轮追问）**

- 把每行的可用列压成一个整数掩码 `bits`：`avail = ~(cols|diag|antiD) & mask`，取最低可放位 `p = avail & -avail`，递归时传 `cols|p`、`(diag|p)<<1`、`(antiD|p)>>1`。
- 好处是把三个数组的判定与回溯变成整型位操作，常数下降明显（`n=14` 这类枚举能快几倍）。
- 复杂度量级不变，仍是 `O(n!)`。

**对称性剪枝**

- 只把第一个皇后限制在前半列，再把得到的解数乘 2（n 为奇数时中间列单独处理）。
- 适合“只要计数”的变体。

**易错清单**

- 忘清标记，导致后续行误判冲突。
- 对角线下标未加偏移，导致负索引越界。
- `n=0`／`n=1` 边界。
- 输出格式与题目不一致。
- 把“求一个解”与“求所有解”混做：只要求一个解时命中即可短路返回，不必穷举。
- 若题目改问“不同 N 皇后的解数”（LeetCode 51／52 的计数变体），把收集改为计数即可，无需保存棋盘。

#### 深挖追问

1. **为什么复杂度是 n!而不是 2 的 n 平方次方？**（面经实际出现；[[面经/小红书/一面/0001#Q10：手撕八皇后问题；追问：时间复杂度是多少？|MJ040 · 小红书 · 一面 · Q10]]）

   因为每行必须放且只放一个皇后，解空间就是“每行选一列”的组合，规模上界 `n×(n-1)×…×1 = n!`。只有在不按行推进、每格独立选放或不放时，才是 `2^(n²)` 的暴力空间。回答时说清“约束让分支逐层收缩”就够了。

2. **只要求返回一个可行解，怎么改？**（补充练习）

   - 递归命中 `row == n` 后返回成功标志并逐层短路，不再回溯穷举。
   - 也可以用最小冲突启发式做局部搜索，但要说明它不保证完备（可能卡在局部极小）。面试里首选带回溯的完备解法。

3. **n 很大时（比如求 n=20 的解数）还能怎么做？**（补充练习）

   纯回溯成本会爆炸。工程上三招：位运算＋对称剪枝、按列状态做记忆化、并行分治（不同首列分支相互独立，可以并行）。同时要说明这类计数问题没有已知的多项式解法，只能优化常数与并行度。

**参考资料**（查证：2026-09-23）

### ALG-034：如何求海量文件中的全局 TopK（内存受限、多核并行）？

**常见问法**

- 100 个文件、每个文件几亿个数字，找全局最大的 1000 个数字，4 核 CPU，怎么做？
- 内存无限和内存有限（如 32G）两种情况分别怎么处理？
- 数据量太大装不进内存，怎么找 TopK？
- 100 亿行销售数据（商品名、金额），3 台机器算销售额最多的前 3 个商品？

#### 面试回答

先做量级判断再动手：

- 100 个文件乘以“几亿个数”是千亿级元素，即使内存无限也不可能全部装进内存（千亿个 int 就是数百 GB）。
- 所以正确解法本身就是流式的——这与内存是 32G 还是无限其实无关，这个结论要先说出来。

主结构是大小为 K 的最小堆：

- 按行流式读每个文件，对每个数字 x，若堆未满或 `x > 堆顶（当前第 K 大）`，就弹出堆顶、压入 x，否则丢弃。
- 遍历结束时堆内就是 TopK。时间 O(N log K)，空间 O(K)。
- 可以先按文件算局部 TopK（每个文件一个 1000 元素的堆），最后把 100 个局部结果合并：继续喂同一个全局堆，或者做 k 路归并。这样还能天然并行。

并行与性能优化才是这题真正的考点：4 核说明瓶颈在 IO 与文本解析，不在比较。

- 做法是生产者—消费者：按文件分片给 4 个（或 2×核数）worker，每个 worker 维护自己的局部 TopK 堆。
- 关键是不要让多线程共享一个堆，锁竞争会把并行收益吃掉；最后单线程合并 100 个小堆。
- 读取侧用固定字节缓冲流式读，避免一次性 `readlines()` 载入整文件。
- 解析用直接整型扫描（避免正则与逐字符切分），这通常能带来数倍吞吐提升。
- 若要极限吞吐还可以按文件内 `seek` 分段并行，但要处理半行边界，收益一般不如按文件分片直观；答题时说清这个取舍即可。

内存受限（32G）时上述方案本来就成立；只有当题意变成“要把全部数字排序”才需要外部排序：

- 分块内排序后多路归并。
- 或者用按值域分桶（计数／位图，见 ALG-026、ALG-027），在值域可控时省掉排序。

#### 技术细节

**三种 TopK 方案的取舍**

- 大小 K 的最小堆：O(N log K)，空间 O(K)，支持流式、易并行，是最稳的默认。
- 快速选择（QuickSelect）：平均 O(N)，但要求数据能全量驻留内存，不适合这题。
- 值域分桶／计数：O(N + V)。数字范围有限时（如 32 位整数可先按高 16 位分桶定位阈值桶，再桶内求 TopK）比堆更快，且天然适合分布式——每个分片只需上报各桶计数。
- 若还要求“结果去重”，堆方案要额外配集合或先排序去重，内存要按去重后的规模重估。

**正确性检查点**

- 并列于第 K 名的值要不要全部输出：阈值语义与“恰好 K 个”不同，先问清。
- 文件可能为空或不足 K 个元素。
- 数字范围是否溢出，用 64 位读入更保险。
- 解析时是否处理了 `+`／负号与换行混杂。
- 最后输出要不要排序：堆里取出是乱序，一般再排一次 O(K log K)。

**工程细节常被追问**

- 并行度为什么按文件分片而不是按行。
- 如何控制内存峰值：缓冲池复用、每个 worker 设上限。
- 如何让 IO 与 CPU 重叠：预读下一块，用异步 IO 或双缓冲。
- 文件在对象存储上时，还要考虑按文件并发拉流并限制总带宽。
- 任务要跑很多轮时，考虑用列式或二进制格式落盘，避免每次都付文本解析的成本。

**验证方式要能说出口**

- 构造 3 文件 × 10 个数的已知答案小样例，覆盖“全部小于当前第 K 大”“恰好等于阈值”“空文件”三种情形。
- 线上再比对“单线程实现”与“并行实现”的输出是否一致。
- 给出实测吞吐（GB/s 或每秒行数），不要只说“更快了”。

#### 深挖追问

1. **为什么不直接 `sort` 全部数据再取前 1000？**（补充练习）

   全量排序是 O(N log N)，还要把数据（或外部分类）搬运多遍；TopK 只需 O(N log K) 且流式一遍过。K 远小于 N 时差距是数量级的，只需要 TopK 时做外部排序纯属浪费。

2. **如果 K 变大到千万级，堆还合适吗？**（面经实际出现；[[面经/字节/二面/0002#Q08：手撕：100 个文件、每个文件含几亿个数字，找出全局最大的 1000 个数字（4 核 CPU，内存无限或有限如 32G）。|MJ042 · 字节 · 二面 · Q08]] 的延伸）

   K 很大时 `log K` 和内存占用都会上升。堆仍可用，但更划算的是换成按值域分桶先定阈值的两遍法：第一遍统计桶计数、找出第 K 大所在的桶，第二遍只收集桶内元素，把内存压到桶的规模。这也是分布式的自然做法：每个分片上报桶计数，再合并。

3. **多核并行后结果不一致怎么办？**（补充练习）

   多半是共享可变状态没有隔离。每个 worker 只写自己的局部堆、合并阶段单线程做，竞争就消除了。如果为了“更早剪枝”而共享一个全局阈值（worker 读到别的分片的当前第 K 大），要明白这只是加速优化、不影响正确性，但读取要允许拿到旧值（用原子变量），否则又把锁请回来了。

4. **“先按 key 聚合金额、再取 TopK”与纯 TopK 有什么不同？**（面经实际出现；[[面经/帆软/一面/0004#Q18：100 亿行全年销售数据（商品名、金额），用 3 台机器算销售额最多的前 3 个商品，怎么设计？|MJ050 · 帆软 · 一面 · Q18]]）

   多一步 group-by：必须先把同一 key 的行聚到一处求和，才能对聚合后的值排 TopK——所以分片键要选“商品名”的哈希，让同一商品只落一台机器，避免跨机合并求和。取 Top3 用“每机各自小顶堆 Top3、汇总端再取全局 Top3”即可（每分区 Top-K 的并集必含全局 Top-K）。热点商品名（基数极低却量极大）会造成单机倾斜，可对爆品名再按金额二次拆分。另外先问数据在哪：在数仓／ClickHouse 就是一条 `GROUP BY ... ORDER BY SUM() DESC LIMIT 3`，别硬答手写分布式。

### ALG-035：如何用给定数字集合拼出不大于 N 的最大数？

**常见问法**

- 手撕：用给定数字（如｛2,4,9｝）组成不大于 N 的最大数字。
- 给一组数字（可重复使用），拼出不超过 N 的最大值，怎么做？
- 如果每个数字只能用一次呢？

#### 面试回答

先确认两个口径：集合里的数字能否重复使用、结果位数能否少于 N 的位数（一般允许，且不允许前导零）。以下按“可重复”作答。

贪心骨架是从最高位开始逐位对齐 N。记 N 的位数组为 `d[0..m-1]`、集合为 `S`、其中最大数字 `mx`：

- 从左到右，只要当前位 `d[i]` 属于 `S`，就先照抄，保持与 N 前缀相等的“紧贴”状态。
- 遇到 `d[i]` 不在 `S` 中，就在这一位放 `S` 里小于 `d[i]` 的最大数字。一旦放小，后面所有位一律填 `mx`，就是答案。
- 若这一位没有比 `d[i]` 更小的可选数字，必须回退：往左找一个照抄过的位 `j`，把第 `j` 位换成 `S` 中小于原 `d[j]` 的最大数字，其后全部填 `mx`。
- 回退到第 0 位都无处可改，说明不存在同位数的解，退成 `m-1` 位数全体填 `mx`；特例是 `S` 里没有非零数字时答案为 0。

例子（`S={2,4,9}`）：

- `N=427`：4、2 照抄，7 不在集合，取小于 7 的最大者 4，得 424。
- `N=420`：0 不在集合且没有比 0 更小的数字，回退第 1 位 2 也无可替代，再回退第 0 位 4→2，后面填 9，得 299。

复杂度 O(位数)，把“小于 x 的最大数字”预后缀表做到 O(1) 就是线性；空间 O(位数)。

“每个数字只能用一次”的变体要单独说明：

- 不能再简单重复填 `mx`：贪心骨架相同，但选位要跳过已用数字，回退时还得恢复已用集合。
- 更稳的写法是记忆化搜索，状态为位置、已用数字掩码、是否仍紧贴 N 前缀，也就是数位 DP 的标准套路；规模很小（`|S|` ≤ 10、位数 ≤ 20），完全可接受。
- 若还要求长度可自由组合，就再加一维“已用个数”。

#### 技术细节

**实现要点**

- 把 N 拆成位数组：字符串转换最直观，注意大数场景要按字符串处理，避免溢出。
- `less(x)` 返回 `S` 中小于 x 的最大元素、`le(x)` 判断 x 是否在 `S` 内；这两个函数写清楚，主逻辑就短。
- 回退用栈，或者从后向前找第一个可降位的下标。
- 填 `mx` 之前要处理前导零：若第 0 位只能填 0，说明位数必须缩短，取 `m-1` 位全 `mx`。

**测试用例要覆盖**

- `N` 完全可由集合拼出（结果等于 N）。
- 所有位都够不着，退化成短位数。
- 含 0 与不含 0 的集合。
- `S={9}` 与 `N=1000`，答案 999。
- `N` 位数很大的字符串输入。
- 这些用例跑通，比现场解释复杂度更能证明写对了。

**同类变形要能立刻识别**

- 给数字集合求“能被某数整除的最大／最小数”、或“恰好等于 target 的组合”，就回到搜索＋剪枝。
- “字典序最小／最大且不大于 N 的排列”，是把可重复换成给定多重集：贪心骨架不变，但要按剩余可用计数填后缀。

#### 深挖追问

1. **为什么不能从低位往高位贪心？**（面经实际出现；[[面经/字节/三面/0001#Q02：手撕：用给定数字（如｛2,4,9｝）组成不大于 N 的最大数字。|MJ042 · 字节 · 三面 · Q02]] 的延伸）

   因为“不大于 N”这个约束是由高位决定的，低位的选择不会影响高位能否变大；从低位贪心会出现高位已超 N、后缀最优也无效的情况。所以必须从高位起、并维持“是否已经严格小于”的状态，这本质上就是数位 DP 的状态定义。

2. **集合里没有比某位更小的数字时，除了回退还有别的办法吗？**（补充练习）

   有，等价做法是一次性枚举“第一个变小的位置”：对每个位置 i，要求前缀 `0..i-1` 全部与 N 相同且这些位都在 `S` 中，第 i 位取小于 `d[i]` 的最大可用数字，后缀填 `mx`；取所有可行 i 里数值最大的那个，再加上“整条同位数都等于 N”和“缩短位数”两种边界。这个视角写出来分支更少，也不容易在回退时改错。

3. **怎么扩展到多个数字串拼接（每个数字只能用一次且必须全用）？**（补充练习）

   那是全排列约束下的最优化：位数固定，按位从大到小尝试未使用的数字，并检查是否还可能不超过 N（前缀已经更小，则剩余自由按降序排），否则剪枝。骨架仍是“不大于 N 的贪心”，只是“填后缀”要改成对剩余数字排序。

### ALG-036：单链表每两个节点交换一次（Swap Pairs），O(n)／O(1) 怎么做？

**常见问法**

- 一个单链表，从链表尾部开始，每两个节点位置翻转，要求时间复杂度 O(n)、空间复杂度 O(1)。示例：1,2,3,4 翻转后 2,1,4,3。

#### 面试回答

先把题意口径说出来：示例 `1,2,3,4 → 2,1,4,3` 的效果就是相邻两两交换（LeetCode 24）；成对不重叠，所以“从头部处理”和“从尾部开始”输出相同，无需真反转。

- 迭代解法：哑结点 dummy 指头，pre 停在“已处理部分”的尾部；每轮摘 (pre.next, pre.next.next) 一对交换接回，pre 前进两步。
- 时间 O(n) 一趟；只动常数额外指针，空间 O(1)，满足约束。
- 边界：空表／单节点原样返回；奇数长度最后一个节点不动（1,2,3 → 2,1,3）。
- 主动问面试官：允许只交换节点值吗？允许则实现更短，但值可能被共享／很大，改指针是更稳的默认。

```java
ListNode swapPairs(ListNode head) {
    ListNode dummy = new ListNode(0, head), pre = dummy;
    while (pre.next != null && pre.next.next != null) {
        ListNode first = pre.next, second = pre.next.next;
        pre.next = second;
        first.next = second.next;
        second.next = first;
        pre = first;
    }
    return dummy.next;
}
```

#### 技术细节

**三根指针的接法为什么对**

- 每轮动四条边：pre→second、second→first 由赋值完成；first→(下一轮的头) 用 `second.next` 先接上，断链顺序不会丢后续节点。
- 交换后下一轮的 pre 是当前轮的 first（它已沉到这对的末尾），所以 `pre = first` 恰好前进两步的距离。
- 哑结点统一处理“头部也要换”的情况，免去对头节点的分支。

**“从尾部开始”的另一种读法**

- 若题面坚持从尾向头配对（长度奇偶不同起点），两两交换的输出仍与从头一致：配对集合不重叠。
- 若实际要求是“从尾部开始的每 K 个一组翻转”（K=2 时起点受长度影响），标准解是先整体反转、按 K 组翻转、再反转回来，三趟 O(n)、空间 O(1)——答题时先确认，两种都备一句。

**递归写法为什么不算 O(1) 空间**

- `head.next = swapPairs(head.next.next)` 逻辑最短，但递归栈深 n/2，空间 O(n)。
- 题目明确要 O(1)，就交迭代；能主动说出递归的栈开销，是这题的隐藏考点。

#### 深挖追问

1. **和 LeetCode 25（K 个一组翻转）什么关系？**（补充练习）

   K=2 的特例。K 组通用解法：先探测能否数出 K 个，能就翻转这一段，接回前后；不够 K 个的尾巴保持原样。两两交换里“探测”退化成看 `next.next` 是否为空。

2. **链表反转的三种改指针写法会了吗？**（补充练习）

   本题就是“分段局部反转”，与 ALG-032（删除重复元素）同属“哑结点＋pre／cur 推进”的链表模板；相邻节点交换和就地反转（pre／cur／nxt 三指针）要能白板默写。

### ALG-037：每次最多迈 1～m 级台阶，走完 n 级共有多少种走法？

**常见问法**

- 一个人每次最多走 m 阶台阶，问走 n 阶台阶一共有多少种走法？（动态规划）

#### 面试回答

定义先行：f(i)＝到达第 i 级的走法数；最后一步可以是 1～m 级中的任意值，所以

- `f(i) = Σ_{j=1..min(i,m)} f(i-j)`，基准 `f(0)=1`（在地面不动，也算一种“走法”的起点约定）。
- 答案 f(n)；m=2 时退化成爬楼梯斐波那契——先代小例子自检（n=3,m=2→3；n=2,m=3→2）。
- 写码前问三个口径：一次至少迈 1 级？顺序不同算不同走法（默认是）？结果要不要取模（数量随 n 指数级涨）。

```java
long countWays(int n, int m) {
    long[] f = new long[n + 1];
    f[0] = 1;
    for (int i = 1; i <= n; i++) {
        long sum = 0;
        for (int j = 1; j <= m && j <= i; j++) sum += f[i - j];
        f[i] = sum;
    }
    return f[n];
}
```

#### 技术细节

**为什么 f(0) 必须是 1**

- 它是“空序列”计数基准：迈 j 级恰好到达 j 的那一种走法，前缀是“走完 0 级的唯一方式”。把 f(0) 写成 0 会全盘归零——这是本题最高频错误。

**滑动窗口优化到 O(n)**

- 相邻两步的求和窗口只差两端：维护 `window = f(i-1)+…+f(i-m)`，`f(i)=window`；随后 `window += f(i)`，若窗口超过 m 项再 `window -= f(i-m)`。
- 空间同步优化：滚动数组长度 m＋1 即可，O(m)。

**对比记忆网络**

- 本题是“完全组合”型 DP 的一维代表：每步可选集合固定 → 前缀和转移。同族的“零钱兑换”（ALG-023）区别在求最小枚数（min 转移）而非计数（sum 转移）；计数题再升一级是“硬币组合数”（组合 vs 排列，循环顺序决定）。
- 若被追问“n 到 1e18 怎么办”：转移是线性递推，可用矩阵快速幂 O(m^3 log n)（m 小时可行），答到这里足够加分。

**溢出与取模**

- long 也会溢（m=2 时是斐波那契，n≈90 溢出）；题目要精确值就用 BigInteger，要答案先问模数（如 1e9+7），加法转移处处取模。

#### 深挖追问

1. **如果某些台阶不能踩怎么改？**（补充练习）

   f(坏阶)=0、其余照常累加即可——DP 状态定义不变，基准点变了；这正是“计数型 DP 对约束的扩展性好”的示例。

2. **“走法”和“最少步数”两种问法的转移差别？**（补充练习）

   走法数：f(i)=Σf(i-j)（乘法原理，分类相加）；最少步数：f(i)=min(f(i-j))+1（最优子结构取 min）。先听清问题求“多少种”还是“多少步”，两者代码只差一行。

### ALG-038：最长递增子序列的长度怎么求，如何输出子序列本身？

**常见问法**

- 给定一个未排序的整数数组，找到最长递增子序列的长度；再进一步把子序列打印出来。示例 [10,9,2,5,3,7,101,18] → 4（[2,3,7,101]）。

#### 面试回答

分两档，先讲 O(n²) DP（天然能还原序列），再报 O(n log n) 优化：

- 定义：`f[i]`＝以 `nums[i]` 结尾的 LIS 长度；`f[i] = max(f[j]+1)`（所有 j<i 且 nums[j]<nums[i]），基准全 1；答案是 max(f)。
- 输出子序列：转移时记 `prev[i]=j`（是哪个前驱把 f[i] 抬起来的），从 argmax 终点沿 prev 回溯、反转即为一条最长链。
- 关键口径：子序列不要求连续（区别于“最长连续递增”），且严格递增——相等不算上升。
- 先口述 O(n²) 版并写对，再升级 O(n log n)；还原序列是这道题在“只求长度”之上的真正考点。

#### 技术细节

**O(n²) DP＋前驱还原**

```java
int[] longestIncreasingSubsequence(int[] nums) {
    int n = nums.length;
    if (n == 0) return new int[0];
    int[] f = new int[n], prev = new int[n];
    Arrays.fill(prev, -1);
    int best = 0;
    for (int i = 0; i < n; i++) {
        f[i] = 1;
        for (int j = 0; j < i; j++) {
            if (nums[j] < nums[i] && f[j] + 1 > f[i]) { f[i] = f[j] + 1; prev[i] = j; }
        }
        if (f[i] > f[best]) best = i;
    }
    int len = f[best];
    int[] seq = new int[len];
    for (int k = len - 1; best != -1; best = prev[best]) seq[k--] = nums[best];
    return seq;
}
```

- 时间 O(n²)、空间 O(n)；`prev` 数组是还原序列的全部成本。

**O(n log n) 贪心＋二分（tails）**

- `tails[k]`＝所有长度为 k＋1 的递增子序列里，结尾值最小的那个结尾；维护它严格递增。
- 每个 x：二分找第一个 `>=x` 的位置替换（把该长度的结尾压得更小），都更小则追加（LIS 变长）。最终 tails 长度即答案。
- 边界：严格递增用 `lower_bound`（第一个 ≥x）；若题目改成“非降子序列”则用 `upper_bound`（第一个 >x）——被问“相等怎么办”就指这里。

```java
int lengthOfLIS(int[] nums) {
    int[] tails = new int[nums.length];
    int size = 0;
    for (int x : nums) {
        int lo = 0, hi = size;                 // lower_bound：第一个 >= x
        while (lo < hi) { int mid = (lo + hi) >>> 1; if (tails[mid] < x) lo = mid + 1; else hi = mid; }
        tails[lo] = x;
        if (lo == size) size++;
    }
    return size;
}
```

**两个易错点**

- 示例输出不唯一：`[2,3,7,101]` 与 `[2,3,7,18]` 都合法——先跟面试官确认“只要长度”还是“给一条即可”，别为“和你不一样”慌。
- tails 数组本身不是答案序列：它只是“各长度最小结尾”的辅助结构，长度对但元素不构成子序列；要输出具体序列，O(n²) 的 prev 法最直接，O(n log n) 还原需额外记录每个元素入栈时的位置与前驱。

#### 深挖追问

1. **为什么 `tails` 要维护“最小结尾”？**（补充练习）

   结尾越小，后面能接上的数越多、越有潜力延长——贪心地让每个长度的结尾尽量小，才能保证后续扩展空间最大；严格递增性是二分的依据。

2. **最长公共子序列（LCS）和它什么关系？**（补充练习）

   同族二维／一维区间 DP，但 LCS 是两串对比（`dp[i][j]`）、LIS 是单串自身偏序；别把转移方程套错。

### ALG-039：有向图的 Dijkstra 单源最短路怎么算，怎么手写？

**常见问法**

- 描述一下有向图中迪杰斯特拉算法的计算过程。
- 共享屏幕，用自己的 IDE 实现一下 Dijkstra。

#### 面试回答

Dijkstra 求“非负权”有向图的单源最短路，本质是贪心加优先队列。

- 初始化：源点 `dist[src]=0`，其余设无穷大。
- 每轮：从待处理点里弹出当前 `dist` 最小的点 u，u 的最短距离就此确定。
- 松弛：对 u 的每条出边 (u→v, w)，若 `dist[u]+w < dist[v]`，更新 `dist[v]` 并把新值入队。
- 出队时若这条记录的距离大于 `dist[u]`，说明是更早入队的过期值，直接跳过。
- 前提：边权非负；有负权边要用 Bellman-Ford。

现场手写默认用“二叉堆＋惰性删除”，不写 decrease-key。

#### 技术细节

**为什么贪心成立**

- 每次弹出的是未确定点里距离最小的，且边权非负，所以之后再没有别的路径能把 u 改得更短，可以安全确定 u。
- 反例说明前提：有负权边时，u 确定后仍可能被一条“先绕远再走负边”的路径改短，贪心就错了。

**两种实现与复杂度**

- 朴素版：每次线性扫最小值，O(V^2)，适合稠密图。
- 堆优化版：`PriorityQueue`，O((V+E)logV)，适合稀疏图。
- 惰性删除的代价：同一顶点可能多次入队，堆里最多 E 个元素，所以仍是 O((V+E)logV)。

**Java 手写实现（邻接表为 `g[u]` 存 `{v, w}`）**

```java
static final long INF = Long.MAX_VALUE / 4;   // 防相加溢出

static long[] dijkstra(List<int[]>[] g, int n, int src) {
    long[] dist = new long[n];
    Arrays.fill(dist, INF);
    dist[src] = 0;
    // {顶点, 到该顶点的当前距离}，按距离取最小
    PriorityQueue<long[]> pq = new PriorityQueue<>(Comparator.comparingLong(a -> a[1]));
    pq.offer(new long[]{src, 0});
    while (!pq.isEmpty()) {
        long[] cur = pq.poll();
        int u = (int) cur[0];
        long d = cur[1];
        if (d > dist[u]) continue;            // 过期记录，跳过
        for (int[] e : g[u]) {                // e = {v, w}
            int v = e[0];
            long w = e[1];
            if (dist[u] + w < dist[v]) {      // 松弛
                dist[v] = dist[u] + w;
                pq.offer(new long[]{v, dist[v]});
            }
        }
    }
    return dist;
}
```

**要还原路径就加 prev[]**

- 在 `if (dist[u]+w<dist[v])` 里同时记 `prev[v]=u`，最后从终点沿 `prev` 回溯到源点再反转。

**容易说过头的地方**

- 别说“Dijkstra 能处理任意带权图”——负权不行。
- 无权图（边权都算 1）不必上 Dijkstra，BFS 就是它的特化版，O(V+E) 更快。

#### 深挖追问

1. **有负权边怎么办？**（面经实际出现；本题的边界追问）

   Dijkstra 不适用，改用 Bellman-Ford：对全部边松弛 V-1 轮，O(VE)，还能检测负环；稀疏图可用其队列优化 SPFA（最坏仍 O(VE)）。

2. **Dijkstra 和 Floyd-Warshall 有什么区别？**（补充练习）

   单源 vs 多源。Dijkstra 求一个源点到其余点；Floyd 三重循环 DP 求任意两点，O(V^3)，能处理负权（但不能有负环）。

3. **DAG（有向无环图）的最短路能更快吗？**（补充练习）

   能。按拓扑序遍历一次、对每条出边松弛即可，O(V+E)，还天然支持负权（无环故无负环）。

4. **A\* 和 Dijkstra 什么关系？**（补充练习）

   A\* 是把优先队列的键换成 `g(n)+h(n)`（已花代价＋可采纳启发估计）的 Dijkstra；启发函数不高估真实代价时结果仍最优。

### ALG-040：如何求每个连续 k 个元素的最大值和最小值？

**常见问法**

- 给一个长度为 n 的数组，输出所有连续 k 个数的最小值／最大值。
- 讲完思路按测试用例把代码执行流程走一遍。

#### 面试回答

这是滑动窗口最值，标准解是单调双端队列，O(n)。

- 求最大值：维护一个“下标”队列，对应值从队首到队尾单调递减。
- 新元素 i 进来时，从队尾弹出所有值 ≤ `a[i]` 的下标（它们再也不可能成为后续窗口的最大值），再压入 i。
- 队首若已滑出窗口左边界（下标 ≤ i-k）就弹出队首；队首就是当前窗口最大值的下标。
- 求最小值对称：维护单调递增队列。
- 从 i = k-1 起才凑满第一个窗口，开始记录答案。

#### 技术细节

**为什么存下标而不是存值**

- 要判断队首有没有滑出窗口，靠的是下标；只存值无法知道它还在不在窗口内。
- 值相等时靠下标决定谁先过期，所以弹出条件用 `<=` 才能保证队首最新。

**复杂度和正确性**

- 每个元素最多入队一次、出队一次，均摊 O(n)；队列最长不超过 k，空间 O(k)。
- 队列保持单调，队首即窗口极值；被弹掉的一定是“更旧且不更优”的元素，不可能再当答案。

**Java 手写（滑动窗口最大值）**

```java
static int[] maxSlidingWindow(int[] a, int k) {
    int n = a.length;
    if (n == 0) return new int[0];
    Deque<Integer> dq = new ArrayDeque<>();       // 存下标，值递减
    int[] res = new int[n - k + 1];
    for (int i = 0; i < n; i++) {
        while (!dq.isEmpty() && a[dq.peekLast()] <= a[i]) dq.pollLast();
        dq.offerLast(i);
        if (dq.peekFirst() <= i - k) dq.pollFirst();  // 队首滑出窗口
        if (i >= k - 1) res[i - k + 1] = a[dq.peekFirst()];
    }
    return res;
}
```

最小值：把两处 `<=` 换成 `>=`，队列变为值递增。

**按用例讲执行流程的口述法**

- 逐字符列出 `i`、入队前队尾弹出谁、队首是否过期、`res` 记不记录。
- 拿一组小例子（如 `a=[1,3,-1,-3,5,3,6,7], k=3`）现场走一遍最稳。

**容易说错的地方**

- 用“堆／TreeMap”也能做，但是 O(n log k) 且要处理过期删除；被问最优解时答单调队列 O(n)。
- 别忘 `i>=k-1` 才写答案，否则前 k-1 步窗口还没满。

#### 深挖追问

1. **为什么不用优先队列（最大堆）？**（补充练习）

   堆能对但慢一步：O(n log k)，且堆里过期元素要“懒惰删除”。单调队列利用“窗口两端推进”的顺序，能把均摊降到 O(n)。

2. **单调队列还能解决哪些题？**（补充练习）

   下一个更大／更小元素、柱状图最大矩形、和受限的最长子数组、带限制的子数组极值和（min＋max 求和）这类“需要动态维护窗口单调性”的问题。

3. **要同时输出最大和最小，怎么做？**（面经实际出现；本题原题就要最大和最小）

   跑两遍——一遍递减队列求最大、一遍递增队列求最小；或在一个循环里维护两条队列，答案成对返回。

### ALG-041：已知前序和中序遍历，怎么输出后序遍历？

**常见问法**

- 给二叉树的前序遍历和中序遍历，输出它的后序遍历。
- 前序＋中序能唯一确定一棵二叉树吗？为什么？

#### 面试回答

靠“前序定根、中序分左右”递归还原。

- 前序的第一个元素就是当前（子）树的根。
- 在中序里定位这个根：根左边是左子树的中序，右边是右子树的中序；按左子树长度把前序也切成左右两段。
- 对左、右子树递归重复这个过程。
- 只要求输出后序（左—右—根）：递归里先处理左、再处理右、最后输出根即可，不必真的把树 new 出来。

前提：节点值唯一。有重复值时前序＋中序无法唯一确定树。给中序值→下标建哈希表，避免每次线性找根，整体 O(n)。

#### 技术细节

**切分下标的口径**

- 设根在中序的位置为 `inRoot`，则左子树节点数 = `inRoot - inLeft`。
- 前序里左子树区间 = `[preLeft+1, preLeft+1+左子树大小)`，右子树区间是其后剩下的部分。区间算错是这类题最常见的 bug。

**为什么“前序＋后序”不能唯一确定**

- 前序和后序都只告诉你是谁根，但都不告诉你哪些属于左子树、哪些属于右子树；只有中序提供左右划分信息。
- 所以“前序＋中序”或“后序＋中序”能还原，而“前序＋后序”不能（除非每个节点都满或都空）。层序＋中序也可还原。

**Java 递归直出后序（哈希优化定位）**

```java
static StringBuilder post = new StringBuilder();
static Map<Integer,Integer> inIdx = new HashMap<>();

static void build(int[] pre, int preL, int preR, int[] in, int inL, int inR) {
    if (preL > preR) return;
    int root = pre[preL];
    int ir = inIdx.get(root);           // 根在中序中的下标
    int leftSize = ir - inL;            // 左子树节点数
    build(pre, preL + 1, preL + leftSize, in, inL, ir - 1);      // 左
    build(pre, preL + leftSize + 1, preR, in, ir + 1, inR);      // 右
    post.append(root).append(' ');      // 根，左→右→根即后序
}
```

**容易说过头的地方**

- 别说“任何两种遍历都能还原二叉树”——必须有一种是中序（提供左右划分）。
- 递归栈深等于树高，链状树是 O(n)，可能被追问“能否不用递归”，可用栈模拟。

#### 深挖追问

1. **给定值有重复怎么办？**（补充练习）

   前序＋中序不再唯一确定，无法还原出“唯一”的那棵；题目默认值唯一，答题时先点明这个前提，别默认能解。

2. **由中序＋后序怎么还原？**（补充练习）

   对称地：后序最后一个元素是根，在中序里定位分左右，再递归处理。

### ALG-042：如何反转一条单链表？

**常见问法**

- 反转一条单链表（LeetCode 206）。
- 迭代和递归分别怎么写，各有什么代价？

#### 面试回答

迭代三指针最常用，O(n) 时间、O(1) 空间。

- 维护 `prev`、`cur`，每一步：先存 `next = cur.next`，再让 `cur.next = prev`，然后 `prev`、`cur` 各向前移动一位。
- 走到 `cur == null` 时，`prev` 就是新的头结点。

递归写法更短，但会用到 O(n) 调用栈，长链表可能栈溢出——被问取舍时直说这个差异。

#### 技术细节

**迭代 Java 实现**

```java
static Node reverse(Node head) {
    Node prev = null, cur = head;
    while (cur != null) {
        Node next = cur.next;   // 先保存后继，否则断链后找不到
        cur.next = prev;        // 反指
        prev = cur;             // prev 前进
        cur = next;             // cur 前进
    }
    return prev;                // 新头
}
```

**递归口径**

- `reverse(head.next)` 先把后面整段反转，再让 `head.next.next = head`、`head.next = null`，逐层回传新头。
- 理解要点：递归把“反转子链”当成已完成的子问题，只处理当前节点这一跳。

**这题的常见变体**

- 反转区间 [m,n]（LeetCode 92）：先走到 m 前驱，对这一段做反转再接回去。
- 每 k 个一组反转（LeetCode 25）：本专题已有相近的“两两交换”见 ALG-036，k 组是它的推广。
- 判断回文链表：快慢指针找中点＋反转后半再逐一比对（判环思路见 ALG-019）。

**容易写错的点**

- 忘记先保存 `next` 就改了指针，导致断链。
- 头结点为 `null` 或单节点时返回值要正确（返回 `prev`，不是旧的 `head`）。

#### 深挖追问

1. **为什么反转后原来 head 的 next 要置 null？**（补充练习）

   原 head 变成尾节点，尾的 next 必须是 null；迭代写法里它自然被 `prev`（初值 null）接上，递归写法则要显式 `head.next = null`。

2. **双向链表反转要注意什么？**（补充练习）

   每个节点要同时交换 `prev` 和 `next` 两个指针，且整条链的头尾指针都要换。

### ALG-043：二分查找的原理是什么，有哪些边界与变体？

**常见问法**

- 讲一下二分查找的原理。
- 手写二分，边界怎么处理？

#### 面试回答

原理：在有序（或满足单调判定）的区间上，每次取中点和目标比，把搜索区间砍一半，O(log n)。

- 前提：数据有序，或存在“一半成立、一半不成立”的单调性（二分答案）。
- 维护闭区间 `[left, right]`，`mid = left + (right - left) / 2`（这样写防 `left+right` 溢出）。
- 命中就返回；目标更小走左半（`right = mid - 1`），更大走右半（`left = mid + 1`）。
- 循环条件与收缩要和区间定义一致：闭区间用 `left <= right`，否则可能漏查或死循环。

#### 技术细节

**最容易错的是边界一致性问题**

- 区间定义（闭／左闭右开）、循环条件（`<=` 还是 `<`）、收缩写法（`mid` 还是 `mid±1`）三者必须自洽，混用就死循环或漏解。
- mid 溢出用 `left + (right-left)/2` 规避。

**常见变体**

- 找第一个 ≥ 目标（lower_bound）／最后一个 ≤ 目标：不是“命中就停”，而是继续收缩逼近边界。
- 二分答案：在“答案空间”上二分——判定期望值可行与否，适合“最大化最小值／最小化最大值”类。
- 旋转数组二分：靠“半区必有序”判断往哪走。

**Python 手写**

```python
def binary_search(a, target):       # a 升序，闭区间
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if a[mid] == target: return mid
        if a[mid] < target: lo = mid + 1
        else: hi = mid - 1
    return -1
```

#### 深挖追问

1. **为什么用 mid 而不是 (lo+hi)/2？**（补充练习）

   在会溢出的语言里 `lo+hi` 可能越界回绕成负数，`lo + (hi-lo)/2` 更安全；Python 整数无界虽不溢出，但保持这个写法是好习惯。

### ALG-044：如何合并两个有序数组？大规模、内存与线程安全怎么处理？

**常见问法**

- 手撕：合并两个有序数组。
- 数据量极大（百万／装不进内存）时怎么优化？性能、内存、线程安全怎么处理？

#### 面试回答

基础解：双指针归并，O(m+n) 时间。

- 两个指针各指数组头部，比较后取较小的放入结果，被取的指针前移；一方走完把另一方剩余整体接上。
- 若是 LeetCode 88“合并到第一个数组的尾部空位”，要从后往前填（用尾部空间当最大位），避免覆盖还没处理的元素。

```python
def merge(a, b):
    i = j = 0; out = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]: out.append(a[i]); i += 1
        else: out.append(b[j]); j += 1
    out.extend(a[i:]); out.extend(b[j:])
    return out
```

#### 技术细节

**大数据量／内存受限**

- 装不进内存就外部归并：分块读入、两两归并（多路归并用小顶堆按当前元素归并），边读边写，内存只需 O(路数)。
- 流式合并：两边都可迭代时，用生成器产出，避免一次性建大数组。

**稳定性**

- 取相等时优先左边（`a[i] <= b[j]`）即保持稳定，可用于“合并带原始顺序信息”的场景。

**线程安全与并行**

- 归并本身是读多写少、结果独立的操作：把输入切成不相交区间各自并行归并，最后合并——不共享可变状态就不需要锁。
- 若多个线程写同一个结果数组，必须分片（各写各的下标段）或加锁；默认优先“无共享的分段并行”，比锁更快。

**容易说错**

- 别说“用堆合并两个数组更好”——两路双指针就是 O(m+n)，堆是 m 路归并（k 个有序序列）才用得上，见 ALG-034 的 k 路思路。

#### 深挖追问

1. **合并 k 个有序数组／链表呢？**（补充练习）

   用小顶堆维护每路当前最小元素，每次弹出最小、推入该路下一个，O(N log k)，k 为路数；也可两两分治归并。

### ALG-045：如何快速判断一个数组本身是否有序？

**常见问法**

- 如何快速判断一个数组是否有序？

#### 面试回答

一次线性扫描比较相邻元素，O(n) 时间、O(1) 空间：

- 升序判定：只要出现一处 `a[i] > a[i+1]` 就非升序；全程不违反映升序。
- 要说清“严格递增”还是“非递减”：是否允许相邻相等决定比较用 `>` 还是 `>=`。
- 降序对称：`a[i] < a[i+1]` 即违反映降序。

```python
def is_sorted(a, ascending=True):
    for i in range(len(a) - 1):
        if (a[i] > a[i+1]) if ascending else (a[i] < a[i+1]):
            return False
    return True
```

#### 技术细节

- 空数组和单元素数组直接算有序——边界循环 `range(n-1)` 天然覆盖。
- 若频繁查“是否有序”，可在写入时维护有序标志，而不是每次全扫。

#### 深挖追问

1. **让判断本身也线程安全／并行怎么做？**（补充练习）

   数组只读时天然线程安全；加速可分段并行判断各段有序、再检查段边界衔接处是否也满足顺序，最后合并结论。

### ALG-046：编辑距离（Levenshtein）怎么求？

**常见问法**

- 手撕：编辑距离（把一个字符串变成另一个的最少操作数）。

#### 面试回答

编辑距离是把 word1 变成 word2 所需的最少「插入／删除／替换」次数，用二维 DP，O(m·n)。

- 定义 `dp[i][j]` = word1 前 i 个字符变成 word2 前 j 个字符的最少操作数。
- 转移：字符相等 `dp[i][j]=dp[i-1][j-1]`；不等取三种操作的最小＋1：
  - 替换 `dp[i-1][j-1]`、删除 `dp[i-1][j]`、插入 `dp[i][j-1]`。
- 边界：`dp[i][0]=i`（全删），`dp[0][j]=j`（全插）。

```python
def edit_distance(a, b):
    m, n = len(a), len(b)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(m+1): dp[i][0] = i
    for j in range(n+1): dp[0][j] = j
    for i in range(1, m+1):
        for j in range(1, n+1):
            if a[i-1] == b[j-1]:
                dp[i][j] = dp[i-1][j-1]
            else:
                dp[i][j] = 1 + min(dp[i-1][j-1],  # 替换
                                   dp[i-1][j],     # 删除 a[i]
                                   dp[i][j-1])     # 插入 b[j]
    return dp[m][n]
```

#### 技术细节

**空间优化**

- 只用上一行，可压到 O(n)；注意要缓存左上角 `dp[i-1][j-1]` 的旧值再覆盖。

**操作代价变体**

- 若插入／删除／替换代价不同，把 `1+min(...)` 换成各自代价相加再取 min。

**和 LCS 的关系**

- 只允许插入／删除（不许替换）时，最小编辑 = `m+n-2·LCS`——两者同族，都是对齐类 DP。

#### 深挖追问

1. **怎么还原操作序列？**（补充练习）

   从 `dp[m][n]` 反向走：看每一步是从哪个相邻格子转移来的，相等走对角，否则走使 `dp` 最小＋对应操作的那格，回溯到 (0,0) 即得操作序列。

### ALG-047：游戏服务器定时器为什么用最小堆实现，怎么设计字段和取消？

**常见问法**

- 游戏场景要实现定时器（每 30 秒刷小怪、每 5 分钟刷 BOSS、支持取消），为什么选最小堆而不是有序数组？
- 基于给定的定时器结构体，如何实现取消定时器？
- 任务类型、是否循环、时间间隔三个字段是否重复？裁剪保留哪些，只留一个留哪个？
- 触发时间和时间间隔能否组合使用？一次性任务间隔设什么，循环任务怎么继续循环？
- 描述最小堆插入一个元素和删除堆顶元素的过程。

#### 面试回答

- 选型：定时器的工作负载是「高频插入新任务＋只取最早到期」，最小堆插入和删堆顶都 O(log n)、取最小 O(1)；有序数组插入要 O(n) 搬移，它的全局有序用不上。
- 取消：结构体里带取消标志，天然配惰性删除——置标志 O(1)，堆顶弹出时已取消就丢弃；要立即释放内存再考虑「ID→下标」映射的精确删除。
- 字段裁剪：是否循环与时间间隔语义重叠；只留一个留时间间隔——间隔 0 表示一次性，大于 0 表示循环。
- 组合用法：触发时间管「何时执行」，间隔管「执行后隔多久再来」；循环任务回调完成后按「上次触发时间＋间隔」重排入堆。
- 堆操作：插入放末尾、比父小就交换上浮；删堆顶用末尾元素补位、比子大就交换下沉；都是 O(log n)。

#### 技术细节

**两种结构的对比账**

| 操作 | 有序数组 | 最小堆 |
| --- | --- | --- |
| 插入新定时器 | 定位 O(log n)＋搬移 O(n) | O(log n) |
| 取最早到期 | O(1)（队头） | O(1)（堆顶） |
| 删除到期任务 | 删头 O(n) | 删堆顶 O(log n) |
| 按时间顺序遍历全部 | 天然有序 | 做不到（只有偏序） |

- 游戏服里每秒可能新增几十条刷怪／技能／buff 定时器，插入是最高频操作；这条链上数组的 memmove 是纯浪费。
- 边界要说全：定时器总量只有几十条、且很少变动时，有序数组甚至硬编码更简单省常数；堆的优势在量大、增删频繁。

**字段设计与裁剪的讲法**

- 字段冗余点：若「任务类型」只区分一次性／循环，它和「是否循环」「间隔是否为 0」三者表达同一件事，留一个即可；任务类型若是业务分类（刷怪／存档／活动），那它和循环标志正交，不算冗余——裁剪前先确认字段语义。
- 只留一个为什么选间隔：ID 服务于取消、触发时间服务于堆比较、回调服务于执行，都砍不掉；只有「是否循环」和「任务类型」能从间隔推导——间隔 0 即一次性，正数即循环。
- 循环任务重排：新触发时间 = 上次触发时间＋间隔，重排入堆；用「当前时间＋间隔」会把回调耗时累积进周期，长时间运行节奏越漂越晚。

**取消的两条实现路线**

- 惰性删除：置标志；堆顶弹出时检查，已取消丢弃继续弹下一个。堆只做「弹出＋重插」，不破坏结构；代价是堆内暂留垃圾直到期。
- 精确删除：维护「timerId → 堆下标」映射，任意位置删除 O(log n)；代价是每次上浮下沉都要同步更新映射。
- 并发场景惰性更友好：置标志是原子操作，删堆中节点需要锁整棵堆。

**堆操作的准确过程**

- 插入（上浮）：放到数组末尾保持完全二叉树；while 比父小就交换。下标关系：节点 i 的父是 (i-1)/2、孩子是 2i+1／2i+2。
- 删除堆顶（下沉）：末尾元素补到堆顶并删除末尾；与孩子中较小者比较，比它大就交换，直到到叶或不比子大。
- 不变式：任意节点的父不大于子；不保证兄弟之间有序，所以堆不能替代有序数组做范围遍历。

**容易说过头的地方**

- 别绝对化：定时器总量只有几十条时，有序数组的 memmove 常数极小，实测可能更快——要说明选型是在「任务多、增删频繁」前提下成立。
- 惰性删除非免费：大量永不触发又不 pop 的任务会占内存，需要加「堆内计数」兜底。

#### 深挖追问

1. **每 30 秒一波小怪这种固定周期任务，需要每条怪一个定时器吗？**（面经实际出现；[[面经/点点互动/一面/0001#Q02：游戏定时器为什么选最小堆而不是有序数组，两者区别是什么？|MJ064 · 点点互动 · 一面 · Q02]]。原素材未记回答，以下为参考）

   不需要。一个循环定时器到点执行「刷一波」逻辑即可，堆里只占一个节点；只有每条实体有独立到期时间（buff、技能冷却）才各占一个节点。

2. **取消为什么优先惰性删除？**（面经实际出现；[[面经/点点互动/一面/0001#Q03：基于给定的定时器结构体，如何实现取消定时器？|MJ064 · 点点互动 · 一面 · Q03]]。原素材未记回答，以下为参考）

   取消频率远低于创建频率；置标志 O(1) 且实现最简，被取消的节点等到期弹出时才浪费一次比较，量级可忽略。

3. **堆和有序数组之外，大规模定时器还有什么方案？**（补充练习）

   时间轮：插入／删除平均 O(1)，适合海量、精度到 tick 的定时器（游戏长会话、连接超时）；多层时间轮可支持长时间轴。选型口径：量少要序用有序结构，量大增删频繁用堆或时间轮。

4. **量级估算：堆内维持 2 万个定时器、每秒新增 200 个，堆方案每秒大约多少次比较？**（补充练习）

   约 200×log2(20000)≈3000 次比较，微秒级，完全够用；这也说明选型成立的前提是「量大但没到时间轮的量级」。
