### ALG-001：如何把任意字符串转换为 int？

**常见问法**

- 手撕：写一个函数，把任意字符串转为 int 型整数。

#### 面试回答

我会先确认空白、符号、非法字符和溢出的约定。这里按 atoi 风格实现：跳过前导 ASCII 空格，读取可选正负号和后续连续数字，遇到其他字符停止；无数字返回 0，溢出截断到 int 上下界，null 约定返回 0。逐位累加前检查上界，避免先溢出再判断。原题没给规则，这只是明确选定的一种实现。

#### 技术细节

严格解析也可能要求所有字符合法并在错误或溢出时抛异常；不能将下面语义说成原题已经指定。负数绝对值最大可到 2147483648，比正数上界大 1。使用 long 保存当前非负绝对值，但仍在每一步检查，超长字符串不会先溢出 long。仅 ASCII 空格会被跳过，制表符及 Unicode 数字不纳入本约定。

```java
public static int toInt(String s) {
    // 本题约定：null 返回 0；跳过前导 ASCII 空格；读取可选符号和连续数字；
    // 无数字返回 0；遇到非数字停止；溢出截断到 int 边界。
    if (s == null) return 0;
    int i = 0, n = s.length(), sign = 1;
    while (i < n && s.charAt(i) == ' ') i++;
    if (i < n && (s.charAt(i) == '+' || s.charAt(i) == '-')) {
        sign = s.charAt(i++) == '-' ? -1 : 1;
    }
    long limit = sign == 1 ? Integer.MAX_VALUE : 2147483648L;
    long value = 0;
    while (i < n) {
        char c = s.charAt(i);
        if (c < '0' || c > '9') break;
        int digit = c - '0';
        if (value > (limit - digit) / 10) {
            return sign == 1 ? Integer.MAX_VALUE : Integer.MIN_VALUE;
        }
        value = value * 10 + digit;
        i++;
    }
    return sign == 1 ? (int) value : (int) -value;
}
```

时间 O(n)，额外空间 O(1)。例：`"  -42x" → -42`、`"words 42" → 0`、`"2147483648" → 2147483647`、`"-2147483648" → -2147483648`、`"+-12" → 0`。

#### 深挖追问

1. **如果面试官要求严格转 int？**（补充练习）

   改为拒绝 null、空串、任何非法字符及溢出，明确是否允许空白；不要复用“中途停止并返回前缀”的行为。

2. **为什么不能先乘 10 再检查 int 是否超限？**（补充练习）

   int 可能已经回绕，结果失真；可在运算前比较阈值，或用更宽类型并保证它自身不溢出。

### ALG-002：LeetCode 86：分隔链表

**常见问法**

- 手撕：LeetCode 86 分隔链表。

#### 面试回答

我会用两条带哨兵的链表，按原顺序把小于 x 的节点接到第一条，其余接到第二条，最后拼接。每次先保存 next 并断开旧链接，避免形成环。这样保留两个分区内部的原相对顺序，时间 O(n)、额外空间 O(1)。

#### 技术细节

这是稳定分区，不是排序；等于 x 的节点进入第二段。复用原节点且只分配两个哨兵。空链表、全部小于 x、全部大于等于 x 都无需特殊分支。下例代码按 Java 17 验证，可放入外层类中。

```java
static class ListNode {
    int val;
    ListNode next;
    ListNode(int val) { this.val = val; }
}

public static ListNode partition(ListNode head, int x) {
    ListNode smallDummy = new ListNode(0), largeDummy = new ListNode(0);
    ListNode small = smallDummy, large = largeDummy;
    while (head != null) {
        ListNode next = head.next;
        head.next = null; // 摘下节点，避免残留旧链或形成环
        if (head.val < x) {
            small.next = head;
            small = head;
        } else {
            large.next = head;
            large = head;
        }
        head = next;
    }
    small.next = largeDummy.next;
    return smallDummy.next;
}
```

例：`1 → 4 → 3 → 2 → 5 → 2`，x=3，结果 `1 → 2 → 2 → 4 → 3 → 5`。维护不变式：两条链都是已处理节点按原顺序组成，且链尾不指向未处理节点。

#### 深挖追问

1. **为什么要断开旧 next？**（补充练习）

   否则尾节点可能仍指向原链中的节点，拼接后可能重复遍历或成环。

2. **能只交换数值吗？**（补充练习）

   容易破坏稳定性或改变节点语义；本题按节点顺序稳定分区，重连节点更直接。

### ALG-003：如何手写 LRU 缓存？

**常见问法**

- 手撕 LRU。

- 算法：LeetCode 146 LRU 缓存（mid）。

- 要自己实现一个 LRU，要怎么去实现？

- 手撕 LRU；追问：改造成线程安全该怎么做，读多写少怎么优化（并发版正文见 [[专题题库/Java并发#JUC-019：线程安全的 LRU 缓存怎么实现，读多写少如何优化？|JUC-019：线程安全的 LRU 缓存]]）。

#### 面试回答

我会用哈希表定位节点，用双向链表维护最近使用顺序。get 命中和 put 更新时移到头部，新节点也插到头部，超过容量时删除尾部最久未使用节点，并同步删除哈希表记录。哈希表平均 O(1)，链表摘插 O(1)，所以整体操作平均 O(1)，空间 O(capacity)。

#### 技术细节

下面按整数 key/value、未命中返回 -1、容量 0 不存储、负容量拒绝的约定实现。用头尾哨兵减少空链和单节点分支。重点保证 map 中每个节点恰好在链中出现一次，更新已有 key 不增加容量。原题未说明并发要求，本实现是单线程版；并发版需将 map 与链表变更作为一致操作保护，仅换 ConcurrentHashMap 不够。

```java
static class LRUCache {
    private static class Node {
        int key, value;
        Node prev, next;
        Node(int key, int value) { this.key = key; this.value = value; }
    }
    private final int capacity;
    private final java.util.Map<Integer, Node> map = new java.util.HashMap<>();
    private final Node head = new Node(0, 0), tail = new Node(0, 0);

    LRUCache(int capacity) {
        if (capacity < 0) throw new IllegalArgumentException("negative capacity");
        this.capacity = capacity;
        head.next = tail;
        tail.prev = head;
    }
    public int get(int key) {
        Node n = map.get(key);
        if (n == null) return -1;
        unlink(n);
        addFirst(n);
        return n.value;
    }
    public void put(int key, int value) {
        Node n = map.get(key);
        if (n != null) {
            n.value = value;
            unlink(n);
            addFirst(n);
            return;
        }
        if (capacity == 0) return;
        n = new Node(key, value);
        map.put(key, n);
        addFirst(n);
        if (map.size() > capacity) {
            Node victim = tail.prev;
            unlink(victim);
            map.remove(victim.key);
        }
    }
    private void unlink(Node n) {
        n.prev.next = n.next;
        n.next.prev = n.prev;
    }
    private void addFirst(Node n) {
        n.prev = head;
        n.next = head.next;
        head.next.prev = n;
        head.next = n;
    }
}
```

容量 2：put(1,1)、put(2,2)、get(1)、put(3,3)，此时 key=2 被淘汰。更新已存在 key 会刷新最近使用顺序。

### ALG-004：如何合并重叠区间？

**常见问法**

- 手撕：如何合并二维数组中的重叠区间？

- 手撕：重叠区间的总长度。

#### 面试回答

我会先确认区间开闭和输入是否合法。这里约定输入为合法闭区间，端点相接也合并，null 或空数组返回空结果。先按左端点升序排序，依次扫描：当前区间左端点不大于结果末区间右端点时扩展右端点，否则新增区间。排序需要 O(n log n)，扫描 O(n)；为保持输入不变，复制区间后再排序，额外空间 O(n)。完整 Java 实现与边界案例见关联专题。

#### 技术细节

原图未提供语言及边界约束；以下选用 Java 8+。每个子数组须有两个元素且 start <= end；违反约定抛出 IllegalArgumentException。闭区间 [1,2] 和 [2,3] 合并，[1,2] 和 [3,4] 不合并。排序比较用 Integer.compare，避免端点相减溢出。

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class MergeIntervals {
    public static int[][] merge(int[][] intervals) {
        if (intervals == null || intervals.length == 0) {
            return new int[0][2];
        }
        int[][] sorted = new int[intervals.length][2];
        for (int i = 0; i < intervals.length; i++) {
            int[] row = intervals[i];
            if (row == null || row.length != 2 || row[0] > row[1]) {
                throw new IllegalArgumentException("Invalid interval");
            }
            sorted[i] = new int[]{row[0], row[1]};
        }
        Arrays.sort(sorted, (a, b) -> Integer.compare(a[0], b[0]));
        List<int[]> result = new ArrayList<>();
        for (int[] current : sorted) {
            if (result.isEmpty()
                    || current[0] > result.get(result.size() - 1)[1]) {
                result.add(current);
            } else {
                int[] last = result.get(result.size() - 1);
                last[1] = Math.max(last[1], current[1]);
            }
        }
        return result.toArray(new int[result.size()][]);
    }
}
```

扫描不变量：结果始终按左端点有序且互不重叠；排序后新段只能和末段合并，若超过末段右端点，也不可能与更早段重叠。覆盖案例：空输入；单区间；乱序输入；包含与重复；端点相接；不相交；负数与 int 极值；非法子数组；输入未被修改。示例 [[8,10],[1,3],[2,6],[15,18]] 得到 [[1,6],[8,10],[15,18]]。

#### 深挖追问

1. **半开区间也把相接端点合并吗？**（补充练习）

   若题意只合并有非空交集的半开区间，则 [1,2) 与 [2,3) 不重叠，应调整比较条件；若题意允许将相邻区间压缩为同一并集表示，则可以合并，先明确规则。

2. **不输出合并结果，只要“覆盖的总长度”怎么做？**（面经实际出现；[[面经/阿里云/三面/0001#Q03：手撕重叠区间的总长度；拓展到二维计算所有矩阵重叠的总面积（自评：答的一般）。|MJ039 · 阿里云 · 三面 · Q03]]）

### ALG-005：如何求最长回文子串？

**常见问法**

- 手撕：给定字符串，返回最长回文子串。

#### 面试回答

采用中心扩展：回文左右对称，中心可能是一个字符，也可能是两个字符之间的空隙。遍历每个位置，分别向两边扩展奇数和偶数长度回文，遇到边界或不同字符停止，更新最长区间，最后返回子串。所有中心都被检查，因此能覆盖最长回文。时间 O(n²)，除返回字符串外辅助空间 O(1)。这里用 Java 示例，按 UTF-16 char 比较，null 和空串返回空串，同长取最先找到的一段；这些是示例约定，原题未指定字符范围、语言或同长规则。完整实现见专题。

#### 技术细节

不要求连续的是回文子序列，本题要求连续子串。每个回文都有字符或间隙中心，向两侧扩展直到首次不匹配，即得到该中心的最长回文。遍历全部中心，维护全局最长区间。

```java
class Solution {
    public String longestPalindrome(String s) {
        if (s == null || s.isEmpty()) return "";
        int start = 0, best = 1;
        for (int i = 0; i < s.length(); i++) {
            int len = Math.max(expand(s, i, i), expand(s, i, i + 1));
            if (len > best) {
                start = i - (len - 1) / 2;
                best = len;
            }
        }
        return s.substring(start, start + best);
    }
    private int expand(String s, int left, int right) {
        while (left >= 0 && right < s.length()
                && s.charAt(left) == s.charAt(right)) {
            left--;
            right++;
        }
        return right - left - 1;
    }
}
```

示例约定：null 与空串返回空串；同长保留先找到的一段；按 Java UTF-16 代码单元比较。若题目要求 Unicode 码点，应先转码点数组并处理返回位置，空间口径随之改变。时间 O(n²)，除返回值外辅助空间 O(1)。例：babad→bab，cbbd→bb，a→a，aaaa→aaaa，abc→a。

#### 深挖追问

1. **还有哪些解法，复杂度如何？**（补充练习）

   动态规划用 dp[i][j] 表示区间回文，转移为两端相同且内部回文（长度不超过 2 时直接判断），按长度递增填表，时间和空间 O(n²)；Manacher 利用回文半径对称性做到 O(n) 时间、O(n) 空间。面试先写正确的中心扩展，再按要求优化。

def recent_users(logs, now, window):

### ALG-008：LeetCode 32：如何求最长有效括号子串？

**常见问法**

- LeetCode 32：最长有效括号。

#### 面试回答

用栈保存未匹配左括号下标，并以 −1 作为初始边界。遇到左括号入栈，遇到右括号弹栈；弹完为空就把当前右括号下标作为新边界，否则用当前位置减栈顶更新最大长度。时间 O(n)，空间 O(n)。

#### 技术细节

输入按只含左右括号的字符串处理，求连续子串长度而非子序列。栈底保存最近无法匹配的右括号边界，其上为尚未配对的左括号；这保证差值对应有效连续后缀。空串为 0，不能仅计左右括号总数。

```python
def longest_valid_parentheses(s):
    stack = [-1]
    best = 0
    for i, ch in enumerate(s):
        if ch == '(':
            stack.append(i)
        else:  # 前提：输入只有 '(' 和 ')'
            stack.pop()
            if not stack:
                stack.append(i)
            else:
                best = max(best, i - stack[-1])
    return best
```

#### 深挖追问

1. **为什么初始压入 −1？**（补充练习）

   完整匹配从下标 0 开始时，当前位置减 −1 正好得到长度；遇到无法匹配的右括号会重置边界。

### ALG-009：如何手写快速排序？

**常见问法**

- 手撕快速排序。

#### 面试回答

快速排序先选一个基准值，用明确的分区规则把数组拆成两部分，使基准值左边不大于它，右边不小于它，然后递归排序左右区间。手写时要选定一种分区法，让分区和递归边界保持一致，并确保每次递归区间都变小。平均时间复杂度是 O(n log n)，最坏是 O(n²)；原地实现的额外空间主要是递归栈，平均 O(log n)、最坏 O(n)。

#### 技术细节

下面使用 Hoare 风格双指针分区。基准取区间中点的值，循环退出后递归 `[left, j]` 和 `[i, right]`；元素等于基准时也推进指针，避免重复元素导致死循环。

```java
static void quickSort(int[] a, int left, int right) {
    if (a == null || left >= right) {
        return;
    }
    int i = left;
    int j = right;
    int pivot = a[left + ((right - left) >>> 1)];
    while (i <= j) {
        while (a[i] < pivot) i++;
        while (a[j] > pivot) j--;
        if (i <= j) {
            int temp = a[i];
            a[i] = a[j];
            a[j] = temp;
            i++;
            j--;
        }
    }
    if (left < j) quickSort(a, left, j);
    if (i < right) quickSort(a, i, right);
}
```

随机选择基准或三数取中可以降低特定有序输入持续产生极端分区的概率，但不能改变比较排序的最坏 O(n²) 上界。工程实现还可优先递归较短的一侧并循环处理较长一侧，把调用栈控制在 O(log n)。快速排序通常不稳定；若要求稳定性，需要更换算法或付出额外空间。

#### 深挖追问

1. **为什么平均是 O(n log n)，最坏是 O(n²)？**（补充练习）

   每层分区总工作量为 O(n)；均衡分区约有 O(log n) 层。若每次只分出一个元素，层数变为 O(n)，总和为 O(n²)。

2. **大量重复元素怎么办？**（补充练习）

   本实现会在等于基准时同时推进指针，能终止；重复值极多时可使用三向切分，把小于、等于和大于基准的元素分区，减少重复递归。

### ALG-010：如何验证一棵树是二叉搜索树？

**常见问法**

- 代码题：验证二叉搜索树。

#### 面试回答

递归维护每个节点允许的开区间：根节点为负无穷到正无穷，进入左子树时把上界收紧为当前值，进入右子树时把下界收紧为当前值。任一节点不满足 `low < value < high` 就返回 false。这样检查的是节点与所有祖先共同形成的约束，不会只比较直接父子。时间 O(n)，递归栈 O(h)。

#### 技术细节

按常见题意，二叉搜索树不允许重复值，因此使用严格比较。Java 用 `long` 保存边界，避免节点值等于 int 上下界时需要做溢出运算。

```java
boolean isValidBST(TreeNode root) {
    return valid(root, Long.MIN_VALUE, Long.MAX_VALUE);
}

boolean valid(TreeNode node, long low, long high) {
    if (node == null) return true;
    if (node.val <= low || node.val >= high) return false;
    return valid(node.left, low, node.val)
        && valid(node.right, node.val, high);
}
```

也可中序遍历并检查值严格递增；迭代版用显式栈可避免树过深导致递归栈溢出。若业务定义允许重复值，必须先确认重复值放左还是放右，并相应修改边界闭开规则。

1. **为什么只比较节点与左右孩子不够？**（补充练习）

   右子树中的任意节点都必须大于所有相关祖先，不只是大于直接父节点；区间能传递完整祖先约束。

### ALG-011：LeetCode 200：如何计算岛屿数量？

**常见问法**

- 岛屿数量怎么做？
- 能否用并查集解决岛屿数量？

#### 面试回答

按 LeetCode 200 的常见约束，只把上下左右相邻的陆地视为连通。遍历网格，遇到未访问的陆地就把答案加一，再用 DFS 或 BFS 把该连通块全部标记。每个格子至多访问一次，时间 O(mn)，额外空间最坏 O(mn)。若允许修改输入，可以直接把访问过的 `'1'` 改成 `'0'`；网格可能很深时优先用显式队列避免递归栈溢出。

#### 技术细节

```java
int numIslands(char[][] grid) {
    if (grid == null || grid.length == 0) return 0;
    int ans = 0;
    for (int r = 0; r < grid.length; r++) {
        for (int c = 0; c < grid[0].length; c++) {
            if (grid[r][c] == '1') {
                ans++;
                flood(grid, r, c);
            }
        }
    }
    return ans;
}

void flood(char[][] grid, int r, int c) {
    if (r < 0 || r >= grid.length || c < 0 || c >= grid[0].length
            || grid[r][c] != '1') return;
    grid[r][c] = '0';
    flood(grid, r - 1, c);
    flood(grid, r + 1, c);
    flood(grid, r, c - 1);
    flood(grid, r, c + 1);
}
```

并查集做法先把每个陆地作为一个集合，初始连通分量数为陆地数；扫描时只需与右、下的陆地尝试合并，每次成功合并两个不同根就把分量数减一。路径压缩配合按大小／秩合并后，每次操作摊还接近 O(1)，总复杂度约 O(mn α(mn))。并查集更适合动态添加陆地或还要回答连通性的问题；静态计数时 DFS／BFS 代码通常更短。

#### 深挖追问

1. **为什么扫描并查集时只检查右边和下边？**（补充练习）

   每条无向相邻边处理一次就够了；左边和上边已由此前格子覆盖，四个方向都检查会重复 union，但正确性不变。

2. **递归 DFS 有什么风险？**（补充练习）

   极端大连通块的递归深度可能达到 O(mn)，Java 可能栈溢出；可换成显式栈或 BFS 队列。

### ALG-012：每轮取 1 个或 2 个，如何判断必胜策略？

**常见问法**

- 100 个圆圈，双方每次只能涂 1 个或 2 个，谁能涂到最后一个？

#### 面试回答

按“每轮从剩余对象中处理 1 个或 2 个，处理最后一个者胜”的前提，3 的倍数是当前玩家的必败态，其他数量是必胜态。100 除以 3 余 1，所以先手先处理 1 个，给对手留下 99 个；之后对手取 1 个就取 2 个，对手取 2 个就取 1 个，使双方每轮合计取 3 个，最终由先手取到最后一个。

#### 技术细节

设 `win(n)` 表示还剩 n 个时当前玩家能否必胜，则 `win(n) = !win(n-1) || !win(n-2)`，边界为 `win(0)=false`、`win(1)=true`、`win(2)=true`，由此得到 `false, true, true` 每 3 个循环。构造策略就是先取 `n % 3` 个，再用 `3 - opponentMove` 回应。

一般化到每轮可取 1 到 k 个、正常规则下取到最后者胜，`k+1` 的倍数为必败态，其他状态先取余数，再与对手凑 `k+1`。如果改成“取最后者输”，或圆环上的相邻位置对合法动作有额外限制，边界和策略都会变化，必须先确认题意。

#### 深挖追问

1. **为什么不能只说先手有优势？**（补充练习）

   胜负取决于初始数量对 3 的余数。若初始是 3 的倍数且双方最优，后手可采用互补策略获胜。

2. **如果每次能取 1 到 k 个呢？**（补充练习）

   正常取子规则下先把对手送到 `k+1` 的倍数，并在之后每轮与对手凑 `k+1`；初始为其倍数时先手处于必败态。

- 算法：二叉树的直径。

#### 面试回答

直径是任意两节点间最长路径的边数，路径可能不经过根。后序遍历：对每个节点，以该节点为“拐点”的最长路径＝左子树高度＋右子树高度，用全局变量取最大；节点高度＝1＋max(左, 右)。一次 DFS 完成，时间 O(n)，递归栈 O(h)。

#### 技术细节

```java
int diameter = 0;

int height(TreeNode node) {
    if (node == null) return 0;
    int left = height(node.left);
    int right = height(node.right);
    diameter = Math.max(diameter, left + right); // 边数口径
    return 1 + Math.max(left, right);
}

int diameterOfBinaryTree(TreeNode root) {
    height(root);
    return diameter;
}
```

易错点：先确认直径按边数还是节点数——边数口径答案＝上述 diameter，节点数口径是 `diameter + 1`（单节点树分别为 0 和 1）；返回值是高度而不是拐点路径，两者混用是常见 bug。树退化成链时递归深度为 O(n)，面试可提迭代栈或说明约束。

#### 深挖追问

1. **能改成求带权树的直径吗？**（补充练习）

   把“高度＋1”改为“高度＋边权”，拐点更新为左高＋右高；两次 DFS 的解法（任取点找最远点、再从该点找最远点）对非负权树同样成立。

### ALG-015：“求剩余空间最小值”这类最大子数组和改编题怎么做？

**常见问法**

- 算法：求剩余空间最小值（非 Hot100，像“最大子数组和”改编）。

#### 面试回答

原题只记到一句话，完整约束未知——先向面试官复述确认“剩余空间”的定义再动手。两种最可能的口径：① 给定容量，从数组中选一个连续段装走，剩余＝容量−段和，要剩余最小即求最大子数组和，Kadane 一遍扫描；② 直接求最小子数组和，把 Kadane 的取 max 换成取 min。确认后说明口径转换、写代码、给 O(n) 时间／O(1) 空间复杂度。

#### 技术细节

```java
// ① 最大子数组和（LeetCode 53）
int maxSubArray(int[] a) {
    int cur = a[0], best = a[0];
    for (int i = 1; i < a.length; i++) {
        cur = Math.max(a[i], cur + a[i]);
        best = Math.max(best, cur);
    }
    return best;
}

// ② 最小子数组和：cur/best 全部换成 Math.min
int minSubArray(int[] a) {
    int cur = a[0], best = a[0];
    for (int i = 1; i < a.length; i++) {
        cur = Math.min(a[i], cur + a[i]);
        best = Math.min(best, cur);
    }
    return best;
}
```

维护“以 i 结尾的最优连续段”这一状态是改编题的通用套路：把“最优”换成题目目标（最小剩余、不超过容量的最大、绝对值最近目标值等）即可复用框架。若题意是“段和不超过容量且剩余最小”，需在 Kadane 上加约束，常用前缀和＋有序结构或滑窗（全非负时），必须先确认数据是否含负数——含负数时滑窗不成立。空段是否允许（剩余＝容量）也要确认。题意澄清方法同 [[专题题库/算法与数据结构#ALG-013：“最长连续子数组长度”题意不完整时如何澄清与选型？|ALG-013：“最长连续子数组长度”题意不完整时如何澄清与选型？]]。

#### 深挖追问

1. **为什么“以 i 结尾”这个状态定义能兼容各种改编？**（补充练习）

   连续段的最优解必然以某个位置结尾，该状态具有最优子结构；改编只换目标算子，转移形式不变。

### ALG-016：如何求无重复字符的最长子串（LeetCode 3）？

**常见问法**

- 算法：LeetCode 3 无重复字符的最长子串（ACM 模式）。

#### 面试回答

滑动窗口：维护窗口 `[left, right]` 内无重复；右指针逐字符扩张，用哈希表记录每个字符最后出现的下标，若该字符上次位置 ≥ left，则 left 直接跳到“上次位置＋1”（不用逐格缩窗）；每步用 `right-left+1` 更新最大值。O(n) 时间、O(字符集) 空间。先确认字符集（ASCII／小写／Unicode）与大小写是否敏感，它决定数组大小表还是哈希表。

#### 技术细节

```java
int lengthOfLongestSubstring(String s) {
    Map<Character, Integer> last = new HashMap<>();
    int left = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        Integer prev = last.get(c);
        if (prev != null && prev >= left) left = prev + 1;
        last.put(c, right);
        best = Math.max(best, right - left + 1);
    }
    return best;
}
```

易错点：判断重复必须加 `prev >= left`，否则窗口外的旧记录会把 left 往回拉；用 int[128] 数组可替代哈希表但要先确认字符集。ACM 模式需自己读入：按整行读字符串（可能含空格与否要先问），输出长度即可；空串返回 0。求“最长子序列”是另一题，别把窗口答成子序列。

#### 深挖追问

1. **变体：最多包含两种不同字符的最长子串怎么改？**（补充练习）

   窗口约束从“无重复”改为“不同字符数 ≤ 2”，用计数 Map 维护，超限时缩左边界；框架仍是滑动窗口。

### ALG-017：如何在两个有序数组中找到第 k 小的元素？

**常见问法**

- 手撕：两个有序数组，找到其中第 k 大的元素。

#### 面试回答

先确认口径：“第 k 大”在合并升序视角下换算为第 `m+n-k+1` 小，下面按第 k 小讲。最优解是二分切分：在较短数组 A 上取切分 i，B 上 j=k−i，使两数组“左半（A[..i)、B[..j)）”共含 k 个元素，当 `A[i-1] <= B[j] 且 B[j-1] <= A[i]` 时左半最大值即第 k 小，不满足就按大小关系移动 i，时间 O(log(min(m,n)))。面试策略：先口述并写 O(k) 双指针归并保证正确，再升级到切分二分；越界用 ±∞ 哨兵（i=0 时左边界取 −∞）。

#### 技术细节

```java
int kth(int[] A, int[] B, int k) {           // 第 k 小，1-based，A 为较短数组
    if (A.length > B.length) return kth(B, A, k);
    int lo = Math.max(0, k - B.length), hi = Math.min(k, A.length);
    while (lo <= hi) {
        int i = (lo + hi) >>> 1, j = k - i;
        int aL = (i == 0) ? Integer.MIN_VALUE : A[i - 1];
        int aR = (i == A.length) ? Integer.MAX_VALUE : A[i];
        int bL = (j == 0) ? Integer.MIN_VALUE : B[j - 1];
        int bR = (j == B.length) ? Integer.MAX_VALUE : B[j];
        if (aL <= bR && bL <= aR) return Math.max(aL, bL);
        if (aL > bR) hi = i - 1; else lo = i + 1;
    }
    throw new IllegalArgumentException("k 越界");
}
```

易错点：k 的基准（1-based 还是 0-based）、短数组长度不足时由另一数组补足（lo/hi 初值已处理）、重复值下切分仍成立（用 ≤ 比较）、降序数组要先反转口径。同类变体“两个有序数组的中位数”即 k=(m+n)/2 的特例（LeetCode 4）。

#### 深挖追问

1. **为什么二分较短数组而不是二分 k？**（补充练习）

   切分点 i 的取值受短数组长度限制，在短数组上二分复杂度 O(log(min(m,n)))；对“值域”二分则需每次数出两数组 ≤x 的总个数，可行但常数与边界更繁琐。

### ALG-018：数组和链表有什么区别，各自适合什么场景？

**常见问法**

- 数组和链表知道吧，讲一下区别以及不同应用场景。
- ArrayList 和 LinkedList 怎么选？

#### 面试回答

内存布局决定一切差异：数组元素连续存放，因此按下标随机访问 O(1)（地址＝基址＋下标×元素大小），代价是头部/中间插入删除要搬移后续元素 O(n)，且定长数组容量要预先确定；链表节点分散在堆上，靠指针前后串联，因此已定位到节点后插入删除只改指针 O(1)，代价是不能随机访问——按下标取值必须从头顺着走 O(n)，每个节点还要额外存指针。
场景选择：需要频繁按下标读写、顺序批量遍历、要求缓存友好 → 数组/ArrayList、原始 int[]、字符串缓冲（StringBuilder 本质是动态数组，靠容量倍增把 append 摊还成 O(1)）；长度动态变化大、经常在头部或已知位置插拔、且不愿为一块连续内存负责 → 链表/Deque、LRU 与 LFU 里的双向链表（哈希表定位节点＋链表 O(1) 摘挂，见 [[#ALG-003：如何手写 LRU 缓存？|ALG-003：如何手写 LRU 缓存？]]）、多路归并中把“下一个元素”挂成链表。
必须补的一句真实结论：现代机器上数组的缓存局部性让线性扫描往往比链表快数倍，渐进复杂度相同甚至链表“更优”的场景，实测仍常输给数组——所以 Java 里绝大多数场景默认选 ArrayList，LinkedList 只在确实需要双端 O(1) 摘挂且不做下标访问时才考虑。

#### 技术细节

| 维度 | 数组 | 单链表 |
| --- | --- | --- |
| 随机访问 | O(1) | O(n) |
| 头部插入 | O(n)（搬移）或 O(1)（已预留位置） | O(1) |
| 中间插入/删除 | O(n)（搬移，但定位可能 O(1)） | 定位 O(n)＋改指针 O(1) |
| 内存 | 连续、无每元素额外开销，扩容需拷贝 | 每节点多 1～2 个指针＋分配器开销，离散 |
| 缓存 | 好（顺序预取生效） | 差（指针追逐，cache miss 高） |
| 长度 | 定长或倍增扩容 | 天然动态 |

易错点三条：① “链表插入一定 O(1)”忽略了查找前驱的成本，多数题面里成本在定位；② 数组扩容是**摊还** O(1)——第 k 次扩容要拷贝 k 个元素，n 次操作总计 O(n)，不能只说“最坏 O(n) 所以慢”；③ 删除单链表节点本身也需要前驱指针，因此实际常用双向链表或“复制后继再删后继”的技巧（LeetCode 237 式，且不能删尾节点）。语言实现细节：`ArrayList` 的 `remove(i)` 用 `System.arraycopy` 搬移，`LinkedList` 是双向链表且 `get(i)` 会从较近的一端开始走——两者都不是 O(1) 随机访问。

#### 深挖追问

1. **为什么 LinkedList 在实际测速中常输给 ArrayList？**（补充练习）

   指针追逐打断顺序预取，每节点独立对象还带来分配器与 GC 压力；即便操作次数相同，常数项差距可以盖过渐进优势。

2. **既要随机访问又要 O(1) 插入删除怎么办？**（补充练习）

   组合结构：哈希表提供“值→节点引用”的定位，链表提供顺序与摘挂，就是 LRU 的做法；或改用跳表（有序＋期望 O(log n) 定位，见 Redis zset）、树/跳表类索引结构。

3. **数组头部插入有 O(1) 的做法吗？**（补充练习）

   有：预留头偏移的 deque（环形数组，双端 O(1)、随机访问 O(1)，如 `ArrayDeque`），或分块数组（rope／块表，插入只拆块）。这类结构说明“数组 vs 链表”不是二选一。

### ALG-019：如何判断链表中是否有环，如何找环的入口？

**常见问法**

- 如何判断一个列表里面有环？
- LeetCode 141／142：环形链表与环的入口节点。

#### 面试回答

判环用快慢指针（Floyd 判圈）：slow 每次走一步、fast 每次走两步，从同一起点出发；如果 fast 或 fast.next 走到 null，说明有终点即无环；如果两者在环内相遇，说明有环。时间 O(n)、空间 O(1)，比 HashSet 记录访问节点（O(n) 空间）更优。
找入口再走一步：相遇后把其中一个指针移回链表头，两个指针都改成每次一步，再次相遇的位置就是环的入口——因为设头到入口距离 a、入口到相遇点 b、相遇点绕回入口 c，快慢路程关系 2(a+b)=a+b+k(b+c) 可推出 a=(k−1)(b+c)+c，即从头走 a 步与从相遇点走 a 步都正好落在入口。
如果题目给的“列表”其实是数组，而环体现在**下标跳转**上（元素值指向下一个下标，如 LeetCode 457 环形数组、287 寻找重复数），同样能用快慢指针，因为“每个位置恰好一个后继”就构成隐式链表；更直白的是 HashSet 记录已访问下标，或在不要求保留输入时把访问过的位置原地打标记／置为 −1 来实现 O(1) 空间。

#### 技术细节

```java
public boolean hasCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) return true;
    }
    return false;
}

public ListNode detectCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) {
            ListNode p = head;
            while (p != slow) { p = p.next; slow = slow.next; }
            return p;
        }
    }
    return null;
}
```

五个易错点：① 循环条件必须同时判 `fast != null` 和 `fast.next != null`，否则两步跳会 NPE；② 相遇判断要在**移动之后**做，起点同一位置直接比较会立刻“相遇”而误判；③ 自环（`next` 指向自己）与整条成环都要覆盖；④ 快指针步长取 2 与 3 都能判环，但入口推导的等式依赖步长关系，别混用；⑤ 数组版判环要小心值为负或超出长度（不是合法后继），以及“从 index 0 出发”可能进不了环——这类题常要求先确定入口起点，或改用图遍历（入度拓扑／visited 状态三色标记）。

#### 深挖追问

1. **为什么不能用 HashSet 一步到位？**（补充练习）

   可以且更好懂：逐个把节点引用放进 HashSet，第二次遇到即有环。O(n) 时间与空间，面试写完要主动补“若要 O(1) 空间则用快慢指针”。

2. **如何求环的长度？**（补充练习）

   相遇后固定一个指针，另一个每次一步再走一圈回到它，计数即环长；或记录相遇时的步数差推导。

3. **判环能否用在树上？**（补充练习）

   树的父指针唯一、无环则天然成立；如果节点带 parent 指针，判环等价于判两条根路径是否相交（LeetCode 160），做法是先量深度差再同步前进，或用 HashSet。有向图判环则要用 DFS 三色标记或拓扑排序看剩余节点。

### ALG-020：冒泡排序的原理是什么，如何优化？

**常见问法**

- 排序算法知道吗？讲一下冒泡排序的原理。

#### 面试回答

冒泡排序重复扫描未排序区间，每次比较相邻两个元素、顺序不对就交换，一轮结束后本轮最大值被“冒泡”到未排序区的最右端；下一轮把右边界左移一位，重复到区间为空。两个必要优化：一是记录本轮是否发生过交换，没有交换说明已经有序，可以提前退出，使最好情况达到 O(n)；二是记下最后一次交换发生的位置作为新的右边界（该位置右侧已有序），避免死按 n−1 递减。
复杂度：最坏和平均都是 O(n²) 次比较，空间 O(1)，且因为只在严格大于时才交换，相等元素不互换位置，是**稳定**排序。工程上不用它排大数据（规模稍大就被插入排序、TimSort 全面取代），它的价值是简单、易写对、易验证，以及教学上承载“比较排序、稳定性、最好/最坏复杂度”这几个概念。

#### 技术细节

```java
static void bubbleSort(int[] a) {
    if (a == null || a.length < 2) return;
    int lastSwap = a.length - 1;
    while (lastSwap > 0) {
        int boundary = 0;
        for (int i = 0; i < lastSwap; i++) {
            if (a[i] > a[i + 1]) {
                int t = a[i]; a[i] = a[i + 1]; a[i + 1] = t;
                boundary = i;
            }
        }
        lastSwap = boundary;
    }
}
```

要点：内层循环写 `i < lastSwap`（比较 `a[i]` 与 `a[i+1]`，天然不越界）；用 `>` 而不是 `>=` 才稳定。
横向对比常被追问：同样是 O(n²) 的插入排序在**近乎有序**的数据上远快于冒泡（它靠移动而非逐次交换，比较与写次数都更少），选择排序交换次数少（O(n) 次）但不稳定且比较恒为 O(n²)；工业实现基本是混合策略——Java 的 `Arrays.sort` 对对象用归并系（TimSort，稳定、O(n log n)、需额外空间），对基本类型用双轴快排，C++/Python 亦用 intro-sort／Timsort。排序题的标准回答顺序：先说清原理与不变量，再给复杂度与稳定性，最后说“工程上会选什么以及为什么”，参见 [[#ALG-009：如何手写快速排序？|ALG-009：如何手写快速排序？]]。

#### 深挖追问

1. **冒泡排序稳定吗，为什么？**（补充练习）

   稳定。只在严格 `a[i] > a[i+1]` 时交换，相等元素永不互换，因此相等键的相对次序全程不变。

2. **最好复杂度为什么是 O(n)？**（补充练习）

   输入已有序时，第一轮扫描不发生任何交换，靠 swapped／boundary 标志立刻退出，只做了 n−1 次比较。

3. **为什么工程里不用冒泡？**（补充练习）

   O(n²) 的增长在 n=10⁴ 量级就不可接受，且它每轮只能把元素移动有限距离，交换次数与逆序对数同阶；插入排序、归并、快排在常数与增长上都占优。

### ALG-021：两数之和如何用哈希表一次遍历求解？

**常见问法**

- 两数之和：给定数组和目标值，返回两个数的下标。

#### 面试回答

一次遍历＋哈希表：map 保存“已经扫过的值 → 它的下标”，对每个 `nums[i]` 先计算补数 `target − nums[i]` 去 map 里查，命中就返回 `{查到的下标, i}`；没命中再把当前值和下标写进 map。时间 O(n)、空间 O(n)。关键顺序是**先查后放**：这样每个元素只会与它之前的元素配对，天然避免用自身配自身（例如 target 恰好是某元素两倍时不会自匹配），也满足“同一元素不能重复使用”。
对比其他做法：暴力双重循环 O(n²) 时间 O(1) 空间；若数组已排序可用左右双指针 O(n) 时间 O(1) 空间，但一般无序数组要先排序就会打乱下标，需要额外保存原索引且复杂度升到 O(n log n)——题目要的是下标时哈希表最直接。

#### 技术细节

```java
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> indexByValue = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        Integer j = indexByValue.get(target - nums[i]);
        if (j != null) return new int[]{j, i};
        indexByValue.put(nums[i], i);
    }
    return new int[0];
}
```

四个易错点与变体：① 存在重复值时“后写覆盖”会让 map 保留较新的下标；因为先查后放，返回的下标顺序是“早出现的在前”，若题目要求升序需自己调整。② 用 `get` 返回 `Integer` 判空，不能用 `containsKey`＋`getOrDefault` 混着写；`0` 是合法下标，别拿返回值当假值判断。③ 溢出：`target - nums[i]` 在 int 范围内做减法仍可能溢出（target 为 `Integer.MIN_VALUE` 且元素为负），严谨实现可用 long 计算补数再判是否落回 int。④ 变体：三数之和（排序＋固定一个＋双指针，去重是关键，见 [[#ALG-004：如何合并重叠区间？|ALG-004]] 同类“排序后双指针”思路）；四数之和在三层循环外加剪枝；“和为 S 的最多配对数”用计数 map；“两数之和 II（有序）”用对向双指针。

#### 深挖追问

1. **为什么不用两次遍历？**（补充练习）

   两次遍历（先建 map 再查）也可行，但要先处理“自己配自己”：得判断 `map.get(complement) != i`。一次遍历的先查后放把这层特判消掉，代码更短，也少维护一份状态。

2. **哈希表的最坏复杂度是多少？**（补充练习）

   期望 O(1)，最坏 O(n)（大量哈希冲突退化成链表；Java 8 后 HashMap 在链表长度超阈值且表长足够时会转红黑树，退化风险降低但树化只解决最坏查找，不改变哈希函数分布问题）。极端对抗输入可考虑随机化或换结构。

3. **数据量到亿级、内存放不下 map 怎么办？**（补充练习）

   外存/分片思路：按值域哈希分桶落盘，逐桶加载做两两配对（同桶内必有配对时可直接处理，跨桶配对的用另一趟排序归并）；或排序＋外部归并后双指针扫描。核心是把 O(n) 额外内存换成多趟顺序 I/O。

### ALG-022：如何求字符串数组的最长公共前缀？

**常见问法**

- 最长公共前缀：求字符串数组的最长公共前缀，无公共前缀返回空串，注意空数组边界。

#### 面试回答

纵向扫描最直观：拿第一个字符串当基准，按下标 `col` 逐位比较所有字符串的第 `col` 个字符——只要出现“某个串长度已经到 `col`”或“字符与基准不同”，就返回 `strs[0].substring(0, col)`；整个基准都被比完，说明它自己就是答案。边界先处理：数组为 null 或长度为 0 直接返回空串；数组里含空串时结果自然是空串，这个逻辑会覆盖。复杂度 O(S)，S 为全部字符总数。
另外两种常见写法：横向归约——把第一个串当答案，依次与后面每个串求“两串公共前缀”并缩短，一旦为空提前 break；排序法——排序后只需比较最小串与最大串（字典序相邻两端），取它们的前缀即整体前缀，代价是 O(n log n) 排序且不宜修改入参。三种都正确，纵向扫描最容易在面试中讲清楚。

#### 技术细节

```java
public String longestCommonPrefix(String[] strs) {
    if (strs == null || strs.length == 0) return "";
    for (int col = 0; col < strs[0].length(); col++) {
        char c = strs[0].charAt(col);
        for (int k = 1; k < strs.length; k++) {
            if (col >= strs[k].length() || strs[k].charAt(col) != c) {
                return strs[0].substring(0, col);
            }
        }
    }
    return strs[0];
}
```

易错点：① 循环条件顺序——必须先判 `col >= strs[k].length()` 再取字符，短路写法不能反；② 用 `charAt` 而不是 `substring` 拼接来比，避免每步造字符串；③ 单元素数组直接返回该串；④ 只有 null 与空数组要特判，`strs[0]` 为空串时外层循环天然不进入并返回 `""`；⑤ 需要按码点比较的国际化文本时，`charAt` 会拆代理对，要用 `codePointAt`/`offsetByCodePoints`。
延伸：横向归约的“两串公共前缀”可以复用为“任意时刻动态维护前缀”的能力，配合 Trie 可以把一批字符串插入后沿唯一子路径下探得到最长公共前缀；数据量大且要支持“任意子区间的最长公共前缀”查询时，可用线段树/稀疏表对逐位相等做区间归约（这是把 LCP 从 O(S) 变成预处理＋O(log n) 查询的思路）。

#### 深挖追问

1. **为什么可以只比较排序后的首尾两串？**（补充练习）

   字典序最小与最大串之间的所有串，其前缀必然包含这两者的公共前缀：若某串的公共前缀更短，它就会排在首串之前或尾串之后，与“首/尾”矛盾。因此排序后比较 `strs[0]` 与 `strs[n-1]` 即得答案，代价换成 O(n log n)＋排序可能改动输入。

2. **能比 O(S) 更快吗？**（补充练习）

   单次查询不能——每个字符至少要被看一次才能确认前缀；但同一批字符串上的多次查询（如“区间 [i, j] 内串的最长公共前缀”）可以预处理，用逐位比较＋ST 表在 O(1)～O(log n) 内回答。

### ALG-023：零钱兑换（LeetCode 322）如何用动态规划求最少硬币数？

**常见问法**

- 手撕：硬币找零问题（LeetCode 322）。

#### 面试回答

给定硬币面额 `coins`（每种无限个）和金额 `amount`，求凑出 `amount` 所需的**最少硬币数**，凑不出返回 -1。这是完全背包型动态规划：`dp[j]` 表示凑出金额 `j` 的最少硬币数，`dp[0]=0`，其余初始化为一个不可达的哨兵（用 `amount+1`，比任何合法解都大）。转移：对每种面额 `c`，`dp[j] = min(dp[j], dp[j-c] + 1]`（`j>=c`）。最后 `dp[amount]` 若仍是哨兵则返回 -1。时间 O(amount·|coins|)，空间 O(amount)。

#### 技术细节

```java
int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);
    dp[0] = 0;
    for (int j = 1; j <= amount; j++) {
        for (int c : coins) {
            if (c <= j) dp[j] = Math.min(dp[j], dp[j - c] + 1);
        }
    }
    return dp[amount] > amount ? -1 : dp[amount];
}
```

- 求“最少数量”时外层遍历金额、内层遍历硬币最直观（每个 `j` 枚举最后一步用哪种硬币）；这与“凑法种数”题（518）的遍历顺序不同——数硬币最少时两重循环顺序不影响最值，但计数题必须“外层硬币、内层金额”以避免顺序重复计数，别把两者混为一谈。
- 哨兵选 `amount+1` 而不是 `Integer.MAX_VALUE`：`MAX_VALUE+1` 会溢出，`amount+1` 天然表示“不可能达到的上界”（最多也就 amount 个面额 1 的硬币），判断 `>amount` 即无解。
- 贪心不可通用：只有当币值体系“规范”（如某些面额）时贪心才最优，一般 `coins=[1,3,4], amount=6` 贪心得 4+1+1=3 枚但最优是 3+3=2 枚——所以必须 DP。

#### 深挖追问

1. **如果要输出具体用了哪些硬币，怎么改？**（补充练习）

   加一个 `prev[j]`/`choice[j]` 记录把 `dp[j]` 更新为最优时所用的面额，最后从 `amount` 沿 `choice` 回退到 0 还原方案；不要求方案时可不记录以省空间。

2. **和“凑出金额的组合数”（LC 518）区别在哪？**（补充练习）

   518 求方案数、且组合不计顺序，用 `dp[j]+=dp[j-c]` 且**外层硬币内层金额**保证不重复计数；322 求最少枚数、用 `min`，遍历顺序对结果无影响。状态定义与转移方向都不同，别套错。

### ALG-024：LeetCode 31：如何原地求下一个排列？

**常见问法**

- Leetcode 31，没有让手撕，讲思路和时间复杂度。

#### 面试回答

下一个排列＝字典序中恰好更大的排列，不存在时回绕成最小排列。三步：从右往左找第一个升序相邻对 a[i] < a[i+1]，i 称为枢轴，i 右侧是降序后缀，已是该前缀下的最大排列；找不到枢轴说明整体降序，直接全局反转；从右往左找第一个大于 a[i] 的数与 a[i] 交换；最后把 i 之后的后缀反转成升序。时间 O(n)，至多两遍扫描加一次反转，原地 O(1) 空间。口述要点是讲清不变量：交换前后后缀保持降序，所以“从右找第一个大于枢轴的数”就是后缀中比枢轴大的最小值，反转尾部是让后缀最小。

#### 技术细节

```java
void nextPermutation(int[] a) {
    int i = a.length - 2;
    while (i >= 0 && a[i] >= a[i + 1]) i--;          // 找枢轴
    if (i >= 0) {
        int j = a.length - 1;
        while (a[j] <= a[i]) j--;                    // 后缀中 >a[i] 的最小值
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }
    reverse(a, i + 1);                               // 后缀转升序（i=-1 时即全局反转）
}
void reverse(int[] a, int l) {
    for (int r = a.length - 1; l < r; l++, r--) {
        int t = a[l]; a[l] = a[r]; a[r] = t;
    }
}
```

- 例子走一遍：`1 5 8 4 7 6 5 3 1` → 枢轴 i=3（4<7），j 找到 5，交换得 `1 5 8 5 7 6 4 3 1`，反转后缀得 `1 5 8 5 1 3 4 6 7`。
- 有重复元素时比较用 `>=`／`<=`（非严格），否则会跳过相等值导致结果错误；这是本题最常见的边界坑。
- 第二个查找可在降序后缀上二分（找“大于 a[i] 的最大下标”），但整题复杂度仍是 O(n)，反转是瓶颈之外的常数，面试不值得为此牺牲可读性。

#### 深挖追问

1. **为什么交换后后缀仍保持降序？**（补充练习）

   交换对象 j 是后缀中大于枢轴的最小值，a[j-1] ≥ 原 a[i]（否则 j-1 才是可交换的更大值……实际由“从右第一个大于”保证 a[j-1] > a[j] 且 a[j-1] ≥ a[i]），把原 a[i] 放进 j 位后与两侧仍满足不升；原 a[j] 放到 i 位不影响后缀内部序。所以后缀只需一次反转即成全局最小。

2. **如果是上一个排列呢？**（补充练习）

   对称操作：找第一个降序相邻对 a[i] > a[i+1]，与左侧“小于 a[i] 的最大值”交换，再把后缀反转成降序。

### ALG-025：如何用异或找出只出现一次的数？

**常见问法**

- 有一堆数，有一个数出现了一次，其他的数都出现了两次，怎么才能快速地找出这个出现一次的数？

#### 面试回答

全体异或一遍。异或满足交换律、结合律，且 x^x=0、x^0=x，出现两次的数两两抵消，最终留下的就是只出现一次的数。时间 O(n)、空间 O(1)，不需要哈希表计数也不需要排序。前提假设要主动说出：恰有一个落单、其余都是两次；条件变化方法随之变化（三次、两个落单见追问）。

#### 技术细节

```java
int singleNumber(int[] nums) {
    int r = 0;
    for (int x : nums) r ^= x;
    return r;
}
```

- 适用域：整数按位异或即可，对负数与补码表示同样成立（逐位抵消与符号无关）。
- 对比口径：哈希计数 O(n) 时间但 O(n) 空间；排序后两两比较 O(n log n) 且修改输入——面试说“异或赢在线性时间加常数空间”。
- 该技巧依赖“配对”这一代数结构，元素出现次数不满足可抵消条件（如 3 次）时，要换成按位统计后对次数取模。

#### 深挖追问

1. **其余数出现三次、一个出现一次怎么办？**（补充练习；与 [[面经/帆软/二面/0002#Q12：一堆数中只有一个出现一次、其余都出现两次，如何快速找出它？|MJ035 · 帆软 · 二面 · Q12]] 同场的变体问法）

   按位统计：对 32 个位分别累加所有数该位为 1 的次数，对 3 取模，余数即答案的该位；O(32n) 时间 O(1) 空间。进阶是 ones／twos 双掩码状态机：`ones = (ones ^ x) & ~twos; twos = (twos ^ x) & ~ones;`，用两个变量记录每位“模 3”状态，一趟完成。

2. **有两个数各出现一次，其余两次，怎么找？**（补充练习）

   全体异或得 a^b；取任一为 1 的位（`v & -v`）说明 a、b 在该位不同，按该位把数组分成两组分别异或，两组结果即 a 和 b。

3. **为什么异或对负数也成立？**（补充练习）

   异或是逐位操作，Java 的 int 以补码存储，配对的两个负数按位全部抵消，与符号位无关。

### ALG-026：取值范围远小于数据量时如何给海量数据排序？

**常见问法**

- 对 2 亿个数据进行排序，取值范围是 1 万到 2 万之间，怎么实现？

#### 面试回答

计数排序：值域只有约 1 万种时，开长度 10001 的计数数组，流式扫一遍输入，每来一个数 count[x-10000]++；再按值域从小到大扫描计数数组，每个值重复输出对应次数。时间 O(n+k)（k=10001），约两趟；额外空间只有几千个计数器，2 亿数据本身不需要全部进内存，瓶颈是顺序 I/O。对比说明选型理由：n log n 内存排序放不下 2 亿条数据；位图只能表达“存在与否”会丢重复次数，要保频次就用计数数组。

#### 技术细节

```java
// 输入以 int 流（文件或迭代器）给出，值域 [10_000, 20_000]
long[] cnt = new long[10_001];            // 2 亿 > int？计数上限 2e8 < 2^31，int 也够；留余量用 long
while (stream.hasNext()) cnt[stream.nextInt() - 10_000]++;
for (int v = 0; v <= 10_000; v++)
    for (long c = cnt[v]; c > 0; c--) out.writeInt(v + 10_000);
```

- 稳定性：计数排序天然稳定（按前缀和定位时），本场景输出只有值没有附加信息，稳定性无关紧要。
- 内存感受：即使 n=2 亿全进内存也才约 800MB（每个 int 4 字节），面试官给“取值范围极小”的条件就是指向 O(n+k) 的计数法，别答成外部排序起步。
- 值域稍大（如上亿种取值但 n 仍 2 亿）时计数数组放不下：退到分块外部排序，或若允许丢失重复次数用位图。

#### 深挖追问

1. **和基数排序、桶排序什么关系？**（补充练习）

   计数排序是“桶＝每个取值一个”的极限情形；值域连续均匀时桶排序分 √n 量级的桶、桶内再排，是它的折中；基数排序按位分趟使用计数排序作稳定子过程。

2. **数据从磁盘来，怎么减少 I/O？**（补充练习）

   计数阶段只需一次顺序读，输出阶段顺序写，天然最优；若还要“排序后原样带附属记录”，改成两遍——第一遍只读 key 计数得值域边界，第二遍按值域分桶把记录写到 10001 个追加文件，再一次顺序读出，仍是 O(n) 趟数。

### ALG-027：如何用位图对已知值域的数据去重排序？

**常见问法**

- 对取值范围 0 到 1000 的数组去重并按顺序打印。
- 如何节约内存？
- 取值范围扩大到 0 到 10 亿且内存放不下全部数据，如何实现？
- 能否用压缩方式直接在内存处理？

#### 面试回答

值域已知且远小于数据量时用位图：0—1000 只需 1001 个 bit，约 126 字节的 long[]。第一趟把每个数 x 置位 `bits[x>>6] |= 1L << (x&63)`，重复置位无副作用即去重；第二趟从低位到高位扫描为 1 的位，按位下标顺序打印，即“去重＋排序”一步完成。时间 O(n + 值域)，空间与 n 无关只与值域有关。内存再省的口子在结构本身：布尔数组每元素 1 字节，位图压成 1 bit 已省 8 倍；数据稀疏时进一步按字分块压缩存储；值域大到位图也放不下时按段分趟扫描用 k 遍 I/O 换内存 1/k，或退回分块外部排序。

#### 技术细节

基础位图与按字压缩位图（编程珠玑式 word bitmap，稀疏时全 0／全 1 字不存 64 位原值）：

```java
class CompressedBitmap {                       // 值域 [0, nWords*64)
    static final int EMPTY = 0, FULL = 1, OTHERS = 2;
    final byte[] type; final long[] word;      // word 仅 OTHERS 使用
    CompressedBitmap(int bits) { type = new byte[(bits + 63) >>> 6];
                                 word = new long[type.length]; }
    void set(int i) {
        int w = i >>> 6;
        switch (type[w]) {
            case EMPTY: type[w] = OTHERS;              // 分块惰性分配
            default:    word[w] |= 1L << (i & 63);
        }
    }
    void clear(int i) {                              // 删除：FULL 要先展开
        int w = i >>> 6; long mask = ~(1L << (i & 63));
        if (type[w] == FULL) { word[w] = mask; type[w] = OTHERS; }
        else if (type[w] == OTHERS) {
            word[w] &= mask;
            if (word[w] == -1L) type[w] = FULL;
            else if (word[w] == 0)  type[w] = EMPTY;  // 回收：字归零可不释放，视实现
        }
    }
    boolean get(int i) {
        int w = i >>> 6;
        if (type[w] == EMPTY) return false;
        if (type[w] == FULL)  return true;
        return (word[w] & (1L << (i & 63))) != 0;
    }
    void printAll() {                              // 顺序输出：去重排序的“排序”侧
        for (int w = 0; w < type.length; w++) {
            if (type[w] == EMPTY) continue;        // 全 0 字整块跳过
            if (type[w] == FULL) { for (int b = 0; b < 64; b++) emit(w*64 + b); continue; }
            long x = word[w];
            while (x != 0) { int b = Long.numberOfTrailingZeros(x); emit(w*64 + b); x &= x - 1; }
        }
    }
}
```

- 普通位图 Java 直接用 `java.util.BitSet`（自动扩容的压缩词结构）；C++ 用 `vector<bool>` 或手写 `uint64_t[]`。
- 0—10 亿量级：完整位图 10^9 bit ≈ 119 MB——其实多数现代机器放得下；面试说“放不下”时给两把钥匙：分趟（第 t 趟只统计区间 [t·M, (t+1)·M) 的数，位图大小 M，扫输入 k 次）与压缩位图（稀疏数据实际字数远小于总字数）。
- 位图表达“存在性”，天然去重但丢重复次数；要频次就升级成计数数组（见 [[#ALG-026：取值范围远小于数据量时如何给海量数据排序？|ALG-026：取值范围远小于数据量时如何排序]]）。
- 与布隆过滤器的区别：位图存精确存在性、无假阳性，值域必须小且已知；布隆用极小空间换“可能有假阳性”的判断，见 [[专题题库/Redis#REDIS-002：缓存穿透是什么，布隆过滤器能完全解决吗？|REDIS-002：布隆过滤器]]。

#### 深挖追问

1. **如何节约内存？**（面经实际出现；[[面经/帆软/三面/0002#Q02：0 到 1000 的数组去重并按序打印：位图及其内存优化与超范围扩展（含四个追问）。|MJ035 · 帆软 · 三面 · Q02]]）

   位图本身即答案的第一层：从“每元素 1 字节”压到“每元素 1 bit”；第二层是按字类型压缩（EMPTY／FULL／OTHERS），稀疏时全 0 字不占存储；再往下可差值编码＋变长整数，但都会牺牲 O(1) 置位能力，面试给到字级压缩即可。

2. **值域扩到 0—10 亿、内存存不下怎么办？**（面经实际出现；同上来源）

   分趟扫描：值域切 k 段，每段单独建位图，每趟全文扫一遍只处理本段的数，用 k 遍顺序 I/O 换内存 1/k；若允许非精确去重可换布隆过滤器；若是通用排序需求则分块外部排序。10 亿 bit≈119MB 的量级感受要能当场报出来，先判断“真放不下”还是“可以硬扛”。

3. **压缩后能直接在内存处理吗？**（面经实际出现；同上来源）

   能，前提是数据稀疏（实际写入的远离散，全 0 字占比高）：压缩位图只存非空字，内存占用从值域线性变成与元素数线性相关，置位、判存、顺序打印都能在压缩结构上做，全 1 字还能整块跳读加速。

4. **写出压缩部分的主要逻辑。**（面经实际出现，要求现场编码；同上来源）

   见上方技术细节代码：核心是 type 数组惰性分派＋set／clear 的三类型状态转换（EMPTY→OTHERS、FULL→OTHERS 展开、OTHERS→EMPTY／FULL 回收），printAll 按类型分支顺序输出。

### ALG-028：如何在 0 到 N 中找出缺失的那个数？

**常见问法**

- 给定长度为 N 的数组，取值范围为 0 到 N（本应有 N+1 个数但缺失一个），如何找到缺失数字？如 [0,1,3,4,5,6]，缺失 2。

#### 面试回答

O(n) 时间 O(1) 空间两法。异或法：0^1^…^N 再依次异或数组每个元素，成对抵消后剩缺失值，无溢出顾虑。求和法：期望和 N(N+1)/2 减去实际和即差值，但必须主动声明用 long——N 到 10^5 量级 int 就会溢出，这是本题最常见的追问埋点。若数组不可修改、只能读一遍，两法都满足；若允许 O(N) 额外空间，布尔标记数组最直观，作为对照提一句。

#### 技术细节

```java
int missing(int[] a) {                 // 数组长度 N，值域 0..N 缺一个
    int x = 0;
    for (int i = 0; i < a.length; i++) x ^= i ^ a[i];
    return x ^ a.length;               // 再异或 N 本身
}
```

- 循环内同时异或下标与元素，下标走 0..N-1，最后补异或 N，等价于“0..N 全体异或数组全体”。
- 求和版：`long miss = (long) n * (n + 1) / 2 - sum;`
- 与 [[#ALG-025：如何用异或找出只出现一次的数？|ALG-025：异或找只出现一次的数]] 同族：都靠“配对抵消”，这里把 0..N 的完整序列当作“影子数组”与残缺数组配对。

#### 深挖追问

1. **缺了两个数怎么办？**（补充练习）

   全集与数组整体异或得 a^b；取结果中任一为 1 的位作分组键，把 0..N 和数组元素各自按该位分成两组，组内分别异或，两个非零组结果即两个缺值。若改用求和，需 S1、S2 两个方程（和与平方和）联立，有溢出风险。

2. **取值范围变成 0..M（M>N-1 的稀疏情形）还能这么做吗？**（补充练习）

   异或／求和依赖“值域大小与数组长度耦合”的结构；M 远大于 N 时元素不再一一对应，退回哈希集合或排序后线性扫描，或值域可容纳时用位图标记（见 [[#ALG-027：如何用位图对已知值域的数据去重排序？|ALG-027：位图]]）。

### ALG-029：如何求最大子数组乘积（LeetCode 152）？

**常见问法**

- 手撕：最大子数组乘积（LeetCode 152）。

#### 面试回答

与最大子数组和（LC 53）的分岔点在负数：当前乘积是一个很小的负数时，再乘一个负数可能翻身成为最大，所以“以 i 结尾的最大乘积”不只由前一个最大值转移来。解法是同时维护以当前元素结尾的最大积 mx 与最小积 mn，每步对 `x`、`mx*x`、`mn*x` 三者取最大／最小——要么续接前面的子数组，要么从 x 重开；全局答案取历史 mx 最大。乘法遇 0 归零，0 天然充当断点。时间 O(n)、空间 O(1)。初始化用 a[0] 而不是 0：全负数组（如 `[-3]`）正确答案是最大负数，初值 0 会错。

#### 技术细节

```java
int maxProduct(int[] a) {
    int mx = a[0], mn = a[0], ans = a[0];
    for (int i = 1; i < a.length; i++) {
        int x = a[i];
        if (x < 0) { int t = mx; mx = mn; mn = t; }   // 乘负号翻转，先交换再乘
        mx = Math.max(mx * x, x);                      // 续接 or 重开
        mn = Math.min(mn * x, x);
        ans = Math.max(ans, mx);
    }
    return ans;
}
```

- 不用交换的等价写法：`int p = mx*x, q = mn*x; mx = max(x, max(p, q)); mn = min(x, min(p, q));`，先存旧值避免用更新后的 mx 推 mn。
- 验证用例：`[-2,3,-4]` → 24（整段相乘）；`[2,-5,-2,-1,3]` → 20（子数组 `[2,-5,-2]`）；`[0,2]` → 2（0 处重开）；`[-2]` → -2（单元素负数）。
- 溢出：题目约束 int 数组下连续乘可能越界（如大量 -1 与 2 交替），LC 官方数据在 int 内安全，口述时主动提“生产实现换 long 或按约束设防”即可。

#### 深挖追问

1. **为什么不能只维护一个最大值？**（补充练习）

   反例 `[-2, -3]`：走到 -2 时最大结尾积是 -2、最小也是 -2；到 -3，(-2)·(-3)=6 恰恰由“最小值 × 当前负数”产生。最大值序列在负数处不闭合，最小值序列携带了翻身信息。

2. **和 LC 53 最大子数组和、ALG-015 改编题的迁移关系？**（补充练习；见 [[#ALG-015：“求剩余空间最小值”这类最大子数组和改编题怎么做？|ALG-015：最大子数组和改编]]）

   同为“以 i 结尾”的 Kadane 型 DP，状态从 1 个（最大和）变 2 个（最大积＋最小积），转移由 max 换成 max/min 双开口；这族题的通式是“先定义以 i 结尾的状态，再判断转移是否需要重开”，乘法和负数只是让状态需要成对出现。

### ALG-030：如何做字符串相加（LeetCode 415）？

**常见问法**

- 手撕 LeetCode 415（字符串相加）。

#### 面试回答

题意：两个非负整数字符串，不用内置大整数，模拟竖式加法返回结果字符串。双指针从两串末尾起，每轮 `d1+d2+carry`，本位 `sum%10` 追加到 StringBuilder，进位 `sum/10`；两指针都耗尽且无进位才停——循环条件写成 `i>=0 || j>=0 || carry>0` 就不用在循环外补最高位进位。逆序拼接最后 `reverse()`。时间 O(max(m,n))，空间 O(max(m,n))。口述时主动报坑：char 转数值必须 `c-'0'`，直接把 char 相加得到 ASCII 和；`"0"+"0"` 返回 `"0"`（题目约定无多余前导零，不需要额外裁剪逻辑）；最长结果可能比长串还多一位（999+1），空间预留 max+1。写完用 `["999","1"]→"1000"` 与 `["0","0"]→"0"` 走一遍。

#### 技术细节

```java
String addStrings(String a, String b) {
    StringBuilder sb = new StringBuilder();
    int i = a.length() - 1, j = b.length() - 1, carry = 0;
    while (i >= 0 || j >= 0 || carry > 0) {
        int d1 = i >= 0 ? a.charAt(i--) - '0' : 0;
        int d2 = j >= 0 ? b.charAt(j--) - '0' : 0;
        int sum = d1 + d2 + carry;
        sb.append(sum % 10);
        carry = sum / 10;
    }
    return sb.reverse().toString();
}
```

- 同族迁移：这道题与字符串相乘（LC 43）、链表相加（LC 2）、二进制求和（LC 67）共用“逐位对齐＋进位”骨架，差别只在结果落位方式（链表节点／数组下标／字符串追加）——会一道就要能现场推其余。
- 变体风险：若输入可能有前导零或空串，先归一化；本题按 LC 约束（非负、无前导零）处理，答题前把假设说出口。

#### 深挖追问

1. **为什么进位要放进循环条件而不是循环后补？**（补充练习）

   放条件里循环自然处理“全零但 carry=1”的尾轮，少一段收尾代码也少一个漏判；两种写法都对，面试要的是边界说清。

2. **两串都 10^5 位，还能优化什么？**（补充练习）

   复杂度已是下限（每位至少看一次）；工程上预分配 `capacity = max+1` 避免 StringBuilder 扩容拷贝，其余是常数优化。

### ALG-031：如何求多个矩形的重叠总面积（扫描线）？

**常见问法**

- 如果拓展到二维，计算所有矩阵重叠的总面积该怎么做？
- 手撕：重叠区间的总长度（一维铺垫）。

#### 面试回答

先确认口径再动手：“重叠的总面积”有两种读法——① 所有矩形覆盖到的总面积（并集面积），这是扫描线经典题；② 被矩形们公共覆盖的面积（交集面积），那只是依次求交集，相交部分仍是矩形，逐步收缩边界最后算面积，复杂度 O(n)。两种答案差很多，别默认。以下按并集作答，并顺带说清一维铺垫。

一维版本：求区间并集总长度，按左端点排序后线性扫描，维护当前段 `[start, end]`——新区间左端点大于 `end` 就结算上一段并另起，否则把 `end` 扩到 `max(end, 右端)`，最后再结算一次；O(n log n)。若问“被两个及以上区间覆盖的长度”，把每个区间拆成 `(左, +1)`、`(右, -1)` 事件排序扫描，累计覆盖计数≥2 的跨度（阈值换成 n 就是全部区间的公共重叠）。

二维并集（扫描线）：把每个矩形拆成左边界“加入区间”、右边界“移除区间”两类 x 事件并按 x 排序；扫描时维护当前有效的 y 区间集合，每处理一个事件就把“上一个 x 跨度 × 当前 y 覆盖总长度”累加进答案，核心是把二维面积降成一维覆盖长度。当前 y 覆盖长度的维护有两档：每次对 y 区间排序合并，实现简单、不易写错，O(n² log n)；把 y 坐标离散化后用线段树维护“覆盖计数＋被覆盖长度”，整体 O(n log n)。面试里先给朴素版并说清瓶颈，再给线段树版，比直接上来写线段树更容易讲明白。

#### 技术细节

线段树版本的要点：节点存 `count`（被完整覆盖的次数）与 `len`（该区间内被覆盖的长度）；`count > 0` 时 `len` 直接等于该节点的实际坐标跨度，否则等于左右孩子 `len` 之和（叶子为 0）——因为坐标是离散化后的点，跨度要用原坐标差而不是下标差，且相邻离散点之间的“段”才是更新单位，通常把区间端点减一处理半开段。加与删是同一函数带符号 delta，不做懒 propagated 的常规写法而依赖 `count` 语义，是该题的标准结构。

边界与易错点：端点相接是否算重叠（半开处理最省事，面积上不影响并集结果，但“公共重叠”口径会影响）；重复矩形、完全包含、只共边、坐标为负与坐标范围极大（需要离散化，否则数组开不下）；面积累加用 long 防溢出；事件同 x 上“先处理后一个加入”会导致多算，稳妥做法是把同一 x 的所有事件一起处理，算一次 y 覆盖长度再推进 x 跨度。

复杂度与取舍：n 个矩形并集面积 O(n log n)（线段树）或 O(n² log n)（排序合并）；朴素“逐格统计”只在坐标范围小时可行（网格＋计数，类似 [[#ALG-027：如何用位图对已知值域的数据去重排序？|ALG-027：位图]] 的值域思路）；若题目是 n 维推广，扫描线递归嵌套（分治）会显著变难，面试里点到“可用 k-d tree／区间树但代价高”即可，别硬编。

#### 深挖追问

1. **为什么不能简单两两求交集再相加？**（面经实际出现；[[面经/阿里云/三面/0001#Q03：手撕重叠区间的总长度；拓展到二维计算所有矩阵重叠的总面积（自评：答的一般）。|MJ039 · 阿里云 · 三面 · Q03]]）

   会重复计算：三个矩形两两相交于同一块时，成对交集相加重叠部分被算了多次；要按容斥原理做就是 2ⁿ 项，指数级。扫描线的正确性来自“沿 x 推进时把已覆盖区域切成不重叠的竖条”，每条只算一次。

2. **n 很大、坐标范围也很大时，内存怎么省？**（补充练习）

   离散化只保存出现过的坐标（O(n) 个）；再按 x 分块或外部排序分治处理，把同时活跃的矩形数控制住；纯位图网格在坐标跨度大时不可行。

3. **一维“覆盖≥2 的长度”用差分不是更简单吗？**（补充练习）

   值域小时可以：差分数组前缀和即可，O(值域)；值域大就退化成事件扫描（等价于稀疏差分），复杂度只跟区间数走——先问坐标范围再选实现。

### ALG-032：如何删除链表中所有重复元素（LeetCode 82）？

**常见问法**

- 手撕：删除链表中的所有重复元素。
- 链表里重复的节点全部删掉，一个都不留，怎么写？

#### 面试回答

先确认三件事：链表是否有序、“重复值全删”还是“保留第一个”（LeetCode 82 与 83 的区别）、能否用额外空间。全删且有序的解法：建哨兵节点指向头，游标 `prev` 始终停在“最后一个已确认保留的节点”上；观察 `prev.next` 起的同值段——若连续出现两个及以上相同值，就把整段跳过、让 `prev.next` 指向段后第一个不同值节点（不移动 `prev`，因为新来的段也可能重复），否则 `prev` 前进一步。返回 `dummy.next`：头节点本身可能被删，用哨兵就不用特判。时间 O(n)、空间 O(1)。若题目只要求重复值保留一个（83），只需逐个跳过相同值，不需要“整段”概念。若链表无序且要求所有同值都删除：先扫一遍用哈希表统计每个值的出现次数，再第二遍按计数决定保留或摘除，多 O(n) 空间换掉“必须有序”的前提。

#### 技术细节

```java
public ListNode deleteDuplicates(ListNode head) {
    ListNode dummy = new ListNode(0, head);
    ListNode prev = dummy;
    while (prev.next != null) {
        ListNode cur = prev.next;
        if (cur.next != null && cur.val == cur.next.val) {
            int v = cur.val;
            while (cur != null && cur.val == v) cur = cur.next; // 整段跳过
            prev.next = cur;                                    // 不移动 prev
        } else {
            prev = cur;
        }
    }
    return dummy.next;
}
```

三个易错点：① 判定相同后要一路跳到值不同的节点，中途 `cur` 可能为 null（末尾整段重复）；② 跳段后不能立刻 `prev = cur`，因为接上来的段也可能是重复段；③ 返回 `dummy.next` 而不是 `head`。用例覆盖：`[1,1,1,2,3]`→`2→3`、`[1,2,3,3,4,4,5]`→`1→2→5`、全部同值→空、单节点、空表、`[1,1]`（整表被删）。无序＋要全删的哈希计数版：第一遍 `merge` 计数，第二遍用同一哨兵把 `count>1` 的节点摘掉，被跳过的节点不必手动释放（Java 无手动内存管理；若用 C++ 要 `delete` 被摘节点，注意不要访问已释放内存）。

#### 深挖追问

1. **为什么不能用双指针“看一眼下一个就删”？**（补充练习）

   删除当前节点需要它的前驱，单链表拿不到；用 `prev` 停在已确认保留节点上，等于给每个待删段留了一个可回退的锚点，这也是哨兵存在的理由。

2. **有序链表能不能不用哨兵？**（补充练习）

   可以，但要先处理“头部整段重复”：先推进 head 到第一个不重复节点，再从它开始维护前驱。哨兵把这个特判消掉，写起来更短也更不容易错，面试里通常推荐哨兵。

3. **如果要求保留一个且不修改相对顺序，能否 O(1) 空间？**（面经实际出现；[[面经/阿里云/二面/0001#Q05：手撕：删除链表中的所有重复元素。|MJ039 · 阿里云 · 二面 · Q05]] 的延伸）

   有序时 O(1) 空间直接单趟跳过重复即可（83）；无序时“判断是否首次出现”需要记已见值，O(1) 空间就要先排序（改变顺序、O(n log n)）或接受平方级比较——用空间换时间还是换顺序，取决于题目允许哪个。

### ALG-033：如何解八皇后／N 皇后问题，时间复杂度是多少？

**常见问法**

- 手撕：八皇后问题。
- 八皇后的算法时间复杂度是多少？
- 求 N 皇后的所有解，怎么剪枝？

#### 面试回答

按行递归是最好写也最好讲的形式：`dfs(row)` 时枚举每一列 `col`，判断这个位置是否已被前面的皇后攻击——同一列、同一斜线。三条约束各用一个布尔数组标记就能 O(1) 判定：列用 `col`，一条对角线上 `row - col` 为常数（值域 `-(n-1)~n-1`，加 `n-1` 偏移作下标），另一条对角线上 `row + col` 为常数（值域 `0~2n-2`）。放置时把三个标记置 true、记录 `queen[row] = col`，递归 `row+1`，返回后清标记完成回溯；`row == n` 时收集一个解。输出方案按题目要求给字符矩阵或列下标数组，别自己混用。自测锚点：`n=4` 有 2 个解、`n=8` 有 92 个解（去掉旋转与镜像对称后是 12 个基本解）。

时间复杂度答 **O(n!)**：逐行放皇后，第一行至多 n 种选择，第二行受列约束至多 n-1，依次递减，上界即 `n!`（每个解的收集与拷贝再乘一层成本）。要能解释这个上界为什么比“每行随便选一列”的 `O(n^n)` 紧：列标记让每行候选数单调减少，斜线标记又进一步剪掉大量分支——所以 `n!` 是最坏分支数的上界，实际访问的节点数明显更少。空间 O(n) 量级（三个标记数组与递归栈，不计输出；要保存全部解则与解数同阶）。

#### 技术细节

判定条件的推导要能现场说：主对角线（左上→右下）上 `row - col` 恒定，副对角线（右上→左下）上 `row + col` 恒定；用偏移 `n-1` 把负下标搬正，是本题最容易写错的一行。若不用标记数组而每次沿三个方向回扫检查，正确但把每层判定变成 O(n)，整体退化到 `O(n·n!)` 级别——被问“为什么用数组”时答的就是这个。

位运算优化是常见第二轮追问：把每行的可用列压成一个整数掩码 `bits`，`avail = ~(cols|diag|antiD) & mask`，取最低可放位 `p = avail & -avail`，递归时 `cols|p`、`(diag|p)<<1`、`(antiD|p)>>1`。它把三个数组的判定与回溯变成整型位操作，常数下降明显（`n=14` 这类枚举能快几倍），复杂度量级不变仍是 `O(n!)`。对称性剪枝：只把第一个皇后限制在前半列，得到的解数乘 2（n 为奇数时中间列再单独处理），适合“只要计数”的变体。

易错清单：忘清标记导致后续行误判冲突；对角线下标未加偏移导致负索引越界；`n=0`／`n=1` 边界；输出格式与题目不一致；以及把“求一个解”与“求所有解”混做——只要求一个解时命中即可短路返回，不必穷举。若题目改问“不同 N 皇后的解数”（LeetCode 51／52 的计数变体），把收集改为计数即可，无需保存棋盘。

#### 深挖追问

1. **为什么复杂度是 n!而不是 2 的 n 平方次方？**（面经实际出现；[[面经/小红书/一面/0001#Q10：手撕八皇后问题；追问：时间复杂度是多少？|MJ040 · 小红书 · 一面 · Q10]]）

   每行必须放且只放一个皇后，因此解空间是“每行选一列”的组合，规模上界 `n×(n-1)×…×1 = n!`；只有在不按行推进、每格独立选放或不放时才是 `2^(n²)` 的暴力空间。回答时说清“约束让分支逐层收缩”即可。

2. **只要求返回一个可行解，怎么改？**（补充练习）

   递归命中 `row == n` 后返回成功标志并逐层短路，不再回溯穷举；也可用最小冲突启发式做局部搜索，但要说明它不保证完备（可能卡在局部极小），面试里首选带回溯的完备解法。

3. **n 很大时（比如求 n=20 的解数）还能怎么做？**（补充练习）

   纯回溯成本爆炸，工程上按位运算＋对称剪枝、按列状态做记忆化或并行分治（不同首列分支相互独立可并行），并说明这类计数问题没有已知的多项式解法，只能优化常数与并行度。

### ALG-034：如何求海量文件中的全局 TopK（内存受限、多核并行）？

**常见问法**

- 100 个文件、每个文件几亿个数字，找全局最大的 1000 个数字，4 核 CPU，怎么做？
- 内存无限和内存有限（如 32G）两种情况分别怎么处理？
- 数据量太大装不进内存，怎么找 TopK？

#### 面试回答

先做量级判断再动手：100 个文件乘以“几亿个数”是千亿级元素，即使内存无限也不可能全部装进内存（千亿个 int 就是数百 GB），所以正确解法本身就是流式的——这与内存是 32G 还是无限其实无关，这个结论要先说出来。

主结构是大小为 K 的最小堆：按行流式读每个文件，对每个数字 x，若堆未满或 `x > 堆顶（当前第 K 大）`就弹出堆顶压入 x，否则丢弃；遍历结束堆内即 TopK。时间 O(N log K)，空间 O(K)。可以按文件先算局部 TopK（每文件一个 1000 元素的堆），最后把 100 个局部结果合并（继续喂同一个全局堆，或做 k 路归并），这样还能天然并行。

并行与性能优化是这题真正的考点：4 核说明瓶颈在 IO 与文本解析，不在比较。做法是生产者—消费者，按文件分片给 4 个（或 2×核数）worker，每个 worker 维护自己的局部 TopK 堆——关键是不要让多线程共享一个堆，锁竞争会把并行收益吃掉；最后单线程合并 100 个小堆。读取侧用固定字节缓冲流式读，避免一次性 `readlines()` 载入整文件；解析用直接整型扫描（避免正则与逐字符切分），这通常能带来数倍吞吐提升。若要极限吞吐还可以按文件内 `seek` 分段并行，但要处理半行边界，收益一般不如按文件分片直观，答题时说清这个取舍即可。

内存受限（32G）时上述方案本来就成立；只有当题意变成“要把全部数字排序”才需要外部排序：分块内排序后多路归并，或用按值域分桶（计数／位图，见 ALG-026、ALG-027）在值域可控时省掉排序。

#### 技术细节

三种 TopK 方案的取舍要能对比：① 大小 K 的最小堆——O(N log K)，空间 O(K)，支持流式、易并行，是最稳的默认；② 快速选择（QuickSelect）——O(N) 平均，但要求数据能全量驻留内存，不适合这题；③ 值域分桶／计数——O(N + V)，当数字范围有限（如 32 位整数可先按高 16 位分桶定位阈值桶，再桶内求 TopK）时比堆更快，且天然适合分布式（每个分片只需上报各桶计数）。若还要求“结果去重”，堆方案要额外配集合或先排序去重，内存要按去重规模重估。

正确性检查点：并列于第 K 名的值要不要全部输出（阈值语义与“恰好 K 个”不同，先问清）；文件可能为空或不足 K 个元素；数字范围是否溢出（用 64 位读入更保险）；解析时是否处理 `+`／负号与换行混杂；最后输出要不要排序（堆里取出是乱序，一般再排一次 O(K log K)）。

工程细节常被追问：并行度为什么按文件分片而不是按行；如何控制内存峰值（缓冲池复用、每 worker 上限）；IO 与 CPU 重叠（预读下一块，异步 IO 或双缓冲）；如果文件在对象存储上，还要考虑按文件并发拉流并限制总带宽；如果任务要跑很多轮，考虑用列式或二进制格式落盘（避免每次都付文本解析成本）。

验证方式要能说出口：构造 3 文件 × 10 个数的已知答案小样例，覆盖“全部小于当前第 K 大”“恰好等于阈值”“空文件”三种情形；线上再比对“单线程实现”与“并行实现”的输出一致性，并给出实测吞吐（GB/s 或每秒行数）而不是只说“更快了”。

#### 深挖追问

1. **为什么不直接 `sort` 全部数据再取前 1000？**（补充练习）

   全量排序是 O(N log N) 且要把数据（或外部分类）搬运多遍，TopK 只需 O(N log K) 且流式一遍过；K 远小于 N 时差距是数量级的。外部排序在只需要 TopK 时纯属浪费。

2. **如果 K 变大到千万级，堆还合适吗？**（面经实际出现；[[面经/字节/二面/0002#Q08：手撕：100 个文件、每个文件含几亿个数字，找出全局最大的 1000 个数字（4 核 CPU，内存无限或有限如 32G）。|MJ042 · 字节 · 二面 · Q08]] 的延伸）

   K 很大时 `log K` 与内存占用都上升，堆仍可用但要换成按值域分桶先定阈值（两遍法：第一遍统计桶计数找出第 K 大所在桶，第二遍收集桶内元素），把内存压到桶规模；这也是分布式的自然做法（每分片上报桶计数再合并）。

3. **多核并行后结果不一致怎么办？**（补充练习）

   多半是共享可变状态没有隔离：每个 worker 只写自己的局部堆、合并阶段单线程做，就消除竞争；如果为了“更早剪枝”而共享一个全局阈值（worker 读到别的分片的当前第 K 大），要注意这只是加速优化，不影响正确性，但读取要允许旧值（原子变量），否则又引入锁。

### ALG-035：如何用给定数字集合拼出不大于 N 的最大数？

**常见问法**

- 手撕：用给定数字（如｛2,4,9｝）组成不大于 N 的最大数字。
- 给一组数字（可重复使用），拼出不超过 N 的最大值，怎么做？
- 如果每个数字只能用一次呢？

#### 面试回答

先确认两个口径：集合里的数字能否重复使用、结果位数能否少于 N 的位数（一般允许，且不允许前导零）。以下按“可重复”作答。

贪心骨架是从最高位开始逐位对齐 N。记 N 的位数组为 `d[0..m-1]`、集合为 `S`、其中最大数字 `mx`。① 从左到右，只要当前位 `d[i]` 属于 `S` 就先照抄（保持与 N 前缀相等的“紧贴”状态）；② 遇到 `d[i]` 不在 `S` 中，就在这一位放 `S` 里小于 `d[i]` 的最大数字——一旦放小，后面所有位一律填 `mx` 即可，得到答案；③ 若这一位没有比 `d[i]` 更小的可选数字，必须回退：往左找一个照抄过的位 `j`，把第 `j` 位换成 `S` 中小于原 `d[j]` 的最大数字，其后全部填 `mx`；④ 回退到第 0 位都无处可改，说明不存在同位数的解，退成 `m-1` 位数全体填 `mx`；特例是 `S` 里没有非零数字时答案为 0。

例：`S={2,4,9}`、`N=427`——4、2 照抄，7 不在集合，取小于 7 的最大者 4，得 424；`N=420`——0 不在集合且没有比 0 更小的数字，回退第 1 位 2 也无可替代，再回退第 0 位 4→2，后面填 9，得 299。复杂度 O(位数)，把“小于 x 的最大数字”预后缀表做到 O(1) 就是线性；空间 O(位数)。

“每个数字只能用一次”的变体不能再简单重复 `mx`：同一贪心骨架，但选位要跳过已用数字，且回退时要恢复已用集合——更稳的写法是记忆化搜索（状态：位置、已用数字掩码、是否仍紧贴 N 前缀），也就是数位 DP 的标准套路，规模很小（`|S|` ≤ 10、位数 ≤ 20）完全可接受。若还要求长度可自由组合，就再加一维“已用个数”。

#### 技术细节

实现要点：把 N 拆成位数组（字符串转换最直观，注意大数场景要按字符串处理避免溢出）；`less(x)` 返回 `S` 中小于 x 的最大元素、`le(x)` 判断 x 是否在 `S` 内，这两个函数写清楚主逻辑就短；回退用栈或从后向前找第一个可降位的下标；填 `mx` 之前要处理前导零（若第 0 位只能填 0，说明位数必须缩短，取 `m-1` 位全 `mx`）。

测试用例要覆盖：`N` 完全可由集合拼出（结果等于 N）、所有位都够不着（退化成短位数）、含 0 与不含 0 的集合、`S={9}` 与 `N=1000`（答案 999）、`N` 位数很大的字符串输入。这些用例跑通，比现场解释复杂度更能证明写对了。

同类变形要能立刻识别：给数字集合求“能被某数整除的最大／最小数”、或“恰好等于 target 的组合”就回到搜索＋剪枝；“字典序最小／最大且不大于 N 的排列”是把可重复换成给定多重集，贪心骨架不变但要按剩余可用计数填后缀。

#### 深挖追问

1. **为什么不能从低位往高位贪心？**（面经实际出现；[[面经/字节/三面/0001#Q02：手撕：用给定数字（如｛2,4,9｝）组成不大于 N 的最大数字。|MJ042 · 字节 · 三面 · Q02]] 的延伸）

   因为“不大于 N”这个约束是由高位决定的，低位的选择不会影响高位能否变大；从低位贪心会出现高位已超 N 而后缀最优也无效的情况。所以必须高位起、维持“是否已经严格小于”的状态，这本质就是数位 DP 的状态定义。

2. **集合里没有比某位更小的数字时，除了回退还有别的办法吗？**（补充练习）

   等价做法是一次性枚举“第一个变小的位置”：对每个位置 i，要求前缀 `0..i-1` 全部与 N 相同且这些位都在 `S` 中，第 i 位取小于 `d[i]` 的最大可用数字，后缀填 `mx`，取所有可行 i 里数值最大的那个（再加“整条同位数都等于 N”与“缩短位数”两种边界）。这个视角写出来代码更少分支，也更不容易在回退时改错。

3. **怎么扩展到多个数字串拼接（每个数字只能用一次且必须全用）？**（补充练习）

   那是全排列约束下的最优化：位数固定，按位从大到小尝试未使用数字并检查是否可能不超过 N（前缀已经更小则剩余自由按降序排），否则剪枝；仍是不大于 N 的贪心骨架，只是“填后缀”要改成对剩余数字排序。
