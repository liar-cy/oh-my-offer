### CAREER-001：为什么没有继续实习或选择实习转正？

**常见问法**

- 为什么没有选择继续实习、实习转正？

- 为什么转部门，是否拿到转正，为什么还考虑这个部门？

#### 面试回答

回答框架：我在这段实习中主要负责【真实职责】，收获了【能力或经验】。没有继续实习／转正的主要原因是【真实原因，如学业安排、岗位方向或招聘安排】，目前希望寻找更匹配【目标方向】的长期岗位。关于是否有转正机会，我会如实说明【实际情况】，不把主动离开和未获得名额混为一谈。

#### 技术细节

按“事实—决定—当前目标”组织。先分清是没有继续实习、没有申请转正，还是没有获得转正机会；这些并非同一件事。只解释与求职有关的背景，不将团队评价或个人猜测当事实。用实际工作成果说明投入程度，但指标必须能解释来源。原材料未给出个人原因，因此本题保留框架，不能生成确定的个人故事。

部门转换与求职选择：先如实说明【当前是否取得转正及确认方式】，解释【转部门原因】与【目标岗位职责的匹配点】。有转正机会仍考虑其他部门并不矛盾，但理由要基于真实方向、工作内容和客观安排，不臆测原团队问题。

#### 深挖追问

1. **如果有转正机会你会接受吗？**（补充练习）

   结合岗位职责、成长方向及客观安排给出真实判断，并解释与当前求职选择是否一致。

2. **你在实习中最大的收获是什么？**（补充练习）

   挑一个亲自负责的改进，说明问题、行动、验证结果，不只列使用过的技术。

3. **为什么转部门，拿到转正后还考虑这个部门？**（面经实际出现；[[面经/百度/三面/0001#Q12：为什么转部门，是否拿到转正，为什么还考虑这个部门？|MJ010 · 百度 · 三面 · Q12]]）

   交代真实转正状态及选择原因，再用岗位职责与长期方向解释动机，不预设已拿到转正。

### CAREER-002：如何介绍项目、个人职责与遇到的难题？

**常见问法**

- [[面经/美团/一面/0002#Q01：项目是学习项目还是实际部署的项目？|MJ032 · 美团 · 一面 · Q01]]
- 选一个项目介绍一下。
- 在项目中负责什么？
- 项目中有没有遇到什么问题？

- 介绍实习经历。
- 先介绍一下上一段的实习。
- 实习的 Agent 项目做了哪些工作？
- 介绍一下你的 Agent 项目。
- 你最大的难题是什么，怎么提高效果、怎么降低延迟？
- 为什么做这个项目？
- 介绍实习与项目、具体工作，以及 OpenManus 在其中的职责。
- 实习里开发一个 Skill 的流程是什么，遇到了哪些问题？
- 对于这个开源项目，你自己做了哪些升级改进？
- 有没有用 AI 落地做过实际的项目，怎么做的？
- 在原部门主要做了什么？
- 讲一下第二个项目从用户输入到输出的完整链路。
- 从达人接受发布任务开始，系统链路是怎么走的？
- 当前系统还有什么没有完成？

- 拷打实验室项目（整段自我介绍式深挖）。
- 做过的项目里遇到的核心挑战有哪些，如何解决的？这个项目的核心目标是什么、具体场景是啥？

- 拷打实习（约 20 分钟），以及各种引申。
- 实习项目的背景与价值、系统架构与具体流程、方案设计与效果评估。
- 拷打项目和实验室研究（约 15 分钟）。

- Agent 项目是实习项目还是个人项目，有没有上线？

#### 面试回答

回答框架：这个项目为【用户】解决【问题】，核心链路是【输入—处理—输出】。我负责【明确模块】，与团队其他成员的边界是【分工】。最难的问题是【真实问题】，我用【排查证据】定位原因，比较【备选方案】后采取【方案】，最终通过【测试或指标】验证效果。没有测过的提升幅度不报数字。

#### 技术细节

项目介绍先覆盖业务目标、系统边界、关键数据流与个人贡献，再展开一项难点。难点回答要说明为什么难、如何定位、为何选择该方案及代价。知识库项目可从解析质量、检索效果、权限或延迟中选择真实经历，不能默认这些能力都已实现。用离线评测或上线指标区分“能跑通”与“有效果”；团队成果应注明本人参与程度。

项目动机与组件职责可按【原业务痛点／为何值得做】→【目标与备选方案】→【本人实现】→【验证结果】说明。对被隐去的公司或部门不补猜；OpenManus 在某项目中的实际职责要结合真实集成、改动代码与边界说明，不能仅凭框架名字推断其承担规划、浏览器或执行模块。

说业务链路时，用状态流串起触发、校验、同步／异步处理、外部回调、落库和通知，对每步补充幂等、重试与补偿。介绍未完成项时，说明已完成边界、未完成内容、影响、当前缓解方案、下一个里程碑和验收指标，不要把规划写成已上线功能。

#### 深挖追问

1. **为什么不是团队其他人解决的？**（补充练习）

   说明自己负责的接口、代码或实验，以及协作部分，不贬低同事。

2. **如果重做一次会改什么？**（补充练习）

   指出已观察到的限制，给出与数据规模和资源约束相称的改进。

3. **为什么做这个项目，框架在实习里具体负责什么？**（面经实际出现；[[面经/百度/一面/0006#Q09：为什么做这个项目？|MJ010 · 百度 · 一面 · Q09]]；[[面经/百度/二面/0002#Q01：介绍实习与项目、具体工作，以及 OpenManus 在其中的职责。|MJ010 · 百度 · 二面 · Q01]]）

   填写实际需求来源、本人分工、框架接入点与可核实结果；没有材料时保留框架。

4. **怎么介绍尚未完成的系统内容？**（面经实际出现；[[面经/字节/一面/0003#Q11：当前系统还有哪些未完成的内容？|MJ013 · 字节 · 一面 · Q11]]）

   如实划分已上线、部分完成和规划中的能力，说明未完成原因、影响、临时边界、计划和可验收的完成标准。

5. **自己的项目和学校课程作业有什么区别，考虑了什么？**（面经实际出现；[[面经/传音控股/一面/0001#Q06：自己的项目和学校课程作业有什么区别，考虑了什么？|MJ029 · 传音控股 · 一面 · Q06]]）

   按真实经历选点：需求形态（作业题目给定且稳定 vs 真实需求模糊、会变更、要与人对齐）、验收标准（demo 能跑 vs 上线的稳定性/性能/成本/体验）、工程约束（协作、测试、发布回滚、监控、数据规模与异常分支）、权衡意识（方案选型要能讲清代价）。用【真实取舍案例】落地，泛泛而谈会露馅。

### CAREER-006：如何说明 Agent 方向与工程能力并重的职业规划？

**常见问法**

- 未来的职业规划是什么？

- 未来职业规划，想走专家还是管理路线？

- 你对自己未来的职业发展有什么倾向或想法？

#### 面试回答

保留候选人实际回答：在做好 Agent 的同时精进工程技术。展开框架：短期在【真实业务】中持续改善 Agent 的【可验证效果】，同时补齐【后端基础与工程短板】；通过【具体项目实践与验收方式】检验进步，逐步承担从功能实现到稳定运行的完整责任。时间安排和目标须按真实意愿填写。

非 Agent 方向（如纯后端）通用版：短期把 ______（后端工程能力，如并发、存储、服务治理）在具体业务里做扎实、补齐学校项目缺的工程实战；中期在 ______（高并发服务／分布式／某领域）深入，能独立负责一条链路从设计到稳定运行；长期对“专家还是管理”保持开放，但强调当前重心是把技术做深，且与应聘岗位方向匹配。忌空喊口号、忌为迎合虚构承诺。

#### 技术细节

把方向、能力差距和行动对应起来。Agent 侧可选任务成功率、评测与失败分析；工程侧可选网络、并发、存储、测试、可观测性与故障恢复。这里只提供选题方法，不代表候选人已经完成这些实践，也不虚构晋升或成果承诺。

#### 深挖追问

1. **如何让规划有可验证的行动？**（补充练习）

   选择一个实际短板和项目场景，说明计划完成的改动、如何验证以及何时复盘，用真实约束确定节奏。

2. **专家路线还是管理路线怎么选？**（面经实际出现；[[面经/帆软/三面/0001#Q16：你的未来职业规划，想走专家还是管理路线？|MJ024 · 帆软 · 三面 · Q16]]）

   如实回答倾向并给出当前重心：现阶段把【某方向工程深度】做出来，用可验证结果检验；不把两者说成对立——深度到位后自然承担协作与带教，届时按组织需要与个人表现再选。避免“都行”式空话。

3. **平时关注哪些技术博客、学习渠道？**（面经实际出现；[[面经/帆软/三面/0001#Q18：你平时关注哪些技术博客、学习渠道？|MJ024 · 帆软 · 三面 · Q18]]）

   如实列举真实在用的渠道（官方博客/文档、技术社区、论文或开源动态），重点讲“输入→输出”闭环：最近从某渠道学到什么、在哪个项目用上、怎么验证效果；只报名单没有产出会暴露收藏式学习。系统化的学习方法（含大模型方向怎么跟进）以 [[#CAREER-017：被问“平时怎么学习大模型和新技术”怎么答？|CAREER-017]] 为主题维护，本题不重复展开。

4. **“你最近在做的是什么方面，现在主要偏 AI、做一些沉淀是吗？”怎么答？**（面经实际出现；[[面经/美团/一面/0001#Q22：你最近在做的是什么方面？现在主要偏 AI、做一些沉淀是吗？|MJ031 · 美团 · 一面 · Q22]]）

   这类确认方向的追问是在核对“你的重心是否落在岗位需要的方向”，也是纠正简历印象的机会。回答口径：① 直接给当前重心（AI 应用／后端／客户端）与承载它的具体项目或实习模块；② 给可验证产出（已上线功能、评测集、文档、被他人复用的模板或规范），不说“在看资料”；③ 主动解释“沉淀”具体是什么、被谁在什么场景用上；④ 说明下一步补的短板与验证方式，与岗位需求挂上钩。若面试官的判断与实际不符（例如误以为你只偏 AI），当场澄清真实比例，不要顺着标签走。

### CAREER-007：学业规划、就业意向与实习时长问题怎么答？

**常见问法**

- 未来打算直接就业还是读研呢？为什么不选择读研？
- 能实习多久？
- 对工作地是怎么考虑的？

- 如果实习的话最早能什么时候来？持续多久？

#### 面试回答

如实回答并按“决定—原因—安排”组织：我的打算是【直接就业／读研／其他】，依据讲客观安排与目标匹配（希望先在工程实践积累、家庭或时间规划、目标岗位更看重经验），不贬低另一条路线，也不为迎合面试官虚构承诺。实习时长给出明确的【每周天数 × 持续月数】与起止时间，说明学业如何保障投入；与就业意向的回答保持自洽。

工作地点同理：如实报意向城市 ______，理由挂钩通勤、家庭、行业聚集或长期发展等客观因素；有弹性就说明可接受范围（如“base 优先 A，B 也可”），不为过面随意承诺服从调配，保持与就业意向、职业规划（CAREER-006）回答一致。

#### 技术细节

这类问题考察稳定性与投入预期：面试官关心你能干多久、会不会中途返校、转正意愿是否真实。可信度来自一致性——实习时长、城市安排、读研意向几项回答互相矛盾最减分；给出保障机制（课程已修完、导师安排、远程课时间）比单纯承诺“能久干”更有说服力。确实打算考研／保研就如实说明时间线，可表达“若获得实习机会将如何安排”，不冒充无计划的长期投入。个人真实规划需按【实际情况】填写。

#### 深挖追问

1. **想读研但投了实习岗怎么答？**（补充练习）

   说明本次实习的时间边界与收获目标，读研方向与岗位的关联如实表达；不把“不考虑读研”当作讨好答案，后续计划变化会反噬信任。

2. **被问“最早什么时候能来、能待多久”怎么答？**（面经实际出现；[[面经/阿里国际/二面/0001#Q15：如果实习的话最早能什么时候来？持续多久？|MJ038 · 阿里国际 · 二面 · Q15]]）

   直给结论再给保障：到岗时间【年月】、每周出勤【天数】、可持续【月数】、返校与答辩时间线，以及为什么这些安排能兑现（课程已修完、导师已确认、可远程）。时长确实有限时就如实说明并给出交接计划，稳定性靠机制说服而不是靠承诺时长；这类口径会与后续 offer 沟通交叉核对，不能为过面临时抬高。

相同：都是软件工程——需求拆解、架构设计、可靠性、可观测、协作交付一样不少。不同：① 输出概率性，因此多了评测集、bad case 回归、置信度与拒答设计；② 数据与 Prompt 是一等交付物，需要版本化；③ 成本与延迟结构不同（按 token 计费、外部模型依赖），容量规划要算整条调用链；④ 行为不确定，必须用结构化契约与服务端校验兜底。关系：AI 应用开发是后端工程的延伸——模型调用本质是昂贵、会出错、不稳定的外部依赖，恰恰要靠后端功力（隔离、重试、限流、观测）把它工程化；两者互补，不是替代。

#### 技术细节

回答时给一个具体对照更有说服力：同一个“接口超时”，后端方案是重试＋熔断；AI 链路还要先判断“结果未知”（可能已生成计费）并配幂等与状态查询（见 [[专题题库/系统设计#SYS-018：HTTP 接口如何从业务层兜底请求丢失与重试？|SYS-018：HTTP 接口如何从业务层兜底请求丢失与重试？]]）。反方向也成立：AI 带来的新工具在改变后端开发方式（代码生成、运维诊断）。避免两种极端：“AI 只是调 API”与“后端经验过时了”。

#### 深挖追问

1. **AI 项目里你最依赖的旧后端能力是什么？**（补充练习）

   如实选一项并给例子（如可观测建设、并发与配额控制、故障恢复），说明它如何直接决定 AI 功能能否上线。

2. **AI 时代程序员还有什么用，怎么看未来发展？**（面经实际出现；[[面经/传音控股/一面/0001#Q08：AI 时代程序员有什么用，未来的发展观念？|MJ029 · 传音控股 · 一面 · Q08]]）

   观点：AI 压缩的是“把想法写成代码”的环节，没压缩也不能代责的部分——定义与拆解问题、约束下取舍方案、对正确性和工程后果负责（测试/灰度/回滚/成本）、故障时兜底定位。发展观：从“coder”移向“能验证 AI 产出的人”，深耕一类系统问题与一个领域知识；结合自身真实用法（怎么用 AI、边界在哪）讲，不喊“取代/不会取代”的极端口号。

#### 面试回答

这类题没有标准答案，考察的是表达真实、内容具体与生活状态可持续。兴趣/社团按【真实经历】答：爱好＋坚持的时间与投入＋带来的可迁移习惯（长期主义、协作、节奏调节）；社团说清角色与做过的一件具体小事。没参加过也如实说，补一句时间真正花在哪。MBTI 先给准确定义（四维度行为偏好自评、16 型），再给清醒评价：更像自我认知与沟通的框架，重测稳定性和预测工作表现的能力有限，心理学界更常用大五人格，不该拿来贴能力标签；“i 人”指独处恢复能量，不等于社恐、不等于不会沟通、不等于能力弱；落点回到“我知道自己的协作方式并会管理它”（如深度工作前减少会议、重要讨论先书面准备）。不为迎合面试官编造人设——编出来的爱好经不起第二个问题。

### CAREER-012：如何回答“最大困难”这类复盘型行为题？

**常见问法**

- 人生中最大的困难是什么？

#### 面试回答

选“已走过、能复盘”的真实困难（学业求职受挫、项目重大失误、家庭或健康类变故均可），避开仍陷在情绪中的和无法自圆其说的。叙述按 STAR：情境与困难程度如实交代（不渲染不比惨）→ 我当时做了什么推动解决（重点，占一半篇幅：拆问题、求助路径、行动节奏）→ 结果与现在可检验的变化 → 复盘出的方法而非口号。准备好追问“再来一次会怎么做”：给出当时的信息条件下确实改不了的、与现在会提前做的区别，体现反思真实存在。

#### 技术细节

这题考抗压与自我修复的真实证据：面试官会分辨“被帮助度过的难关”和“自己主动走出来的困难”，后者才是加分项——叙述里要能看到自己的动作，而不是运气或他人拯救。选材雷区：与岗位强相关的负面（如“最大的困难是不喜欢写代码”）、仍在持续的敏感纠纷、纯情绪叙事没有行动。篇幅控制两分钟内讲完，留细节给追问，避免背诵感。

#### 深挖追问

1. **觉得自己的经历“不够惨”答不出这题怎么办？**（补充练习）

   这题考的是应对与复盘能力不是苦难等级；选一件真实的小困难（如【第一次独立交付模块出的事故】）把行动与改变讲扎实，远好过夸大。

### CAREER-013：被问“还有哪些亮点没体现”时怎么主动展示？

**常见问法**

- 你觉得还有哪些亮点没有体现，你可以提出来向我展示？
- 简历上没写但你想让我知道的能力有哪些？

#### 面试回答

这是面试官主动递机会，回答要**具体、可验证、能当场展开一层**。结构：挑一件事 → 说清方法 → 给可核对的产出 → 收一句与岗位的关联。示例框架（按真实经历填）：「简历主要写了项目，但有件事没体现——我是转码的，补计算机基础是按专题系统做的：把【操作系统／数据库／网络】各自整理成笔记，每学完一块做真题或写最小 demo 验证，目前【N 篇笔记／某个可运行的实现】。比如刚才聊到索引，我可以直接讲 B+ 树为什么矮、三层大概能放多少行。」——说完要真的能讲下去，否则这句反而扣分。

选题标准三条：① 与岗位相关（全栈岗就挑能证明自学与工程基础的事，别讲与岗无关的竞赛奖项除非能迁移）；② 有产出物（笔记、仓库、评测集、博客、被他人复用的模板），不是“我看了很多课”；③ 能自证方法（我怎么定计划、怎么检验效果、卡住时怎么办），这体现的是自驱力的可持续性而不是一次性努力。

两个常见失误：一是谦虚推掉（“我没什么亮点了”）等于放弃加分；二是堆形容词（“我学习能力强、能吃苦”）——面试官无法验证，只会顺着追问，答不上来就是负分。若确实没有硬产出，就选“学习方法＋一件已完成的证据”这个最小可信单元，例如把最近一次踩坑复盘成文档并修掉了同类问题。

#### 技术细节

展开顺序建议“结论先行＋可追问”：先一句话给结论（“我的自驱体现在把基础补齐并留下可核对的产出”），再给一个能立刻被追问的技术点（例如 MVCC 版本链、GC 日志怎么看），让面试官有路径往下挖——他挖得越深，你展示的其实是学习深度而不是背诵。数字要真实：笔记条数、投入时长、题目正确率这类数字一旦被追问口径必须自洽。

对转码同学，常见可展示的产出类型：① 系统化的知识笔记或题库（能说明组织方式与更新频率）；② 复现过的最小实现（手写 LRU、简易线程池、简单 KV 存储），能讲设计取舍；③ 读源码的输出（某开源项目的模块分析与流程图）；④ 用新技能完成的小项目并上线。避免只列课程清单或证书。

#### 深挖追问

1. **如果确实想不出亮点怎么办？**（补充练习）

   把“正在做且已有阶段性证据”的事讲出来（例如正在按专题整理基础、已完成某两块并能现场讲清），并明确下一步与验收方式；诚实的“正在补”远好于虚构“已掌握”。

2. **面试官接着让你现场展示，怎么接？**（补充练习）

   提前准备 1—2 个能在白板上讲 3 分钟的点（数据结构容量估算、GC 观察方法、一次真实排障过程），先给结论再给推导，讲完主动留一句“可以再往下问细节”，把节奏交给对方。

### CAREER-014：项目进度落后、需要赶工时怎么看待和应对？

**常见问法**

- 如何看待和应对项目中期进度不理想、需要赶工的情况？

#### 面试回答

这是压力／情境行为题，考点是“抗压 + 优先级判断 + 沟通透明度”，不是表决心加班。用可复用框架回答（真实经历填空）：

1. **先定位差距和原因**：落后是估算偏差、需求膨胀、技术卡点还是外部阻塞？量化“还差多少、卡在哪儿”。
2. **重排优先级**：按价值／依赖排序（MoSCoW、关键路径），砍或延后非核心项，先保关键交付能上线。
3. **对齐范围与时间**：把真实情况和取舍方案同步给上级／产品，用“减少范围”或“分阶段交付”换可行的 deadline，而不是默默承诺。
4. **集中投入作为手段之一**：关键路径攻坚、能并行就并行、减少返工与切换损耗；但赶工是有代价的，主动防质量下滑、防埋技术债。
5. **复盘**：事后归因（估算/依赖/风险识别），改进流程避免复发。

一句话立意：进度落后首先靠**缩小范围、对齐预期**解决，加班只是短期缓冲，不拿质量换速度。

#### 技术细节

区分“真落后”和“看起来落后”：有时是早期不可见的后端／联调工作没被看见，先同步进展与里程碑再谈补救。判断能否靠加人追回—— Brooks 定律（往延期项目加新人会增加沟通成本、短期更慢），加人只适合可切分、低耦合的任务；纯赶工要评估测试与灰度是否被压缩，别把风险转移到线上。留痕与预警机制（每日站会／燃尽／风险清单）让“中期才发现落后”尽量提前。

#### 深挖追问

1. **如果 deadline 完全不可动怎么办？**（补充练习）

   与利益方确认“必须上线的最小核心集”，其余转为快速迭代；同时评估技术债并登记，赶工上线后安排补救重构；把风险与临时方案透明同步，别单方面承诺。

### CAREER-015：手握多个 offer 时如何选择公司，怎么答？

**常见问法**

- 若手握多个 offer，如何选择公司？

#### 面试回答

这题考的不是排名，而是决策框架与对本机的诚意。答法分三层：先给稳定的评估维度并说明口径一致——业务与岗位技术栈匹配度、团队工程实践与成长空间、公司赛道与产品的确定性，薪酬放最后但承认会看；再落到行动与事实：“目前还在流程中／拿到了【数量】家的意向，按这套维度我倾向于【本机或真实排序】，因为【一条具体且真实的理由，如岗位内容与我的规划吻合、业务场景复杂度】”；收尾给承诺感：一旦选择就按约定到岗，不会拿着 offer 比价拖延。两个雷区：虚报竞对 offer 抬价（背调与行业圈子会拆穿），和把其他公司贬得一无是处（显得逐利 unstable）。信息未定口径：手头进展如实但模糊化，“都在等结果”是安全且真实的答法。

#### 技术细节

- 面试官是 HR／三面时更看重稳定性信号（工作地、长期规划一致性），面试官是技术 leader 时更想听“技术匹配”这条——同一框架按对象调整重心。
- 维度要给可验证细节：说“团队工程实践”就补一句从面试环节观察到的证据（题目风格、流程、面试官反馈），比空谈文化可信。
- 真拿到多 offer 后的操作与面试口径要一致：横向比较总包、税基、期权流动性、试用期条款；口头答复 deadline 前主动同步进展，不玩消失。

#### 深挖追问

1. **如果反问“那两家钱给得更多呢”？**（补充练习）

   承认薪酬权重但拉回长期账：前几年看能力增长曲线与业务天花板，给出自己“值得牺牲短期薪酬换取的条件”（如核心业务、导师制），避免回答成“只看钱”或“完全不看钱”两个极端。

2. **被问“你还在面哪些公司／岗位”怎么答？**（补充练习）

   如实给范围与阶段（同赛道后端开发、都在流程中），不点名具体公司敏感进展；表达筛选标准与本题框架呼应，展示的是决策一致性而非海投。

### CAREER-016：被问“读过哪些框架源码、怎么读的”怎么答？

**常见问法**

- 有没有阅读过 Java 生态中一些经典框架或工具的源代码？
- 你平时看源码吗，看了什么，有什么收获？

#### 面试回答

这题不是考报名字，而是考“你能不能读懂别人的设计并转成自己的判断”，所以答法要落在方法与产出。不要罗列“看过 Spring、MyBatis、JDK”——面试官随便挑一个追问细节就会露馅；只讲真读过且能讲清主干的一处。可信的结构是：带着什么问题去读（自己踩过或常问的机制）→从哪个入口进（扩展点或主流程）→怎么读（断点调试、写最小复现工程、画流程图）→读出什么设计意图与代价→用回到哪里（项目里的配置决策或对某个线上行为的解释）。收尾给可核对的产出：一张自己画的流程／结构图、一个复现 demo、一篇带结论的笔记。如果被追问细节答不上，坦率说“这块我只读到某某层次，还没看到那部分”，比现场编机制安全。

#### 技术细节

三条可复用的读法（面试时说出来就是加分项）：① 问题驱动——从症状入手定位到源码，比如事务自调用失效、循环依赖为什么需要三级缓存、HashMap 并发扩容的历史问题、线程池提交任务时的分支判断与参数含义，这类“面试常问且我真需要”的点最有性价比；② 主干优先——先看一次真实调用的调用链（入口→核心处理→扩展回调），沿主干 debug，不逐行啃工具类；抓扩展点与生命周期（BeanPostProcessor、拦截器链、TypeHandler、AQS 的入队出队与状态流转），设计模式往往就藏在这些接缝处；③ 对照演进——同一机制的版本差异、Javadoc 与 issue／讨论里的设计权衡，能看出“为什么这样设计、代价是什么”，这是把源码读成架构能力的关键一步。

配套习惯也要能讲：本地建一个最小验证工程（只引入相关依赖、断点打在关键处）、用 Arthas／jstack 一类工具在线上看真实调用栈与线程状态辅助印证、读完用自己的话写结论并记录与预期不符的地方。要避免的答法：把“看过别人写的源码解读文章”说成“读过源码”；只讲设计模式名词不讲机制；声称读了自己项目里根本没用到的框架（一追问版本与配置就崩）。个人事实需按【真实读过的框架与版本】填写，不虚构阅读深度。

#### 深挖追问

1. **读源码对做业务开发有什么实际用处？**（补充练习）

   三点：把“配置玄学”变成因果（知道线程池参数在源码里的分支才好定大小）、能定位到框架层而不是猜（异常栈能读懂）、做技术选型时能判断实现代价（比如知道缓存或事务的失效边界）；答题时给一个自己因源码知识而改变决策的具体例子。

2. **那你说说这个机制为什么要这样设计，换一种不行吗？**（面经实际出现；[[面经/阿里国际/二面/0001#Q11：有没有阅读过 Java 生态中一些经典框架或工具的源代码？|MJ038 · 阿里国际 · 二面 · Q11]] 的延伸）

   这是必然的第二层追问。答法是按“约束→选择→代价”组织：当时要解决什么问题（性能／兼容性／易用性），有哪些替代方案，为什么选了这个，付出了什么代价；说不清代价就说明其实没读懂。

3. **没读过源码可以吗？**（补充练习）

   可以，如实分层比硬撑好：“没有系统通读，但在排查问题时读过相关模块的调用链，收获是【具体一条】”，同时给出自己的替代学习方法（官方文档、issue、复现验证）。切忌把“看过教程”包装成“读过源码”。

### CAREER-017：被问“平时怎么学习大模型和新技术”怎么答？

**常见问法**

- 平时怎么学习大模型和 AI 相关知识的？
- 你一般怎么跟进新技术，最近学了什么？

#### 面试回答

这题考的是学习闭环是否成立，不是信息源清单，所以别把答案说成“看公众号、刷 B 站、读论文”。可信的答法给三层再加一个证据：① 输入以一手资料为主（模型卡与官方文档、协议规范、原始论文），二手解读只当索引不当结论；② 每学一个机制就做一个最小可跑的验证——几百行的检索链路复现、自己接一个工具服务、把某篇论文的实验跑一遍，形成“我测过的差异”而不是“我读过的说法”；③ 输出与复盘——笔记要带结论与适用条件，badcase 归档，能在组会或分享里讲清楚；同时如实说明这行的局限（模型行为随版本变化、社区结论要自己复测）。证据就是最近一次这样的学习：学了什么、怎么验证、结论是什么、改变了项目里的哪个决定。最忌讳两种答法：“刷过很多课”和把“看过新闻”当成知识储备。

#### 技术细节

跨方向的迁移点值得主动讲（这也是后端同学投 AI 岗的差异化优势）：把模型当成一个会出错、按量计费、延迟不稳定的外部依赖来对待，用已有工程方法约束它——评测集与回归、可观测与分段耗时、超时与降级、限流与成本控制。这样学的东西能直接落到项目里，也解释了为什么同时投 Java 后端与 Agent 方向（与 [[#CAREER-008：AI 开发和后端开发有什么异同，怎么看待二者关系？|CAREER-008]] 呼应）。

追新要有取舍标准，否则会被更新频率拖垮：优先学“会改变架构决策”的东西（上下文与工具调用机制、评测方法、推理成本结构），其次才是具体库的新版本；对自己项目用不到的热点，能说出它解决什么问题即可，不必跟着调参。信息源按可靠性分层：一手规范与论文＞官方文档与变更日志＞维护者或作者的分享＞社区转述；引用二手结论前要能回溯到一手来源，这也是面试里被追问时的护身符。学习成果要与求职主线连起来（见 [[#CAREER-002：如何介绍项目、个人职责与遇到的难题？|CAREER-002]]）：学的东西最终要变成项目里的一个模块、一次实验或一份评测，否则会被判断为“兴趣广泛但不落地”。具体读什么、跟到哪一步属个人事实，按【真实经历】填写，不虚构读过的论文与做过的实验。

#### 深挖追问

1. **最近读的一篇论文或学的某个机制是什么，讲讲。**（面经实际出现；[[面经/阿里国际/二面/0001#Q12：平时怎么学习大模型和 AI 相关知识的？|MJ038 · 阿里国际 · 二面 · Q12]] 的延伸）

   这是必问的验证题。按“它解决什么问题→方法核心一句话→我自己怎么验证→与我的项目差在哪”四段答，并能说出不认同或存疑之处；只背摘要会在第二层追问崩掉。

2. **看视频课和读官方文档，你更依赖哪个？**（补充练习）

   入门可看课建立框架，但结论要以官方文档与规范为准——课程容易滞后于版本变化；答题时给出“因为信了过时说法踩过坑”的具体经历，比讲道理更有说服力。

3. **你怎么判断一个新技术值不值得投入？**（补充练习）

   看它是否改变当前瓶颈：能解释或解决我正在遇到的问题就投入，且先做小成本验证（一次实验、一个 demo），验证有效再迁移进项目；否则只做了解，不追细节。
