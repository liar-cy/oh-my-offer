### CLOUD-001：Docker 容器和虚拟机有什么区别，为什么更轻量？

**常见问法**

- Docker 容器和虚拟机有什么区别，为什么更轻量？

- Docker 是什么，如何实现隔离和资源限制，如何进入容器？

#### 面试回答

传统虚拟机通过虚拟化硬件运行独立客户操作系统内核；常见 Linux Docker 容器是隔离的进程，共享宿主 Linux 内核，用 namespace 隔离资源视图、cgroup 约束资源，并通过镜像提供应用与依赖。容器通常不用为每个实例启动完整客户内核，因此启动快、额外资源开销较少，但隔离方式与虚拟机不同。

Linux namespace 隔离 PID、网络、挂载点、IPC、UTS 等资源视图，user namespace 涉及用户身份映射，具体启用情况依配置；cgroup 控制资源额度，capabilities、seccomp 等用于限制权限与系统调用。用 docker exec -it 容器名 sh 可在运行容器中新建 shell 进程，bash 需镜像内存在；attach 是连接主进程输入输出，不能混同 exec。docker run 的 --memory=512m、--cpus=1.5 是限额示例，CPU 配额不是绑定某个核；--cpuset-cpus 才指定 CPU 集合。镜像极简且没有 shell 时 exec sh 会失败。

#### 技术细节

镜像可以包含发行版用户空间文件，不代表每个容器有自己的内核；镜像分层和写时复制也可减少重复存储。Docker 是容器工具与运行平台，不能把名称直接等同于所有容器技术。Docker Desktop 在 macOS／Windows 运行 Linux 容器时通常有 Linux 虚拟机层，不能说整个环境绝不用虚拟机。容器仍有网络、存储和资源管理开销，也不能直接运行依赖不兼容内核的任意系统。

#### 深挖追问

1. **为什么容器通常比虚拟机轻量？**（面经实际出现；[[面经/百度/一面/0003#Q17：Docker 容器和虚拟机有什么区别，为什么更轻量？|MJ006 · 百度 · 一面 · Q17]]）

   容器实例主要增加应用进程和必要用户空间，不重复运行完整客户内核；实际成本仍取决于镜像、宿主平台和应用本身。

2. **容器如何隔离、限资源并进入交互环境？**（面经实际出现；[[面经/百度/一面/0005#Q19：Docker 是什么，如何实现隔离和资源限制，如何进入容器？|MJ008 · 百度 · 一面 · Q19]]）

   Docker 提供构建、分发和运行容器的工具。常见 Linux 容器共享宿主内核，通过 namespace 隔离进程号、网络、挂载点等视图，用 cgroup 限制 CPU、内存等资源，并结合 capabilities 等约束权限；镜像提供用户空间和依赖。运行中的容器可用 docker exec -it 容器名 sh 启动交互 shell，镜像含 bash 时才用 bash。启动参数 --memory 和 --cpus 可设置内存与 CPU 限额；网络隔离不等于资源限额，容器内存预算也不能只按 JVM 堆设置。

3. **Docker 做中间件本地化部署，常见踩坑有哪些？**（面经实际出现；[[面经/帆软/二面/0001#Q07：Docker 做中间件本地化部署，遇到过什么问题？|MJ023 · 帆软 · 二面 · Q07]]）

   高频问题：端口映射与服务名解析（宿主机与容器网络视角不同）；忘挂 volume 导致重建丢数据；镜像 tag 不锁定造成版本漂移；arm Mac 跑 x86 镜像的模拟兼容；内存/CPU 配额与 JVM 参数不匹配被 OOMKill；时区与字符集差异；compose 启动顺序——应用先于依赖就绪，需 healthcheck＋条件等待。回答按“现象→定位→解决→固化进 compose/文档”组织，并只讲亲自踩过的坑。

### CLOUD-002：Kubernetes 是什么，解决什么问题？

**常见问法**

- Kubernetes 是什么，解决什么问题？

- 是否了解 Kubernetes？

#### 面试回答

Kubernetes 是容器化应用的编排平台，通过声明期望状态，让控制器持续协调实际状态。它解决多节点上应用调度、副本管理、故障后重建、服务发现与负载分发、滚动发布和扩缩容等问题。Docker 侧重构建与运行容器，Kubernetes 侧重管理集群中的工作负载，两者关注的层次不同。

#### 技术细节

Pod 是基本调度单元，可包含需要共同运行的容器；Deployment 管理无状态应用副本与滚动更新，Service 为变化的 Pod 提供稳定访问入口。控制平面经 API 接收声明，调度器选节点，节点 kubelet 协调容器运行时；控制器不断对比期望与实际状态。故障重建依赖检测、可用容量和配置，扩容依赖指标与策略。持久卷不自动提供数据库一致性和备份；Kubernetes 也不自动构建业务镜像或修复应用逻辑。

#### 深挖追问

1. **它怎样维持应用副本数？**（补充练习）

   控制器发现实际副本少于声明值后创建替代 Pod，调度器安排节点，kubelet 启动工作负载；就绪检查决定副本何时接收流量。

### CLOUD-003：单机 Docker 容器如何通过网络通信？

**常见问法**

- 单机 Docker 容器如何通过网络通信？

#### 面试回答

常用方式是把两个容器接入同一个用户自定义 bridge 网络，利用容器名或网络别名解析对方，再访问对方的容器端口。Linux 上一般经 veth 与软件网桥转发，通常不需要先发布宿主端口。服务要监听容器可访问的地址；某容器里的 localhost 指它自己的网络命名空间，不是另一个容器。不同网络的容器不能默认互通，需要明确共享网络或路由与发布端口方案。

#### 技术细节

以 Linux Docker Engine 用户自定义 bridge 为例：

```sh
docker network create app-net
docker network connect app-net container-a
docker network connect app-net container-b
```

示例假定两个容器已经存在且运行。之后 A 可用 B 的容器名或网络别名加服务端口访问 B；应用需监听可访问接口，例如 0.0.0.0。用户自定义 bridge 提供名称解析，与默认 bridge 的行为不同。发布端口主要解决网络外部访问，容器内互访不应误用宿主映射端口。Linux veth／网桥转发是常见实现，不代表 host 或共享 network namespace 模式；共享网络命名空间的容器才可能通过相同 localhost 互访。

#### 深挖追问

1. **同机两个容器能直接用 localhost 通信吗？**（补充练习）

   默认独立网络命名空间时不行；应访问对方名称或 IP。共享网络命名空间是另一种显式配置。
