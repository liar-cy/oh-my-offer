## Q02：PPT 文档怎么去噪声？

以下为可选处理方案。

### 面试回答

我会结合版式和跨页重复信息两条线去噪：

- 识别并去掉页眉页脚、页码，以及每页重复的模板元素。
- 保留标题层级、正文、表格和图注。
- 扫描页再走 OCR（光学字符识别，把图片里的文字提出来），并检查还原出来的阅读顺序对不对。

一条原则：规则不能简单写成“重复就删”。标题、业务术语、单位本来就会重复。所以我会抽样对比清洗前后的结果，确认有没有丢掉有效信息。

## Q03：怎么检测重复？

按知识库文档及片段去重理解。

### 面试回答

我会分层处理，从完全相同一路做到近似重复：

- 文件级：先比文件哈希，完全相同的文件直接判重。
- 内容级：把文本规范化之后再算哈希，用来识别格式不同、但内容相同的材料。
- 近重复：用词片段指纹或向量相似度先筛候选，再结合差异做判断。

粒度可以是文档、页面或 chunk。但有一条要守住：要保留所有来源和版本关系，不能把出处一起删掉。

## Q05：query 的时候有没有用 embedding？

不能推断原项目实际用了向量检索。

### 面试回答

如果项目做向量检索，用法是这样的：

- 把 query 用 embedding（把文本编码成向量的模型）编码，而且要和文档向量用的是同一个模型、同一个向量空间。
- 在这个空间里检索，再结合关键词召回和重排。

为什么值得用：embedding 能匹配“换了措辞但意思一样”的语义。

但有边界：它不能保证事实正确。专有名词、编号、精确条件这些，通常还需要关键词或结构化过滤。

## Q07：了解哪些 Agent 框架，为什么选择 LangGraph？

### 面试回答

我了解过 LangChain、LangGraph，以及一些原生 function calling 方案（让模型按你定义的函数结构直接吐出调用参数）。

三者的定位：

- LangChain：更像应用组件库，把模型、工具、检索这些封装好给你用。
- LangGraph：把 Agent 的运行过程建模成一张有状态的图——节点处理任务，边决定怎么转移。
- 它适合有循环、条件分支、人工确认和中断恢复的流程。

选 LangGraph 的原因要落到项目的真实需求上，例如【需要保存状态／循环调工具／人工介入】。

反过来也要会说：如果只是一次检索加一次生成，用普通代码串起来反而更简单。

## Q08：从输入 www.baidu.com 到显示的整个流程是什么？

### 面试回答

按阶段往下讲，别背成一条固定链路：

- 浏览器先解析 URL，并处理缓存或 HTTPS 升级策略。
- 需要联网时，先解析域名，再建立或复用连接。
- 以 HTTPS over TCP 为例：走完 TCP 握手，再做 TLS 握手，然后发 HTTP 请求，服务器返回响应。
- 浏览器解析 HTML、CSS，执行脚本，构建页面，最后做布局、绘制和合成。

一个边界要说准：HTTP/3 用的是 QUIC，所以不能讲成所有网页请求都先建 TCP 连接。

## Q09：HTTP 和 HTTPS 有什么区别，如何验证证书，需要每次远程查验吗？

### 面试回答

先答第一问：HTTPS 是在 HTTP 通信中使用 TLS，提供传输的机密性、完整性和身份认证。

再答证书怎么验，客户端查这几点：

- 证书链能不能一路追到一个信任根。
- 域名是否匹配，有效期和用途对不对。
- 握手中还要验证对方确实掌握对应的私钥。

第三问“需不需要每次远程查验”——不需要：

- 验证签名主要在本地完成，不用每次都去问 CA。
- 吊销状态的检查可能用缓存、OCSP stapling 或浏览器自己的机制（OCSP：在线证书状态协议）。具体怎么走，取决于客户端策略。

## Q10：服务器断了之后有什么表现？

原文未区分进程退出、正常关闭、掉电和断网，回答按情况展开。

### 面试回答

要分三种情况说：正常关闭、复位、突然失联。

- 收到正常 FIN：客户端先把已经缓冲的数据读完，recv 才返回 0。
- 收到 RST：可能报连接重置。
- 断电或者网络黑洞，什么报文都没到：客户端未必能立刻知道。

最后一种最坑，发现手段分两条：

- 有数据在发的时候，会经历重传，最终超时才发现。
- 连接空闲的时候，需要 keepalive 或应用层的心跳和超时机制才能发现。

## Q11：TCP 怎么保证可靠传输？

### 面试回答

不是一条机制，是几套机制叠出来的：

- 序号和确认：按字节编号跟踪数据，接收方确认收到了哪里。
- 校验和：把坏包筛掉。
- 重传：由超时或者其他丢包检测机制触发。
- 接收端重排、去重：乱序到的段排回原顺序。
- 滑动窗口：做流量控制。
- 拥塞控制：根据网络状况调节发送速率。

合起来的效果是可靠、有序地交付。

最后一句边界要说准：连接永久中断时会报错，TCP 并不保证业务操作一定完成。

## Q12：TCP 如何传大文件，一次写入、TCP 单段和 IP 包的大小有什么区别？

### 面试回答

先给结论：大文件可以通过同一条 TCP 连接持续传完，但不是靠一个 TCP 段传完。

三个“大小”要分开记：

- 一次 write 或 send：提交的是一大块缓冲，量可以很大，也可能出现短写。它和单个 TCP 段的大小不是一回事。
- 单个 TCP 段：数据量受 MSS（最大段长度）、路径 MTU 和首部约束。常见 MTU 是 1500，IPv4／TCP 无选项时通常是 1460 字节。
- IP 包：IPv4 数据报总长度最多 65535 字节，这个数包含 IP 头；IPv6 普通 payload 长度最多 65535 字节，不含固定 40 字节的头，另外还有 jumbo 机制。

两个别踩的说法：

- 实际还受分片和路径 MTU 影响，不能把 65535 当成 TCP 通用的数据载荷上限。
- 本地写成功，也不等于对端已经收完。

关联专题：[[专题题库/计算机网络#NET-007：大文件如何通过 TCP 传输，TCP／IP 一次最多传多少？|NET-007：大文件如何通过 TCP 传输，TCP／IP 一次最多传多少？]]

## Q13：ICMP 知道吗？

### 面试回答

知道。ICMP 是 IP 网络用来报错和做诊断的协议，常见报文有：

- 目的不可达。
- TTL 超时。
- Echo 请求与响应。

两个工具就是用它做的：

- ping：用 Echo 检查可达性。
- traceroute：利用逐跳的 TTL 和超时信息，观察路径。

两条边界：

- ICMP 不是 TCP 或 UDP 那种端口服务。
- ping 不通不能直接说明网站一定不可用，因为可能被策略过滤了。

## Q14：fork 后父子进程共享什么，子进程是否复制父进程内容？

### 面试回答

分三层说父子进程的关系：

- 地址空间：各有各的虚拟地址空间，初始内容相同。Linux 通常用写时复制（读的时候共用物理页，谁写谁才复制），写入时才分离。
- 文件描述符：描述符表会复制，但对应描述符指向同一个 open file description，所以文件偏移和相关状态是共享的。
- 显式共享内存：仍然共享；普通堆栈变量的修改，不会直接同步到另一个进程。

所以“是否复制父进程内容”这句可以这么答：虚拟地址空间各自独立、初始内容相同，物理页靠写时复制往后推。

## Q15：子进程结束后，父进程需不需要处理？

### 面试回答

通常要处理：父进程得用 wait 或 waitpid 回收子进程的退出状态，否则退出记录可能一直留着，变成僵尸进程。

两种写法：

- 监听 SIGCHLD，收到之后循环做非阻塞回收，避免一次只处理掉一个退出事件。
- 如果明确配了自动回收机制，可以不逐个等待；但代价是可能再也拿不到退出状态。

## Q16：分四次，每次分配 1 GB，系统内存只有 4 GB，这时会爆吗？

### 面试回答

结论：不一定爆。关键是把“申请虚拟地址空间”和“实际触碰物理页”分开看。

结果受这几点影响：

- Linux 的 overcommit 策略（允许申请超出实际物理内存的虚拟地址）。
- 有没有 swap、进程自身的地址空间限制、容器配额。

时序上有个容易答错的点：

- 四次申请可能都成功，真正往大量页面写入时才出现回收、换页或 OOM。
- 如果用的是严格提交策略，也可能在申请阶段就直接失败。

最后补一句：系统本身也要占内存，不能认为 4 GB 全都能给这个进程。

## Q17：write（字符串）后，文件里立刻就会有吗？

### 面试回答

先把两件事分开：可见性和持久化。

- 对普通本地文件，一次成功的 write，通常是把数据交给内核页缓存。
- 之后再去读，能看到已写入的部分——这叫可见。
- 但这不代表数据已经落到持久介质——那才是持久化。

要求持久化就得显式做：正确使用 fsync 或 fdatasync，并且检查它们报的错误。

还有一层容易漏：如果调的是带用户态缓冲的库函数，得先 flush 到内核，才轮到上面这一步。

## Q18：手撕 LRU。

原文没有给语言和接口，专题采用 Java、整数 key/value、未命中返回 -1 的约定。

### 面试回答

结构选两个：哈希表负责定位节点，双向链表负责维护最近使用的顺序。

操作上就三步：

- get 命中、put 更新时，把该节点移到头部；新节点也插到头部。
- 超过容量时，删除尾部那个最久未使用的节点。
- 删节点的同时，把哈希表里对应的记录一起删掉。

复杂度：哈希表平均 O(1)，链表的摘除和插入是 O(1)，所以整体操作平均 O(1)，空间 O(capacity)。
