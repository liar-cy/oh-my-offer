## Q02：PPT 文档怎么去噪声？

以下为可选处理方案。

### 面试回答

我会结合版式和跨页重复信息去噪：识别页眉页脚、页码和重复模板元素，保留标题层级、正文、表格及图注；扫描页再用 OCR，并检查阅读顺序。规则不能只按“重复就删”，因为标题、业务术语和单位也可能重复，我会抽样对比清洗前后是否丢失有效信息。

## Q07：了解哪些 Agent 框架，为什么选择 LangGraph？

### 面试回答

我了解过 LangChain、LangGraph 以及一些原生 function calling 方案。LangChain 更像应用组件库，提供模型、工具、检索等封装；LangGraph 把 Agent 运行过程建模成有状态图，节点处理任务，边决定转移，适合有循环、条件分支、人工确认和中断恢复的流程。我选 LangGraph 的原因应该落到项目的真实需求上，例如【需要保存状态／循环调工具／人工介入】。如果只是一次检索加一次生成，用普通代码串起来反而更简单。

## Q08：从输入 www.baidu.com 到显示的整个流程是什么？

### 面试回答

浏览器解析 URL、处理缓存或 HTTPS 升级策略，需要联网时解析域名并建立或复用连接。以 HTTPS over TCP 为例，经过 TCP 和 TLS 握手后发送 HTTP 请求，服务器返回响应；浏览器解析 HTML、CSS，执行脚本，构建页面并进行布局、绘制和合成。HTTP/3 使用 QUIC，不能说所有网页请求都先建 TCP 连接。

## Q09：HTTP 和 HTTPS 有什么区别，如何验证证书，需要每次远程查验吗？

### 面试回答

HTTPS 在 HTTP 通信中使用 TLS 提供传输机密性、完整性和身份认证。客户端检查证书链能否到达信任根、域名是否匹配、有效期及用途等，握手中还验证对方掌握相应私钥。验证签名主要在本地完成，不需要每次远程询问 CA；吊销状态检查可能使用缓存、OCSP stapling 或浏览器机制，取决于客户端策略。

## Q10：服务器断了之后有什么表现？

原文未区分进程退出、正常关闭、掉电和断网，回答按情况展开。

### 面试回答

要分正常关闭、复位和突然失联。收到正常 FIN 后，客户端先读完已缓冲数据，recv 才返回 0；收到 RST 可能报连接重置。若断电或网络黑洞没有任何报文到达，客户端未必立即知道，有数据发送时可能经历重传并最终超时，空闲时需要 keepalive 或应用心跳与超时机制发现。

## Q11：TCP 怎么保证可靠传输？

### 面试回答

TCP 用序号和确认跟踪字节，结合校验和、重传及接收端重排去重提供可靠有序交付；滑动窗口实现流量控制，拥塞控制根据网络状况调节发送。丢包可以通过超时或其他丢包检测机制触发重传。但连接永久中断时会报错，TCP 不保证业务操作一定完成。

## Q12：TCP 如何传大文件，一次写入、TCP 单段和 IP 包的大小有什么区别？

### 面试回答

大文件可以通过同一 TCP 连接持续传完，但不是一个 TCP 段完成。一次 write 或 send 可以提交较大缓冲，也可能短写；它和单个 TCP 段的大小不同。单段数据受 MSS、路径 MTU 和首部约束，常见 MTU 1500 且 IPv4/TCP 无选项时通常为 1460 字节。IPv4 数据报总长度最多 65535 字节，包含 IP 头；IPv6 普通 payload 长度最多 65535 字节，不含固定 40 字节头，另有 jumbo 机制。实际还受分片与路径 MTU 影响，不能把 65535 当作 TCP 通用数据载荷上限，也不能把本地写成功当成对端已收完。

关联专题：[[专题题库/计算机网络#NET-007：大文件如何通过 TCP 传输，TCP／IP 一次最多传多少？|NET-007：大文件如何通过 TCP 传输，TCP／IP 一次最多传多少？]]

## Q13：ICMP 知道吗？

### 面试回答

ICMP 用于 IP 网络的错误报告和诊断，例如目的不可达、TTL 超时、Echo 请求与响应。ping 常用 Echo 检查可达性，traceroute 利用逐跳 TTL 及超时信息观察路径。ICMP 不是 TCP 或 UDP 的端口服务；ping 不通也不能直接说明网站一定不可用，因为可能被策略过滤。

## Q14：fork 后父子进程共享什么，子进程是否复制父进程内容？

### 面试回答

fork 后父子进程具有独立虚拟地址空间，初始内容相同，Linux 通常用写时复制共享物理页，写入时再分离。文件描述符表会复制，但对应描述符指向同一 open file description，因此共享文件偏移和相关状态。显式共享内存仍可共享；普通堆栈变量的修改不会直接同步到另一进程。

## Q15：子进程结束后，父进程需不需要处理？

### 面试回答

通常需要通过 wait 或 waitpid 回收子进程的退出状态，否则退出记录可能保留成僵尸进程。父进程可以监听 SIGCHLD 后循环非阻塞回收，避免只处理一个退出事件。若明确配置了自动回收机制，则可不逐个等待，但也可能无法再获得退出状态。

## Q16：分四次，每次分配 1 GB，系统内存只有 4 GB，这时会爆吗？

### 面试回答

不一定，要区分申请虚拟地址空间与实际触碰物理页。Linux 的 overcommit 策略、swap、进程地址空间限制和容器配额都会影响结果。申请可能成功，真正写入大量页面时才出现回收、换页或 OOM；严格提交策略也可能在申请阶段失败。系统本身也占内存，不能认为 4 GB 都能给这个进程。

关联专题：[[专题题库/操作系统#OS-003：4 GB 内存机器连续申请四次 1 GB，一定会 OOM 吗？|OS-003：4 GB 内存机器连续申请四次 1 GB，一定会 OOM 吗？]]

## Q17：write（字符串）后，文件里立刻就会有吗？

### 面试回答

要区分可见性和持久化。对普通本地文件，成功的 write 通常把数据交给内核页缓存，后续读取可看到已写入部分，但不代表数据已经落到持久介质。若要求持久化，需要正确使用 fsync 或 fdatasync 并检查错误；如果调用的是带用户态缓冲的库函数，还需区分 flush 到内核这一步。

## Q18：手撕 LRU。

原文没有给语言和接口，专题采用 Java、整数 key/value、未命中返回 -1 的约定。

### 面试回答

我会用哈希表定位节点，用双向链表维护最近使用顺序。get 命中和 put 更新时移到头部，新节点也插到头部，超过容量时删除尾部最久未使用节点，并同步删除哈希表记录。哈希表平均 O(1)，链表摘插 O(1)，所以整体操作平均 O(1)，空间 O(capacity)。
