## Q03：volatile 的作用是什么？内存屏障的工作原理？volatile int a 执行 a++ 线程安全吗？

### 面试回答

三问一条链，先作用再底层再拆陷阱：

- volatile 管两件事：可见性＋有序性。规则一句话：对 volatile 变量的写 happens-before 后续对它的读；适合发布状态标志、发布不可变对象引用。
- 内存屏障是它的实现手段：编译器／JIT 在 volatile 写前后、读前后插入屏障指令，禁止跨越屏障的重排序，并在写时把 CPU 缓存行的一致性协议触发的修改对后续读者可见。
  - 常用四件套：StoreStore／LoadLoad（普通读写不与前后 volatile 乱序）、StoreLoad（volatile 写后再读要看到最新值，最重的屏障，x86 上由带锁指令／`mfence` 类实现）。
  - 口径提醒：x86 是强内存序，多数屏障天然满足，唯独 StoreLoad 要花代价——说出这句比背全表更显懂。
- a++ 不安全：read-modify-write 三步复合操作，volatile 只保证每步读到的值最新，不保证三步不被穿插——两线程同读 1 各自写回 2，更新丢失。
  - 修正：`AtomicInteger.incrementAndGet()`（CAS）或加锁；只要出现“先检查再更新”，volatile 一律不够。

## Q04：谈谈 MySQL 的 B+ 树索引。

### 面试回答

按“结构—为什么—怎么用”三段：

- 结构：多叉平衡搜索树，层数矮（三两层可放千万级键）；非叶节点只存键值＋子树指针，叶节点存键＋指针且叶子间双向链表串联。
- 为什么是它：等值查找 O(log n) 且树高就是 IO／寻路次数；范围查询沿叶子链表顺序扫，不用回树；对比 B 树（数据也在非叶节点、没有叶链表）扇出更小、范围更弱；对比哈希（O(1) 等值）不支持范围与排序；对比红黑树链太高、缓存局部性差。
- 落地到 InnoDB：聚簇索引叶子＝整行，二级索引叶子＝主键值，所以二级索引命中后要回表；这决定了覆盖索引、最左前缀这些上层话题的根因（延伸见 MYSQL-018／021）。
- 一句代价：树矮是靠写入时维护有序换来的——页分裂、随机写放大都在账上。

关联专题：[[专题题库/MySQL#MYSQL-004：InnoDB 索引为什么用 B+ 树，而不是 B 树或哈希表？|MYSQL-004：InnoDB 索引为什么用 B+ 树，而不是 B 树或哈希表？]]

## Q05：user 表有 sex 和 mail_id 两列，`select * from user where sex=1 and mail_id=10` 你会怎么建索引？

### 面试回答

- 先给结论：建联合索引 `(mail_id, sex)`；单给 sex 建索引基本没用。
- 两个条件都是等值，对这一条 SQL 而言列序不影响定位——(sex, mail_id) 同样能两列全用。
- 那为什么 mail_id 在前：
  - 选择性：sex 只有两三个值，单独走它过滤掉的信息量太小；mail_id（邮编）离散度高，单独前缀就能收敛大量行。
  - 前缀复用：将来出现“只按 mail_id 查”的语句能直接吃这个索引，反向则不能——列序为未来的查询模式留空间。
- 严谨补两句：`select *` 不在索引里，回表免不了，想要覆盖得把常用列塞进索引（收益小就别）；“区分度高放前”不是通用法则——先服务高频查询的左前缀与排序方向，这一题恰好在等值场景两者等价、拼复用与选择性。

## Q06：联合索引四题实战：范围切断、等值＋范围、等值前缀排序与跳列排序怎么走索引？

### 面试回答

四问共用原则一句话：联合索引按列序全局有序；等值前缀钉住位置后，遇范围则后续列不再参与定位；ORDER BY 要吃到索引序，等值列＋排序列必须从最左连续。

- ① `(province_id, mail_id)`，`where mail_id=10 and province_id>5`：首列就是范围——只能按 `province_id>5` 圈一段区间扫；mail_id 不参与树定位，作为索引条件下推（ICP）在索引层过滤。答案口径：“索引能用，但只定位到 province_id，mail_id 是过滤”。
- ② `(province_id, city_id, mail_id)`，`where mail_id>=10 and province_id=5 and city_id=10`：等值条件书写顺序无所谓，优化器会整理成 province=5、city=10 的等值前缀，mail_id>=10 是第三列范围——三列全用上，定位后沿叶子链表扫。
- ③ 同表 `where province_id=5 and city_id=10 order by mail_id`：两等值钉死后，组内 mail_id 本来就升序——排序由索引直接给出，无 filesort（Extra 不出现 Using filesort）。
- ④ 同表 `where province_id=5 and mail_id=10 order by city_id`：province 等值后，(city_id, mail_id) 是复合序——挑出 mail_id=10 的行散落在不同 city_id 段里，city_id 不再整体有序，必须 filesort。这题的“差一步”就在排序列没被等值前缀连续覆盖。

收尾一句：判断都回同一张图——沿索引序“从最左钉、钉到哪算哪，断了就过滤或回表，排序另看连续性”。

## Q07：手撕：最长递增子序列的长度（LC300），并把子序列本身打印出来。

### 面试回答

两问两版：先 O(n²) DP 出长度，再加 prev 数组还原序列；顺手报 O(n log n) 的贪心＋二分升级方向。

- DP 定义：`f[i]`＝以 nums[i] 结尾的 LIS 长度；`f[i]=max(f[j])+1`（j<i 且 nums[j]<nums[i]），基准全 1。
- 打印子序列：转移时记 `prev[i]=j`，从最优终点沿 prev 回溯再反转。
- 拼多多环境：不能自跑、二面连执行结果都看不到、报错靠面试官截图——所以交码前口述三组用例（空数组、全递减、含重复值 `[2,2]` 不算递增）自查边界。

```java
int[] longestIncreasingSubsequence(int[] nums) {
    int n = nums.length;
    if (n == 0) return new int[0];
    int[] f = new int[n], prev = new int[n];
    Arrays.fill(prev, -1);
    int best = 0;
    for (int i = 0; i < n; i++) {
        f[i] = 1;
        for (int j = 0; j < i; j++) {
            if (nums[j] < nums[i] && f[j] + 1 > f[i]) { f[i] = f[j] + 1; prev[i] = j; }
        }
        if (f[i] > f[best]) best = i;
    }
    LinkedList<Integer> seq = new LinkedList<>();
    for (int i = best; i != -1; i = prev[i]) seq.addFirst(nums[i]);
    return seq.stream().mapToInt(Integer::intValue).toArray();
}
```

- 口述升级：维护 tails 数组（tails[k]＝长度 k＋1 的 LIS 的最小结尾），每个数二分找第一个 ≥ 它的位置替换、更大则追加——长度 O(n log n)；还原序列要在替换时记下标＋前驱指针，别口头吹成“同样简单”。
- 示例自检：`[10,9,2,5,3,7,101,18]` → 长度 4（2,3,7,101 或 2,3,7,18——任一合法都行，主动说明“答案不唯一”，免得被“和我想的不一样”误判）。
