## Q01：UI 跟 AI 交互需要写 prompt 吗？怎么写高效、让 AI 生成效果好的 prompt？

### 面试回答

需要。界面里只要调用了大模型，发过去的那段话本身就是 prompt，区别只是写死在服务端模板里，还是开放给用户自己改。

怎么写得高效，我的要点是六条：

- 目标明确：一句话讲清角色、任务和“什么算做对了”。
- 上下文给足、而且要结构化：输入数据、字段含义、边界条件用分隔符或 XML／JSON 分块给，不要混成一长串自然语言。
- 定死输出契约：要求固定的 JSON schema 或枚举值，这样前端能直接渲染，后端能直接校验。
- 给少样本示例：重点给容易出错的边界样例，最好再配几个“期望不要这样输出”的反例。
- 复杂任务分步：先让模型出拆解或布局，再往里填内容，不要一次要到底。
- 用真实 bad case 迭代：每次只改一处，在固定样例集上回测，而不是把 prompt 越写越长。

原文“券/准”按“生成效果准确、稳定”理解。想稳定，靠的是输出契约、把温度调低、加校验和重试，不是靠堆措辞。

**二、操作系统（原题 9—15 → Q02—Q08）**

## Q02：操作系统有哪些功能？

### 面试回答

操作系统就干两件事：对下把硬件抽象成统一的接口，对上做全局限价的资源管理。具体功能分六块：

- 进程／线程管理：创建、撤销、调度、切换，还有同步和通信。
- 内存管理：地址映射、虚拟内存和缺页、分配回收、页面置换。
- 文件管理：目录、磁盘空间、读写和权限。
- 设备管理：驱动抽象、缓冲、I/O 调度。
- 网络和进程间通信：给上层一套统一的收发接口。
- 安全保护：用户和权限隔离、访问控制。

对应用来说，这些最终都表现为一组系统调用（fork、read、write、mmap 之类），程序不用自己去操作硬件。

## Q03：操作系统的用户态和内核态分别是什么？

### 面试回答

这是 CPU 的两个执行权限级别。

- 用户态：程序只能访问自己的地址空间，只能执行非特权指令，不能直接操作硬件、不能改内核数据。
- 内核态：权限全开，可以执行特权指令，能访问物理内存和所有进程的资源。

平时应用代码都在用户态跑，只有两种情况会进内核态：自己主动发起系统调用，或者被中断／异常打断。内核校验完参数和权限，把活干完再返回用户态。

切换要把寄存器上下文保存和恢复一遍，所以有固定开销。这就是频繁的小 I/O 慢的原因——每次都陷内核，所以要靠缓冲和批处理把次数摊薄。

## Q04：进程和线程的区别是什么？

### 面试回答

一句话：进程是资源分配的单位，线程是 CPU 调度的单位。

- 进程：有独立的虚拟地址空间、自己的文件描述符表和信号处理。创建和切换开销大，好处是隔离——一个进程崩了通常不牵连别人。
- 线程：同一个进程内的线程共享堆、全局变量和打开的文件，自己只保留栈、寄存器上下文和调度状态。所以创建切换更轻，通信只要读写共享内存；代价是有竞态，而且一个线程崩会拖垮整个进程。
- 协程：更轻的用户态执行单元，由语言运行时自己调度，切换不进内核。

面试时补一句差异的根源就够了：隔离级别不同——进程之间隔地址空间，线程之间只隔栈。

## Q05：线程之间怎么通信？进程间的通信方式呢？

### 面试回答

线程之间是“共享状态 + 同步协议”：

- 传数据：用 BlockingQueue 生产消费，天然带背压；要拿返回值用 Future。
- 发状态：volatile 或原子类做可见性发布。
- 条件等待：synchronized 配 wait／notify，Lock 配 Condition，或者底层一点用 park／unpark。
- 协调阶段：CountDownLatch 之类等大家跑完再往下走。

一句话总结：可见性、原子性、等待唤醒这三件事都得有明确协议来保证，缺一都会出诡异 bug。

进程之间不能直接共享内存，得走内核或者显式约定：

- 匿名管道（只能父子）、命名管道：单向字节流。
- 消息队列：保留消息边界，不用自己拆包。
- 共享内存：吞吐最高，但同步要另外做一套。
- 信号：异步通知，不适合传大块数据。
- Socket：能跨机器，网络服务必选。

选哪个就看五点：数据量多大、要不要消息边界、要不要额外同步、生命周期怎么管、是否跨主机。

## Q06：什么是死锁？

### 面试回答

死锁就是一组执行单元各拿着对方要的资源，又在等对方手里的资源，谁都不放，没有外力就永远卡住。

最常见的画面：线程 A 持有锁 1 去抢锁 2，线程 B 持有锁 2 去抢锁 1，等待关系成一个环。不止线程会这样——数据库事务互等锁、分布式服务互相 RPC 等待，同样是死锁。

判断标准是四个必要条件同时成立，缺一个就死不了：

- 互斥：资源同一时刻只能被一个持有。
- 占有且等待：手里拿着不放，还在等新的。
- 不可剥夺：不能强行把资源抢走。
- 循环等待：等待关系首尾相接成环。

再补一句区分：死锁不等于饥饿。饥饿是某个线程长期抢不到资源、但系统整体还在推进；死锁是这一组线程全停住。

## Q07：怎么避免产生死锁？还有别的办法吗？

### 面试回答

思路只有一个：破坏四个必要条件里的任意一个。

- 破“循环等待”和“占有且等待”：全局固定加锁顺序，或者一次性把需要的资源申请齐。这是应用层最常用、也最有效的做法。
- 破“不可剥夺”和无限等待：用 tryLock 带超时，或者可抢占的锁。要说清一点——超时是“解除等待”，不是“预防”，慢操作有可能被误判成死锁。
- 从设计上避免成环：缩小锁范围、拆分资源、不要在持锁期间嵌套调用别人的锁。

还有两条别的路线：

- 避免：像银行家算法那样，分配前先判断会不会进入不安全状态。理论漂亮，工程上很少真做。
- 检测：维护一张等待图找环，发现了再回滚。

所以现实中的主流组合是“预防 + 事后检测恢复”，而不是严格避免。

## Q08：发生了死锁要怎么解除或恢复？

### 面试回答

先定位，再恢复。

定位：

- Java：jstack 打线程栈，或者用 ThreadMXBean 的 findDeadlockedThreads，能直接看到谁持有什么、在等什么。
- 数据库：查死锁日志（MySQL 是 `SHOW ENGINE INNODB STATUS` 里的 LATEST DETECTED DEADLOCK）。
- 服务端：看线程栈和锁的持有关系。

恢复的本质都是破坏“不可剥夺”——挑代价最小的一个回滚：

- 杀掉或中断环上的一个线程／进程：应用要能容忍局部失败并把状态重建起来。
- 数据库：引擎自己会检测，选 undo 量小的那个事务回滚。业务侧捕获死锁错误码后要重试整个事务，不能只重放失败的那一条语句。
- 靠带超时的锁和熔断让系统自己解套：要注意这可能只是慢，不一定是真锁死。
- 线上解不掉就只能重启实例，同时把加锁顺序改掉防止复发。

最后一步别忘：恢复完要回看有没有留下脏数据或不一致状态。

## Q09：TCP/IP 四层模型有哪些？每一层有什么作用？每层有哪些对应协议？

### 面试回答

从下往上四层：

- 链路层（网络接口层）：在一条物理或逻辑链路上把数据成帧、寻址、发送，管的是和硬件打交道的那段。协议：以太网、Wi-Fi、ARP。
- 网际层（网络层）：把包从源主机跨网络路由到目的主机，负责寻址和分片。协议：IP、ICMP。
- 传输层：端到端、进程到进程的通信，用端口区分是哪个应用。TCP 可靠有序，UDP 轻量无连接。
- 应用层：规定具体业务的语义。HTTP、HTTPS、DNS、FTP、SMTP、SSH。

封装方向记一条线：应用消息 → TCP 段／UDP 数据报 → IP 包 → 链路帧，每层加自己的头部。

另外说明口径：有的教材把链路层再拆成物理层 + 数据链路层，讲五层模型；开口先说清自己讲的是四层还是五层，别和面试官对不上。

## Q10：HTTP 状态码有哪些？5 开头的呢？

### 面试回答

状态码分五类：

- 1xx 信息：100 Continue。
- 2xx 成功：200 OK、201 Created、204 No Content。
- 3xx 重定向：301 永久、302 临时、307／308 保持原方法、304 缓存校验后未修改。
- 4xx 客户端错误：400 参数错、401 没认证、403 不给做、404 找不到、405 方法不允许、409 冲突、429 请求过多。
- 5xx 服务端错误。

5 开头重点记四个：

- 500：服务器自己抛异常了，通用兜底。
- 502：网关或代理从上游拿到了无效响应——后端崩了，或者返回了不合规的报文。
- 503：服务暂时处理不了，过载或在维护，可以带 Retry-After。
- 504：网关等上游超时。

区分 502／503／504 的窍门是看错在谁身上：503 是本服务明确拒了，502 是上游给了个坏响应，504 是上游压根没给。

## Q11：HTTP 和 HTTPS 的区别？两个协议的端口号？

### 面试回答

HTTP 是明文的应用层请求／响应协议；HTTPS 是在 HTTP 下面加了一层 TLS，管传输的机密性、完整性和服务端身份认证。

具体四点区别：

- 明文 vs 密文：HTTP 中间设备能直接看到内容，HTTPS 的载荷是加密的。
- 证书：HTTPS 需要 CA 签发的证书，客户端要验证证书链、域名，以及握手时的私钥证明。
- 建连开销：HTTPS 多一次 TLS 握手，TLS 1.3 一个往返、1.2 两个，所以首包延迟更高。
- 默认端口：HTTP 80，HTTPS 443（都可以配置）。

最后补一句边界，显得理解到位：HTTPS 只保护传输链路，既不保证服务端业务没有漏洞，也不等于内容不会在落盘的一方被看到。

## Q12：HTTP 有哪些请求方法？GET 和 POST 的区别？哪个请求的参数放在请求体里？

### 面试回答

标准方法有八个：GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS、TRACE。

GET 和 POST 的区别按语义讲最稳：

- GET：读资源，用 URL 定位，语义上安全且幂等，可以被缓存，参数放在 URL 的查询串里。
- POST：把数据交给服务端处理，非幂等，默认不缓存，参数放在请求体里。

所以“哪个参数放请求体”——POST。PUT、PATCH 这类带载荷的方法同样放请求体，用 Content-Type 描述编码。

其余的差异要说准，别背错：

- URL 长度限制来自浏览器和服务器的实现，不是协议规定的。
- GET 的查询串会进日志和 Referer，所以不适合放敏感信息。
- “GET 比 POST 安全”“只有 GET 能传中文”都是误解。两者在协议层都只是明文，加密靠 TLS。

## Q13：数组和链表的区别及不同应用场景

### 面试回答

核心差别就一句：数组的内存是连续的，链表不是。这一点决定了两边各自擅长什么。

- 数组：元素在内存中连续存放。
  - 按下标随机访问 O(1)。
  - 但头部或中间插入删除要搬移元素，是 O(n)。
  - 定长数组还得预先分配。
- 链表：节点靠指针串联。
  - 插入删除只需改指针，是 O(1)——前提是你已经定位到那个位置。
  - 但按下标访问要顺着一路走过去，是 O(n)。
  - 每个节点还多一份指针的额外开销。

应用场景这么选：

- 频繁随机访问、整体遍历、做连续内存运算（缓存友好）：用数组和 ArrayList。
- 长度变化大、频繁在头部插入，或者位置已知还要反复插删：用链表和 LinkedList。
- 字符串缓冲、序列化：用动态数组，并靠容量倍增把扩容成本摊还掉。
- 多路归并、LRU 的淘汰队列这类要频繁摘挂节点的场景：用链表。LRU 就是哈希表＋双向链表。

最后补一句实战结论：真实机器上数组有缓存局部性，线性扫描往往比链表快得多，不能只看渐进复杂度。

## Q14：如何判断一个列表里面有环？

### 面试回答

如果“列表”指链表，用快慢指针，也就是 Floyd 判圈。

- 慢指针一次走一步，快指针一次走两步。
- 有环的话，两者一定会在环内相遇，返回 true。
- 快指针先走到 null，说明无环。
- 复杂度：时间 O(n)、空间 O(1)，不需要额外集合。

延伸一步（找环入口）：相遇后把其中一个指针回到头节点，两个指针都改成一次一步再走，再次相遇的点就是环的入口。

如果“列表”指的是数组、每个元素存了下标（像 138 题那种随机链表结构，或者 happy number 式的下标跳转）：

- 同样可以用快慢指针，因为按下标跳转本质就是一次链表遍历。
- 更简单的是 HashSet：记录访问过的下标，第二次访问到就说明有环，空间 O(n)。
- 还能用原地标记：把访问过的位置改值或者打符号，空间降到 O(1)，前提是允许修改输入。

## Q15：讲一下冒泡排序的原理

### 面试回答

冒泡排序就是反复遍历数组，每一轮只比较相邻的两个元素，顺序不对就交换。

- 一轮走完，本轮最大的元素被“冒泡”到未排序区的末端。
- 下一轮把比较范围缩短一位，已经排好的尾部不再动。
- 提前结束：如果某一轮没有发生任何交换，说明已经有序，直接退出。

复杂度和性质：

- 时间：平均和最坏都是 O(n²)；最好 O(n)，靠的就是上面那条提前退出（输入已有序时）。
- 空间：O(1)。
- 稳定排序：相等的元素不交换，相对次序不变。

工程定位：大规模数据基本不用它。它的价值是简单、易验证，教学上用来理解比较排序和稳定性的概念。面试写代码时记得加上 swapped 标志这层优化。

## Q20：接口和抽象类的共同点和区别？接口里能有静态方法、静态变量吗？方法能有默认实现吗？

### 面试回答

共同点三条：

- 都不能被直接实例化（接口可以含 default 方法，但接口本身不实例化）。
- 都能声明方法、表达抽象类型、实现多态。
- 子类／实现类都必须覆盖那些未实现的抽象方法。

区别看定位：

- 抽象类是“is-a”的部分实现：能有构造器、实例字段、任意访问修饰符；子类只能单继承。
- 接口是“can-do”的能力契约：字段只能是 public static final 常量；实现类可以多实现。
- Java 8 之后接口能有 default 实例方法，所以接口也能携带一部分共享实现。

怎么选：

- 多个子类要共享状态和骨架流程（模板方法）——选抽象类。
- 只约定能力、需要多实现、或者要做解耦——选接口。

后面三个追问，逐个直答：

- 接口里能有静态方法吗？能，Java 8 起。它不属于实例、不能被实现类继承，要用接口名调用。
- 接口里能有静态变量吗？可以有字段，但隐含 public static final。所以所谓“静态变量”实质是常量，接口没有普通的实例字段。
- 方法能有默认实现吗？能，就是 default 方法（Java 8 起）。实现类没覆盖时直接继承；如果两个接口给了冲突的默认实现，实现类必须显式重写来解决。

## Q21：Java 里怎么实现线程安全？

### 面试回答

从弱到强分五层说，越靠前越省事。

- 不共享：栈封闭、ThreadLocal、不可变对象（final 字段＋正确发布、record、只有常量的类）。没有共享可变状态就没有竞态，这是最省事的方案。
- 无锁的可变共享：volatile 保证可见性、禁止重排；java.util.concurrent.atomic 里的原子类和 LongAdder 靠 CAS（compare-and-swap，比较并交换）做无锁更新。注意 i++ 这类复合操作，单靠 volatile 不安全。
- 互斥：synchronized（方法或代码块，锁的是对象；静态方法锁 Class 对象）、ReentrantLock（可配公平策略、可中断、能有多个 Condition），再配合正确发布。
- 并发容器与同步包装：ConcurrentHashMap、CopyOnWriteArrayList、BlockingQueue，以及 Arrays.parallelSort／ConcurrentMap.computeXxx 这类原子复合操作。用它们就是为了避免自己拼 check-then-act。
- 结构层面：用有界线程池和单线程写者，把共享收敛到队列里；或者用 Actor／消息传递。

真正的要求是这么句话：先讲清不变量是什么、由哪个协议保护，读写两端都走同一个协议才算安全。另外还要覆盖初始化安全（final 语义、正确发布）和终止安全（中断、shutdown）。

## Q24：两数之和：返回两数下标，哈希表 O(n) 一次遍历

### 面试回答

做法是一次遍历配哈希表。

- map 里存“已扫过的值 → 下标”。
- 对每个 nums[i]，先算 target−nums[i] 去 map 里查；查到就直接返回这两个下标。
- 查不到，再把当前值和它的下标放进 map。

为什么这么做：

- 每个元素最多一次读、一次写，所以时间 O(n)、空间 O(n)。
- 先查后放还天然避免了同一个元素被用两次——target 是某个元素两倍时不会自匹配。

另外两条路为什么不选：

- 暴力双循环是 O(n²)。
- 排序加双指针虽然能到 O(n log n)，但会打乱下标，还得额外保存原索引。题目要的是下标，所以哈希表最直白。

```java
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> indexByValue = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        Integer j = indexByValue.get(target - nums[i]);
        if (j != null) {
            return new int[]{j, i};
        }
        indexByValue.put(nums[i], i);
    }
    return new int[0];
}
```

## Q25：最长公共前缀：求字符串数组的最长公共前缀

### 面试回答

纵向扫描最直观：以第一个字符串为基准，按下标 col 逐字符去比所有字符串的第 col 位。

- 只要有任何一个字符串长度已经到了 col，或者这一位字符和基准不同，就返回 strs[0].substring(0, col)。
- 所有列都比完了还没中断，整个基准串就是答案。

边界先处理：

- 数组为 null 或长度为 0，直接返回空串。
- 数组里含空串时结果自然是空串，上面的逻辑会覆盖到。
- 完全没有公共前缀时返回空串，符合要求。

复杂度：O(S)，S 是所有字符串的字符总数。

也可以走横向做法：

- 把第一个串当成答案，逐个和后面的字符串求两串的公共前缀并不断缩短，为空时提前 break。
- 排序法取最小值和最大值来比较同样可行，但会改变输入，或者多花 O(n log n)。

```java
public String longestCommonPrefix(String[] strs) {
    if (strs == null || strs.length == 0) return "";
    for (int col = 0; col < strs[0].length(); col++) {
        char c = strs[0].charAt(col);
        for (int k = 1; k < strs.length; k++) {
            if (col >= strs[k].length() || strs[k].charAt(col) != c) {
                return strs[0].substring(0, col);
            }
        }
    }
    return strs[0];
}
```
