## Q02：对 MCP 的理解；MCP 客户端调用服务器工具的整体交互流程。

原题 2—3 同话题，按提问顺序合并。

### 面试回答

MCP 是 Anthropic 发起的开放协议，用 JSON-RPC 给“模型上下文供给”定标准接口：Host（IDE／Agent 应用）内建 Client，Client 连 Server，Server 对外暴露 tools、resources、prompts 三类能力——常被类比成 AI 世界的 USB-C，把 M×N 的私有适配收敛为 M＋N。它解决的是工具与数据接入碎片化问题，和 Function Calling 不冲突：后者是模型层“选哪个工具、传什么参数”的能力，MCP 是应用层“工具怎么被发现、被调用、被鉴权”的协议。交互流程六步：① Client 发 initialize，双向协商协议版本与能力；② notifications/initialized 就绪；③ tools/list 拉取工具定义，转成模型可见的工具描述；④ 模型推理产出调用意图（工具名＋参数），运行时做参数与权限校验；⑤ Client 发 tools/call，Server 路由到实现执行，返回 content 或 isError；⑥ 宿主把结果回填消息流继续推理。补充两点显示理解深度：初始化与发现可复用、不必每次调用重做；写操作超时要靠幂等与状态查询判断，别盲目重试。

## Q03：讲一下 Spring AI Alibaba Graph 的底层原理。

### 面试回答

它是阿里在 Spring AI 之上做的工作流／多 Agent 编排引擎，设计借鉴 LangGraph——把应用建模成状态图而不是链。核心四件：① StateGraph 声明图结构，Node 封装一段逻辑（LLM 调用、工具、纯函数），Edge 与条件边决定路由；② OverAllState 是全局状态，节点不传消息而是返回“状态增量”，按每个 key 的合并策略（Replace／Append）写回——这决定了并行分支的写冲突语义；③ compile() 把声明式图转成可执行结构并做图校验（可达性、路由完整性）；④ 执行是“超步”模型：每个超步跑完当前激活节点集合、合并状态、再算下一批，天然支持并行分支与循环；配 Checkpoint 按 threadId 持久化状态，实现中断恢复与 human-in-the-loop，输出侧用 Reactor Flux 流式。与直接用 ChatClient 链式编排的区别：链是一趟单向流水线，图能表达分支、循环、状态回溯与暂停续跑，复杂 Agent 拓扑的控制流从代码里的 if-else 外化成数据。答题落点：我在项目里用它做过【真实场景，按实际填写】，节点划分与状态 key 设计是主要工程量。版本口径 1.x，细节以官方文档为准。

## Q05：为什么要有线程池？怎么创建线程池，拒绝策略有哪些？

原题 6—8 同属线程池话题，按提问顺序合并。

### 面试回答

为什么：线程创建销毁是系统调用级成本，无节制创建还会打爆内存与调度；线程池做三件事——复用线程摊薄创建成本、限制在途并发保护 CPU／内存／下游、统一管理生命周期与监控。创建方式：正确姿势是显式 `new ThreadPoolExecutor(核心数, 最大数, 空闲存活时间, 单位, 工作队列, 线程工厂, 拒绝策略)` 七参构造；Executors 工厂方法只是包装且有官方明示隐患——newFixedThreadPool 与 newSingleThreadExecutor 用无界 LinkedBlockingQueue，任务积压能 OOM；newCachedThreadPool 与 newScheduledThreadPool 允许 Integer.MAX_VALUE 线程数，线程爆炸。生产按《阿里巴巴 Java 开发手册》口径禁用快捷工厂，Spring 场景常用 ThreadPoolTaskExecutor 再接生命周期管理。拒绝策略四种：AbortPolicy 默认、抛 TaskRejectedException；CallerRunsPolicy 让提交线程自己跑，形成天然背压但会拖慢提交方；DiscardPolicy 静默丢新任务；DiscardOldestPolicy 弹掉队首最老任务再重试——丢任务都要求业务可容忍，生产实践是自定义 RejectedExecutionHandler：记日志、报警、降级入队或持久化补偿，而不是选一个内置策略完事。

## Q06：多线程怎么保证线程安全？

### 面试回答

按成本从低到高给一个梯度：① 根本不共享——栈封闭、每线程各一份、不可变对象（final 正确发布、record）；② 共享但不写——只读的派生数据，或 volatile／Atomic／LongAdder 这类单变量无锁更新，注意它们只保证单操作原子，i++ 复合动作不行；③ 显式互斥——synchronized 或 ReentrantLock 圈住临界区，配 wait/notify 表达条件；④ 直接交给并发组件——ConcurrentHashMap 的 computeIfAbsent、BlockingQueue，把 check-then-act 这类竞态收进原子方法，别自己拼；⑤ 架构层面消灭共享——单写者＋消息传递（Disruptor／队列）、分片降低争用。收尾立判断标准：先问“这份数据真的需要跨线程可变共享吗”，能降级成前两种就不用锁；同时保持死锁四条件与锁顺序的警觉。

## Q07：synchronized 和 ReentrantLock 的区别。

### 面试回答

都是可重入独占锁，差别在使用契约与能力面：synchronized 是 JVM 内建，monitor 语义、获取释放由字节码与管理器自动完成，不会忘记解锁，支持锁升级优化（轻量级／重量级，偏向锁 JDK 15 起废弃）；ReentrantLock 是 API 层实现，必须 finally unlock，换来 synchronized 给不了的能力——可中断获取 lockInterruptibly、超时 tryLock、公平锁选项、多个 Condition 精确唤醒（如读写分离队列），以及和 AQS 生态的可组合性。选择口径：没有特殊需求用 synchronized，代码更安全可读；需要超时／中断／公平／多条件等待才上 ReentrantLock。JDK 21 虚拟线程场景下 synchronized 长临界区曾钉住载体线程（JDK 24 JEP 491 缓解），阻塞式锁在高并发 IO 服务里更推荐 Lock 或无锁结构。

## Q08：ReentrantLock 底层原理；AQS 怎么实现、如何保证 state 的原子性？

原题 11—12 递进话题，合并作答。

### 面试回答

ReentrantLock 内部是一个 AQS 子类 Sync：锁状态就是 AQS 的 `state`（int）——0 表示无人持锁，加锁是 CAS 把 state 0→1 成功后记 owner，重入是同线程再 CAS 自增，释放递减到 0 才真正放开；公平与非公平只差获取时一步——公平版先 `hasQueuedPredecessors()` 查队列、非公平版直接插队 CAS，所以非公平吞吐高但可能饥饿。拿不到锁的线程被包成 Node（存线程、waitStatus）CAS 入 CLH 变体的 FIFO 双向队列，前驱是 head 且重试成功才出闸，否则 park 挂起；释放时 unparkSuccessor 从 tail 向前找有效后继唤醒。Condition 队列独立存放 await 节点，signal 时整体转移到同步队列参与竞争。AQS 怎么保证 state 原子：state 是 volatile 保证可见性与禁重排，但 volatile 管不了“读—改—写”复合动作，所以所有修改统一走 compareAndSetState——Unsafe／VarHandle 落到 CPU 原子指令（x86 lock cmpxchg），要么整个成功要么不变，失败重读重试；“volatile 读＋CAS 写”组合就是无锁原语的标准形态，锁自身不再依赖上层锁。

## Q09：垃圾回收算法有哪些？

### 面试回答

基础三件套：标记—清除（快但碎片化）、标记—整理（无碎片但移动成本高）、复制（年轻代专用，存活少时高效，代价是空间减半——实践按弱分代假设定 Eden:S0:S1＝8:1:1 把浪费压到两成）。在这个之上是分代收集：Minor GC 用复制算法处理新生代，Full GC 用标记—整理处理老年代。收集器演进要连着报：Serial／ParNew→CMS（并发标记清除、低停顿但碎片与 CPU 敏感，JDK 14 移除）→G1（堆划 Region、可预测停顿模型、混合回收，JDK 9 起默认）→ZGC／Shenandoah（着色指针／转发指针做到停顿与堆大小基本无关，ZGC JDK 15 转正、21 起分代）。加分点：算法与收集器是两层概念，别把“标记整理”和 G1 并列背；判断对象存活用可达性分析（GC Roots），引用强度四级决定回收时机。

## Q10：对象在 JVM 中的生命周期；新生代 S0/S1 的作用与晋升老年代的时机。

原素材在 15 题保留候选人自评“这个没怎么答好、没说完整”，故此处给完整版供复盘。

### 面试回答

生命周期一条线：new 之后在 Eden（带 TLAB 的线程私有分配）诞生；Minor GC 来临时可达对象被复制到 Survivor，年龄＋1；反复存活到 MaxTenuringThreshold（默认 15）晋升老年度，之后老年代回收（Full GC／mixed GC）时若不可达被清除，对象终结。中间穿插三类捷径：大对象按 `-XX:PretenureSizeThreshold`（Serial／ParNew 口径，G1 用 Region 直接放）或动态判定直接进老年防 Survivor 颠簸；Survivor 内同龄对象总和超过其一半时，年长对象提前晋升（动态年龄判定）；逃逸分析开启时，不逃逸的对象根本不上堆——标量替换拆成栈上局部变量，锁也可能被消除。S0/S1 的作用：复制算法要求“从一块活区倒进一块空区”，两个 Survivor 互为 from／to 角色，每轮 Minor GC 后交换，活对象始终集中在一个区——这就是不产生碎片、成本只与存活对象数成正比的来源；如果只有一个区就得整堆扫描整理，代价高得多。没答全的点常是“什么时候去老年代”：满阈值晋升、动态年龄、大对象直达、Minor GC 时 Survivor 放不下（分配担保进老年）四条，缺一条就不完整。

## Q11：Kafka 特性、与 RabbitMQ 的区别、高吞吐量的原因。

原素材在 17 题保留候选人自评“答的很一般”，此处给完整版供复盘。

### 面试回答

特性：Kafka 本质是分布式提交日志——topic 分区、分区内有序追加、消费者按 offset 拉取，消息是“可重放的流”而非“消费即消失的队列”；配合消费者组、副本 ISR、Connector／Streams 生态。与 RabbitMQ 的区别从模型讲起：Rabbit 是 broker 路由模型（exchange 按规则分发到 queue，push 为主，消息取出即删），擅长复杂路由、低延迟（微秒级）、per-message 可靠语义；Kafka 是日志模型（pull＋offset，分区决定并行与顺序），擅长吞吐（百万级 TPS）、消息回溯、流处理，顺序只保证到分区粒度。选型：订单通知类业务消息用 Rabbit，日志采集、行为流、大数据管道用 Kafka。高吞吐四个支柱：① 顺序写磁盘＋页缓存——追加写把随机 IO 变顺序，OS page cache 让热数据根本不过用户态；② 零拷贝 sendfile——消费时数据从页缓存直达网卡，省四次拷贝三次切换；③ 分区并行——生产消费都可按分区水平扩展，并行度随分区数线性涨；④ 批量＋压缩——producer 攒批、broker 按批存储、消费者按批拉，压缩批原样传输，摊薄协议与网络开销。

## Q12：大模型产生幻觉的原因及解决方案。

### 面试回答

原因从生成机制讲就不是玄学：模型学的是 token 条件概率分布，训练目标是“像下一个词”不是“真”，知识以参数化记忆存在、长尾事实稀疏或过期就会编；解码带随机采样，错误 token 会沿自回归滚雪球（暴露偏差）；训练数据本身有错误与冲突；上下文里矛盾信息或超长窗口里的注意力稀释也会诱发。解决分层：知识侧——RAG 接地，外部证据可更新可引用；推理侧——CoT 拆步、把计算交给确定性工具（SQL／计算器／检索），降温度；生成侧——提示词显式允许拒答、要求带引用；验证侧——自一致性多采样比对、引用支持度校验、独立模型或规则审查，关键链路 human-in-the-loop；训练侧——SFT 提质数据、DPO／RLHF 把“不确定时坦白”对齐进模型。收口诚实声明：只能压缩幻觉率与影响面，不能归零；按场景定预算，财务数字类要校验兜底，创意类可宽松。

## Q13：RAG 的具体实现过程。

### 面试回答

离线在线两段讲。离线入库：文档采集→解析清洗（格式归一、去噪、保留结构与来源元数据）→分块（按语义／标题层级切，控制粒度并保留上下文重叠，块大小按下游模型窗口与召回精度实验定）→embedding 向量化＋关键词索引双写进向量库；更新策略是增量重算加版本失效。在线查询：问题理解（改写、补全指代，复杂时路由到不同库）→混合召回（向量 top-k 加 BM25，权限过滤必须在召回层生效）→重排（cross-encoder 精排压噪声）→上下文组装（去重、按预算截断、指令约束“仅依据资料回答、缺证据明确拒答”）→生成带引用→出口校验引用是否支持结论。最后一块是评测闭环：建评测集跑召回命中与答案忠实度，坏例回流优化切块与索引——没有评测的 RAG 只是玄学拼接。项目细节（模型选型、指标数字）按【真实实现】口径替换。

## Q14：预训练和微调的区别。

### 面试回答

预训练是在海量无标注语料上做自监督（下一 token 预测），把语言与世界知识压进参数，产出 base 模型——这是算力大头，千卡月级，一次性投入决定能力上限。微调是拿小规模任务数据继续训练：SFT 用“指令—回答”对学会听指令与输出格式，偏好阶段 RLHF／DPO 对齐人类偏好，工程上常用 LoRA／QLoRA 只训旁支参数把成本降到单机可跑——产出 instruct／chat 模型，改变的是行为方式与领域风格，不创造预训练没有的底层能力。对比维度一起报：数据（规模、标注程度）、目标函数、算力与频率（预训练一次、微调可反复低成本）、风险（微调过量会灾难性遗忘通用能力，混入通用数据或用 PEFT 缓解）。落点接实践：知识时效问题不该用微调解决（会过期、会幻觉），该走 RAG；微调用于固定格式、风格、领域行为，见 LLM-008。

## Q16：手撕 LeetCode 415（字符串相加）。

按 LeetCode 415 标准题解作答：给定两个非负整数字符串，模拟竖式加法返回结果字符串，不得直接使用内置大整数库。

### 面试回答

双指针从两串末尾对齐扫描：每轮取 `num1[i]`、`num2[j]`（越界记 0）与进位求和，`sum%10` 追加、`sum/10` 作进位；一方耗尽继续走另一方，最后进位若有余再补一位；因为是逆序拼接，结束反转。时间 O(max(m,n))，空间 O(max(m,n)) 存结果。Java 用 StringBuilder 从尾追加再 `reverse()`。坑点：全零边界（`"0"+"0"`→`"0"`，循环条件要允许“两指针耗尽但进位为 1”多跑一轮或循环后补位）、char 转数值是 `c-'0'` 别直接加 char、题目约定无前导零所以不必自己裁剪。写完用 `["999","1"]→"1000"` 走一遍验证。
