## Q02：迁移前的 Workflow 是什么形式，节点是提示词还是代码？

原文题号：2。

### 面试回答

迁移前的 Workflow 需按真实项目说清【使用的框架】和【节点图】。Workflow 不等于一串 Prompt：一个节点可以调模型，也可以执行普通代码、工具、条件分支或人工审批。迁移时，可以把可复用的处理经验和操作规则抽成 Skill，把可确定执行的校验放进脚本或服务，状态和权限仍由运行时管理。如果业务必须严格按固定顺序执行，Workflow 仍然应该保留，Skill 不是它的无条件替代品。

## Q09：一次 MCP 调用如何完成，模型、Agent、Client 和 Server 分别做什么？

原文题号：9。

### 面试回答

以 MCP 2025-06-18 的 tools 调用为例：宿主建立 Client 与 Server 的连接并初始化协商能力，通过 tools/list 获取工具定义，转换成模型可理解的工具描述。模型通常提出工具名和参数，Agent 运行时校验参数及授权，再由 MCP Client 发送 tools/call；Server 路由到工具实现，执行代码或调用业务系统后返回结果；宿主把结果交回模型，继续推理或作答。模型提出调用意图，Client 发协议请求，Server 及其后端执行操作；固定程序也能主动调工具，协议不要求每次调用都由模型决定。初始化和发现通常可复用，不必每次调用重复。

## Q11：上下文过长时如何继续对话，怎样有重点地压缩？

原文题号：11、12。

### 面试回答

我会在耗尽窗口前按 token 预算处理，并预留输出和工具往返空间。先按需加载文件与工具定义，限制检索数量、分页或缩减冗长工具输出；再对旧对话做结构化摘要，结合近期消息与外部状态继续会话。压缩不能一视同仁：优先保留当前目标、用户约束、有效授权范围、关键事实和标识、已做决定、未完成事项、失败原因及证据入口；重复讨论和可重新读取的长日志可以缩减。摘要要区分已完成与计划、事实与推测，保留工具请求与结果的关联，重新读取关键状态验证后继续。压缩只能降低信息损失风险，不能保证无限无损对话。

## Q12：OpenCode、Claude Code、Codex、DeepSeek 的上下文机制有什么差异？

原文题号：13。

### 面试回答

先区分产品层次：OpenCode、Claude Code、Codex 是带运行循环和上下文管理的编码 Agent 产品；“DeepSeek”未说明具体产品，这里暂按模型 API 理解。按 2026-09-13 查到的滚动官方文档，OpenCode 有 compaction.auto、prune、reserved 等配置；Claude Code 会清理旧工具输出并按需摘要，支持 /compact 指定关注内容；Codex 有 model_auto_compact_token_limit 自动压缩阈值配置。模型 API 的上下文窗口与缓存能力不能直接当作 Agent 的摘要、状态恢复和长期记忆机制。DeepSeek 指代及具体上下文实现待确认，不猜测其内部压缩算法。

## Q14：Memory 如何检索和更新，用户从北京搬到上海后怎样处理旧记录？

原文题号：15。

### 面试回答

我会按用户身份、记忆类型和有效时间先过滤，再结合关键词、语义相关性及可信度召回，不只按向量相似度。用户明确说已搬到上海后，将“当前居住城市”更新为上海，给北京记录设置失效状态或结束时间；若业务需要且允许保留历史，保存它作为过去居住记录。只说去上海出差不能覆盖居住地，生效日期不明也不要编造。写入应做去重、冲突判断及版本控制，更新检索索引和缓存，避免旧北京记录继续作为现状返回；长期记忆还应支持用户纠正和删除。

## Q15：手撕：给定字符串，返回最长回文子串。

原文题号：16。

### 面试回答

采用中心扩展：回文左右对称，中心可能是一个字符，也可能是两个字符之间的空隙。遍历每个位置，分别向两边扩展奇数和偶数长度回文，遇到边界或不同字符停止，更新最长区间，最后返回子串。所有中心都被检查，因此能覆盖最长回文。时间 O(n²)，除返回字符串外辅助空间 O(1)。这里用 Java 示例，按 UTF-16 char 比较，null 和空串返回空串，同长取最先找到的一段；这些是示例约定，原题未指定字符范围、语言或同长规则。完整实现见专题。
