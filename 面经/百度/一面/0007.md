## Q01：手撕快速排序。

### 面试回答

快速排序先选一个基准值，用明确的分区规则把数组拆成两部分，使基准值左边不大于它，右边不小于它，然后递归排序左右区间。手写时我会选定 Lomuto 或 Hoare 其中一种分区法，分区和递归边界保持一致，确保每次递归区间都变小。平均时间复杂度是 O(n log n)，最坏是 O(n²)，平均递归栈深度是 O(log n)。随机选基准或三数取中可以降低持续出现极不均衡分区的概率。

## Q02：从输入 URL 到页面渲染经历哪些步骤？

### 面试回答

浏览器先解析 URL，并检查缓存、Service Worker 等可复用结果；需要联网时解析 DNS，建立或复用传输连接。HTTPS over TCP 还要完成 TCP 与 TLS 握手，HTTP/3 则基于 QUIC。浏览器发送 HTTP 请求、处理重定向并接收响应，解析 HTML 构建 DOM、解析 CSS 构建 CSSOM，执行脚本后形成渲染树，再完成布局、绘制与合成；子资源会继续触发请求。实际链路可能命中缓存或复用连接，并非每次都完整重走。

## Q03：HTTP 状态码如何分类，503 和 504 有什么区别？

### 面试回答

1xx 表示信息性响应，2xx 表示成功，3xx 表示重定向或缓存协商，4xx 表示客户端请求问题，5xx 表示服务端处理失败。503 Service Unavailable 表示当前服务暂时无法处理请求，常见于过载或维护，可结合 `Retry-After`；504 Gateway Timeout 表示充当网关或代理的服务器等待上游响应超时。两者都可能由上游故障引起，但 503 强调服务暂不可用，504 强调网关等待上游超时。

## Q04：TCP 三次握手的过程是什么？

### 面试回答

客户端发送 SYN 并给出初始序列号 x，进入 SYN-SENT；服务端回复 SYN+ACK，给出自己的初始序列号 y，并确认 x+1，进入 SYN-RECEIVED；客户端再发送 ACK 确认 y+1，双方进入 ESTABLISHED。三次握手让双方确认彼此的收发能力，并同步初始序列号；只做两次无法让服务端确认客户端是否收到了自己的序列号，也更难避免历史连接请求造成错误建连。

## Q05：缓存穿透和缓存雪崩是什么，如何解决？

### 面试回答

缓存穿透是持续查询不存在的数据，缓存无法命中而反复访问数据库；可用参数校验、短期空值缓存、布隆过滤器和限流缓解。缓存雪崩是大量 key 集中过期或缓存服务不可用，导致大量请求同时回源；应打散 TTL、提高缓存可用性，并通过限流、熔断降级和回源并发控制保护数据库。布隆过滤器存在假阳性，TTL 抖动也不能解决 Redis 整体故障，因此要组合治理。

## Q06：Redis 的过期删除和内存淘汰策略是什么？

### 面试回答

过期删除处理已经超过 TTL 的 key：Redis 在访问时进行惰性删除，同时周期性抽样并主动清理过期 key。内存淘汰则在达到 `maxmemory` 后按 `maxmemory-policy` 腾出空间，两者触发条件不同。策略包括 `noeviction`，面向所有 key 或仅带 TTL key 的 LRU、LFU、随机淘汰，以及 `volatile-ttl`；选择要结合 Redis 是纯缓存还是还承载不可丢状态，并监控淘汰率、命中率和内存余量。

## Q07：Redis 的 RDB 和 AOF 持久化有什么区别？

### 面试回答

RDB 保存某一时刻的数据快照，文件通常更紧凑、适合备份和较快加载，但故障可能丢失最近一次快照后的写入。AOF 记录写操作并在恢复时回放，数据丢失窗口取决于 fsync 策略，代价是更多写入与重写开销。两者可以同时启用，也可以采用 RDB 基础数据加 AOF 增量的混合形式；选型要结合可接受的数据丢失、恢复时间和运行成本。

## Q08：聚簇索引和非聚簇索引是什么？

### 面试回答

以 InnoDB 为前提，聚簇索引决定行数据的存储组织，其叶子节点保存完整记录；表通常按主键组织，没有合适主键时 InnoDB 会选择或生成内部聚簇键。非聚簇索引通常指二级索引，叶子节点保存索引列和聚簇主键值；查询所需列不能被二级索引覆盖时，要再按主键访问聚簇索引，即回表。一个表只有一种聚簇组织，但可有多个二级索引；不同存储引擎的实现不能一概而论。

## Q09：排查和优化慢 SQL 的思路是什么？

### 面试回答

先用监控、调用链和慢查询日志确认慢的是哪条 SQL、参数、频率及影响范围，并区分执行慢、锁等待、连接池等待和网络问题。对可复现 SQL 查看 `EXPLAIN`，在安全环境按需用 `EXPLAIN ANALYZE` 对比估算与实际行数、循环和耗时；检查访问行数、索引选择、连接顺序、排序、临时表、回表和统计信息。再针对原因调整 SQL 或索引、减少无用列和扫描、缩短事务或处理锁竞争，并用代表性数据压测和上线监控验证，不能只看到全表扫描就盲目加索引。
