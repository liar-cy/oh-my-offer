## Q01：HTTP 和 HTTPS 有什么区别，TLS 握手如何进行？

### 面试回答

一句话：HTTPS 就是用 TLS 给 HTTP 补上三件事——传输加密、完整性保护、服务端身份认证。这三件事 HTTP 本身都不提供。

握手按基于 TCP、走证书认证的 TLS 1.3 完整握手来讲：

- 客户端发 ClientHello，带上自己支持的版本、算法和 key share（密钥交换的临时公钥份额）。
- 服务端回 ServerHello，定下选用的参数和它自己的 key share；到这里双方就能各自派生出握手密钥。
- 服务端接着发一组已经加密的消息：EncryptedExtensions、Certificate、CertificateVerify、Finished。
- 客户端验证证书和握手证明，没问题再发自己的 Finished。
- 之后切换成应用流量密钥，用它来保护 HTTP 数据。

一句话收尾：证书证明的是“服务端身份”，加密和完整性保护的是“这段传输”，范围要说准。

## Q02：进程、线程和协程有什么区别，协程适合什么场景？

### 面试回答

按隔离程度从强到弱排：

- 进程：资源和地址空间的隔离单位，彼此隔开。
- 线程：进程内的执行单元。同一进程的线程共享堆等资源，但各自的调用栈和执行状态是独立的。
- 协程：由语言运行时或库来管理暂停、恢复和调度，通常比内核线程更轻。

协程适合什么场景：大量网络请求这类 I/O 等待很多的任务，用少量线程就能挂住很多等待中的工作。

反过来要说清边界：CPU 密集的任务想真正多核并行，还是得有多个实际的执行线程或进程，协程本身不解决这个问题。

## Q03：什么是系统调用，用户态和内核态有什么区别？

### 面试回答

先给定义：系统调用是用户程序请求内核服务的受控入口，比如读写文件、创建进程、操作网络。

两个态的区别就在权限：

- 用户态：权限受限，不能任意访问内核内存，也不能执行特权操作。
- 内核态：可以按硬件权限去做资源管理类操作。

一次过程这么说：程序执行系统调用指令陷入内核，内核检查参数和权限，执行完服务再返回用户态。

## Q04：select、poll 和 epoll 有什么区别？

### 面试回答

共同点先说一句：三者都是让线程等待多个文件描述符就绪。

差别在这里：

- `select`：用有容量限制的 `fd_set`（一位对应一个描述符的集合），调用之后还要重建集合。
- `poll`：改用数组，绕开了那个固定集合的限制，但还是要线性扫描。
- `epoll`：关注集合由内核维护，通过 `epoll_wait` 只把就绪事件返回来。

所以 `epoll` 通常更合适的场景是：连接数多、但活跃比例低。

三个补充点别说漏：

- 它仍然只是就绪通知，数据得应用自己读写。
- ET 模式（边缘触发，只在状态变化时通知一次）一般配合非阻塞 I/O，要一直读到返回 EAGAIN 为止。
- 不能把它说成“任何负载下都比前两个快”，不成立。

## Q05：TCP 为什么需要三次握手，两次行不行？

### 面试回答

先把三次说清楚：

- 第一次：客户端发 SYN，带上自己的初始序号 x。
- 第二次：服务端回 SYN+ACK，一边确认 x，一边发出自己的初始序号 y。
- 第三次：客户端再 ACK，确认 y。

两次为什么不行：那时候服务端其实还不知道两件事——客户端有没有收到它的初始序号，以及客户端是不是还在参与这次连接。

所以第三次的价值有两条：

- 完成双向序号同步。
- 避免服务端只凭一个延迟到达的旧 SYN，就把连接当成已经建立。

## Q06：什么是 TCP 滑动窗口，丢包后如何处理？

### 面试回答

先说窗口是什么：它允许发送方在确认回来之前，连着发一段范围内的数据，不用发一段就停下来等一次 ACK。

它怎么“滑动”：ACK 一到，已确认的边界往前推，窗口跟着往前挪。

窗口大小由两个方向一起卡：

- 接收窗口 rwnd：卡接收方扛得住多少。
- 拥塞窗口 cwnd：卡网络里在途的数据有多少。

丢包这一块，分发送方和接收方说：

- 发送方：靠重传超时，或者重复 ACK、SACK（选择性确认，告诉对方哪几段已经收到）这些线索发现丢包，然后重传。
- 接收方：把乱序到的数据先缓存下来、去掉重复，最后按序交付给应用。

## Q07：DNS 解析过程是什么，递归和迭代有什么区别？

### 面试回答

解析过程按顺序说：

- 客户端先查适用的本地缓存和主机映射。
- 没命中，通常就去问递归解析器。
- 解析器自己缓存里有，直接返回。
- 缓存没有，它按需从根服务器、顶级域服务器一路问到权威服务器，拿到目标记录后先缓存再返回。

递归和迭代怎么区分，看“谁去跑完剩下的路”：

- 递归：委托对方去查，对方要么给最终结果，要么给错误。
- 迭代：对方只给它手上有的答案，或者告诉你下一步该问谁，剩下得自己接着追。

所以实际常见组合是：客户端对解析器用递归，解析器对各级服务器用迭代。

## Q08：Cookie、Session 和 Token 有什么区别？

### 面试回答

三者根本不在一个层次上：

- Cookie：浏览器保存数据的一种机制，按域、路径这些规则随请求自动带上。
- Session：维护会话状态的一套方案。常见做法是状态存服务端，客户端用 Cookie 带一个 session ID。
- Token：代表身份或授权的凭证。形态有两种：不透明的值，需要服务端查；或者带签名、自包含的令牌。

容易答错的地方是把它们当成三选一。其实不互斥：

- Cookie 可以装 session ID，也可以装 Token。
- Token 也不等于 JWT。

## Q09：MySQL 的 InnoDB 和 MyISAM 有什么区别？

### 面试回答

先交代版本口径：以 MySQL 8.4 为例。

能力上的区别：

- InnoDB：支持事务、MVCC、行级锁和外键，并且靠 redo 这类日志实现崩溃恢复。常见的并发事务业务用它。
- MyISAM：不支持事务，也不支持外键；锁主要是表级锁；没有 InnoDB 那种事务层面的崩溃恢复能力。

存储结构上的区别：

- InnoDB：行按聚簇索引组织，二级索引里放的是主键。
- MyISAM：索引和数据分开存，索引指向数据记录的位置。

## Q10：redo log、undo log 和 binlog 分别有什么作用？

### 面试回答

三者各管一件事：

- redo log：InnoDB 崩溃恢复用的重做记录。价值在于已提交的修改即使数据页还没落盘，也能恢复回来。
- undo log：一来用于事务回滚，二来给 MVCC 提供历史版本。
- binlog：MySQL 服务层的变更日志，用于复制，以及配合备份做时间点恢复。

职责边界要划清，两句“不能替代”别说反：

- undo 代替不了备份。
- binlog 也不能单独代替 InnoDB 的崩溃恢复。

最后补一句协同：开启 binlog 时，引擎日志和 binlog 之间靠内部两阶段提交来协调事务状态。

## Q11：什么是覆盖索引，如何设计索引？

### 面试回答

先定义：覆盖索引是指某条查询要取的列，一个索引就全能提供，因此通常能减少回表（拿着主键再回聚簇索引取整行）。

一个概念澄清：它是“某条查询和某个索引之间的关系”，不是一种独立的索引类型。同一根索引用在这条 SQL 上是覆盖，换一条要取别的列就不覆盖了。

怎么设计，按这个顺序说：

- 从高频 SQL 出发，看它的过滤列、连接列、排序列和返回列。
- 再定联合索引的列顺序，考虑最左前缀。
- 然后用选择性、写入成本、执行计划去验证取舍。

一句话收尾：不能给每个字段都建一个索引。

## Q12：缓存穿透、击穿和雪崩有什么区别，如何解决？

### 面试回答

一句话区分：穿透查的是根本没有的数据，击穿是一个热点 key 失效，雪崩是一片 key 一起失效。

- 穿透：请求不存在的数据，缓存永远命不中，于是反复绕过缓存去查数据库。
  - 解法：参数校验、短期空值缓存、布隆过滤器，再加限流。
- 击穿：单个热点 key 失效的瞬间，大量请求同时回源。
  - 解法：互斥重建、请求合并、提前刷新；业务允许的话，也可以先返回旧值、异步去更新。
- 雪崩：大量 key 集中过期，或者缓存服务整个不可用，造成大范围回源。
  - 解法：把 TTL（过期时间）打散、提升缓存本身的可用性，再用限流、熔断降级和限制回源并发把数据库护住。

## Q13：Redis 有哪些持久化方式，RDB 和 AOF 有什么区别？

### 面试回答

Redis 有两种持久化，各自的取舍不一样。

- RDB：把某一时刻的数据存成快照。文件通常比较紧凑，适合备份和快速加载；代价是故障时可能丢掉最近一次快照之后的写入。
- AOF：把写操作记下来，靠回放恢复。丢多少由 fsync（刷盘）策略决定；文件通常更大，而且需要重写。

两者不是二选一：可以同时开，也有“以 RDB 为基础数据、再叠 AOF 增量”的混合形式。

怎么选，就问一句：业务能接受多少数据丢失，再对照恢复时间和运行开销来定。

## Q14：CSRF 和 XSS 有什么区别，如何防御？

### 面试回答

先分清攻击本质：

- XSS：不可信的内容被当成脚本，在受害站点的上下文里执行了。
- CSRF：诱导一个已登录的浏览器，带着它会自动携带的凭证，去发一个本人并不想发的请求。

防 XSS，核心是“别让内容变成代码”：

- 按上下文分别正确编码：HTML 正文、属性、URL、脚本各是各的规则。
- 用安全的 DOM API 操作内容。
- 富文本交给可信的清洗器处理。
- 再配一层 CSP（内容安全策略，由响应头声明允许执行哪些来源）兜底。

防 CSRF，核心是“确认这个请求真是用户想发的”：

- 状态修改类请求要校验 CSRF Token。
- 结合 Origin／Referer 校验和 SameSite Cookie。
- 不要用 GET 去做状态修改。

## Q15：JVM 内存模型如何理解，垃圾回收算法有哪些？

题意说明：原文“JVM 内存模型”未明确指运行时数据区还是 JMM，以下分别说明，不把其中一种解释认定为原题。

### 面试回答

开口先问一句自己：这个词在面试里常有两种含义，得先确认面试官问的是哪个。

如果问的是 JVM 运行时数据区：

- 线程私有：程序计数器、虚拟机栈、本地方法栈。
- 线程共享：堆、方法区。
- 运行时常量池属于方法区。
- HotSpot 里，方法区通常是用元空间来实现的。

如果问的是 Java Memory Model（Java 内存模型，简称 JMM）：重点就换成了共享变量的可见性、有序性、原子性，以及 `happens-before` 规则。

垃圾回收这块，先说流程：一般从 GC Roots 出发做可达性分析，判活之后再选算法回收。

- 标记清除：不移动存活对象，但会留下内存碎片。
- 复制：把存活对象搬到另一块空间。适合存活率低的区域，代价是要多留一块空间。
- 标记整理：移动存活对象把空间压缩紧，碎片少了，但有搬迁成本。

最后区分两个常被混用的词：分代收集是“按对象寿命组织回收”的策略，而 G1、ZGC 这些是具体的收集器，不能当成算法名称来讲。

## Q16：HashMap 和 ConcurrentHashMap 有什么区别？

### 面试回答

先看基本定位和 null 的差别：

- HashMap：不支持没有同步保护的并发修改；允许一个 null key，也允许多个 null value。
- ConcurrentHashMap：提供线程安全的并发访问；键和值都不允许 null。

再补一句容易说过头的：ConcurrentHashMap 保证的是单次操作安全，不等于你多步拼起来的业务逻辑自动就是原子的。

典型场景“先判断再插入”，要用 `putIfAbsent` 或者合适的 `compute` 方法，而不是自己读一遍再写一遍。

怎么选：单线程、或者外面统一加锁管理的场景用 HashMap；多线程共享的那张映射，通常选 ConcurrentHashMap。

## Q17：Docker 容器和虚拟机有什么区别，为什么更轻量？

### 面试回答

一句话讲隔离边界：虚拟机虚拟的是硬件，容器隔离的是进程。

- 传统虚拟机：通过虚拟化硬件，跑一套自己独立的客户操作系统内核。
- 常见的 Linux Docker 容器：本质是一个被隔离开的进程，共享宿主的 Linux 内核。
- 它的隔离靠三样：namespace 隔开资源视图，cgroup 约束资源用量，镜像带上应用和依赖。

为什么更轻量：容器一般不用给每个实例都起一套完整的客户内核，所以启动更快、额外资源开销更少。

最后一句别说满：省的是启动和资源开销，但容器的隔离方式跟虚拟机并不相同。

## Q18：Kubernetes 是什么，解决什么问题？

### 面试回答

先给定义：Kubernetes 是容器化应用的编排平台。它的工作方式是声明式——你描述期望状态，控制器不停地拿实际状态去对比并协调，直到对上。

- 多节点上应用怎么调度。

顺手把 Docker 的关系说清，别混为一谈：Docker 侧重构建和运行容器，Kubernetes 侧重管理集群里的工作负载，两者不在同一层。

## Q19：RAG 的流程是什么，如何缓解大模型幻觉？

### 面试回答

一句话定义：RAG 就是把“检索外部证据”接进“生成答案”这条链路。

分两条线说：

- 离线：解析、清洗文档，分块并且保留来源，再建向量索引或关键词索引。
- 在线：理解问题，然后召回、过滤、重排，组装成上下文，让模型依据证据作答并给出引用。
