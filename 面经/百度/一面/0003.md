## Q01：HTTP 和 HTTPS 有什么区别，TLS 握手如何进行？

### 面试回答

HTTPS 使用 TLS 为 HTTP 提供传输加密、完整性保护和服务端身份认证；HTTP 本身不提供这些保护。以基于 TCP、证书认证的 TLS 1.3 完整握手为例：客户端发 ClientHello，携带支持版本、算法和 key share；服务端回 ServerHello 选择参数和 key share，双方派生握手密钥；服务端发送加密的 EncryptedExtensions、Certificate、CertificateVerify 和 Finished；客户端验证证书及握手证明，再发 Finished，随后用应用流量密钥保护 HTTP 数据。

## Q02：进程、线程和协程有什么区别，协程适合什么场景？

### 面试回答

进程是资源与地址空间的隔离单位；线程是进程内的执行单元，同进程线程共享堆等资源，各有调用栈和执行状态；协程由语言运行时或库管理暂停、恢复与调度，通常比内核线程更轻。协程适合大量网络请求等 I/O 等待较多的并发任务，能用较少线程承载很多等待中的工作；CPU 密集任务要想多核并行，仍需多个实际执行线程或进程。

## Q03：什么是系统调用，用户态和内核态有什么区别？

### 面试回答

系统调用是用户程序请求内核服务的受控入口，例如读写文件、创建进程和操作网络。用户态权限受限，不能任意访问内核内存或执行特权操作；内核态可按硬件权限执行资源管理操作。程序通过系统调用指令进入内核，内核检查参数和权限、执行服务并返回用户态。

## Q04：select、poll 和 epoll 有什么区别？

### 面试回答

select、poll 和 epoll 都让线程等待多个文件描述符就绪。select 用有容量限制的 fd_set，调用后还要重建集合；poll 用数组，避免该固定集合限制，但仍需扫描。epoll 在内核维护关注集合，通过 epoll_wait 返回就绪事件，在连接多而活跃比例低时通常更合适；它仍是就绪通知，数据要由应用读写。ET 模式通常配合非阻塞 I/O，处理到 EAGAIN，不能把 epoll 描述为任何负载下都更快。

## Q05：TCP 为什么需要三次握手，两次行不行？

### 面试回答

客户端发送 SYN 和初始序号 x，服务端用 SYN+ACK 确认 x 并发送自己的初始序号 y，客户端再 ACK 确认 y。两次握手时，服务端还不知道客户端是否收到自己的初始序号、是否仍参与当前连接；第三次确认完成双向序号同步，也避免服务端仅凭延迟到达的旧 SYN 就把连接当成已建立。

## Q06：什么是 TCP 滑动窗口，丢包后如何处理？

### 面试回答

TCP 滑动窗口允许发送方在收到确认前连续发送一段范围内的数据，不必每发一段就等待 ACK。ACK 推进已确认边界，窗口随之滑动；接收窗口 rwnd 限制接收方容量，拥塞窗口 cwnd 限制网络中的在途数据。丢包可通过重传超时或重复 ACK、SACK 等线索检测并重传，接收方缓存乱序数据、去重，最终按序交付。

## Q07：DNS 解析过程是什么，递归和迭代有什么区别？

### 面试回答

客户端先检查适用的本地缓存和主机映射，未命中时通常向递归解析器查询。解析器有缓存就直接返回，否则按需从根、顶级域到权威服务器逐级查询，拿到目标记录后缓存并返回。递归是委托对方返回最终结果或错误；迭代是对方返回已有答案或下一步应询问的服务器，由查询方继续追踪。常见模式是客户端向解析器递归查询，解析器向各级服务器迭代查询。

## Q08：Cookie、Session 和 Token 有什么区别？

### 面试回答

Cookie 是浏览器保存并按域、路径等规则随请求发送数据的机制；Session 是维护会话状态的方案，常见做法是服务端保存状态、客户端用 Cookie 携带 session ID；Token 是代表身份或授权的凭证，可以是服务端查询的不透明值，也可以是带签名的自包含令牌。三者不互斥，Cookie 可以承载 session ID，也可以承载 Token，Token 不等于 JWT。

## Q09：MySQL 的 InnoDB 和 MyISAM 有什么区别？

### 面试回答

以 MySQL 8.4 为例，InnoDB 支持事务、MVCC、行级锁和外键，并用 redo 等实现崩溃恢复，适合常见并发事务业务；MyISAM 不支持事务与外键，主要使用表级锁，没有 InnoDB 那样的事务崩溃恢复能力。InnoDB 按聚簇索引组织行，二级索引包含主键；MyISAM 索引和数据分离，索引定位数据记录。

## Q10：redo log、undo log 和 binlog 分别有什么作用？

### 面试回答

redo log 是 InnoDB 崩溃恢复所需的重做记录，使已提交修改即使数据页还未落盘也能恢复；undo log 用于事务回滚，并为 MVCC 提供历史版本；binlog 是 MySQL 服务层的变更日志，用于复制和结合备份做时间点恢复。三者职责不同：undo 不能代替备份，binlog 不能单独代替 InnoDB 的崩溃恢复；启用 binlog 时，引擎与 binlog 通过内部两阶段提交协调事务状态。

## Q11：什么是覆盖索引，如何设计索引？

### 面试回答

覆盖索引指某条查询所需的列都可由一个索引提供，通常能减少回表；它是查询和索引的关系，并非独立索引类型。设计索引要从高频 SQL 的过滤、连接、排序与返回列出发，考虑联合索引列序和最左前缀，再结合选择性、写入成本与执行计划验证，不能给每个字段都建索引。

## Q12：缓存穿透、击穿和雪崩有什么区别，如何解决？

### 面试回答

穿透是请求不存在的数据，反复绕过缓存查数据库，可用参数校验、短期空值缓存、布隆过滤器和限流。击穿是单个热点 key 失效后，大量请求同时回源，可用互斥重建、请求合并、提前刷新，或在业务允许时返回旧值并异步更新。雪崩是大量 key 集中过期或缓存服务不可用，造成大范围回源，要打散 TTL、提升缓存可用性，并通过限流、熔断降级和回源并发限制保护数据库。

## Q13：Redis 有哪些持久化方式，RDB 和 AOF 有什么区别？

### 面试回答

RDB 保存某一时刻的数据快照，文件通常紧凑、适合备份和快速加载，但故障可能丢失最近快照后的写入；AOF 记录写操作，通过回放恢复，持久性由 fsync 策略决定，文件通常更大并需重写。两者可同时使用，也有 RDB 基础数据加 AOF 增量的混合形式；选择要结合能接受的数据丢失、恢复时间和运行开销。

## Q14：CSRF 和 XSS 有什么区别，如何防御？

### 面试回答

XSS 是不可信内容被当作脚本在受害站点上下文执行；CSRF 是诱导已登录浏览器带着自动携带的凭证执行非本意请求。防 XSS 要按 HTML、属性、URL、脚本等上下文正确编码，使用安全 DOM API，富文本采用可信清洗器，配合 CSP。防 CSRF 要对状态修改请求校验 CSRF Token，结合 Origin／Referer 校验和 SameSite Cookie，不用 GET 执行状态修改。

## Q15：JVM 内存模型如何理解，垃圾回收算法有哪些？

题意说明：原文“JVM 内存模型”未明确指运行时数据区还是 JMM，以下分别说明，不把其中一种解释认定为原题。

### 面试回答

这个词在面试中常有两种含义。如果问 JVM 运行时数据区，线程私有的是程序计数器、虚拟机栈和本地方法栈，线程共享的是堆和方法区，运行时常量池属于方法区；HotSpot 中通常用元空间实现方法区。如果问 Java Memory Model，重点则是多线程对共享变量的可见性、有序性和原子性，以及 `happens-before` 规则。

垃圾回收一般先从 GC Roots 做可达性分析，再采用标记清除、复制或标记整理等算法回收。标记清除不移动存活对象但会留下碎片；复制将存活对象搬到另一块空间，适合存活率较低的区域但需额外空间；标记整理移动存活对象以压缩空间，减少碎片但有搬迁成本。分代收集是按对象寿命组织回收的策略，G1、ZGC 等则是具体收集器，不能混为算法名称。

## Q16：HashMap 和 ConcurrentHashMap 有什么区别？

### 面试回答

HashMap 不支持无同步的并发修改，允许一个 null key 和多个 null value；ConcurrentHashMap 提供线程安全的并发访问，不允许 null 键值。ConcurrentHashMap 的单次操作安全，不等于多步业务逻辑自动原子化；先判断再插入应使用 putIfAbsent 或合适的 compute 方法。HashMap 适合单线程或由外部统一同步的场景，共享并发映射通常选 ConcurrentHashMap。

## Q17：Docker 容器和虚拟机有什么区别，为什么更轻量？

### 面试回答

传统虚拟机通过虚拟化硬件运行独立客户操作系统内核；常见 Linux Docker 容器是隔离的进程，共享宿主 Linux 内核，用 namespace 隔离资源视图、cgroup 约束资源，并通过镜像提供应用与依赖。容器通常不用为每个实例启动完整客户内核，因此启动快、额外资源开销较少，但隔离方式与虚拟机不同。

## Q19：RAG 的流程是什么，如何缓解大模型幻觉？

### 面试回答

RAG 把外部证据检索接入生成。离线解析清洗文档、分块并保留来源，建立向量或关键词索引；在线理解问题、召回、过滤、重排并组装上下文，让模型依据证据作答和引用。缓解幻觉要同时改善证据质量和答案约束：使用可靠且及时的资料，检查检索是否命中，要求结论有证据，证据不足时明确无法回答，并校验引用是否真正支持结论。RAG 能降低幻觉，不能保证消除。

## Q20：是否会 Go，goroutine 的底层实现是什么？
