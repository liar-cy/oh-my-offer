原文题号：1。

### 面试回答

## Q02：进程、线程、协程有什么区别，进程间如何通信？

原文题号：2。

### 面试回答

一句话：三者差在隔离级别和谁来调度；进程之间要通信，还得靠显式约定的通道。

- 进程：提供地址空间与资源隔离。
- 线程：进程内的执行单元，共享堆等资源，但各自有自己的栈和执行状态。
- 协程：由运行时或库来调度暂停与恢复，适合大量等待的任务。但要多核并行，仍然需要线程或进程支持。

进程间通信可用的有：管道、命名管道、消息队列、共享内存、信号、Socket。几种的选择点：

- 共享内存：适合批量共享数据，但要另外做一套同步。
- 信号：偏向事件通知。
- Socket：同一台机器或跨机器都能用。

## Q03：Linux 内存如何分布？

原文题号：3（内存部分）。

### 面试回答

开口先澄清一句：“内存分布”没说清是指进程的虚拟地址空间，还是内核的物理内存管理，这是两个问题。

如果问的是进程布局，常见的段有这些：

- 代码段、只读数据段、已初始化数据段。
- BSS：零初始化的那部分数据。
- 堆、文件或匿名映射。
- 线程栈。

这些是虚拟地址，真正的物理页要靠页表映射过去。

如果问的是系统物理内存，那就换成另一套东西：物理页、NUMA 节点（多 CPU 各贴一块本地内存的架构）和 zone、页分配器、内核对象分配、页缓存。

最后补一条边界：不能把进程那套地址布局理解成 RAM 里连续排列的固定分区。具体地址会随架构、ASLR（地址空间布局随机化）和进程不同而变。

## Q04：介绍 I/O 多路复用。

原文题号：3（I/O 部分）。

### 面试回答

一句话：I/O 多路复用就是让一个线程同时等待多个文件描述符就绪，再处理可读可写的事件。

三种做法的差别：

- `select`、`poll`：每次调用都要把关注的集合提交给内核，再检查一遍。
- `epoll`：内核里长期维护关注集合，只把就绪事件返回来。

所以 `epoll` 适合“连接很多、但活跃比例低”的场景。

两个容易说错的点：

- 它只是就绪通知，数据还得应用自己用 `read`／`recv` 去读，不能当成异步完成通知。
- `epoll` 的 ET（边缘触发）通常要配非阻塞 I/O，一次读到返回 `EAGAIN` 才算读干净。

## Q05：OSI 七层与 TCP/IP 四层有什么区别，如何映射？

原文题号：4。

### 面试回答

先按顺序把 OSI 七层背出来，再说它和 TCP/IP 四层的归并关系。

- OSI 从低到高：物理、数据链路、网络、传输、会话、表示、应用层。
- 常见 TCP/IP 四层模型的映射：物理和数据链路归入链路层；网络层对应网际层；传输层还是传输层；会话、表示、应用三层一起归入应用层。

两者的定位不同：

- OSI 是参考用的分层模型。
- TCP/IP 是围绕互联网那一套协议组织起来的。

最后交代一句口径：这个映射是教学上的概括，实际协议的职责不总能严格一一对应。

## Q06：TCP 和 UDP 有什么区别？

原文题号：5（对比部分）。

### 面试回答

最本质的区别：TCP 面向连接，UDP 无连接。

- TCP：可靠的、有序的字节流，自带重传、流量控制和拥塞控制；代价是不保留消息边界。
- UDP：数据报，保留消息边界；但协议自身不保证送达，也不保证有序或去重。

这里字节流的意思是“一串连续的字节，不告诉你一条消息从哪到哪”，数据报则是一条一条独立投递。

补两点显得理解到位：

- 用 UDP 不代表就要放弃可靠性，应用可以在它上面自己实现可靠传输，QUIC 就是这么做的。
- 不能简单说 UDP 必然更快。选哪个，要看业务需要的语义和对时延的要求。

## Q07：TCP 四次挥手如何进行，第二次和第三次能否合并？

原文题号：5（挥手部分）。

### 面试回答

常规过程四个报文：主动方发 FIN，对端回 ACK，对端发完自己的 FIN，主动方再回 ACK。

为什么要拆成两次：

- 收到 FIN，只代表对方不再发送数据了。
- 被动方可能还有数据要发，所以先给一个 ACK 确认。
- 等本方也发送结束时，再发出自己的 FIN。

第二、三次能不能合并，这里要说准：原文“为什么不能合并”这个说法并不是绝对成立。如果本方也已经准备关闭，ACK 和 FIN 是可以合在一条报文里的。常见的四个报文，来自“双向各自独立关闭”这个前提。

收尾补一句：主动关闭方通常会进入 TIME_WAIT，作用是最后那个 ACK 丢失时还能应对重传的 FIN，同时等旧报文在网络里消退干净。

## Q08：HTTP 是什么，各版本有什么特性，常见状态码有哪些？

原文题号：6。

### 面试回答

先定性：HTTP 是应用层的请求／响应协议，规定方法、资源、状态码和表示这些语义，本身是无状态的。

版本按“解决什么问题”来讲：

- HTTP/1.0：通常每次请求都建一次连接。
- HTTP/1.1：默认持久连接；支持管线化，但响应仍然要按顺序来。
- HTTP/2：改用二进制帧，做多路复用，头部用 HPACK 压缩。但它还是跑在 TCP 上，TCP 丢包会造成连接级的队头阻塞。
- HTTP/3：基于 QUIC，把跨流的队头阻塞降低了，头部压缩换成 QPACK。

状态码分五类，各记几个：

- 1xx 信息。
- 2xx 成功：200、201、204。
- 3xx 重定向：301、302、304、307、308。
- 4xx 客户端错误：400、401、403、404、405、409、429。
- 5xx 服务端错误：500、502、503、504。

一个易错点：304 表示缓存验证之后不需要重传表示，不是页面重定向。

## Q10：如何通过 IP 地址获得物理地址？

原文题号：8。

### 面试回答

先定前提：这里的“物理地址”按以太网 MAC 地址来理解。

IPv4 的正常流程是：

- 先查邻居缓存，有记录就直接用。
- 没有记录，就用 ARP 在本地链路广播请求。
- 目标主机回复自己的 MAC。

面试官真正想听的是下一个区分点：一旦路由判断出目标不在本地链路，要解析的就是下一跳网关的 MAC，不是远程服务器的 MAC。ARP 广播不会跨过路由器传遍整个互联网。

再补一条版本差异：IPv6 不用 ARP，改用基于 ICMPv6 的邻居发现。

## Q11：MySQL 的整体架构是什么？

原文题号：9（架构部分）。

### 面试回答

以 MySQL 8.4 为例，自顶向下分三块：

- 客户端连接与认证。
- SQL 服务层：负责解析、优化，以及执行的协调。
- 存储引擎层：负责具体的数据和索引访问。

其中 InnoDB 除了存取数据，还提供事务、锁、MVCC（多版本并发控制）、缓冲池和崩溃恢复。

一次查询的走向是：按执行计划去访问引擎，取出行，再把结果返回。

两条边界别踩：

- 不能把 MySQL 服务层和 InnoDB 说成同一个模块。
- 现代 8.x 的查询流程里已经没有 Query Cache，讲架构时别再把它加回去。

## Q12：MySQL 如何存储 JSON 格式数据？

原文题号：9（JSON 部分）。

### 面试回答

结论：MySQL 8.4 有原生 JSON 列，但也可以拿 TEXT 凑，两者不是一回事。

- 原生 JSON 列：写入时会检查文档是否合法，内部用适合访问成员的二进制表示。
- TEXT 存原始文本：不会自动给你 JSON 类型的校验和访问优化。

怎么读写：

- 取路径用 JSON_EXTRACT 或者箭头操作符。
- 更新字段用 JSON_SET。

什么时候不该继续塞 JSON：

- 需要按字段检索时，可以把标量抽到生成列，再在生成列上建索引。
- 那些要频繁关联、有约束、要排序的稳定字段，通常更适合做成独立的关系列。

## Q13：MySQL 的 CHAR 和 VARCHAR 有什么区别？

原文题号：9（字符类型部分）。

### 面试回答

先纠正一个常见误解：M 是字符数，不是字节数。

- CHAR(M)：固定 M 个字符长度。
- VARCHAR(M)：最长 M 个字符的变长字符串。
- 实际占多少存储，还要看字符集和行格式。

尾空格的处理是两者真正的语义差别：

- CHAR 有补齐、读取时处理尾空格的语义。
- VARCHAR 保存实际内容，额外记一个长度，通常保留尾空格。

怎么选：

- 长度稳定的值可以考虑 CHAR。
- 长度变化大的文本可以考虑 VARCHAR。

最后一句别说满：比较时尾空格有没有意义，还取决于排序规则；也不能说固定长就一定更快。

## Q14：MySQL 事务如何开启，ACID 和隔离级别是什么？

原文题号：10。

### 面试回答

前提先说是 InnoDB，然后分三块讲：怎么开、ACID 是什么、隔离级别有哪些。

怎么开：

- START TRANSACTION，或者普通 SQL 里的 BEGIN。
- 结束用 COMMIT 提交、ROLLBACK 回滚。
- 也可以设 autocommit=0，但要理解这样会话事务会一直持续。

ACID 四项各自管什么：

- 原子性：一组修改要么整体完成，要么整体回滚。
- 一致性：维护业务约束。
- 隔离性：控制并发下的可见性。
- 持久性：保证提交之后不丢。

隔离级别从低到高四档：读未提交、读已提交、可重复读、串行化。InnoDB 默认是可重复读。

两个补充口径，说了更显熟练：

- 具体的读语义还要区分快照读和锁定读。
- 持久性的承诺强度，取决于日志刷盘这些配置，不是无条件成立。

## Q15：索引是什么，有哪些结构和分类？

原文题号：11。

### 面试回答

先给定义：索引是帮定位数据、减少扫描的辅助访问结构，代价是多占存储、写的时候要额外维护。

结构上，InnoDB 常用的是 B+ 树：

- 非叶节点做导航。
- 聚簇索引的叶子存行本身。
- 二级索引的叶子存索引列加主键。
- 所以等值访问和范围访问都合适。

分类别混着说，要按维度来：

- 按约束：主键／唯一／普通。
- 按列数：单列／联合。
- 按组织：聚簇／二级。
- 按用途：全文／空间等。

最后两条边界：其他引擎和特殊索引可能用别的结构，不能说所有 MySQL 索引都是 B+ 树；覆盖索引描述的是“这次查询”和索引之间的配合关系，不是一种索引类型。

## Q16：Redis 有哪些数据类型，底层如何实现？

原文题号：12。

### 面试回答

这题的考点是“对外类型”和“内部编码”要分开讲。以 Redis 7.2 为回答基线。

基础五类：

- String：整数、embstr 或 raw。
- Hash：listpack 或哈希表。
- List：quicklist，里面的紧凑节点用 listpack。
- Set：intset、listpack 或哈希表。

## Q17：什么是 XSS 攻击，如何防御？

原文题号：13。

### 面试回答

XSS（跨站脚本攻击）说的是：不可信的内容，在网站的上下文里被当成脚本执行了。

先分类型和危害：

- 常见三类：存储型、反射型、DOM 型。

## Q18：Java 如何管理内存，堆与 G1 垃圾回收如何工作？

原文题号：14。

### 面试回答

这题分两半：先说运行时内存怎么分，再说 G1 怎么收。

内存区域按线程归属分：

- 线程私有：程序计数器、虚拟机栈、本地方法栈。
- 线程共享：堆和方法区等区域。

堆主要放对象和数组，由 GC 管理。但要注意：堆不等于 Java 进程的全部内存，栈、元空间、直接内存和运行时本身也都在占资源。

G1 怎么工作，以 HotSpot JDK 21 为例：

- 堆被划成多个 Region，年轻代和老年代只是逻辑上的区分。
- 先做并发标记，评估各区域的存活量。
- 再在暂停里把选定区域的存活对象疏散（复制）出去。
- 年轻代回收之后，还可以做混合回收，带上部分老年代区域。

最后一条口径别说反：暂停目标是尽力满足，不是硬实时保证；G1 也不是全程无暂停。

## Q19：Docker 是什么，如何实现隔离和资源限制，如何进入容器？

原文题号：15、16。

### 面试回答

先定性：Docker 是构建、分发和运行容器的工具。

它为什么既隔离又轻量（常见 Linux 容器共享宿主内核）：

- namespace：隔离进程号、网络、挂载点这些视图，解决“看不见”。
- cgroup：限制 CPU、内存等资源，解决“用太多”。
- capabilities 等机制：进一步约束权限。
- 镜像：提供用户空间和依赖。

怎么进容器：

- `docker exec -it 容器名 sh` 起一个交互 shell。
- 只有镜像里确实含 bash 时才用 bash。

怎么限额：启动参数 `--memory` 和 `--cpus` 分别设内存和 CPU 上限。

两条边界：网络隔离不等于资源限额；容器的内存预算也不能只按 JVM 堆来设。

## Q21：RAG、向量模型和 LLM 幻觉是什么？

原文题号：18。

### 面试回答

这三个概念分开说，每个先给定义再说边界。

RAG（检索增强生成）：核心是“生成之前先去检索外部证据”。

- 入库侧：文档解析、切块、向量化。
- 查询侧：先把问题编码，再用关键词或向量召回，然后过滤、重排。
- 最后让模型依据这些证据回答。

向量模型：把文本编码成语义表示，用来做相似检索。

- 它不等于生成答案的大语言模型。
- 一个硬约束：查询和文档的表示必须兼容，否则相似度没意义。

LLM 幻觉：生成出看着合理、但和事实或给定证据不符的内容。

- 来源可能是知识不足、检索失误，或者生成偏离。
- 对策是改善证据、校验引用，证据不足时明确说不确定。
- 别说过头：RAG 不能保证消除幻觉。

实际使用的模型名称与版本待补充。
