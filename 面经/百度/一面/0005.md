## Q02：进程、线程、协程有什么区别，进程间如何通信？

原文题号：2。

### 面试回答

进程提供地址空间与资源隔离，线程是进程内的执行单元，共享堆等资源而各有栈和执行状态；协程由运行时或库调度暂停与恢复，适合大量等待任务，但多核并行仍需线程或进程支持。进程间可用管道、命名管道、消息队列、共享内存、信号和 Socket。共享内存适合批量共享数据但要另做同步；信号偏向事件通知，Socket 可用于同机或跨机通信。

## Q03：Linux 内存如何分布？

原文题号：3（内存部分）。

### 面试回答

“内存分布”未说明指进程虚拟地址空间还是内核物理内存管理。若问进程布局，常见有代码、只读数据、已初始化数据、BSS、堆、文件或匿名映射以及线程栈；虚拟地址由页表映射到物理页。若问系统物理内存，则涉及物理页、NUMA 节点和 zone、页分配器、内核对象分配与页缓存。不能把进程地址布局当成 RAM 中连续排列的固定分区，具体地址依架构、ASLR 和进程而变。

## Q04：介绍 I/O 多路复用。

原文题号：3（I/O 部分）。

### 面试回答

I/O 多路复用让一个线程等待多个文件描述符就绪，再处理可读写事件。select、poll 每次提交并检查集合，epoll 在内核维护关注集合并返回就绪事件，适合连接多而活跃比例低的场景。就绪通知后仍需 read／recv 等完成数据读写，不能当成异步完成通知；ET 通常配合非阻塞 I/O 处理到 EAGAIN。

## Q05：OSI 七层与 TCP/IP 四层有什么区别，如何映射？

原文题号：4。

### 面试回答

OSI 从低到高是物理、数据链路、网络、传输、会话、表示、应用层。常见 TCP/IP 四层模型把物理和数据链路归入链路层，网络层对应网际层，传输层对应传输层，会话、表示和应用层归入应用层。OSI 偏参考分层，TCP/IP 围绕互联网协议体系组织；映射是教学上的概括，实际协议职责不总能严格一一对应。

## Q06：TCP 和 UDP 有什么区别？

原文题号：5（对比部分）。

### 面试回答

TCP 是面向连接的可靠有序字节流，带重传、流量控制和拥塞控制，不保留消息边界。UDP 是无连接数据报，保留消息边界，但自身不保证送达、有序或去重。应用可在 UDP 上实现可靠传输，例如 QUIC；不能简单说 UDP 必然更快，选择要看业务语义和时延要求。

## Q07：TCP 四次挥手如何进行，第二次和第三次能否合并？

原文题号：5（挥手部分）。

### 面试回答

常规过程为主动方 FIN、对端 ACK、对端 FIN、主动方 ACK。收到 FIN 只代表对方不再发送，被动方可能还有数据要发，所以先确认，再在本方发送结束时发 FIN。原文“为什么不能合并”不是绝对成立：若本方也已准备关闭，ACK 与 FIN 可以合并；常见四个报文来自双向独立关闭。主动关闭方通常进入 TIME_WAIT，以处理最后 ACK 丢失后的 FIN 重传并等待旧报文消退。

## Q08：HTTP 是什么，各版本有什么特性，常见状态码有哪些？

原文题号：6。

### 面试回答

HTTP 是应用层请求／响应协议，定义方法、资源、状态码和表示等语义，本身无状态。HTTP/1.0 通常每次请求建连接；HTTP/1.1 默认持久连接，支持管线化但响应仍按序；HTTP/2 用二进制帧、多路复用和 HPACK 压缩头部，仍受 TCP 丢包带来的连接级队头阻塞影响；HTTP/3 基于 QUIC，降低跨流传输队头阻塞，使用 QPACK。状态码分 1xx 信息、2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务端错误：如 200、201、204，301、302、304、307、308，400、401、403、404、405、409、429，500、502、503、504。304 表示缓存验证后无需重传表示，不是页面重定向。

## Q10：如何通过 IP 地址获得物理地址？

原文题号：8。

### 面试回答

按以太网 MAC 地址理解“物理地址”：IPv4 主机先查邻居缓存，若无记录，通过 ARP 在本地链路广播请求，由目标回复其 MAC。路由判断目标不在本地链路时，需要解析的是下一跳网关的 MAC，不是远程服务器的 MAC；ARP 广播不会跨路由器传遍互联网。IPv6 使用基于 ICMPv6 的邻居发现，不使用 ARP。

## Q11：MySQL 的整体架构是什么？

原文题号：9（架构部分）。

### 面试回答

以 MySQL 8.4 为例，可分客户端连接与认证、SQL 服务层和存储引擎层。SQL 服务层负责解析、优化与执行协调，存储引擎负责具体数据和索引访问；InnoDB 还提供事务、锁、MVCC、缓冲池及崩溃恢复。查询通过执行计划访问引擎取得行并返回结果；不能把 MySQL 服务层和 InnoDB 当成同一个模块，也不要在现代 8.x 查询流程中加入已移除的 Query Cache。

## Q13：MySQL 的 CHAR 和 VARCHAR 有什么区别？

原文题号：9（字符类型部分）。

### 面试回答

CHAR(M) 表达固定字符长度，VARCHAR(M) 表达最长 M 个字符的变长字符串；M 不是固定字节数，存储还受字符集和行格式影响。CHAR 有补齐及读取时处理尾空格的语义，VARCHAR 保存实际内容并额外记录长度，通常保留尾空格。适合长度稳定的值可考虑 CHAR，长度变化大的文本可考虑 VARCHAR；比较时尾空格是否有意义还取决于排序规则，不能说固定长就一定更快。

## Q14：MySQL 事务如何开启，ACID 和隔离级别是什么？

原文题号：10。

### 面试回答

以 InnoDB 为前提，可用 START TRANSACTION 或普通 SQL 中的 BEGIN 开始事务，COMMIT 提交、ROLLBACK 回滚；也可设置 autocommit=0，但要理解会话持续事务语义。ACID 是原子性、一致性、隔离性、持久性：一组修改整体完成或回滚，维护业务约束，控制并发可见性，保证提交后的持久性。隔离级别为读未提交、读已提交、可重复读和串行化，InnoDB 默认可重复读。具体读语义还要区分快照读和锁定读；持久性承诺取决于日志刷盘等配置。

## Q15：索引是什么，有哪些结构和分类？

原文题号：11。

### 面试回答

索引是帮助定位数据、减少扫描的辅助访问结构，会增加存储和写维护成本。InnoDB 常用 B+ 树：非叶节点导航，聚簇索引叶子保存行，二级索引叶子包含索引列及主键，适合等值和范围访问。分类要分维度：主键／唯一／普通，单列／联合，聚簇／二级，以及全文／空间等用途。其他引擎和特殊索引可能用不同结构，不能说所有 MySQL 索引都是 B+ 树；覆盖索引是查询与索引的关系。

## Q16：Redis 有哪些数据类型，底层如何实现？

原文题号：12。

### 面试回答

## Q18：Java 如何管理内存，堆与 G1 垃圾回收如何工作？

原文题号：14。

### 面试回答

Java 运行时有线程私有的程序计数器、虚拟机栈、本地方法栈，以及共享堆和方法区等区域。堆主要承载对象和数组，由 GC 管理，不等于 Java 进程全部内存；栈、元空间、直接内存和运行时本身也占资源。以 HotSpot JDK 21 G1 为例，堆划成多个 Region，逻辑上区分年轻代与老年代，通过并发标记评估存活量，并在暂停中疏散选定区域的存活对象；年轻代回收后还可进行包含部分老年代区域的混合回收。暂停目标是尽力满足，不是硬实时保证，G1 也不是全程无暂停。

## Q19：Docker 是什么，如何实现隔离和资源限制，如何进入容器？

原文题号：15、16。

### 面试回答

Docker 提供构建、分发和运行容器的工具。常见 Linux 容器共享宿主内核，通过 namespace 隔离进程号、网络、挂载点等视图，用 cgroup 限制 CPU、内存等资源，并结合 capabilities 等约束权限；镜像提供用户空间和依赖。运行中的容器可用 docker exec -it 容器名 sh 启动交互 shell，镜像含 bash 时才用 bash。启动参数 --memory 和 --cpus 可设置内存与 CPU 限额；网络隔离不等于资源限额，容器内存预算也不能只按 JVM 堆设置。

## Q20：同一台机器上的两个 Docker 容器如何通信？

原文题号：17。

### 面试回答

常用方式是把两个容器接入同一个用户自定义 bridge 网络，利用容器名或网络别名解析对方，再访问对方的容器端口。Linux 上一般经 veth 与软件网桥转发，通常不需要先发布宿主端口。服务要监听容器可访问的地址；某容器里的 localhost 指它自己的网络命名空间，不是另一个容器。不同网络的容器不能默认互通，需要明确共享网络或路由与发布端口方案。

## Q21：RAG、向量模型和 LLM 幻觉是什么？

原文题号：18。

### 面试回答

RAG 在生成前检索外部证据：文档解析、切块和向量化入库，查询时编码问题，结合关键词或向量召回、过滤重排，再让模型依据证据回答。向量模型把文本编码为语义表示，用于相似检索，不直接等于生成答案的大语言模型，查询与文档表示必须兼容。幻觉是生成看似合理却与事实或给定证据不符的内容，可来自知识不足、检索失误或生成偏离；应改善证据、校验引用并在证据不足时明确不确定，RAG 不能保证消除幻觉。实际使用的模型名称与版本待补充。
