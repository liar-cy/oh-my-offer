## Q01：介绍项目，重点说和测试相关的业务背景、流程、目的。

### 面试回答

测开岗要主动把项目往“质量怎么保障”上讲：

- 业务背景：这个项目为谁解决什么。
- 测试相关流程：需求怎么进用例、怎么执行、缺陷怎么流转、怎么卡发布。
- 测试目的：这个测试是为保障哪个风险／指标（正确性、性能、稳定性、回归不复发）。
- 我的角色：设计了什么用例／搭了什么自动化／发现了什么关键问题。

按【真实项目】讲，突出“测试视角的价值”，而不是只讲功能实现。

## Q02：CPU、磁盘 IO、网络 IO 分别怎么测？

### 面试回答

三类资源各有指标和工具，先说“测什么”再说“用什么测”：

- CPU：使用率（用户态／系统态／iowait）、负载 load、上下文切换——`top`／`mpstat`。
- 磁盘 IO：IOPS、吞吐、平均延迟 await、利用率 %util——`iostat -x`，主动压测用 fio。
- 网络 IO：带宽、丢包重传、RTT、连接数——`sar -n`、`ss`、`ping`、`iperf`、`tcpdump`。
- 两种姿势：被动观测（真实负载下看指标）＋主动压测（打压力找饱和点）。

一句话：先分清瓶颈在 CPU、IO 还是网络，再对症看指标。

## Q03：拿到测试需求后完整流程是怎样的？脚本出错怎么处理？

### 面试回答

闭环：理解需求与验收标准 → 定策略与用例（评审）→ 造数据／搭环境 → 冒烟再全量执行（能自动化的进 CI）→ 记录并跟踪缺陷 → 回归验证 → 出报告与沉淀。

脚本出错先判性质：是真 bug、脚本自身脆弱（定位失效／时序／脏数据），还是用例设计错。别一红就重跑掩盖问题——偶发失败要归类加固（显式等待、数据隔离、幂等），确认为缺陷就提单。

## Q04：项目基于什么框架，Agent 如何扩展新功能？

### 面试回答

框架按【真实选型】说（如 LangGraph／Spring AI／自研 loop）。扩展新功能讲“插件化”思路：

- 新功能优先以“新增一个 Skill／工具”的方式接入，而不是改主干——注册接口／schema，让调度层按声明发现。
- 需要新流程时用图的节点／边扩展，或在中心调度里加一条路由分支。
- 好扩展的标志：加能力不动老代码、能力可独立测试与回滚。

## Q05：如何评估 Agent 的生成准确率？

### 面试回答

按任务类型定“对”的口径，再用评测集量化：

- 结构化／事实类：可比对标准答案算准确率（字段级、结果级）。
- 生成类：定义 rubric 或用模型评审＋人工抽检，看忠实度／任务完成率。
- 关键是“评测集独立、样本量够、指标可复现”，并用同一口径看改动前后的趋势。

## Q06：记忆机制是怎样的？如何实现多轮对话、二次向用户确认信息？

### 面试回答

- 短期记忆：当前会话的对话历史＋工作上下文放进 prompt。
- 长期记忆：把该沉淀的事实外置到存储（向量库／KV），按相关性检索回注。
- 多轮对话：每轮把“历史＋新输入＋工具观察”组装进上下文，管好窗口。
- 二次确认：把“缺参／歧义／高风险动作”显式建模成澄清动作——模型判定信息不足就产出“追问”，拿到用户补充再续跑；写操作前做确认门。

## Q07：怎么解决大模型上下文窗口膨胀问题？

### 面试回答

多管齐下压 token：

- 裁剪与摘要：对历史／观察做摘要、丢弃无关轮次，保留关键状态。
- 外置记忆：把长期信息放向量库，按需检索注入而不是全塞进上下文。
- 结构化与精简提示：去掉冗余模板、用工具结果摘要而非原文。
- 复用缓存：稳定前缀用 Prompt Caching 降成本（虽不减占用，但降开销）。

## Q08：如何提升 Agent 输出结果的稳定性？

### 面试回答

接受“模型有随机性、只能收窄”：固定规范化上下文＋模板、调低温度／强制 JSON schema、把能确定的步骤固化成代码只让模型做判断、用带标准答案的评测集测一致性并监控波动。别把稳定说成绝对可复现——要统计多次分布，不拿单次下结论。

## Q09：如何让通用大模型在垂域业务输出更准确？

### 面试回答

按成本从低到高排：

- 先做提示工程（领域术语、few-shot、输出约束）＋检索增强（RAG 把领域知识喂进去）。
- 不够再微调（LoRA 等）把领域表达和任务行为内化进权重。
- 关键数据／事实用检索＋校验兜底，不指望模型记私有知识。
- 配领域评测集验证提升，别凭感觉。

## Q10：哪些逻辑封装成脚本工具，哪些交给大模型动态生成？为什么这么取舍？

### 面试回答

判据是“确定性 vs 灵活性”：

- 封装成脚本／固定流程：规则明确、可枚举、要求正确性与可复现的（计算、格式化、校验、权限、固定 API 调用、确定性流程）。
- 交给大模型动态生成：需要理解模糊语义、路径不可预知、要按上下文应变的（意图理解、拆解、自然语言生成、无法穷举的判断）。
- 取舍逻辑：越靠近“事实、钱、写操作、不能出错”越用代码；越“模糊、开放、要泛化”越交给模型。混合最稳：模型决策＋代码执行＋结果校验。

## Q11：讲一下二分查找的原理。

### 面试回答

在有序区间上每次取中点和目标比，砍掉一半，O(log n)。关键是区间定义、循环条件和收缩写法三者自洽（闭区间用 `left <= right`、`mid = left + (right-left)/2` 防溢出）。变体：lower/upper_bound 逼近边界、二分答案在“答案空间”上判可行。

## Q12：手撕：合并两个有序数组，测试用例应该怎么写？

### 面试回答

先给算法（双指针归并 O(m+n)，若原地合并到第一个数组要从后往前填），再给用例分层：

- 正常：两个非空有序数组。
- 边界：都空、一空一非空、单元素、一方全大于另一方。
- 特殊：含重复元素、含负数。
- 断言：结果升序且长度 = m+n、元素多重集守恒。

## Q14：uv 和 pip 的区别是什么？

### 面试回答

定位差异：pip＝装包工具，uv＝一体化包／项目管理器。

- pip 是官方包安装器、只管装包。
- uv 是 Rust 写的新一代工具，既能当更快的 pip（装包快一个量级、全局缓存＋并行）。
- uv 还能管虚拟环境、依赖锁定（pyproject／uv.lock），甚至 Python 版本。
