## Q03：自研多 Agent 通信如何实现，单机如何扩展到分布式？

考察对象为候选人自研框架；单机还是分布式及其实现是反问后追加的问题。

### 面试回答

消息需要统一定义 taskId、messageId、发送方、接收方、消息类型和 payload，由路由层把消息交给目标 Agent。单进程可以用内存队列和内存状态；扩展到多进程或多机时，需要把 Agent 做成可寻址的服务，并把任务状态放到共享存储。短请求可用 RPC，长任务更适合用消息队列异步投递，通过状态查询或回调返回结果。分布式版还要处理消息确认、幂等重试、超时、死信和链路追踪。面试时先说项目实际完成到哪一层，再说扩展方案。

## Q04：Redis 有哪些限流算法，如何实现？

### 面试回答

固定窗口用计数器统计一个时间段内的请求，实现简单，但窗口交界处可能出现瞬时翻倍流量；滑动日志保存窗口内每次请求的时间，精确但占内存；滑动窗口计数则用多个小分桶做近似。令牌桶按固定速率生成令牌，可以允许一定程度的突发；漏桶按固定速率向外处理，更适合削平流量。Redis 实现时，判断和更新必须是原子操作：固定窗口可用 `INCR` 配合过期时间，滑动日志可用 ZSET，令牌桶则在 Lua 中根据上次时间计算新增令牌并扣减。

关联专题：[[专题题库/Redis#REDIS-004：Redis 如何实现固定窗口、滑动窗口、令牌桶与漏桶限流？|REDIS-004：Redis 如何实现固定窗口、滑动窗口、令牌桶与漏桶限流？]]

## Q05：从输入 URL 到页面渲染经历哪些步骤？

原文说明一面已问过这一题；现已关联到同属 MJ009 的一面记录。

### 面试回答

浏览器解析 URL，检查缓存并按需解析 DNS，建立或复用连接。HTTPS over TCP 会涉及 TCP 与 TLS 握手，HTTP/3 使用 QUIC。发送 HTTP 请求并收到响应后，解析 HTML 形成 DOM、处理 CSS、执行脚本，再布局、绘制与合成；重定向及子资源可引入额外请求，页面可渐进显示，并非每次都重新解析 DNS 或建连。

## Q06：如何从 100 个文件中检索 100 个敏感词？

### 面试回答

先确认文件是可直接读取的文本，以及要返回文件名、行号、词的位置还是次数。一次性检索可把 100 个非空敏感词逐行放入词表，用固定字符串多模式搜索扫描指定文件。需要实现算法时，将词表构建为 Aho–Corasick 自动机，复用自动机逐个扫描文件并输出命中，避免每个词都重新扫描所有文件。

## Q07：如何提取文件第四列 userid 并返回 Top10？

### 面试回答

若 Top10 指出现次数最多的 userid，假设空白分隔、无表头，可用：

```sh
awk 'NF >= 4 {print $4}' input.txt | sort | uniq -c | sort -k1,1nr -k2,2 | head -n 10
```

先提取第四列，再排序让相同 ID 相邻，统计频次，按次数降序取前十；输出为次数和 userid。 若指 ID 数值最大或文件前十条，命令不同，原题含义待确认。
