## Q03：自研多 Agent 通信如何实现，单机如何扩展到分布式？

考察对象为候选人自研框架；单机还是分布式及其实现是反问后追加的问题。

### 面试回答

先说结论：通信靠统一的信封（消息体）加一层路由。扩展到分布式，本质是两件事：把 Agent 变成可寻址的服务，把状态挪到共享存储。

消息与路由：

- 消息统一定义 taskId、messageId、发送方、接收方、消息类型和 payload。
- 由路由层把消息交给目标 Agent。

单机这一层：

- 一个进程内跑，直接用内存队列传递，状态也放内存。

扩展到多进程或多机：

- Agent 做成可寻址的服务，状态放到共享存储。
- 短请求走 RPC；长任务更适合用消息队列异步投递，再通过状态查询或回调把结果拿回来。

分布式版本额外要处理的：

- 消息确认、幂等重试、超时、死信、链路追踪。

面试时先说项目实际做到哪一层，再说扩展方案。

## Q04：Redis 有哪些限流算法，如何实现？

### 面试回答

先按算法讲三类窗口，再讲 Redis 怎么落地。

窗口类算法：

- 固定窗口：用一个计数器统计一个时间段内的请求。实现简单，但窗口交界处可能出现瞬时翻倍流量。
- 滑动日志：保存窗口内每一次请求的时间。精确，但占内存。
- 滑动窗口计数：把窗口拆成多个小分桶做近似，介于前两者之间。

桶类算法：

- 令牌桶：按固定速率生成令牌，允许一定程度的突发。
- 漏桶：按固定速率向外处理，更适合把流量削平。

Redis 实现的关键：判断和更新必须是原子操作。

- 固定窗口：用 `INCR` 配合过期时间。
- 滑动日志：用 ZSET 存请求时间。
- 令牌桶：在 Lua 脚本里根据上次记录的时间算出新增令牌，再扣减。

## Q05：从输入 URL 到页面渲染经历哪些步骤？

原文说明一面已问过这一题；现已关联到同属 MJ009 的一面记录。

### 面试回答

整条链路是“地址处理 → 拿数据 → 画出来”三大段：

- 解析 URL，先看缓存，需要时再解析 DNS，然后建立或复用连接。
- 走 HTTPS over TCP 时会涉及 TCP 与 TLS 握手；HTTP/3 用的是 QUIC。
- 发出 HTTP 请求、收到响应之后：解析 HTML 形成 DOM、处理 CSS、执行脚本，再走布局、绘制与合成。

三个容易被忽略的点：

- 重定向和子资源会引入额外请求。
- 页面可以渐进显示，不必等全部就绪。
- 不是每次都要重新解析 DNS 或重新建连，连接可能复用。

## Q06：如何从 100 个文件中检索 100 个敏感词？

### 面试回答

开口先确认需求，再给方案：

- 要确认两点：文件是不是可直接读取的文本；结果要返回文件名、行号、词的位置还是次数。
- 只要跑一次：把 100 个非空敏感词逐行放进词表，用固定字符串多模式搜索去扫描指定文件。
- 要求实现算法时：把词表构建为 Aho–Corasick 自动机（多模式匹配的 trie 加失败指针）。
- 然后复用这同一个自动机逐个文件扫描，输出命中。

关键取舍再强调一遍：自动机只建一次、文件扫一遍，避免每个词都把全部文件重新扫一次。

## Q07：如何提取文件第四列 userid 并返回 Top10？

### 面试回答

先说前提：这里的 Top10 按“出现次数最多的 userid”理解，并假设字段空白分隔、无表头。命令是：

```sh
awk 'NF >= 4 {print $4}' input.txt | sort | uniq -c | sort -k1,1nr -k2,2 | head -n 10
```

管道做的事按顺序是四步：

- `awk 'NF >= 4 {print $4}'`：先取第四列（只取字段数够 4 的行）。
- `sort | uniq -c`：排序让相同 ID 相邻，再统计每个 ID 的频次。
- `sort -k1,1nr -k2,2`：按次数降序排。
- `head -n 10`：取前十行，输出是次数加 userid。

要说一句边界：如果 Top10 指的是 ID 数值最大、或者文件里的前十条记录，命令就不一样了。原题含义待确认。
