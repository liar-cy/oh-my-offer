## Q02：相似 Skills 被调用错误如何处理和预防，只有一个 Skill 仍误执行怎么办？

原文题号：4—6。

### 面试回答

先看错在哪一层：是选错 Skill，还是 Skill 选对但参数、步骤或工具执行错了。对于相似 Skill，`description` 要明确写出适用场景、不适用场景和关键区别，路由时先用确定性条件缩小候选，仍有歧义再询问用户。即使只加载了一个 Skill，也要先做适用性判断，不能默认必须执行。真正调工具前，执行层还要校验参数、权限和前置条件，执行后再核对结果，防止一次路由判断直接变成不可控的副作用。

关联专题：[[专题题库/Agent开发#AGENT-015：相似 Skill 误选或单个 Skill 误执行怎么办？|AGENT-015：相似 Skill 误选或单个 Skill 误执行怎么办？]]

## Q03：Skill 如何设计、选择、执行，并适配动态入参？

原文题号：7—10。

### 面试回答

先定义真实任务、触发与排除条件、输入输出以及步骤，再组织指引、脚本和参考资源。Agent 根据任务选择候选 Skill，按需加载指引，绑定用户输入与可信状态中的动态参数，校验类型、必填和业务前提后执行工具并验证结果。缺参不猜，失败返回结构化信息；Skill 的文档规范不代替运行时鉴权，也不规定所有系统使用相同路由算法。

## Q06：为什么需要限制 Agent 并发数？

原文题号：13。

### 面试回答

Agent 一次任务可能触发多次模型与工具调用，并发过大会耗尽连接、内存、浏览器实例和配额，也会放大成本与共享状态竞争。我会按租户、任务和下游资源限制在途数，用有界队列、超时和取消形成背压。

## Q07：如何控制 Agent 执行中不暴露密钥？

原文题号：14。

### 面试回答

密钥放服务端凭据系统，由受控执行器在实际请求下游时注入；模型上下文、用户响应、日志和异常只保留必要的脱敏信息。限制工具权限和可访问目标，使用短期、最小权限凭据。不能依赖 Prompt 的保密要求来隔离已经暴露给模型或客户端的明文。

## Q08：HTTPS 建立连接的完整流程是什么？

原文题号：15。

### 面试回答

以首次建立 HTTPS over TCP、TLS 1.3 常规证书认证握手为例：先 TCP 建连，客户端发送 ClientHello（版本、算法和密钥共享），服务端返回 ServerHello 并确定共享密钥参数；后续发送加密的扩展、证书、签名证明与 Finished。客户端验证证书链、主机名、有效期及握手证明，再发送 Finished，之后用派生的对称密钥交换 HTTP 数据。证书用于认证，不是拿证书公钥直接加密全部 HTTP 内容；会话恢复和 HTTP/3 的链路不同。

关联专题：[[专题题库/计算机网络#NET-002：HTTP 和 HTTPS 有什么区别，证书如何验证？|NET-002：HTTP 和 HTTPS 有什么区别，证书如何验证？]]

## Q09：浏览器输入 URL 到服务端返回页面的完整链路是什么？

原文题号：16。

### 面试回答

浏览器解析 URL、处理缓存或 HTTPS 升级策略，需要联网时解析域名并建立或复用连接。以 HTTPS over TCP 为例，经过 TCP 和 TLS 握手后发送 HTTP 请求，服务器返回响应；浏览器解析 HTML、CSS，执行脚本，构建页面并进行布局、绘制和合成。HTTP/3 使用 QUIC，不能说所有网页请求都先建 TCP 连接。
