## Q03：剩下项目选一个来谈，为什么不选另一个，差异在哪里？

### 面试回答

这题在考你的取舍表达和对项目的理解深度：

- 先选一个并给理由：选【某项目】，因为它【技术含量更高／我贡献更完整／与岗位更匹配】。
- 讲差异用同一套维度对比：业务复杂度、我负责的深度、用到的技术栈、可验证的结果。
- 不贬低另一个项目，只说“另一个更适合展开讲 X，这个更能体现 Y”。

提前把两个项目各准备一条主线，现场按岗位需要挑一个展开，避免临场比较时含糊。

## Q04：消息队列为什么选 RabbitMQ，而不是 Kafka 或 RocketMQ？

### 面试回答

选型没有“最好”，只有“最贴合场景”。按需求维度说清为什么是 RabbitMQ：

- 我们的场景是【业务消息：低延迟、需要灵活路由、量级不算大】，RabbitMQ 的 exchange 路由模型和微秒级低延迟正好对上。
- 对比 Kafka：Kafka 是分布式日志，胜在百万级吞吐和重放，但延迟更高、运维更重；我们不需要日志流管道，用它属于杀鸡用牛刀。
- 对比 RocketMQ：RocketMQ 在事务消息、顺序消息、电商级削峰上更强，但生态偏阿里系；我们团队【栈更熟 RabbitMQ／Spring AMQP 开箱即用】。
- 落到决策维度：消息量级、延迟要求、路由复杂度、团队运维成本、与框架的集成度。

关键是把“为什么够用＋为什么更省事”说清楚，而不是背参数。

## Q05：项目中哪里用到限流，限流的原理是什么（用的 Sentinel）？

### 面试回答

先给用在哪，再讲原理：

- 用在【入口接口／对下游调用／秒杀或批量任务】，防止流量打垮服务或压垮第三方。
- 常见限流算法有四种：固定窗口计数、滑动窗口、漏桶、令牌桶。
- 固定窗口实现简单，但窗口边界会突刺（临界两个窗口叠加到 2 倍）；滑动窗口把窗口细分缓解突刺。
- 漏桶把输出速率整形成恒定值，能强制平滑但不容忍突发；令牌桶按速率放令牌、桶里有余额就允许一定突发，最常用。
- 用 Sentinel：它按“资源＋流控规则”做，默认是滑动窗口统计，支持 QPS／线程数／关联／链路限流，还能配熔断降级；规则可热更新，控制台看实时指标。

答题时把“场景→算法→框架怎么落地”连起来，别停在“用了 Sentinel”这句。

## Q06：了解哪些设计模式，项目中怎么用的？责任链模式了解吗？

### 面试回答

按“场景→模式→代价”讲，挑真用过的展开，别只报名词：

- 创建型：单例（Spring Bean 默认作用域）、工厂（解耦创建与使用）。
- 结构型：代理（Spring AOP、远程调用）、装饰器（Java IO 流）。
- 行为型：策略（用 Map 存一组处理器替代 if-else）、模板方法（骨架固定步骤可变）、观察者（事件发布订阅）、责任链（一串处理器依次放行）。
- 项目怎么用：说清“我在【某处】用了【某模式】，解决了【什么问题】，代价是【多了什么复杂度】”。

责任链单独说：

- 结构是一串处理器共享一个“请求”对象，各自决定处理还是传给下一个，命中即可短路。
- 落地例子：Servlet Filter 链、Netty `ChannelPipeline`、SpringMVC 拦截器链，业务里的风控／审批／多级校验也常用它。
- 好处是解耦“发送方”和“多个处理逻辑”，加节点不改老代码；代价是链条顺序本身成了逻辑，顺序错就是 bug，且每个节点都可能查库会把耗时叠加。

## Q07：关于数据结构，有什么想表达的（开放题）？

### 面试回答

开放题考的是知识结构化与取舍意识，别散着背。给一条主线：

- 按“访问模式选结构”组织：要随机访问用数组，要频繁增删用链表，要有序查找用平衡树／跳表，要按 key 定位用哈希表，要极值或优先用堆，要前缀或去重用字典树／布隆过滤器。
- 挑一两个讲深：例如 HashMap 用数组＋链表＋红黑树（JDK 8 链表到 8 且表长到 64 才树化），本质是在“空间、时间、哈希冲突”三者间折中。
- 结合工程：Redis 的 ziplist／skiplist、MySQL 的 B+ 树，都是同一批结构在真实系统里的落地。

如果没方向，就用“我最熟的一个结构 + 它解决的瓶颈 + 一个对比”这条最稳的线开场。

## Q08：100 万个数快速获取 TopK，选什么数据结构？

### 面试回答

先判断量级：100 万个数能整个放进内存，这决定了可选方案。

- 默认解：维护一个大小为 K 的小顶堆。遍历每个数，比堆顶大就替换堆顶，结束堆里就是 TopK。O(N log K)、空间 O(K)。
- 内存够、且只要 TopK 不要求流式时，可用快速选择（QuickSelect）平均 O(N)，比堆更快。
- 若取最大 K 用最小堆、取最小 K 用最大堆——堆顶始终是当前候选里最该被替换的那个。

追问“数大到装不下内存”时，就切到分片＋各自 TopK 再归并的流式方案。

## Q09：如何判断一个链表是否有环（只说思路）？

### 面试回答

思路是快慢指针（Floyd 判圈）：

- 快指针每次走两步、慢指针每次走一步，从头同时出发。
- 有环则两者必在环内相遇；无环则快指针先到 null。
- 只判断是否有环，到这一步就够了。

若被进一步要求找环入口：相遇后把一个指针放回头节点，两者改为每次各走一步，再相遇处就是入口。

## Q10：谈谈对 Java 多线程／高并发的认识，以及如何创建、使用、什么场景用？

### 面试回答

这题分三层答，别混成一团。

为什么需要多线程／高并发：

- 为吞吐和响应：IO 密集场景用并发把等待时间重叠起来；CPU 密集用多核并行算。
- 代价是共享状态带来的可见性、原子性、有序性问题，这才是并发的难点所在。

怎么创建和使用：

- 创建线程常见有三种：继承 `Thread`、实现 `Runnable`（配合 `Thread`）、用 `Callable`＋`FutureTask`（能拿返回值和抛异常）；本质都是包一个 `Runnable`。
- 生产上不自建裸线程，用线程池：核心参数是核心线程数、最大线程数、队列、拒绝策略、存活时间，任务先入核心线程→入队→扩到最大→触发拒绝。
- 线程间协作靠 `wait/notify`、`CountDownLatch`、`Semaphore`、`CyclicBarrier`、并发容器等。

什么场景用：

- Web 请求处理、异步任务、批量数据聚合、定时调度、生产者—消费者解耦。
- 落回线程安全手段：能不共享就不共享（栈封闭、ThreadLocal），要共享就用不可变、加锁（`synchronized`／`Lock`）、无锁（CAS／原子类）、并发容器按需选。

## Q11：一条 SQL 语句的执行过程是怎样的？

### 面试回答

以 InnoDB 的一条查询为例，从客户端到结果按 server 层→引擎层走：

- 连接器：建立连接、鉴权，之后拿到权限做校验（长连接会占用内存，老版本注意重连）。
- 查询缓存：MySQL 8.0 已移除（命中率低、易失效），8.0 之前命中就直接返回。
- 分析器：做词法、语法分析，认出表、列和动作。
- 优化器：决定用哪个索引、多表怎么定连接顺序，生成执行计划。
- 执行器：先按表结构判断权限，再调用引擎接口一行行取数据、边取边过滤。
- 存储引擎（InnoDB）：按索引找数据，命中数据页在缓冲池就直接用，不在就读盘放入缓冲池，返回记录行给执行器。
- 更新语句额外写两类日志：先写 redo log（崩溃恢复、WAL）、再写 binlog（归档与主从复制），两者用两阶段提交保证一致。
