## Q01：长度为 N 的数组取值 0 到 N，如何找到缺失的那个数？

例：[0,1,3,4,5,6]，N=6，本应有 0—6 共 N+1 个数，缺失 2。数组是否原地无序、可否修改等条件未记录，按标准题解作答。

### 面试回答

有两种 O(n) 时间、O(1) 空间的口述方案。

- 异或法：把 0^1^…^N 与数组全部元素再异或一遍，成对的数互相抵消，剩下的就是缺失值。它不依赖求和上限，天然规避了溢出。
- 高斯求和法：用期望总和 N(N+1)/2 减去实际元素之和，差值即答案。

用求和法要主动补一句：得用 long 承载。N 大到 10^5 以上时 int 会溢出，这是面试官常埋的坑。

如果追问“缺了两个数”：

- 异或一次只能定位一个。
- 做法是按两个缺失数异或结果中任一为 1 的位，把 0..N 和数组各分成两组，组内分别异或，得到两个缺值。

对照方案提一句就够：集合标记法（布尔数组）也能做，但是要 O(N) 的额外空间。

## Q02：0 到 1000 的数组去重并按序打印：位图及其内存优化与超范围扩展（含四个追问）。

原题链条：

- 原题 2：对取值范围 0—1000 的数组去重并按顺序打印。
- 追问 1：如何节约内存。
- 追问 2：取值扩大到 0—10 亿、内存放不下全部数据怎么办。
- 追问 3：能否用压缩方式直接在内存里处理。
- 追问 4：按要求编码实现压缩部分的主要逻辑。

四个追问均为面经实际出现的连续深挖，合并作答。

### 面试回答

取值域只有 1001 个，这种场景直接上位图。

主做法两趟：

- 开 1001 个 bit，一个 126 字节的 long[] 就够了。
- 第一趟把每个数 x 映射为置位 `bits[x>>6] |= 1L<<(x&63)`，天然完成去重。
- 第二趟从低位到高位扫描为 1 的 bit 下标，顺序打印，就是“按序输出去重结果”。

代价：时间 O(n + 值域)，值域小时近乎线性。排序加去重那套 O(n log n) 的写法，在这里被值域换掉了。

追问 1，怎么节约内存：

- 位图本身就是从布尔数组每元素 1 字节压到 1 bit，省 8 倍。
- 还要再压就得动结构了。稀疏时按机器字分块，全 0／全 1 的字用特殊标记存储（Roaring，或者编程珠玑里的 word bitmap）。
- 另一条路是差值＋变长编码。

追问 2，值域扩到 0—10 亿：

- 完整位图是 10^9 bit，约 119MB。
- 内存还是放不下时，经典解是分趟扫描：把值域切成 k 段，每段建 1／k 大小的位图，每趟读一遍输入、只统计落在本段的数。本质是用 k 遍 I/O 换内存。
- 如果输入是可以外存的通用排序需求，那就退回分块外部排序。

追问 3，压缩之后能不能直接在内存里处理：

- 能，前提是稀疏——实际存了值的字远少于总字数，压缩位图就能把内存拉回可容纳的量级。
- 全 0 块 O(1) 跳过，全 1 块整字处理，扫描顺序打印不变。

追问 4，编码的核心是三分类存储：

- 每个字记录自己的类型：EMPTY／FULL／OTHER，只有 OTHER 挂 64 位的值。
- 置位时 EMPTY 升格为 OTHER；FULL 减一位要展开成 OTHER。
- 判断和打印都按类型分支。现场写出类结构和三个方法即可。

## Q04：如果手握多个 offer，你如何选择公司？

### 面试回答

先定性：这题考的是你的决策标准和对本公司的诚意，不是让你报其他家的名字。

框架是先给标准、再落到行动：

- 先给一套一致的评估维度：业务与岗位技术栈是否匹配、团队工程实践与成长空间、公司所处赛道的确定性；最后才说薪酬。
- 再落到行动：目前【在流程中的是 X 家，都还在等结果】。
- 最后表态：帆软这边我判断【业务方向＋岗位内容】与我的规划最匹配，如果拿到会优先选择，因为【具体一条真实理由】。

两个坑别踩：虚报竞对来抬价，或者贬低其他公司显得逐利。具体进展按真实情况填写。

## Q06：你的 3—5 年职业规划是什么？

个人规划未记录，以下为框架。

### 面试回答

按“扎根 → 独当一面 → 反哺”三段讲，每一段都绑在岗位路径上。

- 前 1—2 年（扎根）：吃透团队的技术栈和业务域，成为能把模块端到端负责起来的可靠执行者；补齐【数据库内核级性能／高并发中间件，按实际】的短板。
- 3—5 年（独当一面）：在一条有深度的方向上，成为团队内可咨询的人。对后端来说，就是复杂系统设计与性能治理；要能带小项目、做技术选型的论证。
- 同期（反哺）：把经验沉淀成文档和工具，回馈团队。

落点要回到帆软：这份规划成立的前提，是业务场景足够复杂、能长期投入，而这正是我选择这个岗位的原因。

避免两种空转：喊“几年当管理／架构师”这类头衔，或者规划跟公司业务无关（例如转算法）。

## Q07：有没有压力很大的经历？

个人经历未记录，以下为 STAR 框架。

### 面试回答

选一段“真实、已解决、有复盘”的经历，按情境—压力源—动作—结果—沉淀讲。

- 情境与压力源：【项目上线前夜发现线上问题／双轨期课业与实习叠加】，压力大的点是【时间不可退让＋结果可见】。
- 动作，我做了三件事：
  - 按影响面拆任务、排优先级。
  - 每天同步进展，让风险透明。
  - 找【导师／同事】分工兜底。
- 结果：【按时交付／平稳度过】，量化口径要真实。
- 收尾给沉淀：这段经历让我把“压力下靠拆解和沟通管理，而不是硬扛时长”变成习惯；之后再遇【类似场景】，会先做【动作】。

避雷两条：别选与岗位无关的纯体力压力（健身、游戏），也别暴露不稳定信号，比如“压力大到想离职”。
