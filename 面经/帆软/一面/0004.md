## Q03：乐观锁和悲观锁分别有什么特点？各自在什么场景下使用？

### 面试回答

一句话：悲观锁“先锁再操作”，乐观锁“先干再验，失败重试”。

- 悲观锁：`synchronized`、`ReentrantLock`、数据库 `SELECT ... FOR UPDATE` 行锁。特点是冲突概率高时最省——一次串行化，不浪费算力；代价是排队、吞吐被锁上限压住，还有死锁风险。
- 乐观锁：CAS／版本号（`Atomic*`、MySQL `version` 字段条件更新）。特点是读多写少时吞吐高、无死锁；代价是高冲突下重试风暴，且只保得住单个比较对象，跨多条数据的不变量它管不了。
- 选型给判据：冲突率。写少读多、同一资源竞争低 → 乐观；写密集互斥必须、或逻辑复杂（多步骤要在一个临界区）→ 悲观。数据库扣库存这类“判断依赖旧值＋更新”用行锁或带条件的乐观更新（`WHERE stock>=n`）都行，看热点程度。

## Q04：解释型语言和编译型语言的区别？各举两个例子，Java 属于哪种？

### 面试回答

- 判据一条：源码翻译成可执行形态发生在“运行前”还是“运行中”。
- 编译型：提前整体翻译成机器码／本地码，运行快、跨平台要重编——例子 C／C++、Go（Rust 也可举）。
- 解释型：运行期由解释器逐句翻译执行，启动快、灵活（动态类型常见），单条执行开销大——例子 Python、JavaScript。
- Java 属于“两段式”，这句要答全：javac 先把源码编译成字节码（平台无关），运行期 JVM 解释执行字节码，并对热点代码 JIT 即时编译成本地码——所以它是“编译到中间表示＋解释与即时编译混合”，不是纯解释型。
- 加分：正因为混合，Java 才有预热现象（启动慢、跑热后接近本地码性能），这也解释了压测要跳过预热期。

## Q05：有垃圾回收相较无垃圾回收有什么好处和坏处？谈谈 GC 的原理和算法。

### 面试回答

好处／坏处各三条，再给算法主线：

- 好处：消灭“忘记 free”这一整类错误（悬垂指针、double free 都不会发生）；开发者不必手工推理对象生命周期，new 随便用；内存安全换来了语言层面的简化与托管生态（异常路径也不漏）。
- 坏处：STW 停顿（实时场景是硬伤）、吞吐税（GC 线程抢 CPU）、为复制算法预留的空闲空间抬高内存占用、回收时机不可控；而且 GC 防不了“可达但无用”的泄漏——内存管理从“别漏”变成“别钉着不放”。
- 原理三步：判活（从 GC Roots 可达性分析，不用引用计数因为循环引用）；分代（弱分代假说，新生代复制算法便宜，老年代标记整理或标记清除）；增量／并发化（三色标记＋写屏障，CMS→G1→ZGC 的演进主线是停顿越来越短）。
- 收尾报取舍：选 GC 是拿“停顿＋内存冗余”换“安全＋生产力”，JVM 参数就是在这两者间找点。

## Q06：数据库中的 ACID 分别指什么？

### 面试回答

按“特性一句＋机制一句”报：

- A 原子性：事务内改动全生效或全撤销——靠 undo log 回滚。
- C 一致性：数据满足约束与业务不变量——它是目标，由另外三个特性＋约束体系共同达成，不是某个单独机制。
- I 隔离性：并发事务互不干扰——靠锁＋MVCC。
- D 持久性：提交后不丢——redo log＋WAL（先写日志再改页），配 `innodb_flush_log_at_trx_commit` 控制强度。
- 最容易被抓的一句话：别把 ACID 说成“四种事务”；C 常被单独追问“它和 I 什么关系”，按“目标是 C、机制偏 I／A／D”的结构答。

## Q07：知道 Zookeeper 和 Raft 这些一致性协议吗？

### 面试回答

先把“系统”和“协议”分开——这是本题的第一层分：

- Zookeeper 是分布式协调系统，内部用 ZAB 协议（崩溃恢复＋原子广播，先过leader 定序再落盘）；对外提供分布式锁、配置中心、选主、注册发现。
- Raft 是共识协议：选主（任期 term＋心跳）＋日志复制（多数派确认才 commit），设计目标就是“可理解地实现 replicated state machine”。
- 一句话本质：共识＝多副本对“日志顺序”达成一致，使整个组对外表现得像一台不出错的机器；多数派（quorum）是为了防脑裂——分区时只有一边能凑齐多数。
- 边界要补：共识≠线性一致的读（ZK 读可走 follower 快照）；CAP 里它们选 CP（见 SYS-031）。被问“为什么不用 2PC”：2PC 协调者单点阻塞，共识协议去中心化且有 leader 故障接管。

## Q08：你怎么理解数据库中的一致性？

### 面试回答

“一致性”在数据库语境有三层，先分层再答：

- 约束层：主键／唯一／外键／check 不被违反，数据合法——声明式，最具体。
- 事务层：ACID 的 C——事务把数据从一个一致状态搬到下一个一致状态，是“业务不变量”（转账两边总额不变），靠 AID 机制支撑＋正确 SQL。
- 复制层（常被混进来）：主从／多副本间看到相同数据（强一致读 vs 最终一致）——这已经属于分布式一致性语义，跨库时别和 ACID 的 C 混说（对比展开见 Q10）。
- 加分收口：企业报表场景帆软这类产品里，“一致性”多数时候指第 2 层（口径统一）＋第 3 层（主从延迟导致报表读旧数），要按场景对齐语言。

## Q09：消息队列中 exactly-once（恰好一次）是怎么做到的？

### 面试回答

先破题：投递网络不可靠，端到端“只发一次且不重做”物理上做不到，工程口径是**效果恰好一次**＝不丢＋业务幂等／事务：

- 生产侧：at-least-once（确认机制）保不丢；Kafka 幂等生产者用 PID＋序列号在分区内去重（只解决重发重复，跨分区不算事务）。
- 消费侧：处理成功再提交 offset——宕机重启会重复消费，所以真正的 once 靠消费幂等：唯一业务键去重表、状态机版本号、或“更新即幂等”的 SQL。
- 强形态（事务）：把“消费 offset 提交”和“业务写结果”放进同一个事务——本地事务表／outbox，或 Kafka 事务（read-process-write，EOS 域内）、Flink 两阶段提交（checkpoint 驱动 source offset＋sink 事务）。
- 收尾一句：官方 exactly-once（Kafka EOS）范围也只覆盖 Kafka 内部读写闭环；一旦跨到外部系统，就回到“事务消息＋幂等”的组合拳。

## Q10：分布式事务的一致性和数据库的一致性有什么区别？

### 面试回答

同一个词，两个坐标系：

- 数据库一致性（ACID 的 C）：单机事务边界内，数据不违反约束与不变量；边界、锁、日志都在一个 DBMS 手里，能保证强一致。
- 分布式事务“一致性”：多个本地事务跨节点要么都成要么都败——它保证的是“跨库的最终状态合法”，而协调过程只能靠协议逼近：2PC／3PC（同步阻塞、协调者单点）、TCC（业务层 Try-Confirm-Cancel）、Saga（长事务正向链＋补偿链）、事务消息／本地消息表（放弃强一致，换最终一致）。
- 关键区别三句：作用范围（单库内 vs 跨服务／跨库）；代价模型（锁与日志 vs 协调轮次与补偿逻辑）；一致性强度（事务级强一致 vs 大多选最终一致）。
- 加分：分布式里“一致”还可能指复制一致性（主从读到多少旧值），和分布式事务又不是一回事——先把对方问的是哪种再答（见 SYS-041）。

## Q11：值传递和引用传递有什么区别？Java 属于哪一种？

### 面试回答

- 区别看一件事：被调方法里给形参重新赋值，调用方的实参会不会跟着变。会变才有“引用传递”；值传递传的是副本，改绑定不影响实参。
- Java 只有值传递——对象参数传的是“引用的值（副本）”：
  - 方法里 `list = new ArrayList()` 重新赋值 → 外面不受影响（只改了副本）。
  - 方法里 `list.add(..)` 解引用改对象 → 外面可见（副本指向同一个堆对象）。
  - 经典佐证：swap 两个 int 永远交换失败；把对象当参数换指向也不行，改内容就行。
- 对比 C++（`void f(T&)` 真引用传递，形参就是别名）能显出概念边界。
- 易错点：说“Java 对象是引用传递”是话术陷阱——“引用当值传”和“引用传递”不是一回事。

## Q12：什么是死锁？为什么会发生死锁？编码里面怎么避免产生死锁？

### 面试回答

- 定义：一组线程互相持有对方要的资源并都在等对方释放，全体永久阻塞——不是慢，是永远醒不来。
- 为什么：四个必要条件同时成立——互斥、持有并等待、不可剥夺、循环等待；缺一不可。
- 编码避免按“破坏条件”给招：
  - 统一加锁顺序（全局排序后所有人按序拿）——破循环等待，最常用也最可审计。
  - 一次拿齐：`tryLock(timeout)` 拿不到就整体退让重试——破持有并等待。
  - 缩小锁域：锁内不再调外部可能加别的锁的方法；能分段就分段。
  - 能无锁则无锁：并发容器、原子类、不可变对象，根本不进锁世界。
- 兜底：数据库死锁靠检测（等待图／超时）回滚牺牲者，应用层靠看门狗与日志发现——避免是设计问题，发现是运维问题，两句都要有。

## Q13：操作系统为什么有用户态和内核态？哪些操作会触发用户态切到内核态？

### 面试回答

- 为什么分两档权限：系统资源（内存页表、设备、时钟）必须受控——若用户程序可直改页表／执行特权指令，任何 bug 或恶意程序都能拖垮整机；用户态受限执行、内核态统一管理，隔离和保护是所有多任务系统的地基。
- 怎么切：靠硬件支持的“状态位＋受控入口”——系统调用（`read／write／fork`，`syscall`／`int 0x80` 老式）、中断（时钟到点、IO 完成）、异常（缺页、除零、越权指令）三类入口；切换时保存上下文、切内核栈，代价≈两级上下文开销，这也是“频繁小 IO 系统调用慢”的原因。
- 补一句现代表述：现代 OS 用虚拟地址后，用户态代码根本访问不到内核映射（缺页即杀），边界由 MMU 强制。

## Q14：OSI 七层和 TCP／IP 四层模型有什么区别？为什么实际应用以 TCP／IP 为主？

### 面试回答

- 映射与差别：OSI 是理论参考模型（物理／数据链路／网络／传输／会话／表示／应用七层，职责划分教科书化）；TCP／IP 是实践产物（网络接口／网际 IP／传输 TCP·UDP／应用四层），会话与表示的功能被并入应用层，ARP 等协议在分层归属上还常有争议。
- 为什么 TCP／IP 赢：先有实现后成标准——它长在实际网络（ARPANET）上，每层职责被“能用就行”地裁剪；OSI 设计完备但过重、周期长，落地时厂商生态（RFC 迭代 vs 严格标准化）已经站在 TCP／IP 一边。
- 面试价值句：OSI 当“讲协议的坐标系”（说“三次握手”在哪层就靠它），TCP／IP 当“事实标准”——两套并提、按层报协议归属，是这题最稳的答法。

## Q15：HTTPS 如何保证数据传输安全？和 HTTP 的本质区别？

### 面试回答

- 本质区别一句：HTTP 明文传输、内容任何人可读可改；HTTPS＝HTTP over TLS，在不可信信道上提供机密性＋完整性＋身份认证三件。
- 三件各靠什么：机密性——对称加密（AEAD）加密正文，对称密钥靠握手期用证书公钥校验身份后由 ECDHE 临时密钥协商（TLS 1.3 一律前向安全）；完整性——AEAD 自带认证标签，防篡改；认证——证书链逐级验到受信 CA，确认公钥归属域名。
- 补两个常被追的点：证书只证明“公钥是谁签发的”，数据量大了不可能全程非对称加密（性能）——所以全程只有握手用非对称、传输用对称；中间人降级或伪造靠 HSTS／证书钉扎再收口。

## Q16：多线程编程中锁有什么作用？

### 面试回答

锁提供三件东西，一件都替代不了“不加”：

- 互斥：同一时刻只放一个线程进临界区，把“读—改—写”这类复合操作钉成一步，防更新丢失。
- 可见性：解锁前的写对下一个加锁者可见（释放／获取配对建立 happens-before），不用自己操心缓存同步。
- 有序性约束：临界区外的重排不会穿过锁的同步语义。
- 顺带说边界：锁≠线程安全的全部——能不用锁先想不可变、线程封闭、并发容器；该用锁时按最小临界区设计；锁保护的是“同一份共享可变状态的复合操作”，锁对象选错（比如锁装箱 Integer）等于没锁。

## Q18：100 亿行全年销售数据（商品名、金额），用 3 台机器算销售额最多的前 3 个商品，怎么设计？

### 面试回答

先点破题意：要的是“按商品名求和后的 Top3”，不是逐行 TopK——所以核心是把同一商品的行聚到同一台机器：

- 分片：对商品名做哈希 `hash(商品名) % 3` 把文件切给 3 台机器——同一商品全链路只在一台聚合，天然无跨机合并误差；商品名基数决定倾斜风险，个别爆品名可再按金额拆分二次聚合（热点打散）。
- 每台机器内：流式读入（别整文件进内存），HashMap 累加金额；数据量超过内存时对（商品名，金额）先排序外部归并或二次分桶（哈希到临时文件再分块聚合）。
- 取 Top3：本机聚合完用小顶堆维护容量 3（或全量聚合后堆／nth_element 取 Top3）；3 台各交候选，汇总端再取全局 Top3——每机 Top3 的并集一定包含全局 Top3。
- 口径补充：数据在磁盘不在库也照样按此思路；如果本来在数仓／ClickHouse，一条 `GROUP BY 商品名 ORDER BY SUM(金额) DESC LIMIT 3` 才是第一答案——先问清数据形态再设计，这题考的是“知道什么时候不用手写”。

## Q19：HashSet 和 TreeSet 在底层实现以及增删改查性能上有哪些区别？

### 面试回答

- HashSet：底层是 HashMap（元素当 key，value 是共享哑值 DUMMY）——哈希定位，add／remove／contains 平均 O(1)、最坏 O(n)（同桶链，8 且容量够树化降 O(log n)）；元素无序；允许一个 null。
- TreeSet：底层 TreeMap（红黑树），元素自身排序（Comparable／Comparator）——add／remove／contains／firstKey 都是 O(log n)；遍历即有序；**不接受 null**（比较会 NPE），去重按 `compareTo==0` 而不是 equals——两者不一致时行为会“看起来丢元素”。
- 中间形态补一句：LinkedHashSet＝哈希表＋双向链表，保插入序、仍是 O(1)——“要不要序、要哪种序”决定选型。
- 性能对比收口：查找多且无需序 → HashSet；要范围查询（higher／floor／subSet）或天然有序 → TreeSet，为 log n 和对象开销付费。

## Q20：ARM 芯片和英特尔芯片有什么区别？

### 面试回答

设计哲学＋生态两层，避免只答“一个省电一个强”：

- 指令集哲学：传统叙事是 RISC（ARM，定长指令、加载-存储式、易高能效核）vs CISC（x86，变长复杂指令、向后兼容包袱重）；但现代两者已相互吸收——x86 内部也微解码成类 RISC 执行，ARM 也加复杂指令，差异更多在授权模式与生态惯性。
- 功耗与场景：ARM 能效优先主导手机、嵌入式，近年进服务器与 PC（Apple Silicon、云端 ARM 实例）；x86 单线程峰值与存量软件生态强，仍主导传统服务器／PC。
- 商业模式：ARM 卖 IP 授权（厂商自研核、生态分散但灵活），Intel 自产自用＋封闭生态（Windows-x86 联盟）。
- 对 Java 的影响收口：JVM 多 ISA 都有实现（跨平台口径见 JVM-004）；换架构要重编译本地依赖、验证性能，AOT／JIT 行为与原子指令（LL/SC vs lock cmpxchg）在实现上有差异——性能不是绝对值，是负载相关。
