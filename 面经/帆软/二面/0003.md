## Q02：32 位和 64 位操作系统有什么区别？

### 面试回答

根子在 CPU 寄存器宽度和指针位宽，寻址上限只是它的结果。

- 字长：32 位 CPU 一次处理 32 位数据，指针 4 字节；64 位一次处理 64 位，指针 8 字节。
- 可寻址内存：32 位最多 2^32 = 4GB，且单进程用户空间更少；64 位虚拟地址空间大到实际由硬件位数截断（x86-64 当前 48 位）。
- 兼容：64 位系统能靠兼容层跑 32 位程序，反之不行；驱动必须位数匹配。
- 性能：64 位一次搬运更多数据、通用寄存器更多，大整数／加密更快；代价是指针和对象占内存更大。

## Q03：Java 中 long 和 Long 有什么区别？性能上呢？

### 面试回答

`long` 是基本类型，`Long` 是它的包装类。

- 存储：`long` 直接存 8 字节数值；`Long` 是堆上的对象，含对象头，能表示 `null`。
- 用途：泛型、集合、需要“可空”的场景只能用 `Long`；其余优先 `long`。
- 比较：`Long` 之间用 `==` 比的是对象身份，缓存范围（-128~127）外不相等，比值要用 `equals`。
- 性能：`Long` 有装箱／拆箱开销和额外堆分配，数组场景 `long[]` 远比 `Long[]` 省内存、缓存更友好；拆箱遇 `null` 会抛 NPE。

## Q04：怎么理解 Java 的字节码，为什么需要字节码这种设计？

### 面试回答

字节码是 Java 源码编译后、面向 JVM 这台“虚拟机器”的中间指令，存在 `.class` 文件里。

- 为什么需要：它是“一次编写、到处运行”的关键中间层——源码只编译一次成平台无关字节码，各平台的 JVM 再把它翻译成本机指令。
- 好处有三层：跨平台（字节码不绑 CPU 架构）、安全（加载时先字节码校验）、给运行期优化留空间（解释器＋JIT 按热点把字节码编成本地码）。
- 一句收口：跨平台的是字节码和 Java API 语义，JVM 本身仍是平台相关的原生程序。

## Q05：描述有向图上 Dijkstra 算法的计算过程，并现场手写实现。

### 面试回答

Dijkstra 求非负权有向图的单源最短路，核心是“贪心＋优先队列”。

- 初始化：源点距离 0，其余无穷大。
- 每轮：从待处理集合里弹出当前距离最小的点 u，确定它；用 u 松弛它的每条出边 (u,v,w)。
- 若 `dist[u]+w < dist[v]` 就更新 `dist[v]` 并把新值入队；弹出时如果记录比已知距离大，说明是过期记录，跳过。
- 前提：边权非负。有负权边这个贪心前提被破坏，改用 Bellman-Ford。

手写用二叉堆做优先队列，复杂度 O((V+E)logV)。

## Q07：长度为 n 的数组，输出每个连续 k 个数的最大值和最小值，并讲解执行流程。

### 面试回答

这是滑动窗口最值，标准解是单调双端队列，O(n)。

- 求最大值：维护一个下标的递减队列。新元素进来时，从队尾弹出所有比它小的（它们再也不可能当窗口最大值），再压入当前下标。
- 队首若已滑出窗口左边界（下标 ≤ i-k）就弹出队首；队首下标对应的值就是当前窗口最大值。
- 求最小值对称：维护递增队列。
- 前 k-1 个窗口不完整，从 i=k-1 开始记录答案。

复杂度：每个元素入队出队各一次，均摊 O(n)，空间 O(k)。面试官还会给一组用例让你走一遍队首队尾的变化。
