## Q01：密码的加密存储用的什么方案，可能有哪些问题，有没有更优方案？

### 面试回答

先按【项目实际】说明用的什么方案（比如 BCrypt 哈希），再讲这条演进线。

为什么简单方案不行：

- 明文或者可逆加密：绝对不行，库一旦被拖走就是全量泄露。
- 裸 MD5／SHA：彩虹表能查，GPU 能高速爆破。
- 加盐：能防住彩虹表，但哈希太快，照样可以离线爆破。

更优的做法是专用慢哈希＋每人随机盐：

- BCrypt（cost 可调）、scrypt，或者当前推荐的 Argon2id（内存硬函数，抗 GPU／ASIC 爆破）。
- 在线这一侧：登录侧限流加失败锁定，防住在线爆破。
- 存储层再叠一层：
  - pepper（额外存在服务端的密钥）或者 KMS 加密。
  - 定期升级 cost。
  - 做泄露口令检测。

落地提醒：Spring Security 的 PasswordEncoder 可以直接换算法，还兼容旧哈希，能渐进升级。

## Q02：公共字段的填充为什么要引入 AOP，怎么实现的，有什么作用？

### 面试回答

要解决的问题：创建时间、更新人、逻辑删除标记这些公共字段，每个 insert／update 都得填。散在各个 Service 里，既重复又容易遗漏。

用 AOP 切面拦截写操作、统一填充，做法是：

- 切点匹配 DAO，或者带标记注解的方法。
- 环绕通知里从上下文取值（登录用户、当前时间），set 进实体。
- MyBatis 场景还有另一条路：用 MyBatis-Plus 的 MetaObjectHandler／拦截器，在 SQL 执行前自动填充。

作用三点：横切逻辑集中、业务代码无感、字段口径统一。

一个坑要提：自调用不走代理，这时候填充会失效。

## Q03：Redis 具体是怎么缓存数据的（数据类型、存储的内容等）？

### 面试回答

和一面那道 Redis 题同口径，按【真实项目】答。

哪类数据用什么结构：

- 对象整体：JSON 存 String。
- 要按字段更新：用 Hash。
- 排行榜／时间序：用 ZSet。
- 防重复：用 Set。
- 计数：用 INCR。

## Q04：怎么保证 MySQL 和 Redis 的数据一致性，有没有更好的方案？

### 面试回答

基础方案是 cache-aside：先提交数据库、再删缓存，配 TTL 兜底；删失败用重试队列补偿。

更好的方案是把失效交给事件驱动：

- 订阅 binlog（canal 类工具），让数据变更事件去驱动缓存失效。好处是业务代码零侵入，也不容易漏。
- 并发回填旧值：用延迟二次删除或者 key 版本来收敛。
- 强一致读：直接走库，或者加锁重建。

结论要说清：没有普适的完美方案。先定义一致性要求——也就是业务能容忍多久的陈旧——再去选对应的复杂度。
