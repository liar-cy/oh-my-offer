## Q01：密码的加密存储用的什么方案，可能有哪些问题，有没有更优方案？

### 面试回答

按【项目实际】说明（如 BCrypt 哈希）。方案演进与问题：明文或可逆加密绝对不行（库被拖即全量泄露）；裸 MD5/SHA 可被彩虹表与 GPU 高速爆破；加盐防彩虹表但快哈希仍可离线爆破。更优：专用慢哈希＋每人随机盐——BCrypt（可调 cost）、scrypt，或当前推荐 Argon2id（内存硬函数抗 GPU/ASIC）；登录侧限流与失败锁定在线防爆破；存储层再叠 pepper 或 KMS 加密、定期升级 cost、泄露口令检测。Spring Security 的 PasswordEncoder 可直接换算法并兼容旧哈希渐进升级。

## Q02：公共字段的填充为什么要引入 AOP，怎么实现的，有什么作用？

### 面试回答

创建时间、更新人、逻辑删除标记等公共字段在每个 insert/update 都要填，散在各 Service 里容易遗漏且重复。用 AOP 切面拦截写操作统一填充：切点匹配 DAO／带标记注解的方法，环绕通知里从上下文（登录用户、当前时间）取值 set 进实体；MyBatis 场景也可用 MyBatis-Plus MetaObjectHandler／拦截器在 SQL 执行前自动填充。作用是横切逻辑集中、业务代码无感、字段口径统一；注意自调用不走代理的失效场景。

## Q04：怎么保证 MySQL 和 Redis 的数据一致性，有没有更好的方案？

### 面试回答

基础方案 cache-aside：先提交数据库、再删缓存，配 TTL 兜底；删失败用重试队列补偿。更好的方案：订阅 binlog（canal 类）把缓存失效交给数据变更事件驱动，业务代码零侵入且不易漏；并发回填旧值用延迟二次删除或 key 版本收敛；强一致读直接走库或加锁重建。没有普适完美方案——按业务能容忍多久的陈旧选择，先定义一致性要求再选复杂度。
