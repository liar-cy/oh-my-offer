## Q04：谈谈操作系统存储的分页机制，越详细越好。

### 面试回答

“越详细越好”就给完整流水线，按六步讲：

- 为什么分页：给每个进程连续虚拟地址空间的假象，映射到离散物理页框上——隔离、保护、还能换入换出支撑超配。
- 基本单位：页＝固定大小块（常见 4KB），虚拟侧叫页、物理侧叫页框；虚拟地址切成“页号＋页内偏移”，偏移原样拼到物理地址，所以块内依然连续。
- 翻译：MMU 查页表，页表项（PTE）存页框号＋状态位（存在、读写、用户态、脏位、访问位）；命中后拼物理地址，权限不符直接缺页／段错误。
- 多级页表：稀疏地址空间不配整张表，x86-64 用 4／5 级树，只建用得到的分支；代价是翻译要多次访存，所以配页遍历缓存。
- TLB：缓存最近的“虚拟页→物理帧”结果，进程切换配合 ASID 少冲刷；TLB miss 才走页遍历——这也是大页（2MB／1GB）的意义：条目覆盖范围大、miss 率降。
- 与缺页协作：PTE 标记“不存在”不算错——按需分配、COW、换页回读、堆首次触碰都在缺页处理里完成；非法访问才发 SIGSEGV（细节见 OS-011）。

最后主动给边界：分页内部碎片（平均半页）、页替换策略（LRU／Clock，OS-013）、和分段的区别是“定长可换页 vs 变长有外碎片”。

## Q05：怎么理解同步和异步？操作系统和 Java 里分别是怎么实现同步与异步的？

### 面试回答

先把两对概念钉死（最容易混的地方）：

- 阻塞／非阻塞：看发起调用的瞬间——不等出结果就不返回的是阻塞，立刻返回自己接着干的是非阻塞。
- 同步／异步：看结果怎么通知你——调用结束时结果已经就绪（通常也就是自己等出来的）是同步；完成方主动回调／置位／发信号告诉你的是异步。
- 一句话组合：异步不省“等”，只是把“等”从当前线程的忙转成别处完成后的通知。

操作系统的实现：

- `read()` 同步阻塞：线程睡在等待队列直到数据就绪。
- 非阻塞 fd＋epoll：调用立刻返回、用事件循环批量问“谁好了”——通知仍在调用方线程里同步收割，属于“复用等待”而不是真异步 I/O。
- io_uring：提交队列＋完成队列，内核干活完成后回填 CQ 通知，这才是 Linux 上的真异步 I/O 主力；POSIX AIO 是历史方案。

Java 的实现：

- 同步侧：普通方法调用；线程协作靠锁与 `wait`／`notify`、`Condition`（等待唤醒也是同步语义——自己等结果）。
- 异步侧：`Future`／`CompletableFuture`（先拿凭据后取结果、链式回调）、Netty 的 `ChannelFuture` 与回调线程、Servlet 异步处理释放工作线程。
- 加分收尾：JDK 21 虚拟线程改变的是“同步写法的成本”——阻塞不再钉住平台线程，但语义仍是同步取结果；别把虚拟线程说成异步。

## Q06：共享屏幕，用自己的 IDE 写一个简单的 Java 线程通信 demo。

### 面试回答

现场编码考“最短能跑对”：主题未记录【按现场回忆修正】，双线程交替打印是最通用形态，十行内写完：

- 骨架：一个共享锁对象＋一个布尔标志；`synchronized` 块里“while 条件不对就 `wait()`，轮到自己就干活、翻标志、`notifyAll()`”。
- 边写边说的三个点（面试官在看习惯不只看结果）：条件检查必须用 while 防虚假唤醒；`wait` 会释放锁而 `sleep` 不会；两个线程共用同一个锁对象才有通信意义。
- 收尾主动升级口径：生产里不手写标志位，直接 `BlockingQueue`（或 `Lock`＋两个 `Condition` 精确唤醒），可中断、无丢失通知。

```java
public class PingPong {
    public static void main(String[] args) {
        Object lock = new Object();
        boolean[] pingTurn = {true};
        Runnable task = () -> {
            for (int i = 0; i < 5; i++) {
                synchronized (lock) {
                    while (pingTurn[0] != Thread.currentThread().getName().equals("ping")) {
                        try { lock.wait(); } catch (InterruptedException e) {
                            Thread.currentThread().interrupt(); return;
                        }
                    }
                    System.out.println(Thread.currentThread().getName());
                    pingTurn[0] = !pingTurn[0];
                    lock.notifyAll();
                }
            }
        };
        new Thread(task, "ping").start();
        new Thread(task, "pong").start();
    }
}
```
