## Q02：知识库怎么做，如何实现跨文档关联分析？

以下为可选设计，需按真实项目替换。

### 面试回答

如果让我设计，我会拆成离线入库和在线问答两条链路。

离线入库：

- 解析、清洗，按语义切块。
- 保留元数据：文档、页码、版本、权限。
- 建两类索引，关键词和向量。

在线问答：

- 先检索，过滤权限，再重排。
- 组装证据，让模型回答并给出引用。

跨文档关联分析：

- 先建立关联，靠引用、统一实体 ID、主题和版本。
- 再从问题检索出种子证据，扩展相关文档，逐步合成答案。

选型口径：简单场景用元数据加多轮检索就够，关系复杂再考虑图结构。别混着说——只做向量相似检索，不等于跨文档推理。

实际面试时，要把上面这些替换成本人已实现的组件和评测结果。

## Q04：Skill、MCP 和提示词的区别和作用是什么？

### 面试回答

一句话：三者分别是给模型的指令、可复用的方法包、对外连接的协议。

- 提示词：给模型的指令和上下文。
- Skill：可复用的任务方法包，里面是指引，还可以附脚本和资料。
- MCP：连接 AI 应用与外部工具、外部数据的协议（Model Context Protocol）。

拿整理面经举例，三者各管一段：

- 提示词说明这一次的需求。
- Skill 定义归档和去重的流程。
- MCP 可以用来读取外部资料。

边界别说过头：Skill 不等于工具服务，MCP 也不负责替模型决定业务流程。

## Q05：vibe coding 一个项目的大概流程是怎样的？

### 面试回答

我按“先定标准，再小步循环”来走。

准备阶段：

- 明确目标、输入输出和验收标准。
- 读取项目规则与现有结构。
- 再让 AI 帮忙拆成可检查的小任务。

每转一圈：

- 只实现一个可运行的改动。
- 自己检查 diff，跑相关测试，再验证真实的用户流程。
- 确认没问题才继续下一步。

一条纪律：遇到失败先定位原因。别不停追加提示，那样代码会越改越偏。

## Q07：Spring Boot 自动装配的原理是什么？

### 面试回答

一句话：自动装配 ＝ 导入候选配置 ＋ 按条件决定生效 ＋ 往容器注册 Bean。

机制拆开说是：

- `@SpringBootApplication` 里的 `@EnableAutoConfiguration` 负责导入自动配置的候选类。
- 候选项从哪读：Spring Boot 3 主要从 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 拿。
- 哪些真正生效，由条件注解决定。
- 常见条件有：`@ConditionalOnClass`、`@ConditionalOnMissingBean`、`@ConditionalOnProperty` 等。

最后收一句本质：生效的自动配置，仍然是向 IoC 容器注册 Bean。所以开发者自己定义了同类 Bean 时，很多默认配置会自动退让。

## Q08：IoC 和 AOP 是什么，具体原理是什么？

### 面试回答

两个概念分开讲，各自先说是什么、再说原理。

IoC（控制反转）：

- 把对象创建和依赖管理交给容器。
- Spring 读取配置形成 BeanDefinition，再实例化、注入、初始化。
- 生命周期还能通过后处理器等方式来扩展。

AOP（面向切面编程）：

- 把事务、日志这类逻辑集中处理。
- Spring AOP 通常用 JDK 接口代理或 CGLIB 子类代理，在方法调用前后执行拦截器链。
- 容器可以在 Bean 创建过程中就返回代理对象。

一个必考的边界：只有调用经过代理，才会应用相应的增强；同类里 this 自调用通常绕过代理。

口径提醒：具体的代理类型、能拦截的方法范围，要结合配置和版本来说。

## Q09：MySQL 的事务分为哪几种？

原题分类维度不明确，先按隔离级别回答，保留这一解释前提。

### 面试回答

先确认口径：如果您问的是隔离级别，那是四种。

- 读未提交、读已提交、可重复读、串行化。
- InnoDB 默认是可重复读。
- 它们主要权衡的是并发和读一致性。
- InnoDB 结合 MVCC 和锁来实现相应语义。

再主动留一句：“如果您指的是提交方式或分布式事务类型，我可以按那个维度回答。”

顺带澄清一个常见混答：ACID 的四个特性不是四种事务。

## Q10：表有姓名、科目、分数字段，查询分数都大于 80 分的人员名单。

### 面试回答

思路是按人员分组，在 HAVING 里判断最小成绩大于 80。下面把 NULL 视为不合格，并暂按姓名区分人员：

```sql
SELECT name
FROM scores
GROUP BY name
HAVING MIN(score) > 80
   AND COUNT(score) = COUNT(*);
```

不能先 WHERE score > 80，否则低分会被提前过滤。真实表应按人员 ID 分组；如果要求所有应修科目都已参加考试，还需科目清单核对缺考。
