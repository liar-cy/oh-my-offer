## Q04：项目做集群部署，各节点都要基于 WebSocket 做协同处理，怎么部署、会遇到哪些问题、怎么解决？

**怎么部署**：

- WebSocket 是有状态长连接，前置负载均衡必须开会话粘滞（IP hash／一致性 hash）或网关按连接 ID 路由，不能轮询乱打。
- 连接会话信息（连接 ID → 所在节点）注册到共享存储（Redis），跨节点投递靠消息总线（Redis pub／sub、MQ 广播）或路由表转发。
- 协同要处理的数据状态放共享权威源（DB／对象存储／Redis），节点保持无状态，扩节点才有效。

**会遇到哪些问题与解法**：

- 消息只到本节点：A 节点的客户端收不到 B 节点上发生的变更 → 所有变更走总线广播，或经路由表定向转发。
- 连接漂移：节点重启／扩缩容导致连接断，客户端要带重连与状态补齐（重连后按版本号拉增量）。
- 重复与乱序：广播可能重投 → 操作带全局幂等 ID＋单调版本，接收端判重判序。
- 并发写冲突：多节点同时改同一资源 → 锁要在共享介质上（Redis 锁／DB 行锁），单机 `synchronized` 无效；更优是按资源 hash 串行化或用 OT／CRDT 合并。
- 心跳与超时：Nginx／网关默认读超时会掐长连接，需要应用层心跳与调大代理超时。
- 横向扩展瓶颈：单节点连接数受文件描述符与内存限制，要压测定容量。

## Q05：现场代码题：删除 List＜Student＞ 中 number 为 007 的记录

**题面（按图片转写）**：给出一个 `Student` 类——字段 `String name`、`Integer old`、`String number`、`String sex`，带无参构造与全参构造（getter／setter 用“…”省略），要求：给你一个 `List<Student> students`，删除其中 `number` 为 `007` 的学生记录。

**写法（现场首选 removeIf）**：

```java
students.removeIf(s -> "007".equals(s.getNumber()));
```

- `"007"` 写在前面：`number` 可能为 null，常量在前的 `equals` 天然免判空。
- `number` 是 `String`，所以按字符串比较。别转成 int 再比 `7`——学号前导零会丢，`"007"` 和 `"7"` 是两个不同学号。
- `removeIf` 删掉全部匹配项，时间 O(n)，一次遍历。

**另外两种等价写法**：

```java
Iterator<Student> it = students.iterator();
while (it.hasNext()) {
    if ("007".equals(it.next().getNumber())) it.remove();   // 迭代器自己的 remove
}

for (int i = students.size() - 1; i >= 0; i--) {            // 倒序按下标删
    if ("007".equals(students.get(i).getNumber())) students.remove(i);
}
```

- 不能在 for-each 里写 `students.remove(...)`，会抛 `ConcurrentModificationException`——这题写完面试官紧接着就问了这一条（见下一题）。
- 正序按下标删会跳元素：删掉一个后后面的前移，索引不加回退就漏掉相邻那条。

**现场要主动确认的口径**：

- 只删第一条还是全部匹配？只删一条就用迭代器命中后 `break`，或先 `removeIf` 前用 `stream().filter(...).findFirst()` 定位。
- 要不要返回被删的记录？需要就先收集再删（`removeIf` 里做副作用不干净，宁可两趟）。
- `students` 可能为 null 或不可变（`List.of(...)`／`Arrays.asList()` 固定长度）：不可变列表删元素会抛 `UnsupportedOperationException`，要先 `new ArrayList<>(list)` 包一层。

## Q06：在集合的 for 或 for-each 循环中执行删除操作，会有什么问题？

**结论**：for-each 里直接调集合自身的 `remove` 会抛 `ConcurrentModificationException`（CME），因为结构性修改会让 fail-fast 检测生效。

- 原理：`ArrayList`／`HashMap` 等维护一个 `modCount`，迭代器创建时记下期望值，每次 `next`／`remove` 前比对；集合自己改过就不一致，抛 CME。
- for-each 只是语法糖，编译成 `Iterator` 遍历，所以一样受这条契约约束；`ArrayList` 与 `LinkedList` 都适用。
- 普通下标 `for` 正序删除不抛异常，但有另一类错误：删除后元素前移、下标错位，会跳过相邻的重复元素。

**正确写法**：

```java
list.removeIf(x -> shouldDrop(x));        // JDK 8+，首选
it.remove();                              // 用迭代器自己的 remove，同步 modCount
for (int i = list.size() - 1; i >= 0; i--)  // 倒序按下标删，不跳元素
```

**补一句边界**：CME 是“尽力检测”，不是线程安全机制；并发修改场景要用并发集合（`CopyOnWriteArrayList` 的迭代器是快照，不抛 CME 但可能读到旧数据）。

## Q07：Map＜Student, String＞ 允许吗、要注意什么？HashCode 和 Equals 是什么关系？

**允许吗**：语法上完全允许——`Student` 是引用类型，可以做 key。要注意的全在契约上。

**必须注意的三件事**：

- 重写 `equals` 就必须重写 `hashCode`，且只用不可变字段参与。
- key 放进 Map 后别改它参与哈希的字段——哈希定位会失效。
- 想按“内容相同即同一人”检索，得两个方法都按业务字段实现；只按对象身份当句柄，则用默认实现即可（或用 `IdentityHashMap`）。

**hashCode 与 equals 的关系**：

- 契约：`equals` 相等 ⇒ `hashCode` 必须相等；`hashCode` 相等 ⇒ 不一定 `equals` 相等（哈希冲突）。
- 只重写 `equals` 不重写 `hashCode` 会怎样：两个逻辑相等的对象落进不同的桶，`get` 取不到、`put` 覆盖不掉，出现“里面有却查不到”的诡异现象。
- HashMap 的定位流程正好解释了这条：先用 hashCode（高 16 位异或低 16 位扰动）算桶，再在桶内用 `equals` 确认命中；两步都依赖契约成立。

**为什么生产上 key 常用 String／Long 而不是自定义对象**：String 不可变、`hashCode` 有缓存且稳定；自定义可变对象一旦字段被改就定位失效。

## Q08：MySQL 的 join 有几种？给定 T1、T2 数据，inner join 与 left join 各返回几条？

**种类**：

- 语法层：`INNER JOIN`、`LEFT [OUTER] JOIN`、`RIGHT [OUTER] JOIN`；MySQL 不支持 `FULL OUTER JOIN`，用 left union right 模拟。
- 实现层（优化器视角）：连接算法有 Nested-Loop、Block Nested-Loop、Batched Key Access，以及 MySQL 8.0.18 起用于等值连接的 Hash Join；走哪种取决于内表连接列上有没有索引。
- 驱动方向：`LEFT JOIN` 以左表为驱动表（左表全部行保留），`RIGHT JOIN` 是镜像；`INNER JOIN` 由优化器自己挑驱动表。
- 另两类常一起提：交叉连接（笛卡尔积）与自连接。

**本题算条数**：

- T1.id = {1, 2, 3}；T2 两行为 (id=1, aid=1)、(id=3, aid=2)，即 aid 集合 = {1, 2}。
- `inner join on T1.id = T2.aid`：aid=1 对上 T1.id=1（配 T2 第一行）、aid=2 对上 T1.id=2（配 T2 第二行），共 **2 条**。
- `left join on T1.id = T2.aid`：以 T1 全 3 行为基准，未匹配的 T1.id=3 补 NULL，共 **3 条**。
- 说明一句匹配依据：连接用的是 T2 的 aid 列，不是 T2 的 id 列——(3, 2) 这行靠 aid=2 命中 T1.id=2，跟它自己的 id=3 无关。

**易错提醒**：把 left join 写成“匹配不到就不返回”会算少；连接条件写在 `WHERE` 里会让 left join 退化成 inner join（NULL 行被过滤掉）。

## Q09：SQL：统计每个学校面试总人数；再找出人数最多的学校

表 T1(id, name, school, time)——学号、姓名、学校、面试时间。

**每校面试总人数**：

```sql
SELECT school, COUNT(*) AS cnt
FROM T1
GROUP BY school;
```

- 用 `COUNT(*)` 统计行数；如果同一人可能多条面试记录而题意指“人数”，改成 `COUNT(DISTINCT id)`（这题口径要和面试官确认）。

**人数最多的学校**：

```sql
SELECT school, COUNT(*) AS cnt
FROM T1
GROUP BY school
ORDER BY cnt DESC
LIMIT 1;
```

**要主动说的两个边界**：

- 并列最多时上面只返回 1 行；要全部并列项就用子查询取 `HAVING cnt = (SELECT MAX(cnt) ...)`，或用窗口函数 `RANK() OVER (ORDER BY cnt DESC) = 1`（MySQL 8.0+）。
- 只想看前 N 名学校，把 `LIMIT 1` 换成 `LIMIT N`；`ORDER BY` 别名在 MySQL 中可用，标准 SQL 里要重写表达式。

## Q10：Spring 有哪些常用注解？

报名字没区分度，按“用途分类＋每类一句机制”来讲：

- 容器与配置：`@SpringBootApplication`（＝`@EnableAutoConfiguration`＋`@Configuration`＋`@ComponentScan`）、`@Configuration`／`@Bean`、`@Component` 及派生的 `@Service`／`@Repository`／`@Controller`、`@Import`、`@Conditional*`——由配置类解析与自动装配处理。
- 注入：`@Autowired`、`@Value`、`@Resource`、`@Qualifier`——由 `BeanPostProcessor` 在属性填充阶段处理。
- Web 层：`@RestController`、`@RequestMapping`／`@GetMapping`、`@PathVariable`、`@RequestParam`、`@RequestBody`——由 `DispatcherServlet` 与处理器映射／参数解析器处理。
- 切面与事务：`@Aspect`／`@Before`／`@Around`、`@Transactional`——靠 AOP 代理生效，因此自调用会绕过。
- 条件与生命周期：`@ConditionalOnClass`、`@Lazy`、`@PostConstruct`／`@PreDestroy`、`@Order`。

收尾一句：注解本身不做事，做事的是背后的后置处理器与代理；说清“哪个阶段生效”比背全名单更能过这一问。

## Q11：一个接口两个实现类，Controller 层用 @Autowired 注入会有什么问题？怎么解决？

**问题**：`@Autowired` 按类型找 Bean，接口有两个实现时候选不唯一，启动即抛 `NoUniqueBeanDefinitionException`（required=true 时）。

- 有一个特例：若字段名恰好等于某个 Bean 名，会按名称回退匹配成功——但这种“碰巧能跑”依赖命名，重构改字段名就炸，属于隐患不是解法。

**解法**（按推荐度）：

- 注入点限定：`@Autowired` ＋ `@Qualifier("beanName")`，或直接用 `@Resource(name = "beanName")`。
- 定默认：某个实现标 `@Primary`，其余注入点仍可点名覆盖。
- 全都要：注入 `List<PayService>` 或 `Map<String, PayService>`（key 是 Bean 名），运行时按渠道路由——策略模式的标准写法。
- 自定义限定符：定义带 `@Qualifier` 的注解（如 `@Alipay`），语义比字符串 Bean 名更清楚、可编译期检查。
- 从根上消：一个接口对应一个职责，两个实现说明职责该拆分。

**构造器注入的补充**：构造器参数上同样要 `@Qualifier`；只有一个构造器时可省略 `@Autowired`。
