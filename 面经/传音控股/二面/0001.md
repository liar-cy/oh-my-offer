## Q01：介绍 Java NIO 模型、多路复用。

### 面试回答

Java NIO 三件套：Buffer（数据读写都经过它，position/limit/capacity 游标模型）、Channel（双向，read/write 非阻塞）、Selector（一个线程注册多个 Channel 的关注事件，select() 返回就绪集合再逐个处理）——多路复用在 Java 层的封装就是 Selector，Linux 下底层对应 epoll（Windows 为 IOCP 模型实现），Netty 再在其上做 Reactor 主从线程组模型。和传统 BIO“一连接一线程”对比讲：C10K 场景下线程数与内存/上下文切换爆炸，NIO 用少量线程服务大量连接。要点补一句：select 返回只是“就绪”，不代表 read 一定不阻塞/数据一定完整，处理半包与写缓冲是框架层的活。

## Q02：多线程——继承 Thread 和实现 Runnable 接口有什么区别？

### 面试回答

本质区别在“任务与执行载体是否分离”：Thread 自己就是执行载体，逻辑写在 run() 里，Java 单继承导致继承了 Thread 就不能继承别的类，且每个任务要一个新 Thread 对象、状态和数据不好共享；Runnable 只是“要执行的任务”，把任务交给任意 Thread（或线程池）执行，同一实例可被多个线程跑、便于共享数据和统一调度，也适配 Lambda 与 `ExecutorService`。还有第三种 Callable＋`Future`：有返回值、可抛检查异常，配合线程池提交拿结果。实现层面 Thread 本身也实现了 Runnable——线程真正执行的是传入的任务对象。

## Q03：用过什么锁？synchronized 底层和对象头？

### 面试回答

“用过什么”按真实口径答：方法/代码块级 synchronized、JUC 的 ReentrantLock（tryLock/Condition 场景）、并发容器内自带的锁、Redis/DB 分布式锁【真实经历选】。synchronized 底层：字节码是 monitorenter/monitorexit（方法级用 ACC_SYNCHRONIZED 标志），运行时对象监视器信息记录在对象头 Mark Word 里；HotSpot 的锁状态演进是无锁→轻量级锁（CAS 把 Mark Word 复制到栈上锁记录）→膨胀为重量级锁（monitor，基于操作系统互斥量，未抢到的线程阻塞），历史上还有偏向锁、因收益下降维护成本高已在 JDK 15 起废弃。对象头＝Mark Word（哈希/年龄/锁标志位等复用同一字）＋类型指针（压缩类指针），数组另有长度。实现细节按 HotSpot 版本核对，不背死。

## Q04：介绍一下 Prompt 工程，对 harness 怎么理解，用过什么 harness 开源模型？

### 面试回答

Prompt 工程：把任务说清楚的系统化方法——角色与目标、边界与禁令、少样本示例、输出格式契约、思维步骤引导，配合评测集迭代（bad case 驱动、版本化、逐项消融），稳定规则下沉执行层而不是全靠措辞。harness 是模型外的“运行外壳”：上下文组装与预算、工具注册执行与结果回灌、循环与停止控制、状态持久化恢复；同模型不同 harness 效果差异巨大（Claude Code、OpenCode 类产品的竞争力即在 harness）。最后一问指代不明，按两种理解如实答：用过的开源 Agent harness 框架【如跑过的真实项目】，或用过的开源模型【真实列表】；没实际用过就说明了解程度止于文档/源码阅读，不虚报。

## Q05：实习现在每天用多少 token？

### 面试回答

如实框架：按【网关/计费面板】口径报数——日均总量＋构成（输入 vs 输出、缓存命中占比、按场景拆分：对话、代码补全、批处理任务）。算法：调用次数 × 平均（输入＋输出）token，输入侧上下文长度是大头；监控口径用 tokenizer 估算或 API usage 字段回传。这题考点其实是成本意识：报得出数、说得出哪类任务最贵、做过什么优化（上下文裁剪、缓存、分级用小模型）。没统计过就坦白，并给出你估计的方法和量级。

## Q06：MBTI 是什么，怎么理解 i 人？

### 面试回答

先给定义：MBTI 是行为偏好自评问卷，四个维度（能量来源 E/I、信息获取 S/N、决策方式 T/F、生活态度 J/P）组合出 16 型。再给清醒评价：它更像沟通与自我认知的框架，重测稳定性和预测工作表现的能力有限，心理学界更常用大五模型，所以不宜拿它给人贴能力标签。理解“i 人”：I 指独处时恢复精力、社交消耗能量，不等于社恐、不等于不会沟通、更不等于专业能力差。落点：我是什么倾向不重要，重要的是知道自己的协作方式——比如【真实例子：深度工作前段少开会、评审时提前准备书面材料再讨论】。

## Q08：产品给的需求你和老员工方案不同但你的更好，怎么说服他？

### 面试回答

行为题框架（按真实案例填）：先承认“我的更好”当时只是我的判断，第一步是补齐信息差——老员工方案里可能有我不知道的历史约束（兼容性、依赖、踩过的坑），先问清再评价；然后对齐目标和口径，把分歧从“谁的方案好”换成“按什么标准衡量”（成本、风险、可维护性、上线时间），拿数据、原型或小范围验证说话而不是口头之争；范围上可提议先在新模块试点，让结果替你说话；如果对齐后仍要按对方方案执行，尊重团队决策并把它执行好，保留可度量反馈。核心是：对事讲证据、对人给台阶、决策归属团队。
