## Q01：Object 类有哪些方法？equals 和 hashCode 为什么要一起重写？

### 面试回答

Object 有 9 类共 11 个公开方法，按用途分四组说：

- 相等与哈希：equals、hashCode。
- 运行时信息与复制：getClass、clone。
- 等待与唤醒：wait（三个重载）、notify、notifyAll。
- 收尾：toString、finalize（Java 9 起不推荐）。

一起重写的原因，一句话：契约要求“equals 相等的对象，hashCode 必须相等”。

- 只重写 equals 不重写 hashCode，内容相等的两个对象哈希值不同。
- HashMap／HashSet 先用 hashCode 定位桶，再用 equals 确认。
- 哈希对不上就落进不同桶，结果是 get 取不到、去重去不掉、remove 删不掉。
- 反过来 hashCode 相等但 equals 不等是允许的，那叫哈希冲突，由链表兜住。

## Q02：介绍一下 HashMap。

### 面试回答

JDK 8 起的 HashMap 是“数组＋链表＋红黑树”的键值容器，按四条说：

- 存：key 的 hashCode 高低位混合扰动后，用 `(n-1) & hash` 定位桶；容量是 2 的幂。
- 冲突：同桶挂链表；链表长度到 8 且表容量到 64 才树化成红黑树，退化回 6。
- 扩容：元素数超过容量×0.75（默认负载因子）就翻倍扩容；迁移时按 `hash & oldCap` 决定原位还是“原位＋旧容量”，不用重算哈希。
- 特性：允许一个 null key；单线程 O(1) 读写，非线程安全，并发场景用 ConcurrentHashMap。

## Q04：Java 的异常分为哪几种？受检异常和非受检异常在使用上有何不同？

### 面试回答

顶层是 Throwable，往下分两支，Exception 再分两类：

- Error：JVM 自身的问题，如 OutOfMemoryError、StackOverflowError；应用不该捕获、也恢复不了。
- 受检异常（checked）：Exception 下除 RuntimeException 外的部分，如 IOException、SQLException；编译器强制你 catch 或 throws。
- 非受检异常（unchecked）：RuntimeException 及其子类，如空指针、数组越界、类型转换失败；编译器不强制处理。

使用上的差别：

- 受检异常表示“可预期的外部故障”，调用方必须当场表态：重试、换源还是上报。
- 非受检异常多是编码错误，靠前置校验和全局异常处理器兜底，不该到处 catch。
- 一个实践细节：Spring `@Transactional` 默认只对 RuntimeException 回滚，抛受检异常要显式 rollbackFor，这也是业务异常常被定义成 Runtime 的原因。

## Q05：Java 对象的创建过程是怎样的？内存分配到哪儿？

### 面试回答

`new` 一行代码，字节码层面五步：

- 类加载检查：这个类没加载过就先走类加载。
- 分配内存：对象实例分配在堆上，优先从 Eden 区的 TLAB（线程私有分配缓冲）指针碰撞取得。
- 实例字段零值初始化：全部先置为 0／null／false。
- 设置对象头：Mark Word（哈希、年龄、锁状态）＋类型指针。
- 执行构造器 `<init>`：字段显式初始化和构造方法体在这一跑。

两个补充点：

- 栈上放的是引用，对象本体在堆上；`ByteBuffer.allocateDirect` 这类直接内存在堆外，不走这条分配路径。
- 开启逃逸分析后，不逃逸的对象可能被标量替换，根本不在堆上分配。

## Q06：什么情况下会发生堆内存溢出？有垃圾回收器为什么不会把它回收掉？

### 面试回答

堆溢出（`java.lang.OutOfMemoryError: Java heap space`）的常见触发：

- 内存泄漏：只增不删的集合、没关的资源、ThreadLocal 没 remove，老年代持续增长。
- 一次性太大：超大对象或大批量数据，堆放不下。
- 堆配置过小，或长生命周期缓存没有容量上限和逐出策略。

为什么 GC 救不了，一句话：GC 只回收“从 GC Roots 不可达”的对象，溢出的那批对象都还被强引用合法持有。

- 在 GC 眼里它们“还有用”，回收反而是错的。
- 而且 JVM 不是没努力：抛错前通常已经做了多轮 Full GC，回收后仍满足不了分配才抛。
- 真正要做的是找引用链：dump 堆后用 MAT 看“谁还引用着它”。

## Q07：引用类型除了强引用还有什么？

### 面试回答

一共四种，按“多容易被回收”排：

- 强引用：`new` 出来的默认引用，只要可达 GC 就不会回收，宁可 OOM。
- 软引用 SoftReference：内存紧张、快 OOM 时才回收，适合做内存缓存。
- 弱引用 WeakReference：下一次 GC 就回收，不管内存是否紧张；WeakHashMap、ThreadLocalMap 的 key 用它。
- 虚引用 PhantomReference：`get()` 恒为 null，唯一作用是在对象被回收时进 ReferenceQueue 通知你，用于堆外资源跟进清理。

一句收尾：四种引用都可选配引用队列，但回调时机不同——软和弱是“回收前清理入队”，虚是“回收后”。

## Q08：线上 Java 服务报警 CPU 使用率 100%，怎么排查？

### 面试回答

先说三步主线，再说分因：

- `top` 找到高 CPU 进程。
- `top -Hp <pid>` 找到高 CPU 线程，拿到线程 ID。
- 线程号转 16 进制（`printf '%x\n' <tid>`），去 `jstack <pid>` 的输出里匹配 nid，看栈顶在跑什么代码。

然后分三类原因：

- 业务代码：死循环、热点计算、低效正则或序列化。
- GC 风暴：`jstat -gcutil` 或 GC 日志确认是否 Full GC 频繁——这种 CPU 高常伴随响应变慢。
- 环境：容器里报警口径可能是宿主机视角，要区分配额和真实占用。

有 arthas 时可用 `dashboard`／`thread -n 3` 一步到位替代手工命令。

## Q09：synchronized 修饰普通方法和静态方法有什么区别？锁代码块能锁 String 或 Integer 对象吗？

### 面试回答

区别只在锁对象不同：

- 普通同步方法锁 `this`：同一实例互斥，不同实例不互斥。
- 静态同步方法锁声明类的 Class 对象：同一个类的静态同步方法互斥。
- 实例锁和类锁是两个不同对象，彼此不会自动互斥。

代码块能不能锁 String／Integer：语法上任何对象引用都行，但实践上都不该用。

- String：字面量会进字符串池，全程序同一常量是同一把锁，不相关代码会互相排队，还有死锁风险；换成 `new String` 又变成各锁各的对象，锁形同虚设。
- Integer：`valueOf` 对 -128～127 有缓存，锁在小值上会被意外共享；超出范围每次装箱是新对象，值一变引用也变，保护不了共享状态。
- 正确做法：`private final Object lock = new Object()`，专锁专用、不外泄。

## Q10：CopyOnWriteArrayList 怎么保证线程安全？为什么没有 CopyOnWriteLinkedList？

### 面试回答

保证安全靠“写加锁＋引用原子发布”：

- 写操作先拿 ReentrantLock，复制整个底层数组，在新数组上改完再替换旧引用。
- 数组引用是 volatile 语义发布，读操作完全无锁，读的一定是某个时刻的快照。
- 所以它做到的是弱一致性：写完立刻被别的线程读到不保证，迭代器不抛 ConcurrentModificationException。
- 适用条件：读多写少（监听器列表、白名单）；写频繁不行，每次写都是 O(n) 复制，GC 压力大。

为什么没有 CopyOnWriteLinkedList——是“不划算”，不是“不可能”：

- 收益端：COW 的核心卖点是读无锁＋按下标直取，链表本来没有随机读，卖点没了。
- 成本端：数组复制是一次内存拷贝，链表复制要逐个 new 节点，更贵。
- 需求端：真要并发频繁插删，有 ConcurrentLinkedQueue（CAS 无锁队列）和 Collections.synchronizedList，COW 链表两头都不占。

关联专题：[[专题题库/Java并发#JUC-021：CopyOnWriteArrayList 是怎么保证线程安全的？为什么没有 CopyOnWriteLinkedList？|JUC-021：CopyOnWriteArrayList 是怎么保证线程安全的？为什么没有 CopyOnWriteLinkedList？]]

## Q11：线程池有哪些核心参数？能否不入队、先把线程跑满再入队？

### 面试回答

七个参数：corePoolSize、maximumPoolSize、keepAliveTime 和单位、workQueue、threadFactory、拒绝策略 handler。

标准执行顺序：核心线程 → 入队 → 入队失败才扩到最大线程 → 还进不去就拒绝。

能否“先跑满 10 个线程再入队”：默认流程做不到，顺序写死在 `execute` 里；但可以改造：

- 把队列换成 SynchronousQueue：它“不入队、只直接交接”，核心线程都忙时入队失败，就会先建线程到 max；代价是没有缓冲，突发任务直接走拒绝。
- 自定义队列重写 offer()：当前线程数没到 maximumPoolSize 就返回 false，逼线程池先建线程，跑满了才真正排队——这是《Java 并发编程艺术》里的公开做法。
- 说结论时要补一句设计意图：先入队是平台线程贵、切换成本高，故意用队列压线程数；要不要反过来，先看负载是 IO 密集还是 CPU 密集。

## Q12：谈谈 SpringBoot 的自动装配原理。

### 面试回答

一句话：把一批候选配置类导进来，再用条件注解筛掉不适用的，命中的往 IoC 容器注册 Bean。

- 入口：`@SpringBootApplication` 里的 `@EnableAutoConfiguration`。
- 候选清单：Boot 3 从 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 读取；2.7 之前走 `spring.factories`。
- 生效判定：`@ConditionalOnClass`、`@ConditionalOnMissingBean`、`@ConditionalOnProperty` 逐个条件过滤。
- 用户覆盖：很多默认配置自带“你没配我才配”，自己定义同类 Bean 后自动退让。
- starter 的常见作用是聚合依赖，它不等于自动配置类本身。

## Q13：谈谈 Mybatis 的原理。调用的是接口方法，是怎么转变成执行 SQL 的？

### 面试回答

MyBatis 是“半自动 ORM”：SQL 自己写，结果映射它来做。整体四段：

- 启动：解析 XML／注解，把每条 SQL 变成 MappedStatement，以“接口全限定名.方法名”为 key 注册进 Configuration。
- 取代理：Mapper 接口没有实现类；`getMapper` 返回的是 JDK 动态代理（MapperProxy）。
- 转 SQL：调接口方法走到代理的 invoke，用“接口名＋方法名”查出对应 MappedStatement，解析动态 SQL 得到 BoundSql，#{} 变成 JDBC 占位符。
- 执行回填：Executor → StatementHandler 发 JDBC，ResultSetHandler 用 TypeHandler 把行映射成对象返回。

一句话收尾：接口方法名和 XML 里 namespace＋id 的约定，就是“方法”与“SQL”之间的桥。

## Q14：浏览器中输入网址按下回车，都发生了什么？

### 面试回答

按三段讲：请求前、网络、渲染。

- 请求前：解析 URL；先查浏览器／系统缓存，可能要过 DNS——本地 hosts 与各级缓存未命中时，向递归解析器查询域名对应 IP。
- 网络：以 HTTPS 为例，先 TCP 三次握手、再 TLS 握手，然后发 HTTP 请求，服务端（可能经过负载均衡、网关）处理并返回响应。
- 渲染：浏览器解析 HTML 建 DOM、解析 CSS，执行脚本，布局、绘制、合成出画面。
- 一条边界：HTTP/3 走 QUIC（UDP 之上），不能说所有请求都先建 TCP 连接。

## Q15：为什么 TCP 要采用四次挥手而不是三次？

### 面试回答

因为 TCP 是全双工，两个方向的发送要各自关闭，FIN 是“方向性”的：

- 我发 FIN 只表示“我说完了”，不表示“你也说完了”。
- 对方回 ACK 确认收到，但它可能还有数据没发完，只能先确认、之后再单独发自己的 FIN——这就是第二、第三个报文分开的原因。
- 所以常见是四个报文：FIN → ACK → FIN → ACK。
- 补一句严谨口径：不是“必须”四次——对方收到 FIN 时已经无数据可发，ACK 和 FIN 可以合并成一次，就是三次。

## Q16：谈谈布隆过滤器。

### 面试回答

一句话：一种用位数组＋k 个哈希的 probabilistic 判重结构，特点是“说没有就一定没有，说有可能是错的”。

- 插入：元素过 k 个哈希函数，把位数组对应 k 位置 1。
- 查询：k 个位置全为 1 才返回“可能存在”，有一个 0 就一定不存在。
- 没有假阴性、有假阳性；误判率由位数 m、哈希个数 k、数据量 n 决定，近似 `(1-e^(-kn/m))^k`。
- 短板：标准版不支持删除（一位多键共享），要删除得用计数布隆等变体，或者定期重建。
- 典型用途：缓存前置拦截防穿透、爬虫 URL 去重、本地缓存与远程缓存一致性兜底。

## Q17：手撕：整数数组中每个元素出现两次、只有一个元素出现一次，怎么快速找出？

### 面试回答

全体异或一遍，剩下的就是落单的那个数。

- 依据：x^x=0、x^0=x，异或满足交换律结合律，成对的必抵消。
- 时间 O(n)、空间 O(1)，不用哈希表计数也不用排序。
- 主动说前提：恰有一个出现一次、其余都两次；出现三次或两个落单时，按位取模或分组异或，思路都在。
- 补充口径：负数也成立，因为异或按位进行，与补码符号位无关。
