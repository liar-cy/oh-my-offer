## Q02：硕士课题具体研究哪些问题？采取的措施对系统的提升怎么评判？

### 面试回答

课题介绍题，全凭个人事实，按“问题—方法—评判”三层组织：

- 问题：【课题针对的系统／场景】存在【什么瓶颈或缺陷】，用一句非本专业也能听懂的话开头。
- 方法：我提出／采用了【具体措施】，为什么选它、对比过哪些替代方案。
- 评判：提升不能只说“变好了”，要给口径——
  - 指标：【准确率／吞吐／延迟等，按真实实验填】。
  - 对照：与基线方法在同一数据集／环境下的对比，说明实验条件。
  - 局限：哪些场景改善有限，主动说比被问出来好。

被追问“怎么评判”时的关键：区分离线实验指标和真实系统收益，说明你如何保证对比公平（同数据、同环境、多次取均值等）。

## Q04：输入 URL 敲回车到页面显示有哪些行为？往外发请求（如 DNS 请求）更细节的网络行为有哪些？

### 面试回答

主干与一面同题：解析 URL → DNS → 建连（TCP／TLS）→ HTTP 请求响应 → 浏览器渲染。

第二问要求下沉一层，把“往外发一个请求”的细节说全，以 DNS 查询为例：

- 客户端先查本地：浏览器缓存 → 操作系统缓存／hosts → 都没命中才发外网请求。
- 查询报文通常走 UDP 53 端口，源端口随机；报文里带域名和期望的记录类型（A／AAAA）。
- 递归解析器有缓存就按 TTL 直接答；没有则从根域 → 顶级域（.com）→ 权威服务器逐级迭代，拿 referral 再续问。
- 回程细节：
  - CNAME 要顺着别名继续查。
  - 多条 A 记录按策略返回。
  - 否定答案（NXDOMAIN）也会被缓存。
- 拿到 IP 后继续往外发还有：本机的链路层要先用 ARP／NDP 把下一跳 MAC 解出来，再查路由选出口，报文逐跳转发。

一句收尾：发一个“简单”请求，实际是缓存查询、DNS 报文、路由与链路层寻址一串行为的组合。

## Q05：有没有花很长时间、靠自己的努力解决过一个很难的问题？

### 面试回答

素质型行为题，选材和结构比内容更重要：

- 选材：【真实的长周期难题——课题卡点、线上疑难 bug、从零啃下某系统】，要满足“自己主动推动、最后走出来了、细节经得起追问”。
- 按 STAR 讲：情境和难点定量（卡了多久、难在哪）→ 我的拆解动作（查什么资料、做什么实验、何时求助）→ 结果与可检验的变化 → 复盘出的方法。
- 重点放在“行动”段，占一半篇幅：让面试官看到你的排查路径和韧性，而不是运气或他人代打。
- 收尾落在方法迁移：“这套拆问题的办法我后来用在了【场景】”。

## Q06：你对后面的职业发展是怎样的规划？

### 面试回答

按短期／中期／长期三档说，落点与应聘岗位匹配：

- 短期：在真实业务里把【后端工程能力——并发、存储、服务治理，按自己短板填】做扎实，完成从校园到生产环境的过渡。
- 中期：在【某方向，如高并发服务／安全数据分析工程化】深入，能独立负责一条链路从设计到稳定运行。
- 长期：对“专家还是管理”保持开放，强调当前重心是把技术做深。
- 两条禁忌：不空喊口号，不为迎合面试官虚构承诺（如随意答“几年内转管理”“一定干满 X 年”）。
