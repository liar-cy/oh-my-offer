## Q01：接口中可以定义哪些方法？

### 面试回答

按版本报接口能放哪些方法。

- Java 8 起：public abstract 抽象方法、default 默认实例方法、static 方法。
- Java 9 起：还可以有 private 实例方法与 private static 方法，供接口内部复用。

四条边界：

- 接口不能声明构造器。
- private 方法不能是 abstract。
- 接口的 static 方法通常通过接口名调用。
- 它不像默认方法那样被实现类继承。

## Q02：说一下包装类型，包装类型的缓存是什么？

### 面试回答

先报对应关系：八种基本类型对应 Byte、Short、Integer、Long、Float、Double、Character、Boolean。包装对象用于泛型、集合和可空值等场景。

缓存这块：

- Integer.valueOf 保证缓存 -128 到 127，并允许缓存更多。
- 别外推：不能认为所有包装类型的缓存都一样。

比较的规则：

- 比数值：按类型使用 equals 或拆箱。
- 两个包装对象用 == 比较的是身份，不是值。

## Q03：存储小数需要高精度用什么类型？

### 面试回答

结论：Java 中要精确的十进制计算，通常用 BigDecimal。

构造方式有坑：

- 建议用字符串构造。
- 或者在理解语义之后使用 valueOf(double)。
- 别写 new BigDecimal(0.1)，那会把二进制浮点误差直接带进来。

用的时候记三条：

- 除法需明确精度和舍入规则。
- BigDecimal 不可变，运算返回的是新对象。
- 数据库中通常配合 DECIMAL，并统一业务的小数位规则。

## Q04：深拷贝和浅拷贝有什么区别，从 Caffeine 获取对象属于哪一种？

原题二选一的前提不准确；普通本地缓存读取通常直接返回值引用。

### 面试回答

先把三个层次分开：

- 引用赋值：只是共享同一个对象。
- 浅拷贝：创建新的外层对象，但仍共享引用字段指向的成员。
- 深拷贝：把需要独立的可变对象图复制一份。

回到 Caffeine：普通本地缓存命中时，通常直接返回当前值的引用，并不默认创建深拷贝或浅拷贝。

因此有两个风险：

- 修改取出的可变对象，可能影响其他读取者。
- 缓存容器线程安全，也不代表值对象线程安全。

需要隔离时怎么办：用不可变值，或者做明确的防御性复制。

两条边界：加载、刷新和替换都可能改变该 key 对应的引用；自定义封装也可能额外增加一种复制策略。

## Q05：线程有哪些状态？

### 面试回答

先报名字：Java Thread.State 有六种——NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING、TERMINATED。

几个要说准的点：

- RUNNABLE 包含运行及等待 CPU 等情况。
- BLOCKED 特指等待进入 synchronized 监视器。
- wait、join、park 等可以进入等待状态；带时间限制则可能是 TIMED_WAITING。

补一句边界：它们不是操作系统线程状态的一一映射。

## Q06：sleep 和 wait 有什么区别？

### 面试回答

区别在“是谁的方法、要不要让出锁”。

- sleep：Thread 的静态方法，让当前线程暂停一段时间，不释放已持有的监视器。
- wait：Object 的方法，调用者必须持有该对象监视器；等待时释放它，返回前重新获取。

用途上：wait 用于条件协作，sleep 主要用于时间暂停。

一句提醒：不能靠 sleep 建立线程间可见性。

## Q07：线程通信方式有哪些？

### 面试回答

按目的分三类说，比背清单更清楚：

- 传状态：共享状态配合同步，或者用 volatile、原子类来表达。
- 等条件：wait／notify、Condition，或者更底层的 park／unpark。
- 传数据与协调阶段：BlockingQueue 传递数据，Future 获取结果，CountDownLatch 等协调阶段。

选择时同时考虑三件事：数据可见性、原子性和等待机制。

反面结论：不能只靠循环读普通变量或 sleep。

## Q08：线程池有哪些参数，执行流程是什么？

### 面试回答

七个参数先报全：ThreadPoolExecutor 常见七个是 corePoolSize、maximumPoolSize、keepAliveTime、unit、workQueue、threadFactory、handler。

任务到来时的执行流程：

- 通常先扩到核心数。
- 再尝试入队。
- 队列容纳不了时，扩到最大数。
- 仍不能接收，就走拒绝。

一句纠偏：keepAliveTime 管的是空闲线程回收，不是任务最大执行或排队时间。

## Q09：MySQL 索引有哪些类型？

### 面试回答

开口先说：要分维度来讲。

- 按约束分：主键索引、唯一索引、普通索引。
- 按列数分：单列索引、联合索引。
- 按 InnoDB 的存储组织分：聚簇索引、二级索引。
- 按用途分：全文索引、空间索引。

这些分类不互斥，例如一个索引可以同时是“联合、唯一、二级索引”。

底层结构补一句：InnoDB 常规索引主要使用 B+ 树。

## Q10：MyBatis 中 $ 和 ＃ 有什么区别？

原文简称按 MyBatis 的 ${} 与 #{} 语法解释。

### 面试回答

一句话：一个是绑定参数，一个是拼字符串。

- `#{value}`：通常生成 PreparedStatement 参数占位符，由 JDBC 绑定数据值。
- `${value}`：把内容直接拼进 SQL 文本，不能自动防止注入。

实践规则：

- 普通条件值用 `#{}`。
- 表名、列名等不能作为普通值占位时，应从受控白名单选择再构造 SQL，不直接拼用户输入。

## Q12：线程池中提交的任务能取消吗？

### 面试回答

结论：可以尝试取消，但它是“发请求”，不是“保证停止”。

通过 submit 得到 Future 后调 cancel，分几种情况：

- 未开始且取消成功的任务，不会再执行。
- 运行中的任务若用 cancel(true)：通常只是向工作线程发中断请求。任务必须协作响应，不保证立刻停止。
- cancel(false) 不请求中断，任务可能继续运行。

一句要补的边界：Future 显示已取消，也不代表业务副作用已经回滚。
