## Q01：ThreadLocal 是什么，有哪些问题？

### 面试回答

ThreadLocal 为不同线程保存各自的变量值，适合线程内上下文，不是给共享对象加锁。常见问题是线程池复用导致上下文串用，以及值未及时清理造成内存滞留。使用请求上下文时应在 finally 中 remove；跨线程执行也不会自动获得普通 ThreadLocal 的值。

## Q02：反射是什么，有哪些应用场景和安全隐患？

### 面试回答

反射允许程序在运行时获取类、字段、方法和构造器的信息，并创建对象或调用方法。常用于依赖注入、ORM 映射、序列化和插件装配。它可能突破原有封装并把部分错误推迟到运行时，但不是无条件越过所有访问限制；类名或方法名若由不可信输入决定，还可能调用到不该暴露的能力。

## Q03：什么是序列化与反序列化，能否用来实现深拷贝？

### 面试回答

序列化把对象状态编码为可保存或传输的数据，反序列化按格式重建对象。完整地序列化并反序列化对象图，通常可得到独立的可变对象图，用作深拷贝手段；但它们本身不是“深浅拷贝”的同义词。transient、自定义读写及 readResolve 等会改变结果，不能保证每种序列化都完整复制所有字段。

## Q04：线程池最大等待时间是什么，核心与非核心线程如何区分？

表述有歧义；按常见 keepAliveTime 考点回答，同时区分其他等待 API。

### 面试回答

这里的“最大等待时间”通常指 `keepAliveTime`：工作线程空闲超过这个时间后可以被回收，它不是任务的超时时间。`corePoolSize` 和 `maximumPoolSize` 只是线程数的两个阈值，某一条 Worker 并没有永久的“核心线程”身份。默认情况下，当前工作线程超过核心数时，空闲线程才会按 `keepAliveTime` 回收；开启 `allowCoreThreadTimeOut(true)` 后，核心数以内的空闲线程也可以回收。

## Q05：synchronized 和 Lock 有什么区别？

### 面试回答

synchronized 是语言级监视器锁，退出同步块时自动释放；Lock 是接口，常以 ReentrantLock 为例比较，需要在 finally 中显式 unlock。两者都可提供互斥与可见性，ReentrantLock 还支持可中断获取、限时尝试、公平选项及多个 Condition。普通互斥优先考虑代码清晰，需要这些能力时再用显式锁。

## Q06：synchronized 加在普通方法和静态方法上有什么区别？

### 面试回答

普通实例同步方法锁的是 this，静态同步方法锁的是声明该方法的类对应的 Class 对象。同一实例的同步方法互斥，不同实例通常不互斥；同一个 Class 的静态同步方法互斥。实例锁与类锁是不同对象，因此它们不会自动互斥。

## Q07：Lock 怎么实现公平和非公平？

Lock 是接口；此处按常见实现 ReentrantLock 解释，不把所有 Lock 实现等同。

### 面试回答

ReentrantLock 基于 AQS 状态和等待队列实现，状态记录持有次数并支持重入。公平模式在可获取时还会考虑是否有排在前面的等待者，非公平模式允许新线程直接竞争空闲锁。两者失败后都可能排队，不是非公平锁没有队列；公平也不保证操作系统调度绝对公平。

关联专题：[[专题题库/Java并发#JUC-005：ReentrantLock 如何实现公平锁与非公平锁？|JUC-005：ReentrantLock 如何实现公平锁与非公平锁？]]

## Q08：@Transactional 何时失效，如何从其他入口调用事务方法？

保留原句；“事物”按技术语境解释为“事务”，“非方法内”不擅自改成确定含义，回答为条件分支。

### 面试回答

Spring 声明式事务默认靠 AOP 代理拦截方法调用。常见失效情况有：对象是手动 `new` 的、同类中用 `this` 调用事务方法、代理无法拦截目标方法、异常被捕获后没再抛出，或异常类型不符合回滚规则。比较稳妥的做法是把事务方法放在独立的 Spring Bean 中，通过注入的代理对象调用；需要在同一个类内明确控制边界时，可以使用 `TransactionTemplate`。Spring 6 的类代理可支持 `protected` 和包可见方法，接口代理的事务方法仍需是 `public`。

关联专题：[[专题题库/Spring#SPRING-004：@Transactional 何时不生效，如何正确调用事务方法？|SPRING-004：@Transactional 何时不生效，如何正确调用事务方法？]]

## Q09：动态代理有哪几种？

### 面试回答

常见动态代理有 JDK 接口代理和 CGLIB 等基于子类的代理。JDK 代理把接口调用交给 InvocationHandler；子类代理通过覆盖可增强方法加入逻辑。Spring AOP 可用这两类机制，具体选择受接口和配置影响，private／final 等方法在子类代理中有能力边界。动态代理并不只有固定两种库实现。

## Q10：@Resource 与 @Autowired 有什么区别，如何按名称注入？

### 面试回答

@Autowired 属于 Spring，主要按类型解析依赖，可结合 @Qualifier 限定候选；@Resource 属于 Jakarta 注解体系，在 Spring 中可用 name 明确按 Bean 名称注入，未指定时通常先用字段或属性名再按适用规则回退。若用 @Autowired 指定命名 Bean，常写 @Autowired 配 @Qualifier("beanName")，仍要求类型匹配。

## Q11：如何解决循环依赖？

### 面试回答

循环依赖是 A 依赖 B、B 又依赖 A。首先通过拆分职责、抽公共服务或事件协作消除环；某些场景可用注入点 @Lazy 或 ObjectProvider 延后获取。容器在允许循环引用时，能用早期引用处理部分单例属性注入循环，但构造器循环、原型循环或复杂代理情形并非都能解决。

## Q12：懒加载是什么？

按前文 Spring 依赖注入语境解释为 Bean 懒加载。

### 面试回答

Spring 懒加载是把 Bean 创建从容器启动时推迟到第一次需要它时。Bean 定义上 @Lazy 控制初始化时机，注入点上 @Lazy 通常注入延迟解析代理。若一个非懒加载单例在启动时直接依赖该 Bean，即使被依赖 Bean 标了懒加载，也可能因必须满足依赖而被提前创建。

## Q13：事务隔离级别分别解决什么问题，InnoDB RR 如何处理幻读？

纠正原文“事物”为“事务”；以 MySQL InnoDB 为前提。

### 面试回答

四种级别是读未提交、读已提交、可重复读和串行化。读已提交避免脏读，可重复读提供稳定的一致性快照，串行化约束更强。InnoDB 默认 RR：普通一致性读复用 read view，不看到之后提交的新行；范围锁定读则根据索引使用 next-key／gap 锁限制相关插入。前者固定可见性，后者约束并发写；标准 RR 不要求完全排除幻读，解释 InnoDB 实现时也不能忽略事务自身写入或混用当前读的情况。

关联专题：[[专题题库/MySQL#MYSQL-001：MySQL 事务有哪些隔离级别？|MYSQL-001：MySQL 事务有哪些隔离级别？]]

## Q14：MySQL 中有哪几种锁？

### 面试回答

要先说明分类维度。MySQL 有全局读锁、表锁和元数据锁等；InnoDB 的行级并发控制包含共享／排他记录锁，以及 gap、next-key、插入意向等机制，还有表级意向锁。共享／排他描述兼容模式，记录／间隙描述锁定范围，不能把它们当成同一层互斥分类。

## Q15：HTTP 和 HTTPS 有什么区别，HTTPS 如何保证安全？

### 面试回答

HTTPS 在 HTTP 通信上使用 TLS，提供传输加密、完整性校验和服务端身份认证。客户端验证证书链、域名和有效期，并在握手中验证对端私钥证明，协商密钥后用对称加密保护业务数据。证书不是直接拿来对所有 HTTP 数据做非对称加密；HTTPS 也不等于服务端业务绝对安全。

## Q16：TCP 三次握手如何进行，握手期间可以传参数或数据吗？

### 面试回答

客户端发 SYN，seq=x；服务端回 SYN+ACK，seq=y、ack=x+1；客户端回 ACK，ack=y+1，双方建立连接。它让双方确认初始序号及双向通信状态。握手报文可有 MSS、窗口扩大等 TCP 选项；第三次 ACK 可携带应用数据。普通连接不会依赖首个 SYN 交付业务参数，TCP Fast Open 等机制则允许在特定条件下提前发送数据。
