## Q02：了解哪些开源图数据库？不同图数据库的图数据存储结构是怎样的？

### 面试回答

报主流几家＋一句定位：

- Neo4j：属性图标杆，原生图存储＋索引邻接（index-free adjacency），遍历沿着节点自带的邻接链表走，多跳查询快；单机为主，社区版高可用受限。
- NebulaGraph：国产存算分离分布式图数据库，shared-nothing 多副本（Raft），按图分区水平扩展。
- JanusGraph／HugeGraph：图层自建，数据托管给外部存储（Cassandra／HBase／TiKV 等），扩展靠底层 KV。
- ArangoDB：多模（文档＋图＋KV），图是其中一种能力。

存储结构一句话对比：

- 原生图存储（Neo4j）：点、边分开落盘，边记录起终点，节点存首个边指针——关系遍历不经过索引。
- 邻接表派生的分布式存储（NebulaGraph）：点的邻边按（vid，边类型）聚合成块存 KV 引擎，读写按分区路由。
- 托管派（JanusGraph）：点边拆成记录映射进宽列／KV 表，用持久化索引补遍历入口。
- 反面口径：关系表两两 JOIN 或文档嵌套存关系，多跳查询都要运行时拼邻接，深度一大就崩——这是图数据库存在的理由。

## Q04：项目的点、边规模多大？要支持更大数量级如何改进？

### 面试回答

规模如实报口径【点 X 万／边 Y 万，按真实数据，说明统计时间】，然后按分层给改进：

- 分片是主线：图分片按“切边不切点”（vertex-cut）把一条边的两端放不同分片时复制点、切点副本相连——避免跨片查询爆炸；分片键选业务主维度（用户／地域／时间）而不是无脑 hash。
- 存储与计算解耦：底层换分布式 KV／列存（JanusGraph 模式）或直接用存算分离引擎（NebulaGraph 模式），容量随节点线性扩。
- 冷热分层：热点子边进内存／本地缓存，历史版本落对象存储；超大属性从点边记录里拆出去。
- 访问模式配套：多跳查询加缓存与物化视图；写多读少的边表按时间分桶。
- 配套工程：增量迁移＋双写灰度切流，扩容不停服；校验与回滚方案先于扩容上线。

一句收尾：数量级上去后，问题从“图引擎选型”变成“分片、冷热与流量治理的组合拳”。

## Q07：缓存的数据结构是什么？

### 面试回答

题意未指明是项目本地缓存还是 Redis 编码，先反问口径再两边都答（需按原题修正）：

- 项目本地缓存【填真实实现】：常见是“哈希表定位置＋链表／堆维护淘汰序”——LRU 用 LinkedHashMap 或手写 HashMap＋双向链表，带过期用“堆／时间轮管 TTL＋哈希表管数据”；读多写少可上 Caffeine（W-TinyLFU）。
- Redis 侧：对外是 String／Hash／List／Set／ZSet／Stream 六种逻辑类型，底层按数据规模在紧凑编码（listpack／intset）与通用编码（hashtable／skiplist）之间自动切换，命令语义不变。
- 一句衔接：本地缓存拼的是淘汰与过期结构，Redis 拼的是编码选型与阈值——两层都答到才完整。

## Q08：Redis 的 hash 底层实现是什么？压缩列表和哈希表各有什么优劣？

### 面试回答

- 底层两种编码：小 hash 用 listpack（6.2 之前是 ziplist，面试说“压缩列表”指的是它），超阈值转 hashtable（真哈希表，链地址法解决冲突）。
- 阈值默认口径（可配置）：元素数或字符串长度超限即转，转换单向、不会转回。
- 优劣对比：
  - 紧凑编码：连续内存、无指针开销，省内存明显；但查找遍历是 O(n)，每次改动可能触发内存重分配与连锁更新（ziplist 时代问题，listpack 已消除）。
  - 哈希表：读写 O(1)，适合大集合；每个 entry 要指针与元数据，内存开销大，扩容有 rehash 成本。
- 结论句：小 hash 省内存为主、大 hash 性能为主，所以 Redis 用阈值把两种编码拼成一条曲线。

## Q09：谈谈 Redis 的缓存雪崩；解决缓存雪崩的三种方案。

### 面试回答

雪崩定义一句：大量 key 在同一时刻集中过期，或缓存服务整体不可用，请求洪峰直接打到数据库。

三种方案按“事前防集中、事中限冲击、事后保可用”给：

- 方案一 TTL 打散：过期时间加随机抖动，避免同批 key 同秒失效——只管集中过期，管不了 Redis 宕机。
- 方案二 缓存层高可用：主从＋哨兵或集群分片，让“缓存整体不可用”本身成为小概率；宕机时配合多级缓存（本地缓存兜一层）。
- 方案三 回源保护：互斥重建／请求合并限制同一 key 并发回源，再加限流＋熔断降级与线程池隔离，保住数据库不被打穿。
- 收尾：雪崩和击穿（单热点 key）、穿透（查不存在数据）口径别混，三者解法有交集但不互相替代。

## Q10：手撕：求两个非降序数组的中位数（LeetCode 4，hard）。

### 面试回答

先归约：中位数＝合并升序后取第 `(m+n)/2`（奇数）或中间两数平均（偶数），直接复用“两个有序数组第 k 小”的切分二分（ALG-017），再补奇偶口径。

- 在较短数组上二分切分点 i，另一数组切 j 使左半共 `(m+n+1)/2` 个；满足交叉条件 `A[i-1] <= B[j] && B[j-1] <= A[i]` 时，左半最大值即中位候选。
- 时间 O(log(min(m,n)))、空间 O(1)，满足 hard 题预期。
- 偶数情形：中位数 = max(左半界) 与 min(右半界) 的平均；越界用 ±∞ 哨兵。
- 面试策略：先口述 O(m+n) 双指针归并保底，再升级到二分，写出后主动过示例与单数组空的边界。

```java
double findMedianSortedArrays(int[] A, int[] B) {
    if (A.length > B.length) return findMedianSortedArrays(B, A);
    int m = A.length, n = B.length, half = (m + n + 1) / 2;
    int lo = 0, hi = m;
    while (lo <= hi) {
        int i = (lo + hi) >>> 1, j = half - i;
        int aL = i == 0 ? Integer.MIN_VALUE : A[i - 1];
        int aR = i == m ? Integer.MAX_VALUE : A[i];
        int bL = j == 0 ? Integer.MIN_VALUE : B[j - 1];
        int bR = j == n ? Integer.MAX_VALUE : B[j];
        if (aL <= bR && bL <= aR) {
            int left = Math.max(aL, bL);
            if ((m + n) % 2 == 1) return left;
            return (left + Math.min(aR, bR)) / 2.0;
        }
        if (aL > bR) hi = i - 1; else lo = i + 1;
    }
    throw new IllegalArgumentException("输入不合法");
}
```
