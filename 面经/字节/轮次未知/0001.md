## Q01：你觉得 RAG 中最难的是什么？

### 面试回答

同一问题在本场出现两次（原题 1 与 20）。最难的不是接模型，而是“证据链质量”：① 语料侧——文档解析与切块决定召回上限，垃圾进垃圾出；② 匹配侧——用户问法与文档措辞的语义鸿沟、多跳与跨文档问题，单一向量检索不够；③ 验证侧——怎么证明“检索到了正确证据、答案忠实于证据”，需要标注评测集与分层指标，否则优化全靠感觉。回答时挑一个自己踩过的坑展开（如切块切断语义→父子块补全），比罗列名词更有说服力。

## Q02：你是怎么解决幻觉问题的？

### 面试回答

原题 2 与 26 同题合并。分检索与生成两段治理：检索段——保证证据相关且及时（混合召回＋重排、权限过滤、时效校验），召回不到就明确“库内无答案”；生成段——Prompt 约束“只依据给定证据作答并逐条引用”、输出格式带引用字段、后端校验引用是否真实支持结论；兜底——低置信拒答或转人工，用含无答案／冲突样本的评测集分别测“没检到”与“有证据却编造”，不把流畅当正确。

## Q03：微调和 RAG 的区别与优劣势是什么？

### 面试回答

原题 3 与 27 同题合并。一句话：RAG 改“模型能看到什么”，微调改“模型本身会什么”。RAG——知识外置、可实时更新、可溯源、成本低，适合事实问答与私有知识；受上下文预算与检索质量制约，不改变风格与能力边界。微调——用领域数据继续训练，内化风格、格式、行业术语和任务行为，推理时不占上下文；但知识固化进权重，更新要重训、难溯源、数据与算力成本高，还可能灾难性遗忘。事实类问题优先 RAG，输出格式／领域表达不稳优先微调，两者常组合：微调打底行为，RAG 供事实。

## Q04：大模型是怎么训练出来的？

### 面试回答

三阶段：① 预训练——海量文本上做自回归下一 token 预测（因果语言建模），学到语言与世界知识，算力大头；② 后训练——先监督微调（SFT）用指令—回答对教会“听指令、按格式回答”，再用偏好对齐（RLHF／DPO 等）按人类偏好排序数据优化回答风格与安全性；③ 推理侧增强——可选的推理训练（RL 类）与蒸馏、量化降低部署成本。口述时强调各阶段解决什么问题，而不是堆名词。

## Q05：Transformer 的架构，Encoder 和 Decoder 是什么？

### 面试回答

核心是自注意力机制：每个 token 用 Q／K／V 对序列内所有位置加权聚合，替代循环结构，可并行且能建模长程依赖。Encoder 堆叠“自注意力＋前馈网络”，双向看全文，适合理解类任务（BERT 系）；Decoder 在其基础上加带因果掩码的自注意力（只看左侧已生成内容）和可选的交叉注意力（读取 Encoder 输出），适合自回归生成（GPT 系）。当前主流大模型多为纯 Decoder 架构。配套要素：位置编码、残差＋归一化、多头注意力。

## Q06：Function Call 是怎么训练的？

### 面试回答

模型会输出工具调用不是 Prompt 硬凑出来的（也能凑，但可靠性差），而是训练出来的：构造大量“对话上下文＋可用工具 schema→正确的调用决策与参数 JSON”样本做 SFT，含该调用时调用、不该调用时直接回答、缺参时追问三类行为；再用偏好数据对齐调用格式与选择质量。运行时由推理框架配合：把工具定义注入上下文、约束输出（受限解码／文法）保证 JSON 合法、解析后真正执行——模型只“提出调用”，执行与鉴权在宿主侧。

## Q07：微调的方案有哪些，自己做过没有？

### 面试回答

方案谱系：全参数微调（效果上限高、成本高、易遗忘）；参数高效微调——LoRA（冻结原权重，低秩旁路训练少量参数，最常用）、QLoRA（4bit 量化基座＋LoRA，单卡可跑）、Adapter／Prefix／Prompt Tuning 等；数据侧要构造指令集、控制质量与去污染，训练后在保留评测集上对比基线。做过就讲【数据规模、基座、方法、评测结果】，没做过如实说“跑过教程级实践／仅了解”，不虚构。

## Q08：大模型分词器是什么？

### 面试回答

分词器把文本切成模型词表中的 token（子词：BPE／WordPiece／SentencePiece 类），词表是“常见词整存、生僻词拆子词”的折中。它决定了上下文长度的计量单位（token 数≠字数）、计费与截断边界，也影响多语言与数字／代码的处理质量——不同模型分词器不同，同一句话 token 数可能差很多。注意分词是模型输入的第一步，与 embedding 查表是两件事。

## Q09：Embedding 是什么，你们用的哪个模型？

### 面试回答

Embedding 是训练好的模型把文本映射为固定维度实数向量，语义相近文本距离近，用于检索召回、聚类、去重等；维度与含义由训练决定，不是人工定义。模型名称按【项目实际】如实回答（商用 API 向量服务或开源句向量模型），并说明选型依据（业务评测召回、维度、语言支持、成本）；换模型要重建全库向量，查询与文档必须同一兼容体系编码。

## Q10：介绍一下 LangChain。

### 面试回答

LangChain 是 LLM 应用组件框架：统一模型接入抽象、链式编排（LCEL）、工具与检索组件、Agent 能力等；配套 LangGraph 负责有状态图编排。评价要客观：它降低起步成本，但抽象层多、版本演进快，排障时可能要看源码。按【真实使用程度】分层回答：用过哪些模块、哪些只用文档了解。

## Q12：有没有用过大模型的网关框架（LiteLLM）？

### 面试回答

## Q13：为什么手搓 Agent，而不是用框架？

### 面试回答

如实讲动机，通用理由：控制与理解——循环、上下文组装、工具执行都是自己写的，行为可预测、排障不隔抽象层；依赖最小——不被框架版本演进绑架；教学／面试场景能讲清每一步。代价也要认：持久化、恢复、并发、观测等框架已解决的问题要自己实现，团队复用性差。合理结论：理解原理或需求极简时手写，复杂状态编排与团队协作时评估框架（LangGraph 类），两者不互斥。

## Q14：MCP 是什么，和 Function Call 有什么区别，有没有实践过？

### 面试回答

层次不同：Function Call 是模型能力——模型按注入的工具 schema 输出结构化调用意图；MCP 是协议——标准化宿主应用与外部工具／资源服务之间的发现与调用（host—client—server）。实践链路：模型提出调用→宿主运行时校验授权→MCP Client 发 tools/call→Server 执行返回。实践经历按【真实做过】讲：接过什么 Server、工具清单、参数与结果处理。

## Q16：ReAct 是啥，怎么实现的？

### 面试回答

ReAct＝推理（Reason）与行动（Act）交替：模型基于任务与已有观察先想一步、输出结构化动作（工具＋参数），执行器校验并执行，把观察结果回传，循环直到 final 答案。实现要点：动作协议结构化、参数与权限运行时校验、调用 ID 配对请求结果、步数／费用预算与无进展检测兜底。研究范式出自 2022 年论文，生产实现各家有变体。

## Q17：CoT 是啥，为啥效果好，有啥缺点？

### 面试回答

CoT（思维链）是让模型显式生成中间推理步骤再给结论的提示方式（“一步步想”、few-shot 推理示例、零样本触发句）。有效的本质：把一步难以完成的多约束问题分解为多个短步，每步的生成条件在上一步产出上，相当于用自回归串行计算换深度，降低单次映射难度。缺点：token 与延迟成本显著增加；中间步骤错会连锁带偏；流畅的推理链可能是事后合理化并不忠实于真实计算；对简单任务反而降效；隐藏思维链场景拿不到过程。

## Q18：Prompt Caching 是什么？

### 面试回答

对请求前缀（系统提示、工具定义、长文档等稳定部分）复用上次计算的 KV／注意力状态，命中部分按更低价格计费、首 token 延迟下降。要点：按前缀匹配——把稳定内容放前面、易变内容追加在后面；各家实现粒度、TTL、最小可缓存长度与计费折扣不同，按所用厂商文档核对；它只优化计算与成本，不减少上下文占用量，也不改变模型行为。

## Q19：温度／top-p／top-k 分别是什么，各场景最佳设置？

### 面试回答

三者都在采样阶段作用于 logits：温度把 logits 除以 T 改变分布陡峭度（T→0 趋近贪心，越大越随机）；top-k 只在概率最高的 k 个 token 里采样；top-p（核采样）取累计概率达 p 的最小集合。没有普适“最佳值”，只有方向：事实问答／抽取／代码用低温（0~0.3）求稳定，创意写作调高；结构化输出与函数调用配低温＋受限解码。同一 seed 下参数效果可复现比较，别宣称某固定值最优。

## Q20：文档切割策略有哪些，怎么规避语义被切割掉？

### 面试回答

策略：固定长度＋重叠、按分隔符（段落／标题层级）、结构感知（Markdown 标题、代码块、表格整体保留）、递归切分（大单位装不下再拆小）、语义切分（按相似度断点，成本高）、父子分块与滑动窗口。防语义断裂：召回单元与上下文单元解耦——小块精准命中、返回父块或邻块补全；chunk 前缀拼标题路径与摘要；表格图注不拆；改动后用标注片段的召回与答案完整性指标验证，不凭感觉调大小。

## Q21：多路召回是什么？

### 面试回答

同一查询用多条互补路径并行召回再融合去重：关键词（BM25，精确术语／编号）、向量（语义改写）、多查询扩展（换问法）、结构化过滤（元数据／时间）、图关联扩展、不同粒度块（子块定位＋父块补全）。目的：单一检索器各有盲区，多路提覆盖率；融合后统一重排控制精度。各路权重与 top-k 在评测集上调，不是玄学默认值。

## Q23：为什么要用到图数据库？

### 面试回答

## Q26：怎么做的任务拆分，为什么拆分，效果如何、怎么提升？

### 面试回答

## Q27：text2sql 怎么做的，怎么提高准确率？

### 面试回答

链路：schema 整理（表列注释、枚举值、口径说明）→检索相关表→Prompt 生成 SQL→执行前静态校验（语法、危险操作、表列存在性、行数限制）→小样本人工或自动验证→执行。提准确率手段：few-shot 典型问答对、复杂问题拆子查询、生成后用 EXPLAIN／dry-run 校验、失败带错误信息回炉重写、高频问题固化为参数化模板或视图。评测用带标准 SQL 的测试集对比执行结果等价（不只比对字符串），准确率提升必须有数字口径。
