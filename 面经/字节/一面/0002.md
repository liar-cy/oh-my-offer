## Q01：项目中乐观锁如何实现，悲观锁代码怎么写？

原文未说明锁保护的业务对象、数据库与框架。以下以 MySQL InnoDB 中更新一行库存为例；实际项目回答还需补充真实表结构、冲突率、重试和事务边界。

### 面试回答

乐观锁一般用版本号，悲观锁用数据库的行锁，分开讲：

- 乐观锁：读取库存时一起读出 `version`。
  - 更新时执行 `UPDATE stock SET amount = ?, version = version + 1 WHERE id = ? AND version = ?`。
  - 影响行数是 1 说明更新成功。
  - 影响行数是 0 说明数据已被别人修改，需要重读后有限重试，或直接返回冲突。
- 悲观锁：在事务中用 `SELECT ... FOR UPDATE` 锁住目标记录，完成检查和更新后再提交；查询和更新必须使用同一个事务连接。

选型一句：冲突少时乐观锁更合适，冲突多时反复重试可能还不如悲观锁。悲观锁还要记住两点——尽量缩短事务，多行加锁顺序保持一致，减少死锁。

## Q02：如何保证 Redis 与数据库的数据一致性？

### 面试回答

常见读多写少场景用 cache-aside（旁路缓存）模式：读缓存未命中时查数据库并回填；写请求先在数据库事务中更新事实数据，提交成功后删除缓存，让后续读取重建。

再补三层：

- 删缓存失败：数据库更新成功但删缓存失败时，需要可恢复机制，例如事务 outbox、数据库变更日志／CDC（变更数据捕获）或可靠重试任务驱动失效，并配合幂等、监控和 TTL 兜底。
- 并发回填：读可能在写入期间把旧值回填；延迟二次删除可缩小部分时间窗，但延迟值难以普适确定，也不能覆盖所有故障。
- 强一致边界：要求强一致的读写应绕过缓存，或采用版本校验等更严格路径，而不是宣称 Redis 与数据库可以无条件实时一致。

## Q03：Cookie 和 Token 如何维持登录态？

### 面试回答

先分开概念：Cookie 是浏览器存储、按域和路径等规则自动随请求携带数据的机制，本身不是登录方案。维持登录态的传统两条路：

- Session：服务端保存会话状态，Cookie 通常只携带不可预测的 session ID；服务端查到有效会话后识别用户。
- Token：客户端携带访问令牌，服务端验证不透明 Token 对应的状态，或校验 JWT 的签名、有效期、签发方和受众。

Token 也可以放在 Cookie 中，所以 Cookie 与 Token 不是互斥选项。

安全和生命周期各一句：

- 使用 Cookie 要配置 Secure、HttpOnly、SameSite 并防 CSRF（跨站请求伪造）；可被脚本读取的凭证要重点防 XSS（跨站脚本攻击）。
- 注销、续期和撤销策略也必须设计，自包含 Token 并不天然支持立即失效。

## Q04：死锁的四个必要条件是什么？

### 面试回答

四个必要条件，各用一句话说：

- 互斥：资源同一时刻只能被一个执行单元占用。
- 占有且等待：已经持有资源时，还在继续等待其他资源。
- 不可剥夺：资源不能被外部强制夺走，只能由持有者释放。
- 循环等待：等待关系形成环。

四者同时成立才可能死锁，破坏任意一个即可预防。例如：统一资源申请顺序，破坏循环等待；一次申请所需资源，破坏占有且等待。

工程中还可做死锁检测与回滚、超时和有限重试。但要讲清：超时只是恢复手段，不等于从根本上消除死锁。

## Q05：JVM 为什么能让 Java 跨平台？

### 面试回答

一句话：跨平台的是字节码，JVM 是每个平台各自实现的翻译层。

- Java 源码通常先由编译器生成平台无关的 class 字节码。
- 不同操作系统和硬件有各自实现的 JVM，负责加载、验证，并通过解释执行或 JIT（即时编译）把字节码转换为本机指令，同时提供统一的运行时语义。

两个边界要守住：

- 更准确的说法是“同一份符合约束的字节码，可以运行在具有兼容 JVM 的平台上”，而不是 JVM 二进制本身跨平台。
- 若程序依赖 JNI、本地库、操作系统路径、字符集或其他平台特性，仍需做适配。

## Q06：代码题——岛屿数量。

原文只说明可以口述并查集思路，未提供代码语言与完整约束。以下按 LeetCode 200 的常见题意：二维字符网格只计算上下左右相连的 `'1'`，修改输入网格，并使用 Java。

### 面试回答

更直接的写法是 DFS／BFS 洪水填充：

- 遍历每个格子，遇到尚未访问的陆地就把岛屿数加一，再从它出发把同一连通块的陆地全部标记为已访问。
- 每个格子至多处理一次：时间 O(mn)，递归 DFS 的最坏栈空间 O(mn)；网格很大时可改用显式队列避免栈溢出。
- 并查集也可行：把陆地映射为节点，与右侧和下侧陆地合并，答案是陆地连通分量数；但本题只求总数时，DFS／BFS 通常更简洁。

```java
int numIslands(char[][] grid) {
    if (grid == null || grid.length == 0) return 0;
    int count = 0;
    for (int r = 0; r < grid.length; r++) {
        for (int c = 0; c < grid[0].length; c++) {
            if (grid[r][c] == '1') {
                count++;
                flood(grid, r, c);
            }
        }
    }
    return count;
}

void flood(char[][] grid, int r, int c) {
    if (r < 0 || r == grid.length || c < 0 || c == grid[0].length
            || grid[r][c] != '1') return;
    grid[r][c] = '0';
    flood(grid, r - 1, c);
    flood(grid, r + 1, c);
    flood(grid, r, c - 1);
    flood(grid, r, c + 1);
}
```

## Q07：100 个圆圈轮流涂 1 个或 2 个，怎样保证涂到最后一个？

原文未说明圆圈是否首尾相连、能否任意选取以及是否必须连续。以下按常见取石子模型回答：共有 100 个待涂圆圈，双方轮流从尚未处理的序列中涂 1 个或 2 个，涂到第 100 个者获胜。

### 面试回答

结论：先手必胜。关键是凑数——让双方一轮合计总是涂 3 个。

- 每回合可涂 1 个或 2 个，对方涂 x 你就能涂 3−x 凑成 3。
- 100 除以 3 余 1：先手先涂 1 个，剩下 99 个。
- 之后对方涂 1 个先手就涂 2 个，对方涂 2 个先手就涂 1 个；每轮减少 3 个，先手最终会涂到第 100 个。

一般化：在“取 1 或 2、取到最后者胜”的规则下，数量为 3 的倍数时当前玩家处于必败态，否则先取余数个并持续凑 3。

留一句谨慎：若题目还有相邻或环形位置限制，胜负策略可能改变，需要先确认规则。
