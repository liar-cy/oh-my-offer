## Q01：算法：求剩余空间最小值（非 Hot100，像“最大子数组和”的改编）。

### 面试回答

题面只记到“求剩余空间最小值、像最大子数组和改编”，完整约束未知，应先向面试官确认输入与“剩余空间”定义。若按最接近的常见口径——从数组中选一个连续段，使总容量减去该段和后的剩余最小——就是求最大子数组和，Kadane 一遍扫描即可；若直接求最小子数组和，把 Kadane 的 max 换成 min（或取反后跑最大子数组和）。答题时先复述确认题意，说明口径转换，再写代码并给出 O(n)／O(1) 复杂度。

## Q04：主流 Agent 架构有哪些，如何选型选择 ReAct 的？

### 面试回答

先给谱系再讲选型：单次调用＋结构化输出、固定工作流（含 DAG 编排）、ReAct 式推理行动交替循环、Plan-and-Execute（先出全局计划再逐步执行、可带重规划）、反思／评审增强，以及多 Agent 分工。选型看任务是否需要动态工具选择与中途反馈调整、步骤可预测性要求、时延成本预算与失败后果：流程稳定选工作流，长尾开放任务才用 ReAct，计划明确且长周期可试 Plan-and-Execute。选 ReAct 的理由应对应【真实需求】，并用同一任务集与基线对比证明收益。

## Q05：ReAct 如何防止死循环调用？

### 面试回答

多层兜底叠加：最大步数与总预算（耗时、费用、重试次数）；对（工具名＋规范化参数）去重，同参重复调用直接返回已记录结果或拒绝；无进展检测——连续 N 轮任务状态或证据集合无变化即退出；结构化错误反馈促使模型换策略而非原样重试；取消信号与人工接管出口。预算耗尽进入失败状态，不能当成功返回。

## Q06：你对 ReAct 有何理解，如何防止 Agent 执行任务过程中跑偏？

### 面试回答

ReAct 是把推理作为条件化于观察的显式步骤：模型基于任务与历史观察决定下一步行动，工具结果再作为新观察进入下一轮，形成“想—做—看”交替，本质是用外部反馈约束生成，比一次性长链推理更可纠偏。防跑偏：原始目标与约束每轮固定注入而非只出现在开头；计划外步骤需先对照目标验证；输出走结构化动作协议，运行时校验参数、权限与业务前置条件；检测与目标无关的重复动作和话题漂移，超阈值时重注入目标、降级到确定性路径或转人工；结束前做目标达成验证。

## Q07：Agent 架构中的 Prompt 设计有哪些经验？

### 面试回答

分层组织：角色与目标、能力边界与工具使用规则（何时调用、缺参先澄清、失败如何处理）、安全与授权约束、输出格式契约、稳定背景知识。经验核心是把可确定的规则下沉执行层，Prompt 只负责表达方法；易变内容用外部状态或 Skill 按需注入，避免越写越长互相干扰；每次改动在固定评测集验证并留版本，失败样本驱动迭代。

## Q08：如何体现 Agent 能力，保证 Agent 制作的内容达到之前人工制作的质量？

### 面试回答

以人工产物为基线做可核对的比较：取一批人工制作内容为金标，定义明确验收 rubric（完整性、正确性、格式规范、业务约束），让 Agent 在相同输入任务上产出并用 rubric 评分或人工盲评对比；指标看合格率、与人工均差、返工率和成本时延。生产链路上加生成后自动校验（格式、事实、规则断言）＋低置信人工审核，先并行运行观察质量再逐步放量。评测集与调优样本分开，防止只对样例有效。
