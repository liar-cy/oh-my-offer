## Q01：算法：求剩余空间最小值（非 Hot100，像“最大子数组和”的改编）。

### 面试回答

题面只记到“求剩余空间最小值、像最大子数组和改编”，完整约束未知，所以先确认题意再动手。

- 先向面试官问清两点：输入是什么形态、“剩余空间”怎么定义。
- 按最接近的常见口径——从数组中选一个连续段，让总容量减去这段和之后的剩余最小。
- 这个口径就是求最大子数组和，Kadane 一遍扫描即可。
- 如果直接要求最小子数组和，把 Kadane 的 max 换成 min（或者整体取反后再跑最大子数组和）。

说法顺序：先复述确认题意，再说明口径怎么转换，然后写代码，最后给出 O(n)／O(1) 复杂度。

## Q03：项目中的 ReAct 架构如何实现的？

### 面试回答

按【真实实现】填写。通用讲法是把循环走一遍：

- 加载任务状态，构建本轮上下文。
- 模型输出结构化动作（工具名＋参数），或者直接给最终结果。
- 运行时校验参数与权限，再执行工具。
- 把观察与状态写回，决定继续，还是经目标验证后结束。

要点在五个地方：

- 结构化的动作协议。
- 参数校验。
- 用调用 ID 把请求与结果配成对。
- 步数／耗时／费用三类预算。
- 明确的失败出口。

一句话边界：模型只提出调用意图，真正的执行与权限判断都在宿主侧。

## Q04：主流 Agent 架构有哪些，如何选型选择 ReAct 的？

### 面试回答

先给谱系，再讲选型。

架构谱系有这几种：

- 单次调用＋结构化输出。
- 固定工作流，含 DAG（有向无环图）编排。
- ReAct：推理与行动交替的循环。
- Plan-and-Execute：先出全局计划再逐步执行，可以带重规划。
- 反思／评审增强。
- 多 Agent 分工。

选型看四个维度：任务是否需要动态选工具、按中途反馈调整；步骤可预测性要求有多高；时延与成本的预算；失败的后果有多重。

落到结论：

- 流程稳定 → 选工作流。
- 长尾开放任务 → 才用 ReAct。
- 计划明确、周期长 → 可试 Plan-and-Execute。

选 ReAct 的理由要能对应【真实需求】，并且拿同一任务集跟基线对比，证明收益是真的。

## Q05：ReAct 如何防止死循环调用？

### 面试回答

思路是多层兜底叠在一起，不靠单点：

- 硬上限：最大步数，再加总预算——耗时、费用、重试次数都算进去。
- 调用去重：对（工具名＋规范化参数）去重，同参重复调用直接返回已记录的结果，或者拒绝。
- 无进展检测：连续 N 轮任务状态或证据集合没有变化，就退出。
- 结构化的错误反馈：把失败原因讲清楚，促使模型换策略，而不是原样重试。
- 留出口：取消信号、人工接管。

最后一条别漏：预算耗尽要进入失败状态返回，不能当成功返回。

## Q06：你对 ReAct 有何理解，如何防止 Agent 执行任务过程中跑偏？

### 面试回答

先说理解：ReAct 就是把推理写成显式步骤，而且这一步条件化于观察。

- 模型基于任务和历史观察，决定下一步行动。
- 工具结果作为新的观察，再进入下一轮。
- 这样形成“想—做—看”的交替，本质是用外部反馈来约束生成。
- 跟一次性长链推理比，它更可纠偏。

防跑偏按环节给五招：

- 注入：原始目标与约束每轮固定注入，不能只出现在开头。
- 验证：计划外的步骤，先对照目标验一遍再放行。
- 协议：输出走结构化动作协议，运行时校验参数、权限与业务前置条件。
- 检测：盯与目标无关的重复动作和话题漂移；超阈值时重注入目标、降级到确定性路径，或者转人工。
- 收尾：结束前做一次目标达成验证。

## Q07：Agent 架构中的 Prompt 设计有哪些经验？

### 面试回答

Prompt 按分层来组织，五块内容：

- 角色与目标。
- 能力边界与工具使用规则：什么时候调用、缺参先澄清、失败怎么处理。
- 安全与授权约束。
- 输出格式契约。
- 稳定的背景知识。

经验核心三条：

- 把可确定的规则下沉到执行层，Prompt 只负责表达方法。
- 易变的内容用外部状态或 Skill 按需注入，避免越写越长、互相干扰。
- 每次改动都在固定评测集上验证并留版本，用失败样本驱动迭代。

## Q08：如何体现 Agent 能力，保证 Agent 制作的内容达到之前人工制作的质量？

### 面试回答

一句话：以人工产物为基线，做可核对的比较。

评测怎么搭：

- 取一批人工制作的内容作为金标。
- 定义明确的验收 rubric（评分细则）：完整性、正确性、格式规范、业务约束。
- 让 Agent 在相同的输入任务上产出，再用 rubric 评分，或者做人工盲评对比。
- 指标看四个：合格率、与人工的均差、返工率、成本和时延。

生产链路上再加两道闸：

- 生成后自动校验：格式、事实、规则断言。
- 低置信的输出走人工审核。
- 先与人工并行运行，观察质量稳定了再逐步放量。

最后一条边界：评测集与调优样本要分开，否则只会对样例有效，上线就露馅。
