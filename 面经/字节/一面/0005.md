## Q02：介绍一下 LangGraph 这个框架。

### 面试回答

一句话：LangGraph 是面向有状态多步应用的编排框架，用图来描述流程。

- 三个基本概念：state 表示共享状态，node 表示处理步骤，edge 表示转移关系；图支持条件分支和循环。
- 配合 checkpoint（检查点）实现状态保存与中断恢复。
- 相比一次性的链式调用，它适合需要多轮工具调用、人工确认和失败续跑的任务。

项目中的真实用法按【图结构、状态字段、检查点配置】填写；简单任务不必上图框架。

## Q03：编排、tool 调用这几个流程是固定死的，还是比较自由的 agent loop？

### 面试回答

按项目实际说明，两种形态常混合使用：

- 固定编排：由代码或图定义节点顺序与分支。可预测、易验证、成本低，但覆盖不了意外情况。
- 自由的 agent loop：模型每轮根据观察决定下一步工具或结束。能灵活处理长尾，但需要步数、耗时和费用预算、终止条件与失败出口，且错误会跨步骤传播。
- 常见折中：主流程固定，在个别节点内允许模型自主选择工具。

哪种“更好”要用同一任务集比较成功率、延迟和成本，不能默认动态更高级。

## Q04：根因分析时如果发现置信度不够，后续是怎么去拿更多上下文的？

### 面试回答

项目真实机制按【实际实现】填写。通用做法是把“置信度不足”变成循环里的一个可执行分支：

- 扩大或改写检索：换关键词、放宽时间窗、增加 top-k。
- 调用更多采证工具：拉更长的日志窗口、关联指标、上下游依赖调用、变更与发布记录。
- 做时间线对比找差异点。

节奏控制：每轮补充证据后重新评估；设置采证次数与费用预算；仍不足时输出不确定结论、已排除项和需要人工提供的信息，而不是硬给一个根因。

一个前提：置信度本身要用标注样本校准，不能只凭模型自报。

## Q05：说一下 RAG 的概念原理，你这边怎么用的，内容在里面是怎么存储、怎么建的？

### 面试回答

一句话：RAG 把外部证据检索接入生成，让模型依据证据作答，从而降低幻觉。链路分两段：

- 离线：解析清洗文档、分块并保留来源，建立向量或关键词索引。
- 在线：理解问题、召回、过滤、重排并组装上下文，模型依据证据作答和引用。

存储和建法：通常是“向量＋元数据＋原文引用”——chunk 经 embedding 存入向量库，同时保存文档 ID、标题路径、版本、权限等结构化字段；检索后回原存储取全文组装。

项目用法按【真实链路】填写。效果用召回指标与引用正确率验证，不声称消除幻觉。

## Q06：从向量数据库检索完之后为什么要经过重排，直接取前几个不行吗？

### 面试回答

因为向量召回快但粗：

- embedding 把 query 和文档各自独立编码成向量，相似度只表示表示空间接近，对精确条件、否定词和多条件组合不敏感。
- ANN（近似最近邻）索引本身还是近似检索。

重排模型（cross-encoder）把 query 和候选文档拼在一起逐对打分，能建模交互细节，明显更准但慢得多，不可能扫全库。

所以标准做法是两段式：先向量召回扩大候选（如 top50—100），再对候选精排截断到 top5—10，同时做去冗余。直接取向量前几名，会把排序误差和冗余一起带进上下文。

## Q07：你的那个库里面的数据是有重复的吗？

### 面试回答

先如实回答项目现状：

- 有重复：说明发现方式（检索结果总是同一内容、评测时发现冗余）和治理手段。
- 没有重复：说明入库时做了哪些去重。

通用做法是分层检测：

- 完全相同：文件哈希。
- 格式不同、内容相同：规范化文本哈希。
- 近重复：MinHash／SimHash 指纹或向量相似度筛候选，再比对差异。

两个原则：去重要保留所有来源和版本关系，召回阶段也可按内容簇减少上下文冗余；相似不等于相同，版本差异里的一个数字可能正是关键。

## Q08：向量化的原理是什么？embedding 模型是怎么来的，为什么要叫向量？

### 面试回答

向量化就是用训练好的 embedding 模型，把文本映射成一串固定维度的实数。

- 模型怎么来的：多在大规模语料上以对比学习等方式训练——语义相近的文本对拉近、无关的推远。于是各维度成为模型学到的隐式特征组合，没有人工定义的“第几维是什么”。
- 为什么叫向量：因为它是一个有方向和大小的数值数组，可用余弦相似度等度量比较接近程度。
- 部署来源：调用商用 API 或部署开源模型；是否用业务数据微调，按【项目实际】说明。
- 检索约束：检索时文档与 query 用同一兼容体系编码，近邻候选再经校验和重排。

## Q09：embedding 模型和重排模型使用的是什么？

### 面试回答

这题必须填【项目真实使用的模型名称、版本与部署方式】，不能替项目指定型号。可补充选型依据：

- embedding：按业务评测集的召回表现、维度、上下文长度、语言和成本选择，常见为商用 API 向量服务或开源句向量模型。
- 重排：按 NDCG／MRR 提升与推理延迟，选择 cross-encoder 类模型。

同时说明两个约束：换 embedding 模型需重建全库向量；重排模型受候选条数与延迟预算约束。

## Q10：Deep Search 知道是啥吗？

### 面试回答

我会先确认指代：它不是一个有唯一标准的术语。

- 常见所指：“深度检索”类产品形态（如各家 Deep Research／深度搜索），由 Agent 围绕一个任务做多轮“改写查询→搜索→阅读→再检索”，跨来源交叉验证后，产出带引用的综合报告。
- 与普通 RAG 的区别：普通 RAG 一次检索即回答；它把检索变成带规划和预算控制的迭代过程。

若指某产品内的具体功能，实现细节以官方说明为准，我不猜测。

## Q11：RAG 相比直接使用一个向量数据库，就是多了切块和重排吗？

### 面试回答

不是。向量数据库只提供存储和近邻检索这一步；RAG 是端到端链路，多在很多环节：

- 检索侧：查询理解与改写、混合召回、权限与元数据过滤、重排去冗余、上下文组装与预算控制。
- 生成侧：约束模型依据证据作答和引用，证据不足时拒答。
- 离线侧：数据治理、增量更新和分层评测。

切块与重排只是其中两个环节；RAG 的价值主要在“答案有证据支撑且可评测改进”，而不是某个单独组件。

## Q13：文档切块把完整语义切断了，召回内容断裂，有没有办法优化？

### 面试回答

有，核心思路是让“召回单元”和“提供给模型的上下文单元”解耦：

- 切分方式：按标题、段落、代码块等结构切分，并保留重叠。
- 父子块：小块用于精准召回，命中后返回其父块或相邻块补全语义。
- 自带语境：chunk 前缀拼上文档标题路径与摘要，让孤立片段不脱离上下文。
- 特殊内容：表格、图注和跨段引用保持完整，或单独建摘要索引。

改动后用覆盖标注片段的召回指标验证，不凭感觉调块大小。
