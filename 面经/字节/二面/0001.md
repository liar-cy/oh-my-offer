## Q03：Think、Plan、Action、Observation 四个阶段分别保存什么状态，怎么影响下一轮？

### 面试回答

Think 保存本轮推理结论／动作理由摘要（不依赖获取模型隐藏思维链）；Plan 保存步骤清单与每步状态（待办、完成、失败）；Action 保存结构化工具请求：调用 ID、工具名与参数；Observation 保存工具返回或错误及时间戳。下一轮上下文由“目标＋计划进度＋最近观察＋未解决问题”组装：观察驱动模型修正计划，调用 ID 把请求与结果配对，已完成步骤避免重复执行。各阶段状态落库后还能中断恢复与排障回放。

## Q04：Agent 怎么决定继续检索，还是已经可以停止并给出答案？

### 面试回答

停止判定不由模型“感觉”独断：模型侧输出结构化的 final 动作或继续检索的动作，运行时再验证目标是否满足——必要证据是否齐、引用是否可核对、置信度是否过阈值；不足时把缺什么写回任务状态驱动下一轮。同时有硬预算兜底：步数、耗时、费用超限进入失败或人工处理状态，预算耗尽不能当成功输出。

## Q06：多轮检索怎么避免重复查询、循环调用和上下文无限增长，除最大循环次数外还有什么办法抑制循环？

### 面试回答

重复查询：对（工具名＋规范化参数）做去重缓存，同参数直接返回已记录结果；循环抑制除最大次数外还有：无进展检测（连续 N 轮状态或证据集合无变化即退出）、单工具调用与重试预算、结果收敛判据（新证据增量低于阈值停止）、结构化错误反馈让模型换策略而不是原样重试。上下文增长：每轮只注入计划进度与最近观察，旧内容结构化摘要并保留回查 ID，工具输出分页截断，按 token 预算强制裁剪。

## Q07：负向 Prompt 和“不要重复调用工具”这类简单声明有什么区别，怎么验证它是否有效？

### 面试回答

两者都是文字约束，区别只在泛化与具体：负向 Prompt 列一批禁止行为，具体声明针对单一动作；共同弱点是模型可能不遵守，且约束越堆越长互相干扰。可靠做法是把可确定规则下沉到运行时：执行层做参数去重、预算熔断和结构化报错，Prompt 只负责让模型理解何时该怎么做。验证有效性要在含易重复行为的评测集上统计重复调用率、无进展轮数与成功率，做加与不加的对照，不能拿个别成功案例证明。

## Q08：放到业务中，面对简单、中等、困难问题，怎么设计整体流程控制延迟？

### 面试回答

分级路由：入口用规则加小模型或轻量分类判断难度；简单问题走缓存或单次检索直接回答，秒级以内；中等问题走固定工作流（预定义步骤、并行取数、一次生成）；困难问题才进带预算的 Agent 循环，并先返回受理状态、流式输出中间进展。各层设延迟与费用预算，超预算自动降级到下一层的确定性路径；命中率、各层占比与端到端分位延迟持续监控。

## Q09：多 Agent 协同怎么设计，哪些功能放主 Agent、哪些放 Sub Agent，是否需要 Sub Agent？

### 面试回答

能一个 Agent 稳定完成就先用一个。需要拆的判断：子任务有独立专长、独立权限边界或需要独立上下文（如超长检索过程），且可并行。主 Agent 保留目标理解、规划、路由、状态汇总与对用户的最终输出；Sub Agent 承担边界清晰的专项（检索、代码执行、审核），交接结构化结果与证据引用而不是广播全部对话。是否拆分用同一任务集对比单 Agent 基线的成功率、延迟、成本与人工接管率，协调开销大于收益就不拆。

## Q11：能介绍一下 Java 的 GC 机制吗？

### 面试回答

GC 一般先从 GC Roots 做可达性分析判活，再按区域采用标记清除、复制或标记整理回收；分代收集按对象寿命组织回收频率，G1、ZGC 等是具体收集器的实现组合，不与算法混称。要点：回收只处理 JVM 管理的堆内存；并行与并发要分清；选型看暂停、吞吐、堆规模。按 Java SE 21／JDK 21 语境说明，项目收集器与参数按【实际配置】补充。

## Q12：既然有 GC，为什么还会出现内存泄漏？

### 面试回答

GC 只回收不可达对象；对象仍被可达引用“合法”持有但业务上已无用，就是泄漏，典型来源：只增不删的集合与缓存、未注销的监听器回调、未关闭资源、非静态内部类隐式持有外部实例、线程池中 ThreadLocal 未 remove、static 集合长期累积。堆外直接内存和线程栈不受堆 GC 管辖，容器 OOM 时 Xmx 不是进程上限。诊断看 Full GC 后老年代占用是否持续抬升，用堆转储与支配树定位持有链。

## Q13：能介绍一下 SSE 是什么吗？

### 面试回答

SSE（Server-Sent Events）是基于 HTTP 响应流的服务端单向推送：响应类型 `text/event-stream`，事件带 `data`、`event`、`id`、`retry` 字段，浏览器 `EventSource` 原生支持断线重连与 `Last-Event-ID` 续传。适合服务端通知、进度和 LLM token 流等下行场景；需要双向高频通信时用 WebSocket。上行仍走普通 HTTP，二进制需编码或换通道。

## Q14：算法：二叉树的直径。

### 面试回答

后序遍历：对每个节点，以它“经过的最长路径边数”＝左子树高度＋右子树高度，用全局变量取最大；返回给父节点的高度＝1＋max(左, 右)。时间 O(n)，空间 O(h)。原文记“直接秒”，未记录具体作答过程。
